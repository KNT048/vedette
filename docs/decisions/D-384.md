| D-384 | **vedette-host reports the IPv6 default route, each default gateway's MAC and the DNS servers in use; response seeds all of them as never-touch (closes the three limits of D-325).** `GET /v1/state/net` gains three optional fields, compatible both ways (no proto bump: core's client does not refuse unknown fields, and an older host simply sends none, so core seeds what D-325 seeded): (1) `resolvers[]`: the `nameserver` lines of `/run/systemd/resolve/resolv.conf` (the servers systemd-resolved queries, a DHCP lease's included) **and** of `/etc/resolv.conf` (followed when it is a link), without loopback stubs (`127.0.0.53`, `::1`), unspecified or multicast addresses, zone dropped, deduplicated, at most 16; a file read (no exec), opened `O_NONBLOCK`, regular files only, 64 KiB / 1024 lines. Both files, not "the second when the first is absent": either may be what a program on the box uses, and a stale file only adds an address to a protective list. (2) `default_route6 {iface, gateway, mac?}`: from `/proc/net/ipv6_route`, destination `::/0`, flags UP+GATEWAY and not REJECT, unicast next hop (link-local is normal: a router advertisement's), lowest metric, first on a tie; `gateway` is plain text with no zone and `iface` names the link. (3) `mac` on both routes: the kernel's neighbour-table entry for the gateway **on the route's card** (`NUD_VALID`, 6-byte unicast non-zero address), read with one netlink `RTM_GETNEIGH` dump through the standard library (`syscall.NetlinkRIB`, the same kind of request the `net` package already makes for the interface list; `AF_NETLINK` is already in the unit's `RestrictAddressFamilies`). The parser is pure Go over the bytes, bounded (8 MiB, a length that does not fit ends the read) and fuzzed. Core (`hostInfraOf`) seeds the IPv6 gateway, the resolvers and both MACs (`response.HostInfra.MAC`, labelled "Default gateway of this box"); a family with no route in an answer keeps its last gateway, and a gateway whose neighbour entry is missing for a moment keeps its last MAC (`keepGateways`). An IPv6 link-local gateway is protected by its MAC only: response's IP type never accepts a link-local address, so no action can name one. | Why: D-325 left a DHCP box with only its gateway protected (the lease's resolvers were missing), an IPv6 gateway unprotected, and a MAC-only action (switch quarantine by MAC, an event with no IP) able to reach the gateway unless it was an inventory router.
