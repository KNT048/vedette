| D-412 | **v1 host lab findings (L1 lab on fresh Ubuntu 24.04/26.04 VMs, walk 5 on a real box): the AppArmor repair reinstalls the package the installer keeps, a `port_in_use` update failure names the program, no unused honeypot log folder, cloud-init netplan stays read-only in v1** (supervisor, 2026-11-13). (1) **AppArmor profile missing** (D-458 (5)): the postinst message and RUNBOOK §8.5 gave `apt-get install --reinstall … vedette-host`, which fails on every appliance: no apt source carries `vedette-host` (install.sh installs the release's `.deb` from a file). Both now give one command, the same text (a `deploy/deb` test compares them): `dpkg -i --force-confmiss --force-confdef --force-confold /var/lib/vedette-host/selfupdate/packages/vedette-host_$(/usr/lib/vedette/vedette-host -version)_$(dpkg --print-architecture).deb`, i.e. the package install.sh keeps under its SemVer name for the host's own rollback (D-316) and that `adoptHostPackage` keeps for every later self-update; `--force-confmiss` is what brings back a deleted conffile, `--force-confdef --force-confold` keep every other conffile as the applier does. Re-running install.sh is no repair here: apt sees the same version installed and changes nothing. RUNBOOK adds the fallback when that file is missing (a self-update stopped half way): download the same version's asset from the release page and check its sha256 against that release's install.sh before `dpkg -i` (Opus r1). (2) **`port_in_use`** (D-455): the host already names the holder from `/proc/net/*` and `/proc/<pid>/fd` (no program run, no shell), but core turned the code into the generic "the operating system helper could not do this". Core now reads the ports and programs from the head of the host's message (`api.PortsInUse` in `host/api`, the one parser; the host's own test parses its real message with it, so the two cannot drift) and the run says e.g. "Vedette could not switch to 1.4.0: port 8765/tcp (python3, pid 4242) is used by another program on the box. Stop that program or move it to another port, then try again."; only printable ASCII is taken, and a message of another shape gives the same sentence without names ("the box log names it"). Still fail-closed: nothing about the refusal changes. (3) **`/var/lib/vedette-honeypot/log`**: the honeypot's log is the `vedette-hp-log` tmpfs volume since D-318, so the postinst no longer makes the folder (nor checks it: one made before is the container's after `:U`, D-162); boxes installed earlier keep the empty folder until `install.sh --uninstall` removes `/var/lib/vedette-honeypot`.
