(2) **Only the CISA KEV CVEs without NVD ranges** (none stored, or NVD's answer has no vulnerable entry), never-read first, newest KEV entries first; one request per CVE carrying only the CVE ID, 1 s apart, at most 60 a pull, each CVE read again after 12 hours; hourly, and right after a CISA pull that brought new CVEs (after EPSS and NVD), so a new exploited CVE is matched once, with ranges. A busy answer (429, 5xx, timeout) is tried again after 6 s and 30 s (or Retry-After, at most 2 min); a source still busy ends the pull with what it read (the rest next pull), and a pull that read nothing is a feed error with the usual back-off. (4) **A CVE.org list closes nothing unless it is complete** (review H2): CVE JSON 5 reads a missing `defaultStatus` as "unknown", and CNAs often list only the branches they still support. Otherwise (`cve.org-partial`) the rows may raise a version match, but a version outside them stays a product finding (findings turns that No into Unknown). **NVD wins**: `feeds_affected_cve.source` (`nvd`/`cve.org`/`cve.org-partial`); an NVD answer with ranges replaces CVE.org's (and NVD's full pull never deletes CVE.org rows); an NVD answer with no vulnerable entry leaves them; a later CVE.org record without usable versions removes its own old rows.
