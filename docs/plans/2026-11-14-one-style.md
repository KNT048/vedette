# One style: adoption note for Emily's pages (D-543, S-UI-1)

Owner: **Mlee** (Emily's modules). Kiên-side pages are already on the frame: Scans, Response, Reports, Devices, Honeypot, device detail, Settings menu (D-464, D-466, D-471, D-543).
This note says what each of Emily's pages should get, so every page in the main menu looks and works the same. It is layout only: keep every text, behaviour and test id.

## The kit (all in `web/src/components/common`)

| Need | Use | Rule |
|---|---|---|
| Title line | `PageHeader` (`PageHeader.tsx`) | title ~20 px, short description on the same line, actions on the right |
| Numbers that answer the page's question | `KpiStrip` (`PageFrame.tsx`) | at most 4 cells; each cell links to where the detail is (`?tab=<id>` or another page); only numbers a person acts on |
| More than one area on the page | `PageTabs` (`PageFrame.tsx`) | the open tab in `?tab=<id>`; a red count only for work that needs the person now; a tab the role may not see is left out of `tabs` |
| A page-level state (broken, needs you, information, off) | `Notice` (`PageHeader.tsx`) | `tone` = danger / warn / accent / off; title, one paragraph, actions on the right. Replaces hand-made `rounded-md border border-danger/40 bg-danger-soft …` boxes |
| A block with a heading | `Section`, `Panel`, `KeyValue` (`PageHeader.tsx`) | unchanged |
| Empty, error, loading, module off | `EmptyState`, `ErrorState`, `Loading`, `ModuleOff` (`States.tsx`) | unchanged |

The gate in `PageFrame.test.tsx` fails when a feature file imports `@/components/ui/tabs`; a small switch inside one block (like the incident's per-channel preview) is the only allowed exception and is listed there.

When a page moves: old `#hash` links to its sections must land on the right `?tab=` (see how Response does it), keep other query parameters, and leave any other hash (`#main` of the skip link) alone. Each PR adds its tabs to the page's story and runs `e2e/qa/frame.spec.ts` with the page added to `PAGES`.
