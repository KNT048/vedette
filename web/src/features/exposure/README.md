# features/exposure

Story: S-EXP-1 (domain or public IPs the box finds itself → prove ownership → an administrator's first Scan now (D-473) → list subdomains, IPs, open ports, exposed admin interfaces, expiring certificates; daily snapshots and comparing two days).
LEGAL §3 rule: no scan unless ownership is verified, and the commitment ("my company owns this and I am authorized to scan it", with who and when) is recorded. The "Scan now" button is locked with a reason, and the API returns 409 `not_verified` / `expired` / `txt_missing`, or 400 `commitment_required`, if called directly.
Ownership: a domain = DNS TXT record `vedette-verify=<token>`, re-checked right before every scan (missing = blocked). A public IP = only an IP this box itself uses to reach the Internet; no endpoint takes an IP as input (typing one is 400 `ip_not_allowed`). Private, reserved and CGNAT results are refused (400 `not_public`); verification attempts by people are limited to 10 per hour; everything is audited.
Public IPs, auto-detect (kien 2026-11-09): the section "Public IPs of this box" has an auto-detect switch (on by default), a check interval (1 min to 24 h, default 60 min, only shown while auto-detect is on), "Detect now" and the IP list with last seen, expiry and Remove. The box asks three public "what is my IP" services (checkip.amazonaws.com, icanhazip.com, ifconfig.me/ip) over several rounds of new connections at first start and then every interval, accepts an IP only when at least two agree in a round, and adds or renews every IP that passed (several IPs behind a load balancer are all found). An IP is valid for 30 days after the box last saw it (`verified_at` = last seen, `expires_at` = +30 days, `validity` expiring at 5 days or less); it expires only when the box has not seen it for 30 days. Turning auto-detect off keeps the list. A removed IP comes back if the box keeps using it while auto-detect is on. API: `GET /exposure/targets` carries `box_ip {auto, interval_min, last_run}`; `PUT /exposure/box-ip/settings`; `POST /exposure/box-ip/verify` ("Detect now", `{items, message}`); remove = `DELETE /exposure/targets/{id}`.
Mock tables: `exp_targets`, `exp_snapshots`, `exp_commitments`, `exp_attempts`, `exp_settings`. DNS simulation: the first TXT check of a new domain says "not found", from the second it is found. The mock runs the automatic check when `GET /exposure/targets` finds it due (no timer). Box egress simulation: localStorage `vedette-mock-egress` is a comma separated list of the public IPs the box currently leaves through (default `203.0.113.10,203.0.113.11`, a load balancer), , `offline` when no service answers, or `disagree` when they never agree.
For the scan module: `exposureTargetsStore` (kind, value, verified_at, expires_at), `exposureSnapshotsStore`, `exposureCommitmentsStore`; or `GET /api/v1/exposure/targets` and use only `scannable` targets.
Roles: add/delete target, auto-detect settings, Detect now, the first Scan now of a target = admin with two-step sign-in (it records the commitment, D-473); re-check ownership, scan now = operator; view = viewer.
Slots: none provided, none consumed.
Scan-time check (INV-13): `exposureIpPaused` (used by `POST …/scan` and by the `scan` mock's `POST /scans/runs`) answers 409 `ip_not_current` unless a check of the last 5 minutes saw the IP; otherwise one full check runs, and its answer (a "not seen" included) is reused for 5 minutes. Tests move the clock (`vi.setSystemTime`, Playwright `page.clock`). Audit of the box's own runs: only on change (INV-11), a person's click always. `GET` shows the same state without probing: `blocked_reason: ip_not_current` while the last full check that got an answer (`exp_probe.full_ok_at`, a failed check does not move it) did not see the IP and nothing has seen it since; no time window, it stays until a later check sees the IP (the page says "Scans paused", the list "Paused", Scan now stays locked and "Verify again" is the way to check). `box_ip.retry_in_min` is the wait when the 10 attempts an hour (shared by Detect now, Verify again and the DNS Check) are used up. Dates: `dates.ts` (feature-local, "9 Nov 2026, 21:01").
