# Scan Contract

> Tier: optional · Story: S-SCAN-1…4 · Last verified: 2026-11-21 (every statement checked against the code)

Source of behaviour: `web/src/features/scan/{contract,mocks}.ts`. The `/scans/credentialed*` part of the same `contract.ts` belongs to the `scan-credentialed` module.

## Invariants
- **INV-1**: Internal targets: `inventory` `lan_ranges` ∖ `exclusions` ∖ `scan.config.exclusions`, `approved`, and `inventory.VulnScanPolicy(asset, explicit)` (not the `ScanPolicy` of probing scans; the `scanning_off` switch does not apply). Always refused: `regular_scan=never` (`regular_scan_never`), no IP, out of scope. The box itself is `pick_only` as below, with `box=true` on `ScanTarget` so the GUI can say why (the picker: "pick it to scan", and Select all says it needs its own tick); the scheduled scan and the KEV re-scan skip it (note "The Vedette box itself: scanned only when you pick it in Scan now."). Fragile devices, unclassified ones (`kind=unknown`) and hand-declared ones are scanned only when the user **picks them by hand** in "Scan now" (`explicit=true`, writes `core_audit` with the person who clicked); fragile and unclassified ones run at `max(1, rate/4)` (`fragile=true` on `ScanTarget` for both); the scheduled scan and the KEV re-scan skip them (a `skipped` result row with the reason). These devices carry `pick_only=true` on `ScanTarget`; the GUI **never pre-ticks** them (not by "has findings", not by "Select all"/"Only devices with findings", not by `?target=`), so every id in `POST /scans/runs` is one the user ticked and the backend treats each id as one pick. External targets (`exposure`) are listed but **not scanned in this version** (`not_supported`). Each target is checked again just before the job is sent: if it no longer qualifies → dropped, not sent (one `VulnScanPolicy` read for that device alone). The target list, "Scan now", the schedule and the KEV re-scan read the policy of every device with **one store read** (`Inventory.VulnScanPolicies`, two passes: with hand picks and without), not device by device; the result is exactly the same as per device (the tests in `batchpolicy_test.go`). Reasons a target cannot be picked: `unapproved | excluded | out_of_scope | no_ip | regular_scan_never | unverified | expired | not_supported` (`no_ip`: a device in the inventory has no IP, for example declared by hand or seen only through LLDP, not "out of scope"). `ScanTarget` also carries `mac`, `vendor`, `approved`, `last_seen` only for the picker's search and filter, and they enter no decision. `TestContract_INV1_TargetsInScope`, `TestContract_INV1_PolicyCheckedRightBeforeTheJob`
- **INV-2**: No scan when `inventory.scope_confirmed_at=null` (400 `commitment_required`; `can_scan=false`, `block_reason`). External targets: call `exposure.CheckScannable` right before the scan (SYS-7). Scanner not ready (no heartbeat from the `scan` worker, or the heartbeat reports that nuclei or the template pack is missing): `can_scan=false` with `block_reason`, `POST /scans/runs` → 503 `scanner_unavailable`, the scheduled job and the KEV re-scan send nothing (the event stays waiting).
- **INV-3**: One run at a time (409 `already_running`); each `POST /scans/runs` has 1…200 targets (400 `no_targets`/`too_many`); an unknown id is 400 `unknown_target`; a target that cannot be picked is 400 `out_of_scope`.
- **INV-4**: Template limits: only Nuclei templates of the signed content pack, through the no-state-change rule (set `kev`: only templates that a person has read, by sha256; set `deep`: also read-only GET/HEAD): the `kev` set (`kev,vkev`) for every non-full job (LAN scan, the read-only `own_ip` check), the `deep` and `disruptive` sets only for exposure's full job (below); each template sits under `http/`, `network/` or `ssl/` (`pack.Parse` refuses any other path: nuclei runs `-pt http,tcp,ssl` and would skip such a template without printing a line, so a template in the pack always runs: `scripts/scanpack` selects templates only through the top-level YAML key filter plus the directory rule `pack.RunsUnderProtocols`); no DoS outside a full + disruptive job (FORBID-2); **in every set: no state change, no other destination, no third party**: no template changes or resets a password, creates an account, writes SQL (`INSERT`, `UPDATE … SET`, `DELETE FROM`, `INTO OUTFILE`, `xp_cmdshell`), writes a file (a shell redirect, `file_put_contents`, `fwrite`, a multipart file upload), resets an application, sends a write method (only `GET HEAD POST OPTIONS PROPFIND TRACE`, no method override), sends to another host or port than the job's (`@Host:`, a path that does not start with `{{BaseURL}}`/`{{RootURL}}` or that has another port, an absolute request line, a network host with a fixed port), or makes anyone call a third party (an absolute URL to a public host, including inside base64; following a redirect to an out-of-band host); the tags `intrusive`, `instrusive`, `file-upload`, `file-write`, `upload`, `account-takeover`, `osint`; and the list of ids read by hand, `scripts/scanpack` `denylist` (each id with a reason; re-read every time `NUCLEI_TEMPLATES_VERSION` is raised). The builder decides on the YAML (`changeReason`), and the worker re-reads every template file of **every** job with `pack.NoChangeText` before nuclei (`invalid_job`). **The rule is an allow list**, like the default "safe checks" of Nessus: with no tick (the `kev` set and the `deep` set), a template gets in only if (a) every request is an HTTP GET/HEAD with no body, no header or variable carrying login information, every destination and header value passes `pack.RequestPayloadOK` and calls no action (`getVerbRE`), and the id/name does not describe a change (`stateNameRE`) (for the `kev` set rule (a) only puts a template in the "read first" group of the queue, it does not put it in the pack by itself, nor does the `own_ip` mark; the `deep` set still accepts rule (a)); or (b) it is in `scripts/scanpack/reviewed.tsv` with the exact sha256 of the file a person has read (a changed file → `make scan-pack` stops until it is read again). The remaining templates may still **confirm a vulnerability by reading** (reading a file through path traversal, a page that should not answer, the result of a harmless command such as `id`; four reviewed templates run `cat /etc/passwd`, `id`, `ipconfig`) and nuclei keeps up to 4 KB of the answer as evidence; this does not mean "not exploiting", it means that nothing known is created or changed and nothing is sent to anyone else. The `kev` set: **every template has been read by a person (by sha256)**, 327 templates, all in `reviewed.tsv`, `own_ip` 185; the worker re-checks only the text rule of step 1, the already-read rule lives in the builder and the signed index; KEV templates waiting to be read are in `scripts/scanpack/kev-review-queue.md`. `scripts/scanpack` `TestNoTickRule`, `TestReviewedListFormat`, `TestReviewedNeedsTheSameFile`, `TestDestinationHoles`. `scripts/scanpack` `TestBuildLeavesOutStateChangesAndOtherDestinations`, `TestDenylistIsOutOfTheCommittedPack`; `pack` `TestNoChangeText`, `TestChangeInRequest`, `TestThirdPartyURL`; worker `TestNucleiRefusesATemplateThatChangesTheTarget`. `dangerous_checks` is always `false`; `PUT /scans/config` with `true` → 400 `dangerous_locked`. nuclei is a pinned binary in the `vedette-scan` image, run at the worker through the sensor protocol; a job carries only template ids and the pack hash, and the argv is built and checked by `modules/scan/nucleiargv`. The worker's grammar (`nucleiargv`, the last barrier when `core` is taken over) is as narrow as `nmapargv`: only numeric private IPv4 (RFC 1918 or the shared RFC 6598 range 100.64/10, `core/localnet.Addr`; not .0/.255; never 100.100.100.200, Alibaba Cloud's metadata point inside 100.64/10, because nuclei keeps up to 4 KB of the answer as evidence), no domain names, no public IP; protocols only `-pt http,tcp,ssl` (no dns/whois/javascript/websocket/headless/code/file), `-dr` (do not follow redirects), `-nh` (no httpx probing), `-ni`, `-duc`; each template is one `-t <TemplatesDir>/<path>` taken from the checked index (the whole folder is not loaded). The worker runs nuclei with a clean environment: no `ENABLE_CLOUD_UPLOAD`, `PDCP_API_KEY`, `*_PROXY`, no `~/.config/nuclei` (HOME on tmpfs), an empty read-only working directory. **The pack has three sets.** Each index entry carries `sets`: `kev` (exactly the rule above: 327 templates, 185 `own_ip` in pack 2026.11.5, as step 2 above; `pack.Index.ForCVE` sees only this set, so the LAN scan and exposure's `own_ip` job are as before), `deep` and `disruptive` (the templates a **full** job of exposure may run: the target has accepted the testing terms, exposure INV-26). The rule of the full set (`scripts/scanpack` `fullSet`, `pack.Template.check`): only the directories `http/{cves,cnvd,vulnerabilities,exposures,misconfiguration,exposed-panels,technologies,miscellaneous,iot}`, `network/{cves,vulnerabilities,exposures,misconfig,detection,enumeration,backdoor}`, `ssl/` except `ssl/c2`, and `http/default-logins`, `network/default-login` (`disruptive` only); **always excluded at every depth**: a key outside `allowedKeys`, the tags `intrusive`, `fuzz`, `oast`, use of an out-of-band server (`pack.NeedsOAST`: interactsh variables/parts, hosts oast.*, interact.sh, burpcollaborator; outside `technologies/` also the matcher "Interactsh Server", `pack.FullText`), everything in the no-state-change rule above (write methods, state change, another destination, a third party, the tag `osint`…), user-name/password payloads and the tags `hardcoded-credentials`/`default-credentials` → `disruptive`, `fuzzing`/`race`/`pipeline`/`threads`, payloads read from a file or over 64 combinations, a nuclei id that reads as a flag; the tags `dos`, `brute-force`, `default-login`, `authenticated` (`nucleiargv.DisruptiveTags`) → `disruptive`. `CVE` is optional outside the `kev` set; a template outside `kev` carries `name`, `severity`; `generic` = a deep `http/` template of exposures/misconfiguration/exposed-panels/miscellaneous that names no vendor/product and carries no product tag (`pack.ProductTags`). `dos` is allowed only in an entry with exactly `sets: ["disruptive"]`. **The full-set rule**: the `deep` set (no tick) follows exactly the no-tick rule above (read-only GET/HEAD or `reviewed.tsv`; the TLS checks of `ssl/` have been read and listed); a template from a full directory that does not pass that rule (POST, network, login headers, injection-style payloads…) and is not a lasting change → `disruptive` (after a tick); a lasting change (a webshell, enabling a backdoor or service, creating an admin, resetting or changing a password, injecting a script into a page, overwriting settings, deleting logs or files) → in no set, through the `denylist` and the name rule `stateNameRE`. Pack 2026.11.5: 7206 templates, `kev` 327 (all read), `deep` 5222, `disruptive` 1981, `generic` 1238; a network template with a fixed `port:` is excluded, so 5 network templates remain, all `disruptive`. Index limits 12 MiB, 20,000 templates. `content/nucleipack` `TestFullSetsOfTheCommittedPack`, `pack` `TestParse_Sets`, `TestFullText`, `TestLimitsHoldTheMeasuredPack`, `scripts/scanpack` `TestBuildSets`.
- **INV-5**: Configuration: `window.days ∈ 1..7` (1=Monday, 7=Sunday) at least one day, `from/to` HH:MM; `rate ∈ 1..20` requests/second; `exclusions` ≤ 200 IPs/CIDRs; `unresponsive_after ∈ 2..20`. Wrong → 400 `invalid_config`. **When the regular check runs is not here:** it is the `core_schedule` row `scan.vuln` (core/schedule, the shared editor; default weekly on Sunday at 23:00 inside the scan window). When it comes due `Service.startScheduled` queues one `vuln_check` run (trigger `schedule`, `core_run.schedule_id`) in the schedule's transaction, over the devices that need no hand pick, and the run stops by itself when the window it was held for closes; it skips, saying why, while the scope is not confirmed, the scanner is not ready, another check runs or the organization zone cannot be read.
- **INV-6**: Auto-stop: when `stop_on_unresponsive` is on and a device does not respond (nuclei meets `unresponsive_after` errors on that device, which is the job's `-mhe`; counted per **device**, within one run, not the number of consecutive devices), the run changes to `auto_stopped` with `stop_reason` ("… stopped responding after N failed requests"); that device is not hit with further requests. "Not responding" can be seen in two ways: every line nuclei prints is an error (a device that was dead from the start; with `-ms` nuclei prints one line per template × target), **or** the worker reports (`Outcome.HostErrors`, counting timeouts per target from nuclei's error log) that **every** target of the job is `unreachable` (the timeout count ≥ `unresponsive_after`), **even if it answered a few templates earlier** (it died midway); a target that has not reached the threshold does not count. A matching line that it gave before dying is still recorded as usual (`ConfirmFromScan`, the `matched` row and probe); the rest of that device is `no_response`. "Stop now": the status `stopping` and then `stopped` within ≤ 5 seconds; stopping a run that has already ended → 409 `not_running`.
- **INV-7**: Every probe request writes `ProbeEntry {ts, run_id, ip, label, template, request, result}` **before** the job leaves `core` (in the same transaction that queues the job), `result ∈ matched|not_matched|no_response|banner|stopped|not_run|refused` (`stopped`: on its way when "Stop now" was pressed; `not_run`: handed to nuclei but the run ended and nuclei printed no line for that template, so the template did not run; `refused`: the worker refused the job (the own-IP barrier), nothing was sent), kept ≥ 90 days (`retention_days`), downloadable as CSV; written even when stopped. One row per (device, template); a row still being sent has `result=NULL`: `GET /scans/probes` does not list it yet, and the CSV writes `in_progress`; if the box restarts mid-run that row becomes `stopped` (an orphan run is closed before the next one). The CSV blocks spreadsheet formulas (a cell starting with `= + - @`, tab or CR gets a `'` added).
- **INV-8**: Each device's result is one of `matched | not_matched | not_applicable | no_template | no_response | skipped`. "Confirmed yes" (`matched`) is separate from "suspected by version": only `matched` calls `findings.ConfirmFromScan` and carries `finding_id`, the shortened evidence (request/response), `confidence`, and a way to re-check it yourself (S-SCAN-3). `scan` calls `findings.ConfirmFromScan` directly through the `Findings` gate (it gets the `finding_id` at once, errors are logged), and that is the only call: a non-matching line with no evidence means "not affected" (`-ms` is `-matcher-status`, nuclei prints one non-matching or error line per template × target), so `not_matched` and empty output only mean "no match reported", never "no vulnerability"; they never close, downgrade or write anything on a finding (no path closes a finding from an empty scan result), the GUI says "No match reported" in a neutral colour, and empty output is not by itself "not responding" (INV-6 only when there are lines and every line is an error, or when the worker reports that every target is over the timeout threshold; empty output with no host error stays "no match reported") and still emits `scan.finding.confirmed` for others; `findings` does not subscribe to that event (to avoid confirming twice). The template is chosen by the device's findings ∩ the template pack; a CVE with no template → `no_template`, and no pack leaves the box; evidence: request ≤ 2 KiB, response ≤ 4 KiB, valid UTF-8, control/bidi characters dropped, the `summary` has the sentence "To check it yourself, run: nuclei -t … -u …". One template on one device: one matching line is enough (`matched`); "not matched" only when there is a non-error answering line; a template that needs out-of-band interaction (tag `oast`) is refused by the pack, so with `-ni` there is never a false "no match". The self-check sentence uses the job's own target that matched (`-t <path> -u <input>`), never an output field.
- **INV-9**: KEV re-scan (S-SCAN-2): when `feeds.vuln.new_kev` has `has_template` and the template is in the installed pack, scan only the related assets within ≤ 60 minutes if `auto_rescan=true`; every event writes `RescanEvent {cve, product, devices, latency_min, run_id, result ∈ matched|clear|skipped_off|no_match|pick_only|stopped|expired_no_template|expired_scanner|expired_zone}`. `auto_rescan=false` → write `skipped_off`, do not scan. It does not follow the time window; the scheduled scan does. **Catching up**: the bus is best effort only, so each pass of the re-scan job first reads one page (≤ 100) of records of what feeds has announced (`KEVFeed.NewKEVSince`, from the read point `scan_setting.kev_read_at/kev_read_cve` of the last entry read) and writes them as `OnNewKEV` does, with `ts` being the time feeds announced it (the latency is real); the rows and the read point are written in one transaction, an entry that already exists (from the bus) is left alone, so it can be repeated; an entry with no template or announced more than 7 days ago is skipped (the read point still advances; the schedule still covers their devices); if feeds fails to read, it logs and the queue still runs. The events ready in the same pass share **one** `new_kev` run (a long queue does not scan CVE by CVE): only the templates of those CVEs, in total ≤ `nucleiargv.MaxTemplates` templates, ≤ 200 devices (an event over that waits for the next pass), each event is linked to the run in its own transaction, and when done it closes by the row of its CVE's template and keeps its own devices. Implementation: `feeds.vuln.new_kev` (with `has_template`) only writes one waiting `scan_event` row (one row per CVE; `product` is a single lowercase line: control/format/bidi characters dropped, whitespace merged, ≤ 300 characters); a job every minute examines at most 100 waiting events, oldest first, an event that fails is logged and retried the next minute and does not block later events: `auto_rescan=false` → `skipped_off`; wait 1 minute for inventory/findings to finish matching; the template is not in the installed pack yet → wait; a scan is running or the scanner is not ready → retry the next minute, **before** reading findings and devices; waiting over 7 days (the template did not arrive, the scanner was not ready, or the time zone could not be read) closes the row with the matching `expired_*`, shown in the log, and the reason is logged; no device has an open finding for the CVE → `no_match`; there are matching devices but all can only be scanned by hand pick (fragile, unclassified, hand-declared) → `pick_only`, `devices` are the names of those devices, the GUI says "Not scanned automatically: N devices need a hand pick in Scan now" with a link to Scan now; otherwise one `new_kev` run with only the templates of that CVE and only the automatically scannable devices, outside the time window; the run row and the event's `run_id`/`latency_min`/`devices` link are written in the **same transaction**; the run ends → `matched` if there is a match; a run that stops before every device is done (Stop now, auto-stop, shutdown) → `stopped`, the GUI says "Stopped before the end: see the run" with a link to the run; otherwise `clear`: `clear` only means "no match reported" (the GUI says "No match reported"), never "not affected", and does not close, downgrade or write anything on a finding; `latency_min` = from when the event was written until the run started. Scheduled scan (S-SCAN-4): run by `core/schedule` (INV-5); the scan window is read in the **organisation's time zone** (`Config.Location func(ctx)`, `cmd/vedette` `orgLocationAt`; not wired → UTC; wired but unreadable (a timeout, an error, a name that is not a time zone) → **no automatic run starts**: the schedule keeps its due mark (`schedule.Hold`), re-scan events wait (after 7 days they are dropped like a scanner that is not ready), and a warning is written each time; never the process's time zone). One run per due mark, only while the scan window is open (when closed the schedule keeps the mark until it opens), only automatically scannable devices, stopping by itself when that window closes (`stop_reason` says so); a mark that meets a running run, a scanner that is not ready or an unconfirmed scope is kept and retried; if no device can be scanned the mark is dropped with the reason (`schedule.Skip`). The schedule run and `core_run.schedule_id` are written in the schedule's transaction (`startTx`). Remaining, stated plainly: the run starts after the transaction commits; a shutdown at exactly that moment leaves a running run row, `core/run` `Recover` closes it as `stopped`, and that mark or event counts as used (the event becomes `stopped`). The probe log keeps 90 days, `scan_event` one year (job `retention`).
- **INV-10**: Responses from outside/inside devices are untrusted data (SYS-6): evidence is truncated to a fixed cap, stored as text, escaped on display. `nucleiout` fails closed (a line that cannot be read reliably or a template the job did not name → the whole run is dropped), **except** a valid JSON line for a template the job did name that cannot be a result of the job's host:port that the job did not name, an unreadable target (a bare name, IPv6, a name with `_`, a missing port; the host is stored as `(unreadable)`, never the original text), no `matcher-status`, a match with an error: skip that line, count it (`nucleiout.Skipped`: the number of lines, the number of lines that say a match, at most 20 templates), it never becomes a result, and the run is kept. Only broken JSON, a template outside the job and output over the cap drop the whole run. The number of lines and the template + host + port of the first line (checked, ≤ 64 characters) go into core's log and **after** the `request` of the probe rows of those templates, cutting the note and never the request (`AppendNote`: " [not counted: N nuclei line(s) that could not be a result of this check (another address, an unreadable target, no match status, or a match with an error)…]"); a template all of whose lines were skipped still **ran**, "No match reported" (`not_matched`), never `not_run`; **except** when a skipped line says a match (`Skipped.MatchedTemplates`): that template **never** reads "no match reported" but is inconclusive on every target of the job: no finding, a result row `no_response` with the note "nuclei reported a match it could not tie to this address; check by hand" (LAN: the result row and the probe; exposure: the result `error` and the note on the probe row); a template beyond the 20 that `Skipped` lists (`MoreTemplates`) that has no result gets the probe row "not run (over the cap of 20 templates per run)". `TestSkippedMatchIsInconclusiveNeverNoMatch`, `cmd/vedette` `TestExposureTemplatesSkippedMatchIsInconclusive`. Another way of writing the job's own target (a URL with the scheme's default port, "host:port" in `host`) still maps to that target. The line shapes of the pinned nuclei 3.11.1: `nucleiout/testdata/shapes.jsonl` (`-dr`, so a redirect to another host/port is not followed, and the line still names the job's target). `TestRead_SkipsALineForAnotherTarget`, `TestRead_SkipsLinesThatCannotBeAResult`, `TestRead_EveryShapeOfThePinnedNuclei`, `cmd/vedette` `TestExposureTemplatesSkippedLinesAreNoted`, `TestForeignTargetLineIsSkippedAndTheRunKept`.
- **INV-11**: `scope.commitment` is read only from `inventory`; `scan` never writes a commitment itself.
- **INV-12** (the external-surface scanner, `exposure.Runner`, per LEGAL §3): `scan` owns the runner that `exposure` uses for `POST /exposure/targets/{id}/scan` (a leaf package `modules/scan/surface`, Go standard library only, run inside `core`; the adapter `cmd/vedette` `scanRunner`). It follows the switch of the `exposure` module, **not** of `scan` (v1 turns `exposure` on and leaves `scan` off): with `scan` off it still scans; with `exposure` off → 409 `module_off`, no probe at all; `exposure` turned off mid-run → the run's context is cancelled through `modreg.OnChange`, the run stops, nothing is saved, SYS-5; the `scan_probe` probe log is still written while `scan` is off; it does not follow `scan`'s time window, nuclei rate or exclusion list (those belong to internal devices; one run at a time and 10 minutes per target are held by `exposure` INV-12). It accepts a target **after** the `exposure` gate (INV-1, INV-13) and scans nothing outside the scope: (1) an **IP** (the box's own IP, already verified): checked again with `exposure.IsPublicIPv4` (now `core/egressip.IsPublicIPv4`), then (3)–(5). (2) a **domain**: look for names in the CT log at `https://crt.sh/?q=%25.<domain>&output=json&exclude=expired` (45 s, one retry, no redirects followed, reads at most 16 MiB, at most 1 MiB per cert); valid names under the domain, wildcards and e-mail addresses dropped, de-duplicated, **sorted** (the domain first); not complete JSON → an error, fail closed; no answer → stop, `exposure` 502 `unreachable`; **never truncated**: more than 300 names or more than 16 MiB → stop, `exposure` 400 `too_many` (a partial list would change by day and produce false new/lost rows and a false `new_port` event). **Further discovery (exposure INV-27)**, every lookup through the box's own resolver (`Config.Resolver`, the `Resolver` interface with `LookupNetIP`/`LookupCNAME`/`LookupMX`/`LookupNS`; tests use a fake resolver and send no DNS query): the domain's MX and NS (at most 10 of each; a host under the domain becomes a name of source `mx`/`ns`, a host outside the domain is not listed); a wildcard check with two random 20-character labels (if they answer → drop the common-names list, `Result.Wordlist` = `wildcard`); the common-names list `content/wordlist` (≤ 150, at most 20 lookups a second) keeps only names that resolve. The 300-name rule counts **every source** (CT + MX/NS + the list), still all-or-nothing. One `scan_probe` row of kind `exposure: dns` (`ip` and `label` are the domain: the `ip` column is NOT NULL 1–253 characters, `TestExposureDNSProbeRowFitsTheProbeLog`; `request` starts with the number of names so that cutting to 300 characters does not lose it) is written **before** the lookup and completed after. Every name is asked in full form (trailing dot) so that the resolver's `search` list never applies. The whole DNS phase has a `dnsBudget` cap of 60 s (MX, NS and the wildcard check in parallel; known names 32 at a time, the addresses and CNAME of one name in parallel; the common-names list 8 at a time, at most 20 a second); the wildcard check treats only "no such name" as no wildcard, an error or a timeout → drop the list (`WordlistNoAnswer`, fail closed); common names that do not answer in time → `WordlistCut`; a name whose address lookup has no clear answer (a server error, a timeout, the budget used up) is not in `Hosts` but in `Result.Unresolved` (a list of names; exposure copies their old rows over, INV-27); the domain itself having no clear answer → `ErrDNS` (exposure 502 `unreachable`, nothing is saved). The 5-minute cap of the whole run is the sum of the phases at their worst (CT 90 s + DNS 60 s + ports ~8 s + pages ~113 s). `Addr.Contacted` marks an address that the check by name reached (the first public IPv4 of the name). Special IPv6 (NAT64, 6to4, Teredo, documentation, discard, ORCHID, site-local) is `private` (for display only). A + AAAA lookups (`"ip"`) and the final CNAME of each name (5 s, 32 in parallel); a DNS answer is untrusted data: names/CNAMEs must pass `nameRE` (≤ 253), at most 16 addresses per name (IPv4 first, each family sorted). A name that has addresses or a CNAME becomes a `hosts` row (`Host {Name, IP (the first IPv4, empty when none), Source ct|dns|mx|ns|wordlist, CNAME, Addrs [{IP, Class box|public|private}]}`); `box` = an address that `mayScanPorts` (exposure `ScannableIP`) accepts, `private` = not public (IPv6: not global unicast, ULA or documentation range), the rest `public`. A name with a public address: only a **web-page check by name** at ports 80 and 443 (one `GET /` per port, connecting to the first public address, the certificate of 443). A public address is **port scanned** only when `exposure.ScannableIP` (with the person who clicked as the actor) returns `true`: it is a verified IP of the box that has a commitment and is still in use; an error → no scan. (3) **Ports**: a TCP connection (nothing sent, closed at once) to a fixed list of 99 ports that are often exposed to the Internet (`commonPorts`, from the leaf package `modules/scan/commonports`, always inside the `-sV` pass of sensor-active's `external` nmap template, after nmap's pass over the 1000 most common ports: web/admin, remote access, file sharing, databases, mail, VPN, devices and remote management), 1.5 s per connection, at most 300 new connections/second and 100 at a time; no UDP; `service` is the port's usual name. An address where a connection got a TCP reset (`ECONNREFUSED`, a closed port) is in `Result.Refused`: it answered even with nothing open (exposure INV-22), `TestIPScanSaysTheAddressAnsweredWithResets`. ## Forbidden
- **FORBID-1**: Scanning a target outside the scope or not yet confirmed; scanning with no scope commitment.
- **FORBID-2**: A template outside the safe set; turning on `dangerous_checks`. **The only exception**: a template with the tag `dos` (and `brute-force`, `default-login`, `authenticated`) runs only inside exposure's **full + disruptive** nuclei job (the target has accepted the testing terms **and** the separate tick for disruptive checks, off by default), from the `disruptive` set of the pack; in that case the argv's `-etags` drops `dos` (`nucleiargv.FullForbiddenTags(true)` = `intrusive,fuzz`). A full job without the tick: `-etags` = `dos,intrusive,fuzz,brute-force,default-login,authenticated`. LAN and `own_ip` jobs are unchanged: `dos` never runs. `intrusive` and `fuzz` never run at any depth. `nucleiargv` `TestFull_*`.
- **FORBID-3**: Running two runs at once; exceeding `rate`.
- **FORBID-4**: Writing the `inv_*`, `mit_*`, `exp_*` tables directly (go through an interface).
- **FORBID-5**: Sending scan results out of the box.

## Tables owned (`scan_`)
`scan_setting` (one row, columns with a CHECK like `exp_setting`: auto-stop, auto re-scan, the KEV read point `kev_read_at`/`kev_read_cve`; it keeps no copy of the window, rate and exclusions: those belong to inventory; the schedule is the `core_schedule` row `scan.vuln`), `scan_probe` (`run_id` → `core_run`), `scan_event`. A scan run is a `core_run` (`kind=vuln_check`, lane `nuclei`) of `core/run`: each device is a step (total 1), each result row is a `core_run_item` (`subject_kind` `device`; a row with a finding has a `finding` item right after it; Scan now's identification is the items `identification` and `identified`). `runrows.go` writes and reads them back. Restart: `core/run` `Recover` records a running run as `stopped` with the reason "Vedette restarted" (it does not continue: the picks and CVEs of a KEV re-scan run exist only in the process that started it); a `queued` run that the new process has no information about ends `failed`. The status returned by the API: `queued`/`running` → `running`, `partial` (window ended, device stopped answering) → `auto_stopped`, `failed` → `stopped`.

## Behaviour when off
No `/scans*` routes (404), no schedule/re-scan jobs; no LAN nuclei probes. External exposure's "Scan now" **still runs** (the runner follows the `exposure` switch, INV-12) and still writes probes into `scan_probe`, readable again when `scan` is turned on. The `retention` job is cleanup (`Housekeeping`): it still runs every hour while off and only deletes probe rows older than 90 days and re-scan events older than 1 year, without scanning, sending or writing anything new (`TestTheRetentionJobRunsWhileTheModuleIsOff`). Findings stay `suspected` only (no new confirmation); "Scan" disappears in Devices. Configuration, history and the probe log are kept for ≥ 90 days.

## Stories and decisions
S-SCAN-1…4. **The scanner is really wired**: `cmd/vedette` `scanEngine` connects `scan.Engine` to `sensor-active`'s Dispatcher when `d.SensorDispatcher` exists; `scan.Config.Pack` is the committed index in `content/nucleipack` (generated by `make scan-pack` together with the pack of the `scan-base` image; a test keeps it in line with `pins.env`: the source version and sha256, the pack version, the index label). Each job carries the template ids, the pack version and its sha256; the Dispatcher checks the grammar again, refuses a job built for another pack **before sending**, and parses nuclei's lines fail-closed, so `Engine.Run` returns `nucleiout.Outcome{Results, HostErrors}`; output over the cap is an error (INV-10). The error "the scanner cannot run any job right now" (`scan.ErrEngineDown`: the worker is lost or not ready, a different pack, a pack that failed its integrity check) stops the run (`auto_stopped`) with the Dispatcher's own words instead of trying device by device. An empty result is still only "no match reported". **The scanner seam**: `sensoractive.Scanner` (`Ready`, `RunNuclei(ctx, NucleiRequest) (nucleiout.Outcome, error)`) is implemented by `*sensoractive.Dispatcher`; `scan.Engine.Ready` is satisfied by it verbatim, and the run step is wired by an adapter in `cmd/vedette`; `ErrScannerUnavailable` → 503 `scanner_unavailable`. Nuclei is a binary in the `scan` container; the job protocol of the sensor; the vulnerability scanning policy and the KEV re-scan window.

## Security notes
- A hand pick is counted **per device**: only an id that is `pick_only` at `StartRun` carries a pick (each pick is one `core_audit` row `scan.pick`); every other device in the run is checked again like an automatic run, so a device that was marked fragile in the middle of a "Select all" run is skipped. The GUI filters the selection by the list on every refresh; only a hand tick keeps a `pick_only` device. Each pick is one `scan.pick` row in `core_audit`; the `scan.start` row records the number of targets, the number of hand-picked devices and a SHA-256 prefix of the whole list.
- After "Stop now", the run may show `stopped` within 5 seconds before the worker confirms, but no new run starts until the engine call returns (409 `already_running`). `GET /scans/runs` also returns `engine_busy` (true while the engine call has not returned) so that the GUI can lock "Scan now" with a reason.
- A re-scan event that has waited over 7 days is not deleted but closed with `result` `expired_no_template` | `expired_scanner` | `expired_zone` (the template did not arrive, the scanner was not ready, the organisation time zone could not be read), `devices` empty, no run; INV-9 lists these three values.
- Evidence contains no device names (it comes from the network); the self-check sentence is built only from the checked template path, the address through the argv grammar and the job's input.
- A run left unfinished by a restart is closed by `core/run` (`Recover`: `stopped` with the reason "Vedette restarted"; a `queued` run that lost its picks → `failed`); its probe rows are closed as `stopped` by the `recover` job (every 10 minutes, run at once when the module is turned on).
- The address used for a job must be exactly the address that inventory decided; if it differs → skipped. A 15-minute job is not re-checked midway.
- A finding that a person has closed (`false_positive`, `not_relevant`, `patched`, `risk_accepted`) is not probed again; `mitigated` is still re-scanned to check the measure.
- A probe still open when the run ends is closed in `finish`. A device that exceeds 15 minutes (`deviceTimeout`) has its own reason. A device deleted while the list is being built leaves the list.

## Re-scan events and the schedule
- The window and schedule follow the organisation's time zone (`Config.Location func(ctx)`, `cmd/vedette` passes `orgLocationAt`): `TestScanReadsTheOrgTimeZone`, `TestScheduled_AZoneNobodyCanReadHoldsTheCheck`, `TestReview4_ZoneUnknownHoldsTheKEVRescan`.
- The due mark, the missed mark and the window closing are decided by `core/schedule` (one run for all missed marks, no catching up in a burst); `startScheduled` only accepts, holds or drops a mark: `TestScheduled_*`.
- The event queue: wait before reading, 100 events per pass; one failing event does not block the queue; a scanner that is not ready for 7 days drops the event; the link between an event and a run is written in the same transaction as the run row (`runSpec.inTx`), and if refused because of load the event stays waiting; `product` is a single lowercase line.
