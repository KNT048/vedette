# Sensor-passive — Change Impact Map

## Modifying: `sensorpassive.Service` — `Status() []Sensor`, `SetInterface(ctx,id,iface,span)`, `ChooseCard`, `SpanStats()`
- **SPA** (`SensorsSection`, Devices → Scope and sensors; on the container-only build the Configure dialog picks the listening card, SPAN or not, through `PATCH /inventory/sensors/{id}` → `ChooseCard`; it opens according to `Sensor.chosen`: changing the meaning of `chosen` changes whether the dialog shows "Automatic" or the chosen card), **core** (`modules/core/handlers_network.go`: the Box network page shows `SpanStats`), **core** (`/core/logs/export` does not use it). Changing `Sensor` requires editing `inventory/contract.ts`. `Status()`/`SpanStats()` read the heartbeat of the `passive` role (they no longer read `Engine`): changing the `online` threshold (90 s) or how the verdict is computed changes what the GUI shows; keep the S-INV-1 criterion ("offline within 90 s"; never reported is `never_connected`). Changing the "has a host" condition of `ChooseCard` (`HostCards` `ok`/error) changes who may choose a card on the appliance: only the host, through Box network.

## Modifying: `Config.Name` (display name of the sensor, #471)
- **SPA** (`SensorsSection` shows `Sensor.name`), **cmd/vedette** (`newSensorPassive` passes `deps.BoxName.Cached`: the OS machine name reported by vedette-host, `vedette` when there is none, the device-row name when the host has not answered since `core` started). The function is called on every `ensureSensor` (every batch, heartbeat, GET), so it must be cheap and **must never call the host socket**: `Cached` only reads memory, and the inventory `box` job and the certificate re-issuer refresh it (using `Name`/`Get` here would add up to 2 s to a batch every 10 minutes, and every 30 s when the host hangs). The name is for display only: changing it does not change the line key, mTLS or data already received. The `core` unit still has `HostName=vedette` (host CONTRACT INV-17), but `core` does not read `os.Hostname()` for this name.

## Modifying: the default card (`listenOn`, `defaultOfHeartbeat`, `Host.ManagementCard`)
- **Fresh install** (S-INV-1): without it, after the wizard the sensor listens on no card and Devices holds only the box itself (#471). It decides `sensorlink.Config.Interface` when nobody has chosen one, and the `Sensor.interface` of GET (the SPA `SensorsSection` shows that name). The source is `core.NetworkHandlers.ManagementCard` (`mgmtIface` + `cardsOf` of the Box network page): changing the management-card rule or the virtual-link rule changes the card the sensor listens on. Storing the default in `sp_sensor` would make a manual choice and the default indistinguishable (turning SPAN off would not return to the management card): do not store it. The virtual-link rule lives in one place: `sensorlink.VirtualIfaceName` (`core/sensorlink/wire.go`), shared by `cmd/vedette-sensor/passive.go`, `modules/core/handlers_network.go` and `SetInterface`; edit it there.

## Modifying: `Engine` (parsers, confidence scale, filters) and `MetaItem`
- **inventory**: `UsefulValue` keeps UUID hostnames and models without letters out of inventory; loosening it lets an mDNS service name push the real name out of the 32 history rows (INV-16) and lets a junk model make `facts`/`differ` split one machine into two rows. The counter key `value_meaningless` belongs to `sensorlink.DropKeys`.
- **inventory** (the "in use" value), **logs** (metadata field): adding a field to `MetaItem` = storing more about traffic; test `TestContract_INV3` blocks it, so CONTRACT INV-3 must be edited first. Changing the `Conf*` scale changes the display order. Adding a parser = adding a `Fuzz*` (test INV-4 checks the list). LLDP description patterns (`sysdesc.go`): adding or editing a pattern changes the Make/model and OS of that device on Devices (the device name when there is no hostname is vendor + model, `web/src/features/inventory/nameOf.ts`); a pattern may only return a short token whose characters have been checked, never the description verbatim; `TestParseSysDesc` + `FuzzParseLLDP` guard it. **sensor-active** reads the same patterns for SNMP sysDescr through `ParseSysDesc` (source `snmp`, 0.9, `TestIdentifySNMP`): changing one pattern changes the SNMP model/OS too, and the Junos OS of both sources reaching findings. SSDP `SERVER` header patterns (`ssdp.go` `parseSSDPServer`) follow the same rule: adding a pattern = one row + one case in `TestParseSSDPServer`; the `lan-discovery.pcap` recording (pktgen `files.go`, `-update`) carries a FRITZ!Box header, so the router model in `TestLANDiscoveryFixture` and `web/e2e-real/sensor-shared.ts` (`ROUTER.model`) is `FRITZ!Box 7590`: changing the header requires editing both. The passive OS has a cap of 0.5 (`MaxConfidence`), and core clamps to it.
- **cmd/vedette** (`sensorpassive.go`): `netHost` is the place to replace with the `host` module; `sensorBackend` (`sensorwire.go`) and the handler share one `Service`. `Engine` runs inside `cmd/vedette-sensor passive` (package `capture`); `core` has no `capture` job, `netHost.HostCards` serves `SetInterface` and the box's card list (`boxAddresses`); `netHost.Interfaces` is just `HostCards` for `Service.Run` (it does not run in production) and no longer falls back to the cards of the `core` container.

## Modifying: `content/oui` (the OUI table) and `make oui`
- **inventory**: the `vendor` 0.4 observation of a new device. `make oui` pins the source by commit + SHA-256 (`scripts/oui`, constants `pinnedCommit`/`pinnedSHA256`), cleans vendor names (strips C0/C1, bidi, zero-width, soft hyphen, tag characters), and fails if two vendors share one prefix; `TestEveryVendorIsCleanText` guards the table. Changing the table (rerunning `make oui`) changes the vendor name displayed for new devices and does not rewrite old observations. THIRD_PARTY_NOTICES lists the runZero/IEEE source.

## Modifying: `deviceBook` (`book.go`, the new-MAC budget)
- **inventory** (the number of `discovered` devices per day, the audit record, the `asset.discovered` event): changing `maxNewMACsPerMinute/Hour`, `confirmAfter`, `firstSightingTTL`, `maxFirstSightings` changes how fast real devices appear and the bound "fewer than 20,000 new MACs between two frames" (CONTRACT, Flood limits); `maxNewValuesPerHour` changes how fast one device may change its name/model. The book (device, first frame, vendor still owed, value budget) lives in `Service`, not in `Engine`. The inventory `Record` truncates to 32 rows per (device, field, source) (INV-16): changing that constant changes the length of the value history.

## Modifying: the call to `inventory.RecordObservation`
- **inventory**: `source=passive` and the `confidence` scale decide the "in use" value. Changing the confidence scale changes `summary` and the display order on every device.

## Modifying: metadata SPAN trên dây (`capture.LinkMetadata`, `Service.Metadata`, `Config.Mirror`, `sensorlink.MetadataItem`)
- **logs** (`MatchMirror`, wired at `cmd/vedette/logsioc.go` `logsMirror`): changing `kind` or the form of `dest` = losing the alert "which machine asked for the name of / opened a flow to a malicious destination" on the mirror port; the `kind` values must stay in line with logs' `mirrorVia` (`TestWiringMirrorMetadataRaisesABadAddressIncidentWithoutASyslogSource`). Adding a field to `MetadataItem` = sending more packet data to `core`: edit `PRIVACY.md` (the mirror port paragraph) and the Privacy screen in the same commit.
- **core/sensorlink**: the pacing (`MetadataPostsPerFlush`, `MaxMetadataItems`) shares the 10 requests/second budget of the `passive` role with observations and the heartbeat; raising them can make observations fail with `429`.

## Modifying: the `net_raw` and `pcap` permissions in the MANIFEST and the `sensor` container
- **vedette-host/Quadlet** (grants CAP_NET_RAW): adding a permission is a security change that requires editing the CONTRACT; removing one means the module does not start. The `sensor` unit (`host-api.md` §18): `User=<sensor_uid>:<sensor_gid>`, no `UserNS`, only `NET_RAW`; adding `UserNS` breaks raw sockets on the host network; adding `NET_BIND_SERVICE`/`NET_ADMIN` requires editing host CONTRACT INV-17.

## Modifying: the sensor protocol of the `passive` role (`core/sensorlink`, `docs/specs/sensor-protocol.md` §6.1–§6.3)
- **core** (handler, `core_sensor_cert`), **sensor** (`capture` + client), **host** (unit, the `vedette-creds-passive` key volume). Strict decoding on both sides: adding or changing a wire field = bumping `X-Vedette-Proto`; `core` accepts proto N and N-1 (`sensorlink.ProtoPrevious`): a new request field must be optional, and a reply change must return the old form to the N-1 side; an update changes `core` first so an old sensor can still send within that window, and a sensor newer than `core` receives `426` and keeps its queue. Changing the body cap, `items` ≤ 500, `value` ≤ 200 B, or the `seen_at` window requires editing spec §9 and the contract test.
- **`capture_error`** (proto 4): the closed set `sensorlink.CaptureErrors` is the contract between `captureReason` (the `capture` half), `Service.Status` (the `core` half), the `capture_error` enum of `Sensor` in `web/src/features/inventory/contract.ts` (→ `api/openapi.json`, `core/api/oas`) and the GUI text `sensors.capture.*`; adding a reason = editing all four in one commit (an old `core` shows the new reason as `capture_failed`, and the old GUI has no text for it). Bumping the proto makes the `scan` worker (the `active` role) move to the same version as well.
- The flood budget lives in **two places**: `book.go` (the first layer, in `capture`) and the `observations` handler of `core` (`budget_exhausted`); changing one requires changing the other, otherwise either `core` rejects what the sensor lets through (losing real devices), or the `core` layer can no longer stop a compromised sensor.
- The `capture` package must not import `core/store`, `database/sql` or SQLite (`TestBinaryDependencies` of `cmd/vedette-sensor`).

## Disabling this module
- Devices stops receiving new passively discovered devices; "Scope and sensors" is empty; S-INV-3 has only other sources left.
- `logs` loses SPAN metadata; `sensor-active`, `agent-intake` and `honeypot` are not affected.
- **The `sensor` container follows the module**: `cmd/vedette/modulecontainer.go` + `modreg.NewOnGuard`/`OffGuard` call the host's `container.start`/`container.stop persist`; removing these two guards (or deleting `[Install]` from the contract) means that after a fresh install the container does not come up, and after a reboot it runs while the module is off (defect M3 of the RUNBOOK review). Each enable/disable costs one host write command (10/minute for all of `core`).
- Existing observations/devices are kept.

## The `capture` half and the `core` half
- **`capture.Link`** (three functions: `Config`, `PostObservations`, `PassiveHeartbeat`) is where the two halves join: `*sensorlink.Client` (the sensor) satisfies it, and so does `localLink` (`local.go`, wrapping `sensorpassive.Service`, for the test suite). Changing any function changes both and `cmd/vedette-sensor passive`; changing the wire bumps `X-Vedette-Proto`.
- **`Service.Observations`** is the only entry point for passive observations (there is no `SubmitBatch` any more): item check, `FloodBudget`, `confidence` clamp, epoch/seq. Changing the confidence cap (`capture.MaxConfidence`, the `Conf*` constants) or the budget (`capture.NewMACsPerMinute`… shared by the sensor's book and `core`'s `FloodBudget`) changes two layers at once: the `capture` tests and `backend_test.go` guard against drift.
- **`sensorlink.DropKeys`** (35 keys) is the contract between the `capture` counters and the heartbeat: adding a new counter (`drop("...")`, `CountDrop`, `count`) without adding a key turns `TestEveryCounterIsInTheClosedSetOfTheProtocol` red; adding a key changes the wire (bump the proto, because an old `core` rejects an unknown key).
- **`Status`, `SpanStats`** read the heartbeat: the GUI (`SensorsSection`, `SpanCard`) sees empty `interfaces` and `never_connected` ("Not connected yet") until the sensor's first beat, or `starting` ("Starting…", re-read every 10 s) when `Config.Starting` (cmd/vedette `startWatch` of the `sensor` container's OnGuard, appliance only) says the box is still starting it; changing the `startSettle`/`startGiveUp` thresholds changes when the GUI switches to "Not connected yet"; on the container-only build the Configure dialog says "No card reported yet". **`SetInterface` and the box's address list (rejecting an entry about the box, `boxAddresses`) both read `Host.HostCards`** (the host is the authoritative source): removing them must be replaced by the host's `GET /v1/state/net`, not by the heartbeat. Only when core runs without `-host-socket` (the container-only build) do both use the heartbeat's cards **younger than 90 s** (the `online` rule); with no such heartbeat `SetInterface` returns `bad_interface` and an observation batch returns 503 `not_ready` (the sensor resends the whole batch, without splitting the batch or dropping entries: `capture` hunts for the poison entry only on `store_busy`; right after core restarts, the next beat comes within 30 s). Changing the `onlineWithin` threshold changes all three (`online`, `SetInterface`, `boxAddresses`). A configured host that has never answered (no cache) also makes an observation batch return 503 `not_ready` instead of filtering by the `core` container's cards; `netHost.HostCards` returns an error (not `ok=false`) when the host is configured but cannot supply the list (off, missing socket, nothing in the cache yet): fail closed, the heartbeat never decides on a build that has a host. Making it return `ok=false` for those cases changes the source of trust on a build with a host (`TestWiringHostCardsFailClosedWhenAConfiguredHostGivesNoList`).
- **`modules/inventory`**: `Record` drops observations about the MAC/IP of `is_box`, and `claimIP` does not move the IP of `manual`/`is_box` for a source that is not `agent`; `RecomputeAsset` sets the box's MAC only from `agent`. Changing any of the three changes what the test `TestSensorsCannotChangeTheBox` guards.
- **`cmd/vedette-sensor`**: the `capture` package goes into the binary; the test `TestBinaryDependencies` allows only the leaf packages in its list (for `capture`: `content/oui`, `core/observe`, `core/sensorlink`, `modules/sensor-passive/capture`, and `golang.org/x/sys/unix` for an option on the receiving socket), and forbids `database/sql`, SQLite, `core/store`, `core/audit`, `core/secrets`, `core/pki`, `modules/inventory`.
