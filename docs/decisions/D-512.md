| D-512 | **SNMP reads identify network gear: read-only GETs from the scan container, with credentials an administrator saves, only to approved devices of the confirmed scope (item 26, P0 journey A2 "know what each device is"; the Fortinet, Juniper, HPE and gateway devices of the N100 were typed Unknown).** (1) **Where:** the worker of the `scan` container sends the packets, the same place nmap and nuclei run (D-113): a third job kind `snmp` on the sensor link, **protocol 5** (`X-Vedette-Proto: 5`, `core` still takes 4; the heartbeat says `snmp: true` and `core` sends an snmp job only to a worker that said it, so a worker of protocol 4 gets the replies of protocol 4; `running` may name 3 jobs). `core` keeps the scope, the consent, the approval and the probe log; the job carries `{rate, credentials[≤8], targets[≤64]{ip, credentials[≤4]}}`, never an object identifier, and the worker owns the fixed list it GETs. The worker re-checks the grammar (local IPv4 only, `core/localnet`) and answers per target `{status ok|no_answer|auth_failed|unknown_user|error, credential, values}`; `core` checks every answer against the job and parses the values itself, fail closed (SYS-6). gosnmp v1.47.0 (BSD-2, standard library only) is the one third-party package the sensor binary gains (`TestBinaryDependencies`): SNMPv3 USM is key localization, HMAC and AES-CFB, not worth writing again. (2) **What is read, read-only:** one GET of sysDescr, sysObjectID, sysName and ENTITY-MIB entPhysical class, model name, software revision and serial number of index 1 (the chassis or the stack on the devices that have the table; a second GET of the system group alone when the agent refuses the whole PDU). Never SET, WALK or GETBULK: identification needs a handful of objects, and a walk of a switch's interface or ARP tables is load and data the box does not need. Timeout 2 s, one retry, one device at a time, at most `rate` packets a second (two packets per read: a v3 discovery and the GET). (3) **Which devices:** every device that is **approved** (a person, or its osquery enrolment, vouched for it; a v2c community is clear text, RFC 3410 §8.2, so it never goes to a device nobody vouched for, which may be a rogue one collecting communities), in the confirmed scope, not the box or a decoy, not added by hand, not `regular_scan=never`; **fragile and unclassified devices are read** (a few UDP GETs are gentler than the one gentle scan, and SNMP is how a printer or a UPS says what it is); and only with the credentials whose own scope holds it, in order, until one is answered. **The scope of a credential is required** (1–16 IPs or CIDRs the admin types; empty is refused, `scope_required`, and the table's CHECK refuses it too; review #715 M3): an operator can approve a device and osquery enrolment approves one, so "every approved device" would hand a v2c community (or a v3 message to brute-force offline against an engine ID of the attacker's choosing) to a laptop someone plugs in and gets approved; runZero's CIDR allow list is the model. Each batch of a round reads the credentials and every device's policy again right before it leaves (a device set to never, un-approved, moved or deleted, a credential deleted or narrowed since the round started gets nothing), ends with the window like an nmap run (INV-3), and the box's own addresses and decoys are refused even for a fragile device (review #715 M1, M2, L1–L3). **Never-touch union guard** (review #715 M4): a device is on the never-touch gateway list while ANY trusted kind observation (manual, agent, or snmp/nmap of an approved device) says router or firewall, whatever its current kind; SNMP may still set the kind (it outranks nmap: identification matters), so it can add a device to the list (more protection) but never take one off it (an on-path host answering a router's v2c read as a JetDirect does not make the router blockable). (4) **When:** once per scan window after the sweep and the queue (a job row per round, so a window with nothing to read is not looked at again), plus **Test**: an administrator reads one inventory device with one saved credential at once (every rule but the window), sees what it said or a plain reason, and what it said is recorded. Every snmp job writes its `sa_probe` row (shape `snmp`, the credential names, never a secret) before the job leaves; `sa_job` kind `snmp`; migration `sensor-active/0004_snmp.sql` (on top of D-511's 0003, whose `gentle_titles` shape it keeps). (5) **Credentials:** v2c community; v3 user with SHA or SHA-256 and AES-128 (authPriv) or no privacy (authNoPriv). **No SNMPv1** (its community is as clear as v2c's and the devices that answer v1 answer v2c; a v1-only device stays unread until a customer needs it), **no MD5, no DES** (Cisco IOS XE 17.11 refuses them by default, FN72509), **no noAuthNoPriv**. Secrets sealed in `core/secrets` (purposes `sa_snmp.secret`, `sa_snmp.priv`), shown as their last 4 characters, never returned, logged or exported (`sa_snmp` secret ids are `skip` in the export policy); at most 8 credentials; an edit that would send a saved secret to more addresses asks for it again (as a changed Wazuh certificate does, D-308). Opened only to build the job; on the wire only inside the mutual-TLS link, and in the worker's memory for that job. Add, edit, delete and Test are audited. (6) **What it gives:** vendor from the IANA enterprise number of sysObjectID (`content/snmp/enterprises.json`: 31 vendors, product families only where documented: FortiGate .101, FortiSwitch .106, FortiAP .120, HP JetDirect 11.2.3.9; the kind only where the family or vendor makes it clear, only today's kinds; 8072 net-snmp and 311 Microsoft name the agent, not the maker, and are left out); model and OS from the sysDescr layouts LLDP already reads (`capture.ParseSysDesc`: Junos "JUNOS 15.1R7.9", Cisco IOS/IOS XE, ArubaOS-Switch, RouterOS), the ENTITY-MIB model of a chassis, and for a FortiGate (whose sysDescr is empty or the admin's text) the model and "FortiOS 7.2.5" from its firmware text; host name = sysName when it looks like one; source `snmp` (above nmap, DATA_MODEL §5.1), confidence 0.9 (kind 0.8). A Junos version stated over SNMP reaches findings exactly as LLDP's does (D-510, `os` of source `snmp`; FortiOS and IOS are recorded but, as for LLDP, findings reads only Junos today).
