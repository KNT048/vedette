| D-439 | **A finding whose device no longer matches its entry stays open and says so once in its history; Vedette does not close it (findings, S-MIT-1).** Case: CISA changes the vendor or product of a KEV entry, or the device's software changes, so the matcher no longer produces the pair `(device, CVE)` although the finding exists (the matcher only adds, INV-6). Decision: when a match run judges a CVE (it is in the list matched) and a `suspected` finding (basis version or product) is no longer produced, findings writes one history row `no_longer_matches` ("The device no longer matches this entry ... Close it yourself if it does not apply.") and one audit row; status, severity and notifications do not change; a row is not written again while it is the latest one; when the pair matches again and that row is the latest, one `matches_again` row follows (inventory flaps: an observation replaces declared software, a hand edit), so the newest line never tells a person to close a finding that matches; a CVE missing from the list is never judged (a partial list says nothing), a scan-confirmed finding is not judged by the version matcher. Migration 0002 adds the action to the history CHECK. Leading products close such findings by themselves: Tenable sets a vulnerability that no longer appears on the host to Fixed (and Resurfaced if it returns), and Defender Vulnerability Management drops the entry when the software is updated or removed; both rest on a fresh authenticated scan or agent inventory. Not followed: Vedette's matcher reads an inventory that can be stale or partial (passive discovery, hand-declared software), and its FORBID-2 (kien, findings contract) says nothing closes without a person because a wrong auto-close hides a vulnerability that is being exploited; a rescan that no longer matches already only writes `rescan_clear` the same way. The history row gives the person the same signal with no hidden state; a person closes it with "patched" or "not relevant". Rejected: a new status `no_longer_matches` or auto `not_relevant` (changes the status enum in the API, the mock and every GUI filter, and breaks FORBID-2); doing nothing (the finding keeps asking for action on a device that may not have the product). | Sources: Tenable, [Vulnerability States](https://docs.tenable.com/web-app-scanning/Content/WAS/GettingStarted/VulnerabilityStates.htm) (Fixed: once present and no longer found; Resurfaced when it returns); Tenable, [Vulnerability Mitigation](https://docs.tenable.com/vulnerability-management/Content/Explore/Findings/VulnerabilityMitigation.htm); Microsoft Tech Community thread on stale Defender TVM data after a remediated application ([link](https://techcommunity.microsoft.com/discussions/microsoftthreatprotection/tvm-still-showing-outdated-vulnerabilities-despite-applications-being-up-to-date/4427813), community text, not official); Vedette `modules/findings/CONTRACT.md` FORBID-2. | 2026-11-13 |
