| D-311 | **`config_read` evidence is the box's own record of a connection read: table `ai_read`, at most 24 hours old.** The tool runner of "Ask your data" writes one row (id `rd-…`, time, connection id, connection name, tool name, job) after `core/conn/read.CallRead` answered; never the output, never text of the model. `ai.Service.ConfigRead(ctx, id) (ReadRecord, bool, error)` finds a row only when it is ≤ `ReadMaxAge` (24 h) old and the ai module is on; the summary is the box's line `Read "<tool>" on the connection "<name>" at <ts>` (cleaned, bidi stripped, capped). `cmd/vedette` wires it as `response.Config.Evidence.ConfigRead` with `Connection` = the connection id and no `Relates`, so a read relates only to a device action through that connection (D-119). Rows older than 24 h are removed when a read is recorded, and at most 500 are kept; exported (`ai_read`, D-154 policy). The id is not shown to the model in Ask. | D-119 (an existing read tool proves nothing; the evidence must be a read the box made). A row written by box code after the read is the only thing the model cannot forge; the 24 h bound and the 500-row cap keep the table small without a job. Sources: Microsoft Defender XDR automated investigation evidence (https://learn.microsoft.com/en-us/defender-xdr/m365d-autoir) — the evidence of an investigation is what the system collected, each item with its source and time; OWASP LLM06 (above). Not chosen: rows derived from `ai_activity.tools` (masked argument summaries, no connection id, hash-chained so cannot be pruned at 24 h); storing the read output (device text, privacy).
