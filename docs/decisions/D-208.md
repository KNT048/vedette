| D-208 | **feeds: a pull never connects to the box itself.** (1) Every feeds pull (custom and built-in; built-ins use public https, so nothing changes for them) refuses at connect time loopback (127.0.0.0/8, ::1: in the shipped container loopback is Vedette itself) and the box's own host addresses (the /32 and /128 entries: the container's interfaces plus what vedette-host reports through the same `notifyBoxAddrs` source as notify), never the interface subnets, because the user's LAN lives there and internal feeds such as MISP legitimately do. The check runs on the resolved address before `connect` (the dialer connects to that literal and the socket Control hook repeats it, so DNS rebinding is covered), every redirect hop goes through the same dialer (redirects are already same-host only), and no proxy is used. Same rule as notify D-86 (2). (2) Box addresses unknown (vedette-host never answered since start): fail closed like notify (`ErrBoxAddrsUnknown`, every connection refused, text "Vedette does not know its own addresses yet…", the next scheduled pull retries); built-in pulls in that first window also wait. (3) Feed values in row errors were already quoted and cut to 40 UTF-16 units; now unprintable runes (controls, bidi overrides) become spaces instead of escapes, so a snippet is short and plain; the destination rule is the real fix for reading internal endpoints. API error codes and messages do not change.
