| D-603 | **Windows releases come from Microsoft's own release information, read on the box, so a new release needs no Vedette code change; a build Microsoft does not list (Insider) stays "could not be checked" (N100 DESKTOP-55UKKFV 2026-11-17; amends D-546, D-602 (2)).** (1) **The case:** DESKTOP-55UKKFV reports 10.0.26300.9974. Build 26300 is **Windows 11 26H2**, general availability 2026-09-29 (first public build 26300.9457, enablement package on the 24H2/25H2 code base), and .9974 is its November 2026 security update (KB5132061, the same KB and revision as 26100.9974 and 26200.9974): a fully patched, current GA release, not an Insider build as D-602 (2) assumed. `core/winrel`'s hand table stopped at 25H2, so 174 Windows KEV entries were "could not be checked". (2) **Source:** a new built-in feed `windows-releases` (on by default, daily) reads Microsoft's two public pages `learn.microsoft.com/en-us/windows/release-health/windows11-release-information` and `…/windows-server-release-info` (about 140 kB and 170 kB) on the box: per release its OS build and update history (date, build.revision, KB). Derived: the NVD name (Windows 11 `Version NNHn` → `windows_11_nnhn`, `Windows Server 20NN` → `windows_server_20nn`, the names NVD has given every release since 2021; other shapes are left to the hand table), GA day and first public revision (the history's earliest row, as the hand table's rule), and the **line**: a client release whose monthly update is the same KB at the same revision as another release's is on that release's line, so NVD's 24H2/25H2 rows decide a 26H2 PC by its revision (D-546 siblings, D-618 month rule) and NVD's own `windows_11_26h2` rows decide once NVD lists them (it already does for October 2026 entries). Server releases are their own line (Server 2025 is numbered apart from 24H2 since January 2026). Checked against the hand table: the pages give the same GA revision for 24H2 (1742), 25H2 (6584) and Server 2025 (1742) and the same 26100 line for 25H2. (3) **Hand facts win:** `core/winrel.Learn` adds only releases the table has neither by build nor by name; Ended, LTSC and LastFreeRev (paid ESU) are never learned. The table keeps its releases and their upkeep. (4) **Safety:** the pages are untrusted input: bounded (2 MiB each, 64 tables, 2000 rows), every value checked by shape, a page without the tables or without a readable client and server release fails the pull and keeps the last good list (`feeds_winrel`, also kept when the feed is off and exported with the data). A build neither the table nor the list has stays "could not be checked" (not_comparable) with "Windows build N is not a Windows release Vedette knows (an Insider or other pre-release build)" or "is newer than every Windows release Vedette knows (an Insider build, or a release not yet in its list)": Microsoft publishes fixed builds per CVE only for released builds (Security Update Guide, NVD's ranges), never for Insider flights, so an Insider build is not assessed, never guessed. (5) **Why not MSRC CVRF** (`api.msrc.microsoft.com/cvrf/v3.0`): it gives per CVE the product ids, KBs and fixed builds, which NVD's ranges already carry for every Windows KEV entry (NVD copies them from Microsoft); what was missing is only which release a build is and its line. CVRF is one document per month (November 2026: 18.7 MB, measured) to rebuild that; it names 26H2 ("Windows 11 Version 26H2 for x64-based Systems", fixed builds 10.0.26300.9974 and hotpatch .9911) and no Insider build. MSRC's product names ("Windows 11 Version 26H2 for x64-based Systems") would also do; the release pages are smaller and also give GA and the first public build. The same pages do **not** give an Exchange/Office/SharePoint build → CU table (those are on other Microsoft pages and MSRC's KB rows): the post-v1 issue draft `~/vedette-wt/issue-draft-ms-build-cu-table.md` stays separate. (6) **Data leaving the box:** two plain GET requests a day to `learn.microsoft.com` with Vedette's User-Agent, nothing about the customer (PRIVACY flow 1, Settings → Privacy). Terms: Microsoft Terms of Use; facts only are kept, no page text is shown or redistributed (THIRD_PARTY_NOTICES).
