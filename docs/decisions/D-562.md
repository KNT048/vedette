| D-562 | **External exposure scans the web pages of a verified target passively with ZAP's baseline, shows what it noticed apart from the exploited CVEs as "Web findings (passive)", and reads ZAP's report as untrusted data (S-EXP-2, plan exposure-real-vulns §5 slice c; exposure INV-24).** (1) **Passive only, by name in D-559 (K-5).** `zap-baseline.py -m 1 -T 5 -J` with `-config spider.processform=false -config spider.postform=false`: the spider follows links (one minute) and the passive rules read the answers; no form is posted, no AJAX spider, no active scan, no attack. The same extension of D-57 (7) that lets nuclei safe http templates run by name lets ZAP passive run by name. (2) **When it runs**: after service identification, only for a target that passed the gate of that run (INV-1, INV-13), one URL per web port: for an IP target, its own IP on the ports nmap named http or https (an HTTP proxy is not a site), for a domain the domain or a name under it that points at a public address, on the ports 80 and 443 the surface scan found open; at most 4 pages in a scan (each run takes up to 1 GiB and minutes; the rest is a "not scanned" line), one at a time, 8 minutes each; a name of another domain or a private address is never asked for. Exposure writes one probe log row per page (address, port, URL, tool and options, time) through `Config.Probes` before ZAP starts on it, and does not run ZAP when it cannot (same pattern as D-561). Said plainly: a spider finds its URLs while it runs, so its individual requests cannot be logged before they are sent; what is fixed beforehand is the scope, so the probe-log record of a ZAP run is one row per page with its scope (address and port, URL, tool and options, time), written before ZAP starts, and the spider is held to that scope by the host's network fence (amended by D-521: the URLs the spider fetched are not appended). The page carries the exact IP exposure approved (an IP target's own IP, or the public IP the surface scan saw the name at); the host pins ZAP to it (`--add-host`, egress only to ip:port, no DNS) and never lets ZAP resolve the name (the host itself only checks that the name still points at that IP before it starts, D-521), so split-horizon DNS, a changed record or a redirect cannot lead ZAP elsewhere. (3) **A seam, like D-553**: `WebScanner.Baseline(ctx, ScanTarget, WebPage{URL, Host, IP, Port}) (WebScan{Report}, error)` returns ZAP's JSON report (at most 4 MiB) or `*Unavailable{Reason}`; no scanner wired = "Passive web scan (ZAP) is not set up on this box yet." under "Not checked". The container, its network (egress only to that address and port), the image pin and the host re-check of ownership are `vedette-host`'s (`zap.baseline`, Trưởng's). (4) **The report is untrusted** (rules/security.md): `ParseZAPReport` refuses a report over 4 MiB, not JSON, without a `site` list, with a risk or confidence that is not ZAP's, an alert without a name or plugin id, or over 500 alerts, as unreadable ("could not be read", never "no alerts"); a report with no entry for the scanned address is "ZAP reported no page there" (a wrong protocol or a blocked request must not read as a clean page); unknown fields are ignored; text is stripped of markup, printable only and clipped; a sample URL that is not http(s) on the scanned site is dropped; at most 3 sample URLs (scheme, host and path only: the query string and fragment, where ZAP's own rules find session ids and passwords, are never stored) and 200 rows. ZAP's "false positive" confidence is not a finding.
