| D-601 | **(Amended by D-607: SNMP is set up per device with its own read address, inside or outside the LAN ranges; there is no credential list or scope any more, and saving a device's SNMP turns its switch on.)** **Per-device sources, and SNMP outside the LAN ranges per device (kien 2026-11-17, FortiGate added by hand; amends INV-5 / `declared_by_hand` of D-84 and the lan_ranges bound of D-512 for SNMP to a device a person turned SNMP on for).** (1) Each active source of the box is on or off **per device**: `inv_asset.scan_source` (the network scan: discovery's nmap and the vulnerability scans) and `snmp_source` (SNMP reads), set by an administrator on the device's Sources card (`PUT /inventory/devices/{id}/sources`, audited per source: who, device, source, on/off). Default: on for a device a sensor found (the box's own settings decide, as before), **off for a device added by hand**: it gets no packet until a person turns a source on, and turning one on lifts `declared_by_hand` for that source only. (2) **Off stops that traffic for any device**, discovered ones too: scan off (a stored off, or a hand-added device's default) is refused everywhere (discovery, the sweep's protected list, "Check this device now", scheduled vulnerability scans and **a pick in Scan now**), SNMP off as `snmp_off`. What is already running stops at once: the device's own nmap run, the sweep batch that probes its address (nmap cannot drop one host mid-batch, so the batch stops and the next pass reads the protected list again), its vulnerability check (that device's part alone; the run goes on with the next device, its probes closed as stopped) and an SNMP batch holding it. What the source found stays and manual values still win. (3) An agent (osquery, Wazuh) has no switch: it is installed or uninstalled on the machine. Both are pushed or pulled without probing the device (osquery POSTs to `/intake/osquery/*`, `modules/agent-intake/service.go` `Enroll`, `ingest.go` `Log`; Wazuh is pulled from its manager's API, `wazuh.go` `pull`), so the LAN scope never applied to them. (4) **SNMP and the LAN ranges.** Inside lan_ranges a credential's "Send only to" list decides, as before. **Outside them SNMP reads only a device whose SNMP switch a person turned on** (a stored `on`, which "Turn SNMP on and add" on the device page sets) and that the credential's list covers: the person administers that device and said so for it (kien), while no credential saved before this change starts reading outside the LAN by itself (review r1 M4 of #932; like PRTG, poll only what a person configured). lan_ranges are never widened for SNMP (the Add a device SNMP method puts an outside range into the credential only) and keep governing discovery and nmap. Every other rule holds: exclusions always win ("never touched, not even with SNMP", reason `excluded`), local addresses only (`core/localnet`: RFC 1918 and RFC 6598 100.64/10, checked when the credential is saved and again at dispatch, so a public address can never be listed or sent to), approved devices only, never the box or its decoys, one read-only GET of fixed OIDs, the rate, the window for the scheduled round, scanning on and the scope commitment, the probe log. CGNAT 100.64/10 already passes the local check (D-461), so 100.65.255.1 is read once its SNMP is turned on and a credential lists it. | kien's ask on his FortiGate ("I should still be able to add other checks later like osquery or SNMP; let the user toggle each part on/off") and "allow SNMP/osquery outside the scan scope, because the user has rights on the device to configure it" (approved by the director 2026-11-17). Top-tier products keep "do not probe" as an exclusion that wins over everything and stops only active probing while passive data stays (Microsoft Defender for Endpoint device discovery exclusions, learn.microsoft.com/defender-endpoint/configure-device-discovery; Lansweeper scan exclusions take priority over scanning targets and keep already-scanned data, docs.lansweeper.com/docs/exclude-assets-from-scans), and bind an SNMP credential to its own CIDR allow list rather than to discovery ranges (runZero SNMP credentials "CIDR allow list", help.runzero.com/docs/scanning-credentials; monitoring tools such as PRTG, LibreNMS and Zabbix poll any host a person configured, whatever the discovery ranges).
