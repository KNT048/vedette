# Scan — Change Impact Map

> Last verified: 2026-11-21 (every statement checked against the code)

## Modifying: the results of a run (`RunRow.Result`, the items of `core_run`, `stop_reason`, `identification`)
- **The SPA** words a run from them (`web/src/features/scan/shared.tsx` `runOutcome`: "Checked 3 CVEs: 1 confirmed, 2 no check exists (still suspected)"; Settings › Scanning's `LastChecks.tsx` and run page `RunPage.tsx`/`RunsTab.tsx` in `web/src/features/scanning`). A new result kind needs its words there (`scan.json` `outcome.part.*`), or the history says less than the run found.

## Modifying: `DeviceChanged`, `Service.dev`, the per-device context of `scanTarget`
- **cmd/vedette** `wiring.go` subscribes `inventory.asset.updated` (module on). A device's part stops alone (`noteTurnedOff`); the run's `status` stays `done`. Dropping the per-device context makes a scan turned off on the device page keep running until the run ends, which the Sources card says does not happen.
- **inventory** `VulnScanPolicy` (INV-37): a hand-added device whose network scan is off is refused even when picked; `targetReason` lists it as `regular_scan_never`.

## Modifying: the shared window, rate and exclusions (`Inventory.Checks`, `settings`, `Engine`; INV-16)
- **inventory** owns the values (INV-32; `safety.go`): `PUT /scans/config` writes there through `SaveChecks`; Settings › Scanning › Safety (`PUT /scanning/safety`) writes the same keys, and each publishes `inventory.settings.changed`, so a change there moves nuclei's window, speed and exclusions too (the scheduled check reads the window through core/schedule's `ScanWindow`, `cmd/vedette/schedules.go`).
- **`Checks.Version` / `ConfigView.Version` / `Patch.Version`**: the inventory's version of the shared block passes through `SharedChecks`; `PUT /scans/config` with a stale one is 409 `safety_changed` from the inventory's `SaveChecks`, inside this module's transaction (its own row rolls back too).
- **cmd/vedette** `scanningEngines.nuclei` reads `Engine` for the card.
- **`scan_setting`** keeps no copy of the window, rate and exclusions: the inventory is their one home.

## Modifying: `RunView.progress`, `live.prog`, `setProgress`/`progressOf` (INV-15)
- **SPA**: Settings › Scanning and `VulnChecksButton.tsx` show it (contract `web/src/lib/progress.ts` `JobProgress`, shared with exposure). **sensor-active**: its `Dispatcher` reports into the Sink of the context the run probes with; a wrapper of that context in `cmd/vedette` must keep its values (`context.WithoutCancel`, never `context.Background()`).
- `nucleiout.TimeoutTarget` (one line of the error log; `ParseHostErrors` is built on it) is read by the scan worker while nuclei runs, to drop the checks of a target nuclei gave up from the progress total. Changing what counts as a timeout changes both.

## Modifying: `scan.Service.StartRun(ctx, targets, trigger)` and the `Targets()` selector
- **SPA** (`web/src/features/scan/VulnChecksButton.tsx`, `web/src/features/scanning` `DeviceActions.tsx`/`canScan.ts`/`ScanNow.tsx`; `/scans` now only redirects, `ScansMoved.tsx`), **core/schedule** (the `scan.vuln` schedule), `OnNewKEV`. Changing the target selection conditions changes the number of packets/requests leaving the box: update the CONTRACT + tests INV-1…3.
- `scan.Inventory.VulnScanPolicies` is `inventory.VulnScanPolicies` through the `cmd/vedette` adapter (batched by `inventory.MaxPolicyBatch`); changing the rule in `inventory.decideVuln` changes both paths (single device and batch) together. Adding/removing a `ScanTarget` field → `contract.ts` + `api/openapi.json` + ogen.
- `ScanTarget.box`: `scan.Device.Box` from inventory's `is_box` (`cmd/vedette/scan.go`); `DeviceActions.tsx` and `VulnChecksButton.tsx` read it (and `pick_only`) so it is not pre-ticked; changing it means updating `contract.ts` + `api/openapi.json` + ogen at the same time.

## Modifying: `scan.Identifier`, `IdentRow`, `ScanRun.identification` (INV-13)
- **sensor-active** (`IdentifyDevice`, the `Why` codes), the `scanIdentify` adapter in `cmd/vedette/scan.go`; **SPA** (`LastChecks.tsx`, `DeviceActions.tsx`, `shared.tsx`), `contract.ts` `IdentReason`/`RunIdentRow`, the mock's `IDENT_NOTE`/`identOne` (the same text as `identNote`), `api/openapi.json` + ogen. Changing a reason or text: update all four places in the same commit.

## Modifying: `startScheduled`, `windowEnd`, `ScheduleOwner` (the schedule `scan.vuln`)
- Starting a run inside the schedule's transaction is `startTx` (run.go), shared with `start`; the run begins after the commit, so `scan.run.started` is published when the run's work begins, not when it is queued. When a check is due, held (`schedule.Hold`: scope not confirmed, a check running, scanner not ready, window closed, zone unreadable) or skipped (`schedule.Skip`: nothing to check) is core/schedule's rule (`Next`, late-start and window rules); this module only answers Start.
- **core/schedule** (`ScheduleOwner`: `Default` weekly Sunday 23:00 inside the scan window, `DefaultOn`, `FirstInWindow`, `Limits` = the scan window only): the schedule editor, `cmd/vedette/wiring.go`/`scan.go` (registration) and `cmd/vedette/scanning.go` (`nextStart(…, scan.ScheduleKey)`, the nuclei card's next start) read the key `scan.vuln`; renaming it loses the saved schedule.

## Modifying: `identNote` (adding `os_no_patch_level`)
- Reason codes returned by sensor-active (`WhyOSNoPatch`); adding/changing a code means changing the `IdentReason` of `contract.ts`, OpenAPI and `core/api/oas` (generated), the mock's note and the `scan.ident.*` labels.

## Modifying: calls to `inventory.InScope/ScanPolicy` and `exposure.CheckScannable`
- **inventory**, **exposure**: these are the two SYS-7 fences. Loosening one side without updating the other → a scope hole.

## Modifying: `findings.ConfirmFromScan(…)` and the `scan.finding.confirmed` event
- **findings** (creating/confirming findings), **notify** (through findings). Changing `Evidence` breaks the displayed evidence (S-SCAN-3).

## Modifying: `feeds.vuln.new_kev` (the `has_template` field)
- The trigger for rescans. Renaming it or a field → S-SCAN-2 is lost without any error.

## Modifying: the `scan_probe` log / the `scan_probes` category
- **core** (`/core/logs/export`), **SPA** Probes. Cutting retention below 90 days breaks S-SCAN-4.
- A new result (such as `not_run`, `refused`) is a contract change: the table's CHECK, `ExternalProbe.Result` (`ProbeNotRun`, `ProbeRefused`), `contract.ts` `ProbeEntry.result`, `api/openapi.json` + ogen, the tone and `probes.result.*` labels of `ProbesTab`; the writer is `cmd/vedette` `exposureTemplateScan.send`.

## Modifying: the external surface scanner (`modules/scan/surface`, `cmd/vedette` `scanRunner`; INV-12)
- **exposure** (`POST …/scan`, snapshots, `Content`, `ScannableIP` decides which addresses may be port scanned), **response** (the `new_port` trigger listens to `exposure.snapshot.created`), **reports**. Changing the port list, the admin page markers or the name selection rule changes snapshots and day comparisons (false "new" or "gone" ports/pages). Changing where requests go (CT, proxy, User-Agent) changes an outgoing data flow: PRIVACY flow 9 + Settings → Privacy in the same commit. Loosening the address rule (`exposure.IsPublicIPv4`) or port scanning an address `ScannableIP` does not allow breaks SYS-7 and LEGAL §3. `RecordExternalProbes` writes into `scan_probe` (INV-7): changing the table or the retention must keep its rows with a NULL `run_id`.
- (exposure INV-27) `Resolver` gains `LookupCNAME`, `LookupMX`, `LookupNS` (satisfied by `*net.Resolver`): fake resolvers in tests (`surface_test.go`, `dns_test.go`, `cmd/vedette` `resolverFunc`) must have all of them. `Host` has `Source`, `CNAME`, `Addrs`, and `IP` may be empty: the `contentOf` adapter copies them into `exposure.HostRow`. The `content/wordlist/labels.txt` list (≤ 150) changes the number of DNS queries of flow 9 (PRIVACY). The rate of 20 lookups per second uses `time.Ticker`: tests that call `Domain` must run inside `synctest`. `dnsBudget` (60 s) is part of the 5-minute cap (`scanTimeout`): raising it, `ctTimeout`, `pageTimeout` or the number of names requires recomputing the total in the constants' comments. The label of the `dns` probe row is the domain and also the `ip` column (the 1–253 character CHECK of `scan_probe`): changing `scanProbeLog` must keep it non-empty (`TestExposureDNSProbeRowFitsTheProbeLog`).
- **sensor-active**: the 99-port list lives in the leaf package `modules/scan/commonports` (it imports nothing; the sensor binary links it through `nmapargv`) and is the first -sV batches of the nmap `external` shape (after the discovery of nmap's own `--top-ports 1000`; the default scan of the box's public IP probes about 1,070 ports). Adding or removing a port changes those batches: `nmapargv` `TestExternalBatches`. The Go surface scan still connects only to this list (page titles, certificates); a port nmap finds open outside it becomes an exposure `PortRow` through the service step (`addServicePorts`). `commonports.Numbers()` stays the fixed list; the ports a run really probed are `sensoractive.External.Probed` → `exposure.ServiceScan.Probed`.
- `commonports.MaxBelievableOpen` (40, a count of open ports, not a share of the probed ones): above it the default scan still runs -sV over the fixed list and keeps only the ports with a real service (`AnswersEverywhere`, exposure adds `notAnswersEverywhereKept`); exposure does not send the deep scan, and the deep shapes discard their rows (`ErrAnswersEverywhere`). Changing the number changes all three, and `nmapargv.ExternalBatches`.
- (INV-14) `endpoints()` reads the `ssl/` prefix sensor-active writes for `tunnel="ssl"`: changing how the parser names services (sensor-active INV-18) means updating this too.

## Disabling this module
- External exposure's "Scan now" still runs: the runner follows `exposure`'s switch (INV-12); its probes still go into `scan_probe`, only the Scans page (`/scans/probes`) cannot show them until the module is turned back on.
- The Scans page and the scan button are gone; no new confirmations; no automatic rescan after a new KEV.
- `scan-credentialed` cannot run (dependency); `findings` only has `suspected`; `reports` drops the scan section.
- Configuration, history, the probe log and rescan events are kept.

## Modifying: `scan.Engine`
- Seam of the scanner: the worker of the `scan` container over the sensor protocol, a fake in tests. `Ready` decides `can_scan` and the 503 `scanner_unavailable` (INV-2). `cmd/vedette/scan.go` `scanEngine` wires the Dispatcher of **sensor-active** (`sensoractive.Scanner{Ready, RunNuclei}`) when `d.SensorDispatcher` exists, with `scan.Config.Pack` = the committed index of **content/nucleipack** (the same pack as the `scan-base` image). `Run` takes a `scan.Job` (argv job with paths, the same templates by id, the pack version and sha256) and returns a `nucleiout.Outcome` (`Results` already parsed fail closed by the Dispatcher, and `HostErrors`: timeouts per target counted by the worker from nuclei's error log, which is how INV-6 sees a device that answered some templates and then went quiet; `nucleiargv.fixedFlags` carries `-elog /dev/stderr` for it, and the sensor protocol is at proto 3); an error wrapping `scan.ErrEngineDown` (the worker gone or not ready, another pack, a pack that failed its integrity check) stops the run with that message. A change to the seam is a change on both sides of the sensor protocol: check `modules/sensor-active` `NucleiRequest`.

## Modifying: `content/nucleipack`
- The index core plans with. Written only by `make scan-pack` (with `index.source`, from `deploy/containers/pins.env`), never by hand; `TestTheCommittedIndexIsThePinnedPack` holds it to the pins (source version, source sha256, pack version) and to its own label. Raising a pin without `make scan-pack` and a commit of `content/nucleipack` makes that test fail; if core and the image still drift, the Dispatcher refuses every job as `pack_mismatch` and the run stops saying so.

## Modifying: `scan_setting` / `Service.SaveConfig`
- **SPA** (`NucleiSettings.tsx` card, `web/src/features/scanning/SafetyTab.tsx`), **jobs** (window, auto rescan, rate, exclusions). INV-5 is checked twice: in `Settings.validate` (with the mock's words) and by the CHECKs of `0001_scan.sql`.

## Modifying: the ports `Inventory.Devices/VulnScanPolicy`, `Findings`, `External`
- **inventory** (`VulnScanPolicy`; `consent` in `targets.go` is the one place that folds it with `approved` and the scan exclusions), **findings** (`List`, `ConfirmFromScan` only; INV-8: a no-match never reaches findings; adding a call there would let "no match reported" change a finding), **exposure** (`Targets`, listed only: not scanned yet). Adapters in `cmd/vedette/scan.go`. Loosening `consent` widens what leaves the box (SYS-7): change CONTRACT INV-1 and its tests with it.

## Modifying: the jobs `rescan`, `retention`, `recover` and `scan_event`
- A dropped event keeps its `scan_event` row with an `expired_*` result (the CHECK of `scan_event.result` lists every value; a new result changes the baseline migration and `contract.ts`). `engine_busy` in `GET /scans/runs` is read by the SPA (`VulnChecksButton.tsx`, `web/src/features/scanning`); renaming it is a contract.ts change first.
- **feeds** (`feeds.vuln.new_kev`, subscribed in `cmd/vedette/wiring.go` after inventory's rematch, so the new entry's findings exist when the job looks), **inventory** (`VulnScanPolicy` with `explicit=false`: these runs nobody picks never touch fragile, unclassified or hand-declared devices), **SPA** `RescanLog.tsx` (`GET /scans/events`). `RescanEvent.result=clear` means only "no match reported" and changes no finding; `pick_only` and `stopped` say what was not scanned; a new result value is a GUI-first contract change. **core** (`OrgTimeZone` through `orgLocationAt` in `cmd/vedette`): the window is read in the organization zone (`Config.Location`); without a wired `Location` it is UTC, and a zone that cannot be read holds every automated start. `retention` is `Housekeeping`: it keeps its hourly timer while the module is off and must stay a pure delete past the retention; any other work in it needs the flag removed or the job split. Shortening `retention` below 90 days for probes breaks S-SCAN-4.

## Modifying: `KEVFeed` and the catch-up
- **feeds** (`Store.NewKEVSince` over `feeds_kev.announced_at`, through `cmd/vedette/scan.go` `scanKEV`; nothing while feeds is off). The catch-up decides which missed entries are rescanned: the 7-day limit, the template check and the page size are its bounds; widening them makes more automated runs. The batch of a pass is one run: changing its caps (templates, devices) changes how much one automated run touches.

## Modifying: `nucleiargv`, `nucleiout`, `pack`
- The index carries `sets` (`kev`, `deep`, `disruptive`), `name`, `severity`, `generic`; `ForCVE` sees the `kev` set only (the LAN scan and the own_ip checks are unchanged), `FullForCVE`/`Get`/`ProductTags`/`GenericTag` serve the full job of `cmd/vedette/exposurefull.go`. The sets are in the pack's SHA-256 label (`content/nucleipack` test recomputes it). `nucleiargv` gains the full shape of an own_ip job (`DepthFull`, `FullRate`, `FullConcurrency`, `MaxFullTemplates`, `FullForbiddenTags`, `-or -ot`), told apart by its fixed flags; FORBID-2 now lets `dos` run in full+disruptive only. `nucleiout.Result.MatcherName` (capped, cleaned) feeds the product tags of the full job. Changing the set rule changes the pack (`SCAN_PACK_VERSION`), the image size and the time of a deep scan (exposure `FullTemplatesTimeout`). The deep set (no tick) takes reviewed.tsv and rule (a) read-only GETs; any other template of a full category is disruptive.
- `scripts/scanpack/reviewed.tsv` alone decides the KEV set (`noTickReason`); `readOnlyGET`, `getVerbRE` and `stateNameRE` only sort the review queue. Adding a line to reviewed.tsv puts a non-GET check into every LAN scan and own-IP check of a matched device: read the requests, not the name, and record who and when. A nuclei-templates bump that changes a reviewed file stops `make scan-pack` (stale review) until it is read again. `scripts/scanpack/kev-review-queue.md` is written by `make scan-pack`; the scan page (`web/src/locales/en/scan.json` description and `never.*`) and THIRD_PARTY_NOTICES say what the rule allows: loosening it means changing them.
- `pack.NoChangeText`, `ChangeInRequest`, `ThirdPartyURL`, `MethodOK`, `NeverTags` and `scripts/scanpack` `changeReason`, `denylist` (and `reviewed.tsv`) decide which templates may be in the pack at all; the worker runs `NoChangeText` on every template of every job. Making `NoChangeText` stricter without rebuilding the pack makes the worker refuse whole jobs (`invalid_job`): change the rule, rebuild (`SCAN_PACK_VERSION`), and keep the builder requiring it. Loosening a rule or emptying the denylist puts password-reset and write templates back into the LAN scan.
- The index carries `own_ip` per template (decided by `scripts/scanpack` `ownIPSafe` from the template file: read-only GET/HEAD requests only); `pack.Parse` refuses an `own_ip` entry that is not an http GET/HEAD check or carries a refused tag; the worker re-reads the file with `pack.OwnIPText`, which also passes every request target and raw header through `pack.RequestPayloadOK` (no injection-shaped payload). The mark is in the pack's SHA-256 label. The Makefile rebuilds the pack when `modules/scan/pack` changes. Changing the rule changes the pack (`SCAN_PACK_VERSION`, the committed `content/nucleipack/index.json`) and the PRIVACY flow 9 sentence. The LAN scope ignores the field.
- `nucleiargv` has a second scope, `own_ip` (one public IPv4 through `core/localnet.Public`, rate fixed at `OwnIPRate`, `-etags` with `OwnIPForbiddenTags`), told apart from the LAN line by its `-etags` only; `Validate` reads the scope from the flags, never from the target. A change to either shape is a sensor-protocol change and moves sensor-active INV-17 with it.
- Shared with the worker of the `scan` container: a change to the argv grammar or the job limits is a sensor-protocol change (proto number, worker, `docs/specs/sensor-protocol.md` §9). The set of target addresses is `core/localnet.Addr` (RFC 1918 + 100.64/10), shared with `nmapargv`, the inventory scope and setup; widening it without a wire change keeps the proto (§10: an older worker refuses the new targets as `invalid_job`). `nucleiout` is the trust boundary for what devices answered: keep it fail-closed and fuzzed; its one exception is a well-formed line about another host:port, skipped and counted (`Read`, `Skipped`): the callers (`sensor-active` RunNuclei, `scan` `noteSkipped`, `cmd/vedette` `send`) log it and note it on the probe row. Its fixtures are real lines of the pinned nuclei: v3.11.1 writes `host` as the bare address with `port` apart, read by `targetOf`; bumping `NUCLEI_VERSION` means recording them again.

## Modifying: the run kind (`runrows.go`, `runKindName`, `runLane`, `Service.pending`, `runVulnCheck`)
- **core/run** owns the status, the queue, the stop and the restart recovery; this module owns what a run is for. A run's rows are `core_run_item`s of four kinds (`device`, `finding`, `identification`, `identified`): the web reads them back as `RunView.results` and `identification`, and the KEV rescan decides matched/clear from them (`matchedCVE`), so changing the kinds changes both. The `finding` item must stay right after its `device` item.
- A run's picks, CVEs and window end live in `Service.pending` (this process only): a restart ends a running check as stopped and a queued one as failed (`noteLost`). Making the kind resumable needs those stored first.
- **cmd/vedette** registers the kind by building the service before the run manager starts (`scanService`); the lane `nuclei` is the one live check.
