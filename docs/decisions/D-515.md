| D-515 | **A switch heard by LLDP under its chassis MAC and seen by ARP and scans at its management address is one device; a product with no device has no device type (W1-37, W9-1; inventory INV-29).** (1) **What LLDP carries.** The chassis ID (subtype 4 = the base MAC), the port ID, the system name, the description (model and OS by the walk-4 layouts), the capabilities, and the management address TLV (8), which `capture/lldp.go` does not read. On the N100 the Juniper row had no host name, so only the MAC block ties the two rows. (2) **The join** runs in inventory `Record` on every device a batch touched: (b) the same host name (LLDP system name), case-insensitive, on exactly one device with an IP; (c) the chassis MAC is the base of a block: same first five bytes, the other device's MAC 1..0x7f above (N100: base :80, management :ff). Only a **discovered device with a MAC and no IP and a network kind** (switch, router, ap, firewall) joins (never two devices that both have IPs, never the box, never a declared device), never with a locally administered (random) MAC, and only into **exactly one** device with an IP that states no other name, model or OS (as the device states them: a scan's fingerprint guess and a DHCP request's OS family do not count, nmap calls the N100 switch JUNOS 12; host names compare by their first label, "ex4200.lan" = "ex4200") and holds no chassis mark of another MAC. The name rule also needs the same first four MAC bytes and a name that is not a factory default (Amnesiac, MikroTik, switch, router, ap, gateway, localhost); review M1 of #722. **Rule (a), the LLDP management address, is not built now:** the passive engine runs in the `sensor` container and reaches core over the sensor protocol, decoded strictly (unknown field → 400), so carrying the address is a protocol bump (6) with the D-410 `min_upgrade_from` release rule, for a case (b) and (c) already cover on the walk; it is in `.ai/deferred/w1-37.md`. (3) **The merge** keeps the IP device's id, address, MAC and **its own approval only** (review H1 of #722: a MAC in the block is easy to pick, so carrying the approval would approve an intruder; a person approves the joined device once); observations move with their evidence (the chassis MAC stays as a `mac` observation marked `evidence='chassis'`, which never becomes the MAC and makes a later frame naming only that MAC find this device, so no new row and no "new device" incident every frame); software and open ports move; the suspicious flag, notes and scan choices carry over when the IP device has none; model and OS from LLDP win by the usual observation rules; one audit row `inventory.merge` ("<row> is the same device: <rule>"); a new event `inventory.asset.merged {from, into, actor}`, then `inventory.asset.deleted` for the old row, then `inventory.asset.updated` with `match` for the kept device. findings handles `merged` first (review H2 of #722): the old row's findings move to the kept device with their status, history, mitigation log and AI results; for a CVE both hold, the decided one (closed or written to by a person, or with a mitigation item marked applied) beats a confirmed one beats a suspected one, a tie keeps the kept device's; one audit row `findings.merged_with_asset`; if the move fails, the `deleted` that follows does not drop that row's findings (reconcile handles them). The re-match then finds them, so nothing is created or alerted again (the N100 LLDP row holds the Junos CVEs). `deleted` still goes out for the other listeners (notify's new-device incident, sensor-active's queue) and finds no findings left. The duplicate already on a box is fixed by the next LLDP frame it hears (sent again at most every 15 minutes, at once after a restart): no migration, no one-time job. (4) **W9-1**: a product declared with neither IP nor name ("Microsoft Office (no device)") gets no computer type (pc, server, web) suggested by the catalog or by feeds' "I have this" (a type a person or a CSV gives is kept, review M2); an appliance type (FortiGate → firewall) stays, because there the product is the device and mitigation reads declared firewalls/routers.
