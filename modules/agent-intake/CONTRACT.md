# Agent-intake Contract

> Tier: optional (off by default) · Story: S-INV-4 · Last verified: 2026-11-21 (every statement checked against the code)
> The GUI lives under `inventory` (`web/src/features/inventory/{contract,AgentsSection,installScripts,agentConfig}.ts*`). The backend is a separate module.

## Invariants (always true)
- **INV-1** Only two sources: osquery (Vedette is the TLS server for osquery) and Wazuh (the box pulls through the Wazuh server API). No Trivy, no macOS, no shipped agent. `AgentKind = ['osquery']`; Wazuh has no token.
- **INV-2** Supported operating systems are servers only: Linux (Debian, Ubuntu, RHEL, Rocky, AlmaLinux; x86_64 or arm64/aarch64) and Windows Server (x64). Where osquery cannot run (Alpine and other musl systems, Arch, other architectures) the Linux script installs a small **package reporter** (`scripts/osquery.sh`, plain sh: `/usr/local/sbin/vedette-reporter`, run every hour through a systemd timer, cron.d or busybox crond) that enrols with the same token and sends the package list (apk, pacman, dpkg or rpm) together with the operating system to the same `enroll`/`log` paths (there is no `config`). The install scripts differ by OS: Linux uses curl + a SHA-256 check + sh; Windows uses PowerShell 5.1 + `Get-FileHash`; the Windows script calls the box with .NET using a certificate-check function for each request, pinning the embedded CA (no `curl.exe`, no Windows certificate store).
- **INV-3** The osquery token: used only to enrol osquery and ask for status; it **can read nothing else**. It is shown in full exactly once at creation (`CreateTokenResult.secret`); afterwards only `last4`; stored hashed. Expires after 7 days by default (`expires_in_days` 0..365, 0 = never expires); revocable and takes effect at once. A 160-bit token, stored as SHA-256; after `enroll` each machine has its own 256-bit `node_key` (stored as SHA-256, table `intake_osquery_nodes`): expiry only blocks new enrolment, and revocation also deletes the machines of that token.
- **INV-4a** (S-INV-4) The body of `status` is optional: no body = answer by token as before (`enrolled`, `hosts`), with no `host_last_seen`. With a clean `host_identifier` (non-empty, ≤ 200 characters, no control characters; one that is not clean but is of the right type and ≤ 200 characters = treated as not sent, returning 200 without the host field; over 200 characters or the wrong type = a schema 400) it adds `host_last_seen`: looked up only among the machines of the token in the header itself (whoever holds the token can already enrol under any name), `null` when there is none yet; it never reveals a machine of another token (`TestContract_StatusIsPerMachine`).
- **INV-4** A token is never in a URL: only the `Authorization: Bearer` header (`POST /intake/osquery/status`). A token does not enter logs, audit or export (SYS-4).
- **INV-5** The install scripts (`/install/osquery.sh`, `/install/osquery.ps1`) are served publicly and **contain no secret**; the token is passed as a parameter. Each script has a SHA-256 shown in the GUI so the user can compare before running. The official osquery packages are served by the box so servers need no Internet access: five files (`.deb` and `.rpm` for x86_64 and arm64, `.msi`) + `SHA256SUMS` **built into the image**, with version and hash pinned in the repository and checked at build time; nothing is downloaded at run time and there is no new outbound flow. There is a one-line uninstall command. The script and `ca.pem` embed/return the same pinned certificate (INV-11).
- **INV-6** Wazuh: a read-only account (`agent:read`, `syscollector:read`); `url` must be https; the password is stored encrypted through `core/secrets`, and the API returns only `password_last4`; `interval_minutes` ≥ 5 (at most one year; default 15) and is exactly the `core_schedule` row `agent-intake.wazuh` (see INV-16); `status` ∈ {never, connected, error}. Deleting the connection also deletes the password.
- **INV-7** Data from an agent/Wazuh is untrusted (SYS-6): parsers fail closed, with size limits (enrol 64 KiB, config 4 KiB, log 4 MiB, status 1 KiB), and read only columns in the allowlist of the known query; extra keys in osquery's outer layer (`decorations`, `epoch`, …) are **ignored and not stored** (rejecting them would break on every osquery upgrade); a row of the wrong type or with wrong text is dropped on its own and the rest is kept; packages/versions enter the store only through `inventory` with `source = agent` and a fixed `confidence` (the mock uses 0.95; the box's own report of its dpkg packages is 1.0).
- **INV-8** Software with source `agent` is replaced at the next report; manually entered software (`source=manual`) is not touched.
- **INV-9** Every mutation (creating/revoking/removing unused tokens, deleting a node, saving/deleting Wazuh, asking for an immediate report) writes `core_audit` (SYS-3): `inventory.agent_token_create`, `inventory.agent_token_revoke`, `inventory.agent_tokens_remove_unused`, `inventory.agent_node_remove`, `inventory.wazuh_connect`, `inventory.wazuh_disconnect`, `inventory.agent_report_now`; enrolling a node writes `inventory.agent_enroll` (at most one line per node per day). Display labels are in `audit.action` of `web/src/locales/en/core.json`.
- **INV-10** The `.../sample-data` endpoints are **preview (mock) only**; in a real build they remain in the contract and the route table (generated from OpenAPI) but the handler returns 404 `not_found` like a path that does not exist, and the button in the GUI is not shown (`MOCK_BUILD`).
- **INV-11** The pinned osquery certificate is a **CA of the box's own** (its own key, `CA:TRUE`, `pathlen 0`, long-lived) that signs the self-created 8443 leaf certificate; the box only re-issues the leaf with the same CA, so renewal or an address change does not make an enrolled machine lose its connection. The leaf must **not** be a CA (browsers reject that). `GET /intake/ca.pem` and the script embed exactly that CA certificate. A certificate supplied by the box owner (`-tls-cert`) is not touched: `ca.pem` is the chain the box owner supplied (the leaf if the file has only a leaf; the box owner re-runs the install command themselves when they change their certificate); each kind (a self-signed leaf, a private CA, a public CA) has an `openssl verify` test. The box CA is in `cmd/vedette/boxca.go` (a `core_secret` row with purpose `core_box_ca`, core INV-33: it goes into the snapshot with `vedette.db`, and restoring with the master key kept preserves the CA so enrolled machines need not reinstall; it does not go into the JSON export), the leaf is in `tls.go` (`selfSignedPEM`), tests in `cmd/vedette/tls_ca_test.go` (`x509.Verify` with only the CA after first issue, renewal, an address change, an upgrade from the old self-signed leaf, a restore into a new directory; `openssl verify` if available). **`GET /intake/ca.pem`** (`install.go` `InventoryGetIntakeCaPem` through `anchor`): public, `application/x-pem-file` (declared in `contract.ts`, `fileType`), takes `Config.TrustAnchor` (cmd/vedette `trustAnchor`: the box's sealed CA certificate, asked on every request through `intakeTrustAnchor`; or the `-tls-cert` file read once at startup, byte for byte) and **copies only the `CERTIFICATE` blocks** (the PEM headers are dropped; a key in the same file never leaves, `TestContract_INV11_CaPemServesTheCertificateOnly`); `TrustAnchor` nil (a box over HTTP on loopback) → 404; the box CA is returned only when the leaf being served is signed by it, otherwise 503 `server_busy` with `Retry-After` (30 s); module off → 404 (SYS-5). The two install scripts (`/install/osquery.sh`, `.ps1`) embed exactly that certificate (the same `anchor`, the same filter). Remaining: the box-owner kind with a public/private CA chain does not yet have a real `openssl verify`/osquery test.
- **INV-12** The box records the packages and observations of a machine only when the TCP address of the connection (`r.RemoteAddr`, forwarding headers are not read) is among the IPv4 addresses the machine declares in the `interfaces` query (of that very `log` request, or the pair bound last time if the request has no `interfaces` and the address is still right); the MAC used is that of exactly that card. No match (a forged address, NAT, IPv6, loopback/link-local) = nothing is recorded, the bound pair is cleared (`bound_ip`/`bound_mac` NULL), with one log line per hour per machine (closed-fail). Exception (a machine changing IP through DHCP before its next `interfaces` query): a request with **no** `interfaces` from an address different from the bound one goes with a hint that has only the node (`AssetHint{Agent, From: the connection address}`), with no MAC, no name at enrolment, no first report, no approval, and no kernel or Windows release stored on the node; the store writes onto the device bound to the node only when that device is at exactly `From` (a sensor has seen the machine move there), does not move the IP, and creates no device (inventory INV-35), so a copied node key used from another address still cannot record anything; a `config` from an address different from the bound one asks for `interfaces` every 60 s until it is bound again (`TestContract_829_AnOsqueryMachineThatMovesReportsAtOnce`). IPv4 only (the store has only IPv4). The device hint for the store **is the IP** of the connection and the node id the box issued at enrolment (`AssetHint.Agent` = `osquery:<node id>`: the store binds the node to the device for the first report by IP, if that device has no node bound yet and has never been seen with a MAC the node does not report; later reports find the device by node, so a machine that changes IP through DHCP does not become a second device; a node that is replaced on re-enrolment, revoked, or deleted for silence has its binding released by `ReleaseAgents` (after the delete transaction commits; a failure is only logged and not retried: the device stays bound to the deleted node and is found by address); the store releases a binding only on evidence from the wire (a sensor sees the device's original MAC at another address after the node's last report), never by a MAC the node reports about itself, so a machine that changes card (leaving a dock for Wi-Fi) keeps its device), without a MAC (the store finds a device by MAC first, so a MAC the machine reports about itself would let it write onto another machine); the card's MAC enters only as a `mac` observation with confidence 0.9, and the store rejects it if that MAC belongs to another device (test `TestContract_INV12_MACClaimCannotWriteOnAnotherDevice`). Remaining consequence: a machine that changes IP **before** the node is bound may have a duplicate record until a sensor sees the machine's MAC at the new address; then the duplicate record (which lost its address and has only the agent's `mac` observation) merges into the machine's device (inventory INV-31 (3)). Wazuh does not send `Agent` (the agent id is per manager and may be reused).
- **INV-13** The osquery protocol: every credential error (an unknown/revoked/expired token, a wrong or malformed `node_key`, an empty/unclean `host_identifier`) = HTTP 200 + `{"node_invalid": true}`, with no distinction of reason; a body that is too large, not JSON, malformed, or over the rate = 413/400/429 with the standard envelope (`Retry-After` on 429). An exception for `status` alone: 403 `invalid_token` / `token_expired` as the approved mock has it, because that reply type has no `node_invalid`. There is no `distributed` (no remote query execution): that path does not exist.
- **INV-14** Public budgets: > 10 credential failures/minute from one source (IPv6 merged to /64) → blocked for 30 seconds then doubled up to 10 minutes (429 `rate_limited`, including that source's correct calls); each machine gets 6 `config` + 12 `log` per minute; re-enrolling the same (token, `host_identifier`) within 60 seconds = 429; 500 machines per token and 5,000 machines for the whole box = 429 `too_many_nodes`; 500 tokens = 409 `too_many_tokens` (the error text says so plainly and points only to "Remove unused tokens"; a token that has no machines and has expired does not count toward the limit; "Remove unused tokens" deletes every token that has no enrolled machine, except tokens created in the last hour and tokens that still have machines; the prune deletes a token with no machines when it has passed its own expiry, or 24 hours after creation if no machine ever enrolled).
- **INV-16** **Wazuh pull.** A read-only client: exactly one POST (`/security/user/authenticate?raw=true`, Basic), everything else is GET on the allowlist `/`, `/agents`, `/syscollector/{id}/{netaddr,netiface,packages,ports}` with `id` matching `^[0-9]{3,10}$` (checked before sending, `allowedCall`; FORBID-4, `TestWazuh_FORBID4_ReadOnlyCalls`). It goes through the `core/conn` facade (`Service.NewHTTPS`): address policy at dial time, TLS ≥ 1.2, no redirects/proxy, request ≤ 64 KiB, response ≤ 1 MiB, 15 s per call; pages of 250 rows; ≤ 4 calls/second; on 429 wait for `Retry-After` (≤ 60 s, 2 times per call); a 401 midway logs in again once; the first successful pull of a new connection (`last_sync` still empty) that has an agent without `netaddr` yet (newly installed, syscollector has not reported) → the next pull runs after 1 minute, exactly once (a connection that already has `last_sync`, or an agent installed later, waits for the normal beat; `TestWazuh_FirstPullRetriesOnceWhenAnAgentHasNoAddressesYet`); a pull lasts 10 minutes, and a long one continues at the next beat from the agent after `resume_after`. **Pinning**: Save (with a typed password) decides once — a certificate vouched for by a public root → `tls_pin=system` (from then on a public root is required), otherwise the SHA-256 of the public key is pinned (TOFU); pulls and Test with a stored password are sent only to exactly the pin; a changed certificate → the pull stops with `status=error` before sending the password, Test gives 502 `wazuh_tls`, Save with a blank password gives 400 `password_required` — **a stored password never reaches a key other than the pin**, and only retyping the password trusts the new certificate. A stored password also does not go to another host:port (`password_required`). **Device binding**: the hint is just the agent's IP (`ip`, where the manager sees the agent) when it is a unicast IPv4 inside the agent's own `netaddr` (NAT → ignored, closed-fail); the MAC of that card is only a 0.9 observation (`TestWazuh_MACClaimCannotWriteOnAnotherDevice`); a loopback agent (manager `000`), a `disconnected` agent silent for more than 7 days, and an agent with a duplicate IP (keep the one that listened most recently) are dropped; `deb`/`rpm`/`win` packages go through the same mapper as osquery, other formats are dropped. An empty package list deletes nothing. Each agent is written through `inventory` in its own transaction; no transaction is held open across the network. Save/Delete during a pull: `generation` changes, and the pull stops at the next agent and records no result. The `agent` source is shared with osquery: **the later writer wins** (a known limit; upgrade: a `wazuh` source value).
- **INV-17** **Admin path, scripts, package store.** (a) `GET /inventory/agents` returns tokens (only `last4`, `hosts` computed at read time), the Wazuh card from `Service.Wazuh` (no password) and the `install` block: the script text **exactly as the box serves it for the very address this request arrived at** and the SHA-256 of that text, together with `install.packages`: each package of the fixed table has **both** the file in the store directory **and** a line in the directory's `SHA256SUMS` (`sha256sum` format, lowercase hex, at most 4 KiB read), in the order deb x86_64, deb arm64, rpm x86_64, rpm arm64, msi; `size` is the file size, `sha256` is the line from `SHA256SUMS` (the file is not hashed at call time); a missing directory or `SHA256SUMS` = an empty list (no error, one WARN line per minute). `POST /inventory/agents/tokens` returns `secret` **once**, writes audit `inventory.agent_token_create` (name + last 4 characters), and expires after 7 days by default; `DELETE .../tokens/{id}` revokes (also deleting machines, POST-3) and writes audit `inventory.agent_token_revoke`. All three: admin role, module off = 404. (b) The script is served **byte for byte** from the text the GUI renders from `installScripts.ts` (the template copied at `modules/agent-intake/scripts/`, `@@BOX@@` `@@VERSION@@` `@@CA@@` filled in the same order and with the same `trim`); `TestInstall_ScriptsEqualTheGUI` compares both bytes and SHA-256 with exactly the GUI's version, and `TestInstall_VersionsAgree` keeps `OsqueryVersion`, the GUI's `OSQUERY_VERSION` and `deploy/osquery/PINS` the same number. (c) The box address in the script (`boxURL`) is one of, in order: the Box address (`Config.BoxURL()`, asked every time; Settings → Box network, by default the management IPv4; it must be `https://` and consist only of `[A-Za-z0-9.:[]-]`), so the install command carries the same address as every other link of the box no matter which Host the request came with; failing that, the request's Host **if** the server's Host list (`server.HostMatcher`, the same list that let the request in) accepts it, rebuilt from the checked name/IP + a numeric port (the Host string is never copied verbatim; loopback names/`localhost`/loopback IPs do not count); or `https://<VEDETTE_BOX_IP>:8443` (PRE-3) — the placeholder is shown only in `GET /inventory/agents`; in that case the two scripts are **not served**: 404 `no_box_address` (a script that pins a placeholder would pass the SHA-256 check and then fail on every server), and `no_certificate` still wins when the box has no certificate. An unknown Host never enters a script (`TestInstall_HostIsNeverReflected`). (d) `GET /install/osquery/{file}` serves exactly **six fixed names** (five packages: deb/rpm x86_64, deb/rpm arm64, msi; + `SHA256SUMS`, built from `OsqueryVersion`): the request's string is only the key to a table lookup, what is opened is the name stored in the table, inside the store directory through `os.Root` (a link out is not followed, only regular files); any other name (`..`, `%2f`, absolute, NUL, a different case, an unknown file in the directory) = 404 `not_found`; a missing directory or file = 404 `mirror_missing` + one WARN log line; `SHA256SUMS` (~500 bytes) does not take a slot; the five packages: each source address (IPv6 merged to /64) one transfer at a time, at most 8 transfers for the whole box, a refused transfer = 429 `rate_limited` `Retry-After: 5`; every file has `Content-Disposition: attachment; filename="<the name in the table>"` and a fixed Content-Type (`.deb` `application/vnd.debian.binary-package`, `.rpm`/`.msi` `application/octet-stream`, `SHA256SUMS` `text/plain; charset=utf-8`, `TestMirror_DownloadHeaders`); `/install/osquery/` with no name never lists the directory; it streams with `Content-Length`, each chunk has a 30-second write deadline and each transfer at most 10 minutes. A client that stands still is cut after 30 seconds; a client that reads very slowly holds the slot of **its own address** for at most 10 minutes, but cannot lock out another address (`TestMirror_StalledClientFreesItsSlot`, a real server). The `mirror_missing` WARN log line at most one per minute. No outbound flow is opened: the files are already in the image. `ca.pem` and the package store may be cached (1 hour), the script may not.
- **INV-15** An empty package list (or one in which every row was dropped) never replaces the old list; only queries in the schedule (`schedule.go`, with exactly the GUI's text, with a test that compares them) with columns in the allowlist (`columns`) are read, plus the two lists only the package reporter sends (`reporterColumns`: `apk_packages` = name, version, arch, origin; `pacman_packages` = name, version, arch; the same row limit and the same mapper); osquery's `status` results are dropped; differential results (`added`/`removed`) are dropped.
- **INV-18** **First report, kind, approval.** (a) `config` returns a schedule **per machine**: within 1 hour after `enrolled_at`, every query the store has not yet received from that machine (`reported`: `os_version`, `system_info`, `interfaces`, `packages` = deb/rpm/programs, `services` = `listening_ports`/`listening_ports_windows`, INV-22) has `interval` 60; the rest, and after 1 hour, are the normal schedule (the same queries, columns and platforms; only the interval changes). A query enters `reported` only when that `log` request **could be recorded** in the store (the address matched, INV-12; `os_version`/`system_info` have a row; the package list is non-empty and was let through by the 5-minute window per source address: a list dropped by the window does not count, and the first hour asks again; `TestContract_APackageListTheWindowDroppedIsAskedAgain`). The install script sets `--config_refresh=300` (without it osquery keeps the 60 s pace until the next start). `TestContract_FirstReportIsAskedEveryMinute`. (b) `os_version` additionally yields a `kind` observation with source `agent` 0.95 (`kindOf`: Windows with "Server" → server, other Windows → pc, darwin → pc, ubuntu/debian/rhel/centos/rocky/almalinux/ol/amzn/sles → server, otherwise → none), also for Wazuh (the same `observations`). (c) The first time the store has a device for a node (after a `log` that could be recorded), `Config.Approver.ApproveEnrolled` (`core/observe.Approver`, installed by `inventory`) approves the device at the bound IP, together with `bound_mac` (the MAC of the card carrying that IP): the store approves only a row that has never seen another MAC (DHCP re-issuing an old machine's IP → left for a person to approve, still counted as done once; inventory INV-25), with the audit detail "osquery on "<machine>" enrolled with the token "<name>", made by <creator>" (`intake_agent_tokens.created_by` = the actor of `IssueToken`; NULL → "made before Vedette recorded who makes tokens"); once per node (`approved_at`, set even when the store leaves it alone because the device is marked suspicious); the store has no device yet → retried at a later `log`. (d) **Upgrade path**: the job `approve-enrolled` (`ApproveBound`, an ordinary job, run at once at startup and when the module is enabled, then every 24 hours) takes every node with `approved_at IS NULL` that has `bound_ip`, `bound_mac` and `last_result_at` within 7 days (`approveRecent`) through the same `ApproveEnrolled` call (hint = the bound IP, MAC = `bound_mac`, `agentSaw=true`: the store counts as found only a row that has a `mac` observation with source `agent` equal to `bound_mac`, because no live connection proves the address), under the same rules as (c); an error on one node does not stop the run (the first error is returned at the end); a node revoked mid-run is skipped; the audit detail adds ", approved from its earlier reports after an upgrade"; the store also infers a device kind from the OS the agent reported (inventory INV-25). It reads only rows with `approved_at IS NULL`, so running again changes nothing; a node that is not bound yet waits for a `log`. `TestContract_UpgradeApprovesAndTypesEnrolledMachines`, `TestContract_UpgradeNeverApprovesARowTheAgentDidNotReport`, `TestContract_UpgradeKeepsTheBoxAndSuspiciousGuards`, `TestContract_UpgradeSkipsANodeRevokedDuringTheRun`. Wazuh does not approve. `TestContract_AgentClaimsThePassiveRowTypedAndApproved`, `TestContract_SuspiciousStaysForAPerson`, `TestContract_OldTokenSaysItsMakerIsUnknown`, `TestContract_AnAddressDHCPReusedApprovesNothing`.
- **INV-19** The osquery schedule has its own one-line query `kernel_info` (`SELECT version FROM kernel_info;`, the running kernel release "7.0.0-43-generic", 3600 s, part of the first report's `packages` answer); it is not attached to each `deb_packages` row because a log line over `logger_tls_max_linesize` is dropped whole by osquery. The box stores the last valid value of the node (the `kernel` column of `intake_osquery_nodes`) and attaches it to the package list of every later request (`withKernel`); Wazuh: the third field of `os.uname`. The value goes only from the agent to the box like the package list and does not leave the box (PRIVACY.md is unchanged). The Kernel row is the running kernel's image alone; every other installed image (a kernel installed by an update and not booted yet, an older one kept as a fallback) and every kernel metapackage (linux-image-generic, linux-image-amd64) is listed under its own package name with its full version and source, like the kernel's headers, modules and tools, so the device's list shows an installed kernel the device does not run and findings can tell a restart from an update. Running kernel unknown or not matching any image → every image is the Kernel row and the lowest gives its version. `TestContract_KernelOfAnotherRequest`, `TestScheduleEqualsTheGUIText`, `TestMapPackagesKernelFollowsTheRunningKernel`, `TestCount_DistributionKernelFindings` (cmd/vedette).
- **INV-20** The schedule has a query of its own only for Windows, `os_revision` (`SELECT name, version, revision, arch FROM os_version;`, 3600 s, `platform: windows`): the `revision` column (UBR, the monthly patch level) exists only on Windows from osquery 5.12, and osquery itself reads `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\UBR`; this query does not read the `registry` table (that table is read only for one value inside the `programs` query, INV-24). A row is accepted only when `version` is `10.0.<5-digit build>`, `revision` is an integer 1..999999 written as osquery writes it (no sign, no leading zero), and the name is 1..200 characters; otherwise it is dropped and the stored value is kept. The box stores the last valid value of the node (`intake_osquery_nodes.win_name`, `win_version` "10.0.22631.4460", `win_target` x64/x86/arm64/"" from `arch`) because osquery's splay sends queries with the same interval in different requests. The device's OS (`withWindows`) reads "Microsoft Windows 11 Pro 10.0.22631.4460" in an `os_version` report of the **same build** as the stored value, and immediately in the report of `os_revision` itself (the `os_version` row built from it); a different build (a feature upgrade that has not yet reported a revision) keeps "… build 26100". First report (INV-18): `os_revision` is its own answer in `reported`, asked every minute in the first hour until a usable revision exists, even if `os_version` arrives first. **The operating-system software row**: every Windows package list (osquery `programs`, Wazuh `win`) has **first** one row (`windowsRow`, the `core/winrel` table build → NVD release, client/server by the word "server" in the name): display/product "Windows 11 23H2", version "10.0.22631.4460", key `microsoft|windows`, CPE `cpe:2.3:o:microsoft:windows_11_23h2:10.0.22631.4460:*:*:*:*:*:<target>:*` (target from osquery's `arch` or Wazuh's `os.arch` — x86_64/AMD64 → x64, i386/i686/x86 → x86, aarch64/ARM64 → arm64; unknown → `*`), `Packaged` false. A build outside the table (newer than the table) or Azure Local / Azure Stack HCI (a server whose name has no "server", on a client build shared with it): still one row, displayed by the machine's name ("Windows 11 Pro"), a fixed product "Windows (build 28000)" (never the NVD `windows` family product), key `microsoft|windows`, **no** release CPE, so that findings gives each Windows entry "not checked" instead of nothing. No row is added when the request's `os_version` differs from the stored build; a request whose `os_version` has a different build and no usable revision **clears** the stored release (`win_*` = ''), so a machine that has just had a feature upgrade does not carry the row of the old release. First report: a `programs` list without the OS row (the revision has not arrived) does **not** count as the `packages` answer, so the first hour still asks for it every minute until the row exists. Wazuh: `os.version` with a revision (`winFullRE`) gives the same row, and `select` includes `os.arch`. The value goes only from the agent to the box and does not leave the box (PRIVACY.md is unchanged). `TestContract_WindowsRevisionOfAnotherRequest`, `TestParseWinOS`, `TestWithWindows`, `TestWindowsRow`, `TestWazuhWindows`, `TestWazuh_PullFillsTheInventory`, `TestScheduleAsksTheWindowsRevisionOfWindowsOnly`, `TestScheduleEqualsTheGUIText`.

## Postconditions (after completion)
- **POST-1** A server runs the one-line install + a valid token → `POST /intake/osquery/status` returns `{enrolled: true, hosts ≥ 1}` and the device appears in the store with the package list, source `agent`. **The install script exits 0** when this very machine has enrolled: it sends the machine name (`host_identifier` = `uname -n`/the DNS name, filtered to `[A-Za-z0-9._-]`) to `POST /intake/osquery/status` and waits for `host_last_seen` (the last_seen of the machine under the same token that carries that name, case-insensitive, compared with the `host_identifier` and `hostname` columns) to appear or to change compared with before osqueryd restarted, and osqueryd is running; another machine of the same token or of another token does not count, and it prints "Installed and enrolled; this machine's operating system and packages appear in Vedette within a few minutes"; it does not wait for the first report (a few minutes later, INV-18); it exits 3 only when after 2 minutes the machine has not enrolled (`TestInstall_ExitsZeroWhenEnrolledNotWhenFirstReportArrives`). **Re-enrolment:** a token different from the token in the machine's `enroll.secret` (or none yet, as after `--uninstall`) → the script stops osqueryd, deletes the osquery database (`/var/osquery/osquery.db`; Windows `C:\Program Files\osquery\osquery.db`) and only then writes the secret and restarts, so osqueryd enrols under the new token; the same token = a repair, keeping `node_key`. The box changes nothing: the old node row (old token) no longer has a machine holding its key, and stays until `node-prune` deletes it after 90 silent days or the old token is revoked; an `enroll` under a new token does not delete a node of another token (the machine name is self-reported). `--uninstall` also deletes the osquery database (`TestInstall_NewTokenEnrolsAgain`).
- **POST-2** Wazuh connected → every `interval_minutes` cycle updates `last_sync`, `agents`, `packages`; an error → `status=error` and `error` has content; old data is not deleted. **A stored password that cannot be opened** (sealed with a different master key: a restore without the decryption key, or the box key changed): the pull writes `status=error`, `error` = the sentence "was not restored … enter the password again", one WARN, and then **stops** (`next_pull` = 9999-12-31: nothing sent, nothing written, nothing logged every minute) until Save resets `next_pull`, or until the first round in which the password opens again (the root key was reset; only a local trial open, `secrets.IsWrongKey`), in which case that round pulls at once; Test/Save with a blank password → 409 `secret_lost`, nothing sent; retyping the password ends it. The Wazuh card shows `error` when `status=error`.
- **POST-3** Revoking a token → machines using that token are rejected at the next report; data already received is kept.
- **POST-4** Token expiry does not make an enrolled machine stop reporting (a token is only for enrolling; open question 3 is closed). An expired token is deleted only when no machine uses it any more; a machine silent for more than 90 days **while the module is on** is cleaned up (the job `node-prune`, an ordinary job: it does not run while the module is off). The last run is kept in the table `intake_prune_clock`: at the first run after a gap > 3 hours (module off, box off, restart, upgrade) the gap is added to the `last_seen` of every machine (no later than that moment), and then cleanup proceeds as usual. So running 89 days, off 2 days, on again: no machine has been cleaned yet; a restart does not make the 90-day chain begin again (an upgraded box still cleans silent machines, and the 500/5,000 caps do not fill up gradually). No clock row yet (the first run after the table exists): the gap is unknown, and the `last_seen` of every machine is set to that moment (the chain begins again).

`IssueToken(ctx, actor, name, ttlDays) (Token, secret, error)` / `IssueTokenFor(ctx, actor, name, ttlDays, device)` (INV-26) · `NodeHealth(Cadence, now)` (INV-25) · `DeviceMerged` (`core/lifecycle`, INV-26) · `ReportState(ctx, device)` / `AskReport(ctx, actor, device)` (INV-23, through `AdminHandlers`) · `RevokeToken(ctx, actor, id)` · `Nodes(ctx)` / `RemoveNode(ctx, actor, id)` (INV-25) · `ListTokens(ctx)` (the HTTP admin path: `AdminHandlers`; public files: `InstallHandlers`) · `Enroll`/`Config`/`Log`/`Status` (through `IntakeHandlers`) · `Prune` (the `node-prune` job, an ordinary job: machines silent for 90 days, tokens with no machines that are past expiry, or with no machine ever enrolled after 24 hours) · `ApproveBound` (the `approve-enrolled` job, an ordinary job, the upgrade path, INV-18 (d)) · `BodyLimits` (enrol 64 KiB, config 4 KiB, log 4 MiB, status 1 KiB). Writes to the store go only through `core/observe` (`Sink.Record`, `SoftwareSink.ReplaceSoftware`, `Approver.ApproveEnrolled` (INV-18), source `agent`, confidence 0.95; a card's MAC 0.9); `Config.Approver` is mandatory like `Sink`/`Software`. Mapping a package → a KEV key: `content/catalog/products`, with tests that check against the catalog. `KnownSoftware()` (findings INV-4e): a pure function, every row of the mapper for a KEV key (each pair in `content/catalog/products`, with no version, no `Packaged`; the operating-system row `windowsRow` of every `core/winrel` release), for the `reach-audit` job of `cmd/vedette`. Rows from `deb_packages`/`rpm_packages`/`apk_packages` (including Wazuh deb/rpm packages and `MapDebPackages`) carry `observe.Software.Packaged=true` (the distribution's package database), while `pacman_packages` (Arch has no distribution data source) and `programs` do not (inventory INV-28 (3)); `TestMapPackagesGolden`. An exception: a `content/catalog/products` package marked `"upstream": true` (the vendor's own package from the vendor's repository, the version being the product's release: google-chrome-stable/beta/unstable, microsoft-edge-stable/beta/dev) has `Packaged=false`, no `PkgVersion`/`PkgSource`, so findings compares it against the NVD range instead of waiting for a distribution note; `TestMapPackagesVendorBuildIsNotTheDistributions`. The `agent` source is shared with Wazuh: the later writer wins. `MapDebPackages(pkgs) (software, dropped)`: a pure function, the same mapping as the `deb_packages` table, reads no table, and runs even when the module is off; unlike the agent's snapshot (cut at 5,000 rows), it never cuts the list: inventory stores the whole list or rejects the whole list; `cmd/vedette` uses it for the dpkg list of the box itself (vedette-host), so the box and an osquery on the same machine produce exactly the same rows. **Wazuh**: `TestWazuh`/`SaveWazuh`/`DeleteWazuh` (through `WazuhHandlers`; errors 400 `bad_url`, `bad_username`, `password_required`, `bad_password`, `bad_interval`; 422 `wazuh_auth`, `wazuh_forbidden`; 502 `wazuh_unreachable`, `wazuh_tls`, `wazuh_bad_reply`; 409 `wazuh_changed`; 404 `not_found` when deleting with nothing connected; `sample-data` 404, INV-10) · `Wazuh(ctx)` (the connection without the password, for `GET /inventory/agents`) · `WazuhConnected(ctx)` (flow 14 of Settings → Privacy) · `WazuhPull` (the `wazuh-pull` job, a 1-minute beat, an ordinary job; it pulls only when `next_pull` has arrived) · `ScheduleOwner()` (registers the schedule `agent-intake.wazuh` with `core/schedule`: an interval only, ≥ 5 minutes, default 15, off until Wazuh is connected; when due `askPull` sets `next_pull` = now so the next tick pulls; when it does not pull the reason is stated: not connected, the password cannot be opened, the previous round is not finished). It needs `Config.Secrets` and `Config.Conn`; without them the Wazuh routes return 501 and the job does nothing. **Admin path and scripts**: `AdminHandlers` (`GET /inventory/agents`, `POST/DELETE .../tokens`, `POST .../tokens/remove-unused`, `DELETE .../nodes/{id}`, `GET`/`POST .../devices/{id}/report`), `InstallHandlers` (the two scripts, `ca.pem`, the package store; INV-17); `Config.TrustAnchor` (the pinned PEM; `ErrNoTrustAnchor` = the box has no certificate), `Config.HostAllowed` (the `server.HostMatcher` of the same Host list), `Config.BoxURL` (the configured address), `Config.MirrorDir` (the `-osquery-dir` flag, default `/usr/share/vedette/osquery`, the image directory); `OsqueryVersion`. When any of them is missing, that part returns 404 (`no_certificate`, `mirror_missing`) or uses the placeholder address, and never guesses.

## Events
- **Emits**: `inventory.observation` (the name appears in ARCHITECTURE) with `source=agent`.
- **Receives**: none.

## When the module is off (SYS-5)
No `/install/*`, `/intake/*`, `/inventory/agents*` routes; no Wazuh pull (the `wazuh-pull` job is an ordinary job: the context is cancelled at once and nothing more is written; `TestWazuh_SYS5_ModuleOffIs404`); osquery cannot enrol/report (the connection is lost). Tokens, the Wazuh configuration and data already received are kept. Devices with source `agent` stop updating and show the true age of the data, without pretending to be fresh.

## Dependencies
- **DEPENDS ON**: `core` (auth, `core/secrets`, TLS 8443, the `core/conn` HTTPS facade for Wazuh), `inventory` (receives observations), `core/updates` (the official osquery package is in `managed` of Updates).
- **DEPENDED ON BY**: `inventory` (the source column `agent`, high confidence), `exposure/scan` (not required), `reports` (an inventory source in PDPL `inventory.sources`).
