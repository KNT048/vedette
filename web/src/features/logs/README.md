# features/logs

Stories: S-LOG-1 (log sources: a catalogue of 48 device/software types with search, groups, the protocols they can send, whether Vedette reads them or only stores them; a copy-paste config snippet or UI steps for each type; the digest "new / spike"; event search; retention), S-LOG-2 + S-LOG-4 (connections to bad IPs/domains: time, the inventory device, the destination, how it was seen = SPAN DNS/SNI/HTTP host/flow or syslog, the matching feed, confidence; no IDS on the box), S-LOG-3 (Settings, the `siem` section: syslog/CEF/JSON webhook, send a test).
Slot consumed: `logs.panels` (props `{}`), where the ai module attaches the AI digest. Provides no slot.
Mock tables: `logs_sources`, `logs_events`, `logs_retention`, `logs_siem`, `logs_ioc_hits` (`{ id, ts, asset_id, src_ip, dest, dest_kind, seen_via, feeds, confidence }`, the response module reads it with `peek`). A clean install: sources, events and digest are empty.
`kinds.ts` = the type codes (the contract enum); `catalog.ts` = the content of each type (group, protocols, `reads: parsed|stored`, steps, paste-in snippets, notes; the vendor documentation source in a comment). To add a type: add the code to `kinds.ts`, an entry to `catalog.ts`, run `logs.test.tsx`.
