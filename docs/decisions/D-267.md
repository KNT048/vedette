| D-267 | **Docker's FORWARD drop: `vedette-host` keeps two rules in `DOCKER-USER` for the `vedette-int` subnet.** Docker sets the iptables filter FORWARD policy to DROP when it enables IP forwarding; netavark (Ubuntu 26.04) keeps its rules in its own nftables table and an accept there is not final, so on a box with Docker the GUI on 8443 and syslog 514 are unreachable from the LAN (#297) and the containers cannot reach the internet. Decision: only when the chain `DOCKER-USER` exists, `vedette-host` (at start and every 30 s, idempotent: `iptables -C`, then `-I DOCKER-USER 1`) holds R1 `-d <subnet> -m conntrack --ctstate DNAT,ESTABLISHED,RELATED -m comment --comment vedette-int -j ACCEPT` and R2 `-s <subnet> -m comment --comment vedette-int -j ACCEPT`. The subnet is read from the Quadlet file `vedette-int.network` (`Subnet=`, private IPv4, 16 to 28 bits, `net/netip`), never from a request; exec only through the allowlisted `/usr/sbin/iptables` with a closed argv grammar; a stop leaves the rules (they accept only Vedette's own subnet), `install.sh --uninstall` deletes the rules with that comment; `vedette-host.service` gets a soft `After=docker.service`; `install.sh` checks the two rules by effect and, with FORWARD DROP and no `DOCKER-USER` (ufw, firewalld, own firewall), only warns what to allow. Rejected: switching netavark to the iptables driver (changes Podman for every other network on the box; 24.04 and 26.04 differ), `sysctl ip_forward=1` before Docker starts (changes the customer's Docker isolation, does not fix a running Docker), `install.sh` refusing on a box with Docker (a legitimate choice, and the box would still break when Docker is installed later). | Sources: Docker, [Packet filtering and firewalls](https://docs.docker.com/engine/network/packet-filtering-firewalls/) (the drop policy when Docker enables forwarding; DOCKER-USER is the chain for the administrator's rules); LXD, [Prevent connectivity issues with LXD and Docker](https://documentation.ubuntu.com/lxd/en/latest/howto/network_bridge_firewalld/#prevent-connectivity-issues-with-lxd-and-docker) (ACCEPT rules for the bridge in DOCKER-USER); Fedora, [Changes/NetavarkNftablesDefault](https://fedoraproject.org/wiki/Changes/NetavarkNftablesDefault) (rootful Podman beside Docker loses connectivity; the fix is an iptables accept for the Podman traffic). | 2026-11-11 |
