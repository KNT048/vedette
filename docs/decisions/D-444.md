| D-444 | **One device is one log source: the sender IP stays the key, and a UDP source also takes TCP from its IP; a TCP source takes no UDP, TLS only TLS (S-LOG-1, walk 4).** (1) **Why**: walk 4 could not declare a Mac that sends over UDP and TCP: a second source with the same IP is refused (409 `duplicate`) and a source has one protocol, so TCP lines from a UDP source were dropped. (2) **Options weighed**: (a) the pair IP + protocol as key (two rows for one device): needs a unique index change on `logs_sources`, a listener keyed by (IP, protocol), and splits one device's digest, baseline, state and line rate over two rows (signatures are grouped by source, D-30), which reads as two devices; (b) a set of protocols per source: changes `proto` in the API, the mock, the setup snippets (one protocol per device setup) and the table schema; (c) chosen, the smallest correct change: the IP stays unique, `proto` stays one value (the protocol the setup tells the device to use), and the listener's sender check is `listen.Accepts(declared, arrived)`: equal, or declared `udp` and arrived `tcp`. No migration, no API or schema change. (3) **Why that direction only**: TCP needs a handshake, so an off-path host cannot forge it as easily as a UDP datagram; letting a UDP source take TCP lets in nothing harder to forge than what it already takes. The other way would let a forged datagram pass as a device declared TCP to avoid exactly that, so a TCP source still drops UDP (and the D-421 hint names it: "<ip> sends syslog over UDP, but <name> is declared with TCP"). TLS stays strict both ways: its server certificate and optional client pin (D-214, D-435) are why it was chosen, and a plain line must not pass as it. (4) **Where it shows**: the source form's protocol hint (UDP: "The box listens on UDP and TCP and keeps this device's lines from either."; TCP: "The box listens on UDP and TCP but keeps only TCP from this device: UDP is easy to forge."; TLS: "The box keeps only TLS from this device, on port 6514."), and the 409 `duplicate` message ends "a UDP source also takes lines from its IP over TCP.". `UnknownSenders` (Go and mock) leaves out a sender its source now takes, with the same rule.
