| D-421 | **Syslog from an undeclared sender stays dropped, but the Sources page names the sender (S-LOG-1, walk 3; replaces "no GUI" of logs open question 2).** (1) **Why**: on a container install, syslog sent from the machine that runs the containers reaches core from the container network's gateway (172.18.0.1 in walk 3), so a source declared with the device's address got nothing and nothing said why; the listener already counted the sender (`listen.Stats.UnknownSender`). (2) **What**: `GET /logs/unknown-senders` (operator and up: addresses of senders that are not sources) returns the 10 senders seen most recently with the protocol of the last message, the count and the last time; a sender that a source now declares with the protocol it used is left out, so adding the source clears the hint at once. The page says "<ip> sends syslog over UDP, but no source has this IP, so the box drops its lines (N times, last …)", or names the source when the IP is declared with another protocol; admins get **Add as source** (form pre-filled with the IP and protocol) or **Edit <source>**; on a container install a line explains the gateway. (3) **Bounds and trust**: in memory only (the 256-entry LRU of the listener), counted since the listener last started, which the page says; the address comes from the socket, never from the line text; nothing from such a sender is stored (FORBID-5 unchanged). | Syslog servers that filter senders say so where the admin looks: rsyslog's `$AllowedSender` logs the disallowed sender it discards, Wazuh `remoted` logs "Message from '<ip>' not allowed" for an IP outside `allowed-ips`. Both put it in a daemon log the Vedette user never reads (single page, no shell), so the same fact goes on the Sources page, next to the action that fixes it. Not chosen: accepting and storing lines from unknown senders for review (FORBID-5: a spoofed or stray sender would fill the store); a persistent table (the hint is about now; a restart re-learns within one message).
