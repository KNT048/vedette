| D-229 | **External exposure scan: the `scan` module's runner, Go standard library, in `core`, inside D-57 (7) and LEGAL §3 (S-EXP-1; exposure INV-12, scan INV-12).** It follows D-57 (7) ("Subdomain của domain đã xác thực chỉ kiểm HTTP theo tên miền; không quét cổng IP phân giải ra trừ khi IP đã xác thực") and LEGAL §3 (active scans only on verified assets; a public IP only when it is the box's own; no mode that scans IPs out of scope; every probe logged ≥ 90 days); it changes neither. (1) **Owner and switch:** `exposure.Runner` is the `scan` module's (D-55), built in `cmd/vedette` (`scanRunner`) over the leaf package `modules/scan/surface`, set as `exposure.Config.Runner`. It runs only while `scan` is on; off, `POST /exposure/targets/{id}/scan` answers 409 `module_off` after the ownership gate and nothing is probed; switched off during a scan, the scan's context is cancelled (`modreg.OnChange`) and it answers the same (SYS-5). 501 `not_implemented` stays only for a build with no runner. (2) **Standard library, not ProjectDiscovery:** a TCP connect (`net`), `crypto/tls`, `net/http` and `encoding/json` do what the scan needs from the box's own network; naabu needs pcap/cgo for SYN scans and httpx/subfinder pull large dependency trees into `core`'s `go.mod` (the reason D-125 kept nuclei out of `core`). It runs in `core`, which already makes outgoing HTTPS; no raw socket, no new dependency, no container job. THIRD_PARTY_NOTICES drops httpx/naabu/subfinder/dnsx from "planned". (3) **Scope:** only what exposure hands over after INV-1/INV-13. The box's own verified IP gets the port scan (4). A verified domain's names come from certificate transparency at crt.sh, are resolved and listed; a name on a public address (`exposure.IsPublicIPv4`) gets HTTP checks **by name only**: one `GET /` on port 80 and one on 443 (with its certificate), nothing else. An address a name points at is port-scanned only when exposure's `ScannableIP` says it is itself a verified, committed, current IP target (the same gate as a scan of it, the person who clicked as actor); any error means no. A name on a non-public address is listed and never dialed; every dial checks the rule again and goes to the planned address (no re-resolve, no proxy). (4) **Probes:** TCP connect (nothing sent) to a fixed list of 98 commonly exposed ports, about naabu's top-100 default but chosen for what attackers probe first (admin and web, remote access, file sharing, databases, mail, VPN, devices, out-of-band management; no UDP), 1.5 s a dial, at most 300 new connections a second and 100 at once; one `GET /` per open web port and a TLS handshake per TLS port; Host and SNI = the name (the IP for the box's IP), Go's default User-Agent (D-81's rule), TLS not verified (the page and certificate are read, never trusted), 64 KiB, 6 s; **no redirect is followed** (httpx's default too), its `Location` is only a hint for the fingerprints; the crt.sh client follows none either. A built-in list of page fingerprints (title, a few headers, product-only markers; never a word an ordinary site could contain) names admin pages: `danger` for network/firewall, NAS, server and out-of-band management, and tools that run code (several are on CISA KEV); `warn` for applications with their own sign-in often published on purpose; VPN portals name the port only. (5) **Probe log and audit (LEGAL §3):** every probe is a `scan_probe` row (run id NULL, template `exposure: tcp|http|https|tls`) written before it goes out and completed with its answer, kept 90 days with the other probes (Scans → Probe log, CSV); if the row cannot be written, nothing is probed. Every click on Scan now is an `exposure.scan` audit row with its outcome, refused and failed ones included. (6) **Deterministic or nothing (no truncation):** crt.sh's answer is read whole (at most 16 MiB, 1 MiB a certificate), its names deduplicated and sorted; more than 300 names, or a bigger answer, stops the scan with 400 `too_many` and a hint to add a narrower subdomain as its own domain, rather than keep a part that changes from day to day (false new/gone rows, false `new_port` events). Expired certificates are excluded in the query (`exclude=expired`) so the set is the names in use. No other cap can cut: at most 2 × 300 HTTP checks, and the port scan covers only verified IP targets (exposure holds at most 20). Chosen over a "truncated" flag on the snapshot because that would change the approved GUI and the diff for a case a small company rarely has. (7) **Failures save nothing:** crt.sh not answering (asked twice) or the 5-minute cap is 502 `unreachable`; a snapshot without the subdomains would make the day comparison report them gone. (8) **Load limits:** one scan at a time on the box (409 `busy`) and at most one scan of a target every 10 minutes (429 `rate_limited`, the time of the next allowed scan in the message), so repeated clicks do not hammer crt.sh or the targets; the mock's scans are instant and it does not enforce either. (9) **Hairpin, said honestly:** the box scans its own public IP from inside, through the router (NAT loopback); a router may show its own login page only to the inside, one without loopback shows nothing. The results page says this, and that ports are scanned only on the box's verified IPs, instead of "scans from outside". Not chosen now: an outside view from a third party (Shodan InternetDB, free, no key) would remove the limit but is a new outbound flow of the customer's IP, which needs kien; recorded as deferred.
