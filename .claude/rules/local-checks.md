# Kiểm tra: `make check` trên máy, bộ đầy đủ trên CI (kien, 2026-11-09, D-61 → D-62, D-63; D-199)

Repo `KNT048/vedette` là public nên GitHub Actions miễn phí (D-63). CI chạy bộ đầy đủ trên máy GitHub; máy người làm chỉ chạy phần nhanh.

- **Trước khi push / mở PR: `make check`** trên nhánh đã rebase lên `origin/main`. Chỉ kiểm phần đã đổi: Go → build, vet, `go test -race` của gói có file đổi và gói import trực tiếp chúng (D-251), contract, lint, kiểm mã sinh khi hợp đồng/migration/query đổi; giao diện → tsc, lint, `vitest --changed`, kiểm lệch `api/openapi.json` khi `contract.ts` đổi, spec e2e của module bị chạm (desktop); chỉ docs → không chạy gì; file dùng chung (dependency, cấu hình build, `web/src/lib`, `web/src/mocks`, Makefile, `scripts/`) → vẫn `make check`; CI chạy bộ đầy đủ (D-199). `make verify` trên máy chỉ để tái hiện một CI đỏ.
- **Merge khi CI xanh, qua merge queue** (job `go`, `web`; D-245): CI của PR xanh → `gh pr merge <n> --squash`, GitHub ghép PR với `main` rồi chạy lại CI trước khi merge. Không merge `main` vào nhánh chỉ để đuổi `main`; chỉ khi PR xung đột. CI đỏ → sửa, không merge "vì máy mình xanh". Dán phần cuối `make check` vào mục **Local checks** của PR.
- CI (D-140): job `changes` (`make ci-changes`, `scripts/ci`) quyết PR cần `go`/`web` hay không; chỉ bỏ qua với đường dẫn không test nào đọc, `scripts/ci/guard_test.go` giữ điều đó; đường dẫn lạ = chạy cả hai. `go` và `web` là job tổng hợp luôn báo đúng tên. `main` không bao giờ bị huỷ run.
- Workflow chỉ gọi `make` (trừ hai job tổng hợp `go`/`web`, chỉ so kết quả job); action bên thứ ba ghim theo SHA; quyền token tối thiểu. Không thêm workflow tốn phút ngoài `ci.yml` mà không ghi quyết định.
- **E2E (Playwright)** chỉ cho tính năng vừa làm/sửa (`make check` chạy spec của module bị chạm). **Bộ e2e đầy đủ chỉ chạy khi sản phẩm gần sẵn sàng production** (kien, D-64); CI không chạy e2e.
- `make audit` (govulncheck + `pnpm audit`) đầu mỗi phiên; CI cũng quét hằng ngày trên `main`.
- **Máy phát triển là Linux hoặc macOS.** Windows: chạy `make` trong WSL2 (Ubuntu), mã nằm trong hệ file của WSL (không `/mnt/c`); Makefile từ chối Windows gốc.
- **Không chạy song song nhiều việc nặng** (build web, vitest toàn bộ, Playwright, `make verify`) trên cùng máy: tối đa 2 cùng lúc; trước khi chạy Playwright kiểm không còn lượt nào (`pgrep -f playwright/test/cli.js`); lệnh hết giờ thì giết cả cây tiến trình. Máy quá tải làm test timeout giả. Mỗi máy dev cài một lần `make reaper-install`: cứ 10 phút dừng tiến trình test mồ côi (Playwright, Chromium headless, vitest, `go test`, golangci-lint) và vite mồ côi quá 2 giờ; cùng lượt báo (thông báo macOS + log) issue mở mới gắn nhãn `owner:kien` của `KNT048/vedette` — máy của Emily cài bằng `VEDETTE_ISSUE_LABEL=owner:emily make reaper-install`, tắt bằng `VEDETTE_REAPER_ISSUES=0 make reaper-install` (cần `gh` đã đăng nhập).
