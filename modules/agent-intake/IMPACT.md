# Agent-intake — Change Impact Map

> Last verified: 2026-11-21 (every statement checked against the code). Package `modules/agent-intake` (tên Go `agentintake`): osquery `enroll`/`config`/`log`/`status`, token ở mức dịch vụ, ánh xạ gói, kéo Wazuh, đường admin, script cài, `ca.pem`, kho gói.

## Modifying: where the Wazuh pull delivered (`intake_wazuh_agent`, `wazuhAgentSeen`, `WazuhAgentAddresses`)
- **inventory** (`Config.WazuhAgents`, wired in `cmd/vedette/inventory.go` `wazuhAgents`): the only way the Devices list says `wazuh` for a device (`source:wazuh` filter, `DeviceRow.sources`). Writing it before the agent's data, or not cleaning it at the end of a pass, makes a device that took over an old agent's address say Wazuh. `modules/core/export_policy.go` lists the table.

## Modifying: the device hint of a report (`hint` in `Log`, `nodeAgent`, INV-12)
- **inventory** binds `AssetHint.Agent` to a device (INV-31) and finds the device by it before the address: a key that changes per report (or names something other than this box's node id) makes every report a candidate for a second device; never put a value the machine sends (host_identifier, MAC) in it.

## Modifying: the agent state (`nodestate.go` `NodeHealth`, `Cadence`, `nextGap`, `supersededBy`; columns `last_call_at`, `call_every_s`, `call_gap_s`, `report_every_s`; `state`, `quiet_since`, `rhythm_s`, `os` of the device report and `nodes` of GET /inventory/agents)
- **Every reader of agent state calls `NodeHealth`**: `Nodes`, `ReportState` (osquery and Wazuh), and through them the device's agent row (inventory `DeviceSources` via cmd/vedette `sourceFacts.agent`) and findings (`agentReports`). A reader that judges an agent its own way brings back "quiet" beside a recent report. The row's `last_at` is the very time NodeHealth judged by.
- **web/features/inventory** (`DeviceSources.tsx` Agent row, `AgentsSection.tsx` machines table, `AgentQuiet.tsx` commands): `call_every_s` at enrolment is the install scripts' `--config_refresh=300` (`configRefresh`) or the package reporter's hourly run (`reporterEvery`, its timer/cron line in `scripts/osquery.sh`); change a flag or a timer and its constant together. `report_every_s` is the schedule's longest interval (`steadyEvery`, schedule.go): a longer query interval there makes a new agent's first silence longer before quiet. `nextGap` learns only from two config fetches in a row whose gap is the told refresh within ±10 s (`refreshSlack`); learning from result posts (irregular, splayed) or from two service starts would call an agent without config refresh quiet between its results (`TestAgentCadence_ReplayOfSevenAgents`, `TestAgentCadence_TwoServiceStartsAreNoRefresh`). A longer `--config_refresh` in the scripts needs `configRefresh` changed with it, or refreshing agents fall back to the report schedule.
- **findings** (`agent_gone` of GET /findings/plan, the finding page's agent line) and **mitigation** read `stale` through cmd/vedette `agentReports`: a wrong limit says "no agent reports this device now" about a device whose agent reports. `os` picks the service commands (`windows` or `linux`).
- **inventory** binds a device to the first node that read it and never rebinds: a machine enrolled again keeps `osquery:<old node>` on its device, so `reportState` reads the newest record bound to the same source address (`newestOf`; never matched by the name or MAC a node claims). `RemoveNode` and node-prune release the binding (`releaseNodes`).
- **Windows script** (`scripts/osquery.ps1` and its web copy): sets delayed-auto start and restart-on-failure, then reads them from the service's registry key; when they did not apply the agent still starts and enrols, and the run ends with a warning and exit code 4 (`TestInstall_WindowsServiceRestartsItself` holds the lines; no PowerShell in CI).

## Modifying: giao thức osquery (`/intake/osquery/{enroll,config,log}`) — 1 người gọi: `osqueryd` trên máy chủ khách
- **Script cài và cài tay** (`web/src/features/inventory/{scripts/*,agentConfig.ts}`): cờ `*_tls_endpoint` trỏ vào đúng ba đường này; đổi đường dẫn = SHA-256 script đổi và mọi máy đã cài phải cài lại.
- **Lịch truy vấn** (`schedule.go` = `OSQUERY_SCHEDULE` trong `agentConfig.ts`; `schedule_test.go` so khớp từng truy vấn, khoảng, nền tảng): thêm/bớt truy vấn phải đổi `schedule.go`, bảng `columns` trong `parse.go`, GUI và mapper; `interfaces` là truy vấn định danh máy (INV-12), bỏ nó = không máy nào ghi được gì.
- **`os_revision`** (INV-20): câu chỉ cho Windows; cột `revision` không có trên Linux, nên không gộp vào câu `os_version` (câu đó sẽ hỏng trên Linux). osquery < 5.12 làm câu này hỏng riêng, máy vẫn báo như phiên bản cũ (giờ đầu hỏi nó và `programs` mỗi phút rồi thôi). Nó là câu trả lời riêng `os_revision` của báo cáo đầu (`firstReport`, `answers`; cột `reported` ≤ 64 ký tự vẫn đủ). Giá trị đã lưu (`win_*`, có trong `modules/core/export_policy.go`) cho chữ OS và dòng phần mềm hệ điều hành (dưới).
- **Câu `programs` (INV-24)**: một SELECT ghép (`programsQuery`) — registry `PatchLevel` của các phiên bản SQL Server trước, rồi `programs`; cột `sql_setup` phân biệt. Đổi cột hay thứ tự nhánh phải đổi `columns`, `mapPackages` (bỏ dòng `sql_setup`), `agentConfig.ts` và test GUI (`inventory.test.tsx`). Thêm một nguồn phiên bản máy khác (Office C2R `VersionToReport`, Visual Studio) theo cùng mẫu: một giá trị chính xác trong cùng câu, không bảng `registry` rộng. Hỏng nhánh registry làm hỏng **cả** danh sách Windows (một câu): giữ SQL thuần SQLite, một ràng buộc `key LIKE`.
- **`sqlserver.go`**: `sqlFamilies` (năm → họ bản dựng) phải đi cùng `sqlServerMajors` của findings (`schemes.go`, năm của CPE NVD `sql_server:2014` → major); bản phát hành mới (SQL Server 2025 = 17) thêm vào cả hai. Bỏ khoá KEV khỏi dòng thành phần (RsFx) chỉ khi PatchLevel có: đổi điều kiện này là đổi CVE nào còn mở sau một CU.
- **Dòng phần mềm Windows**: `windowsRow` đọc `core/winrel` (cùng bảng findings dùng; cả bản học từ trang Microsoft, feed `windows-releases`): đổi tên NVD, build hay dòng (Line) của một bản phát hành ở đó đổi cả dòng agent gửi lẫn cách findings đọc mục Windows (findings INV-15). Build ngoài bảng và Azure Local/Azure Stack HCI cho dòng không CPE bản phát hành (findings: "not checked"); thêm bản phát hành vào bảng biến dòng đó thành dòng đọc theo bản vá. Dòng mang khoá `microsoft|windows` và CPE bản phát hành: findings bỏ qua dòng "Windows" người tự thêm trên cùng thiết bị. `deliver` không tính `packages` cho danh sách `programs` thiếu dòng OS: đổi điều đó đổi lúc dòng OS hiện sau đăng ký. Wazuh `select` có `os.arch`; fake của test trả trường đó.
- **Báo cáo đầu (INV-18)**: `nodeSchedule` đổi `interval` theo máy (60 s cho câu chưa nhận, giờ đầu); thêm truy vấn mới phải thêm nó vào `firstReport` (`schedule.go`) và `answers` (`ingest.go`), nếu không máy mới hỏi nó mỗi phút suốt giờ đầu. Bỏ `--config_refresh=300` khỏi script (`scripts/*`, `web/src/features/inventory/{scripts/*,agentConfig.ts}`) = máy giữ nhịp 60 s tới lần khởi động osqueryd sau (`TestInstall_ExitsZeroWhenEnrolledNotWhenFirstReportArrives` giữ cờ). Cờ này làm mỗi máy gọi `config` mỗi 5 phút (một lần ghi `last_seen` mỗi lượt; hạn 6/phút).
- **Duyệt + loại**: `Config.Approver` (inventory `ApproveEnrolled`, inventory INV-25) bắt buộc; `firstReport` truyền MAC của `binding` (card mang IP nguồn): đổi `binding` hay bỏ MAC là đổi điều kiện duyệt (không có MAC → chỉ hàng chưa từng thấy MAC nào được duyệt); `kindOf` (`mapper.go`) chỉ trả loại trong danh sách `inventory.Kinds` (kho từ chối loại lạ, cả lô quan sát mất một dòng). Wazuh dùng chung `observations` nên đổi `kindOf` đổi luôn loại của máy Wazuh. `kindOf` là `core/observe.AgentKind`: bảng nền tảng → loại dùng chung với `AgentKindOfOS` của kho (loại từ OS đã lưu, đường nâng cấp), đổi một là đổi cả hai.
- **Job `approve-enrolled` (đường nâng cấp, INV-18 (d))**: `ApproveBound` dùng chung `approve` với `firstReport`: đổi luật "xong một lần" (`found` hay lỗi biên → đặt `approved_at`) là đổi cả hai đường. Nó tin `bound_ip`/`bound_mac` do `markResult` ghi (luật gắn) chỉ khi `last_result_at` trong 7 ngày và kho thấy quan sát `mac` nguồn `agent` bằng `bound_mac` trên hàng đó (`agentSaw`); đổi cách gắn, cách ghi `last_result_at` hay bỏ quan sát MAC của agent trong `observations` là đổi điều kiện duyệt lúc khởi động. Mỗi lần chạy đọc các node chưa duyệt có gắn (≤ 5.000, một `ApproveEnrolled` mỗi node); node mà kho chưa có thiết bị được thử lại mỗi lần chạy (mỗi ngày).
- **core/server**: bốn thao tác là `public`; cổng module (SYS-5) và `BodyLimits` áp theo `operationId` (`inventory_post_intake_osquery_*`); đổi `operationId` (đổi đường dẫn trong `contract.ts`) làm đổi khoá giới hạn thân (`cmd/vedette/modules.go` nhận `agentintake.BodyLimits`; `server.New` từ chối khoá không tồn tại).
- **Đọc địa chỉ nguồn**: `Exchange.ClientAddr()` (`r.RemoteAddr`). Đặt hộp sau proxy/NAT ngược làm mọi máy "chưa khớp" (INV-12) và chung một hạn mức nguồn (INV-14).

## Modifying: ghi vào `inventory` (`observe.Sink.Record`, `observe.SoftwareSink.ReplaceSoftware`, nguồn `agent`) — 1 đích
- **inventory**: nhận quan sát `os`/`hostname`/`vendor`/`model`/`mac` và danh sách gói (≤ 5.000, khoá `vendor|product` ≤ 400 byte, phiên bản ≤ 100 ký tự). Đổi giới hạn của `inventory.checkItems`/`cleanText` → `mapper.go` (`maxName`, `maxVersion`, `maxKeyBytes`) phải đổi theo, nếu không kho từ chối cả danh sách. Đổi độ tin cậy → cách kho gộp nhiều nguồn và cột "nghi"/"chắc" đổi theo. Đổi khoá định danh host (MAC rồi IP) → trùng thiết bị.
- **`PkgVersion`/`PkgSource`**: `mapPackages` đặt cho dòng deb (osquery `deb_packages`, Wazuh deb, `MapDebPackages` của hộp): phiên bản đầy đủ của dpkg và gói nguồn (`source` trống ⇒ tên gói, `name (version)` ⇒ tên). Nhiều gói nhị phân gộp thành một dòng giữ phiên bản đầy đủ **thấp nhất** (`core/debver`), trừ ảnh kernel (`kernelImageRE`): khi dòng deb có cột `kernel` do hộp gắn (kernel đang chạy: câu osquery `kernel_info` riêng, lưu trên node `intake_osquery_nodes.kernel` rồi gắn vào danh sách gói (`withKernel`), Wazuh trường thứ ba của `os.uname`, hộp `GET /v1/info` `os.kernel` qua `DebPackage.Kernel`) và có ảnh `linux-image-<release>` của nó thì chỉ ảnh đó cho dòng Kernel phiên bản; không biết → thấp nhất như mọi gói. Gói meta (`linux-image-generic`) không bao giờ cho phiên bản hay gói nguồn. Source có `(phiên bản)` khác epoch/upstream của gói nhị phân → không phiên bản đầy đủ (trừ `linux-signed*`). `TestMapPackagesKernelFollowsTheRunningKernel`, `TestMapPackagesSourceOfAnotherRelease`. findings so với dữ liệu Ubuntu/Debian; đổi ⇒ finding gói distro đổi (`TestMapDebPackagesKeepsFullVersionAndSource`).
- **`Packaged`**: `mapPackages` đặt cho dòng deb/rpm; findings (qua inventory `MatchSoftware.Packaged`) chỉ khuyên "install your distribution's security updates" cho các dòng đó. Thêm bảng gói khác phải quyết cờ. Cờ `upstream` của `content/catalog/products` (gói của chính hãng) bỏ `Packaged`: findings đọc dòng đó theo khoảng NVD; đánh dấu nhầm gói của bản phân phối là mất lời bản phân phối (backport) cho nó.
- **`MapDebPackages`**: người gọi là `cmd/vedette` `boxPackages` (danh sách dpkg của chính hộp). Đổi `mapPackages` cho `deb_packages` cũng đổi phần mềm của "This box"; hai bên phải giữ cùng dòng để một osquery cài trên hộp không đổi qua đổi lại danh sách. `mapPackages` nhận trần số dòng: agent và Wazuh truyền `maxRows` (5 000), `MapDebPackages` không cắt (inventory lưu cả hay từ chối cả).
- **core/productid** (`content/catalog/products`): tên gói/chương trình → sản phẩm, khoá danh sách khai thác, phiên bản nêu trong tên (Temurin "21.0.7+6" → 21.0.7; Zulu: không lấy số bản dựng riêng). Đổi tên hay mẫu ở đó = đổi dòng phần mềm agent gửi (`TestMapPackagesGolden`, `TestMapPackages_JDKDistributions`, `TestCatalogueKeepsThePackageNames`); khoá `kev` thêm phải có trong `kev-products.json` (productid `TestCatalogue_Loads`).

- **`ReplaceServices`** (INV-22): `Config.Services` = inventory; danh sách cổng nguồn `agent` của osquery và Wazuh dùng chung một hàng nguồn (`agent`) trên thiết bị, bên ghi sau thắng như gói; hộp tự ghi cổng của nó cũng nguồn `agent` (inventory INV-3) nhưng theo id hộp, không qua module này. Giới hạn `maxServices`/`maxSvcName` của `services.go` phải bằng của `inventory` (INV-23).

## Modifying: chứng chỉ ghim (`GET /intake/ca.pem`, INV-11) — `install.go` (`anchor`), `Config.TrustAnchor`; cmd/vedette/boxca.go, tls.go
- **Mọi máy đã đăng ký**: tin cậy nằm ở CA riêng của hộp; đổi khoá CA = mọi máy phải cài lại. Gia hạn/đổi địa chỉ chỉ cấp lại lá (không ảnh hưởng máy). CA nằm trong `core_secret` (core INV-33): khôi phục `vedette.db` + `vedette.key` giữ nó; mất khoá chủ thì không.
- **`Config.TrustAnchor`** (cmd/vedette `deps.TrustAnchor`): nil = 404. Bộ lọc khối `CERTIFICATE` ở `anchor` (`install.go`) là chốt duy nhất giữ khoá của tệp chủ hộp không ra ngoài (cmd/vedette chuyển nguyên byte tệp `-tls-cert`): bỏ nó = lộ khoá TLS của chủ hộp trên `ca.pem` và trong script, cả hai công khai (`TestContract_INV11_CaPemServesTheCertificateOnly`).
- **core**: logic cấp lại lá phải ký bằng CA này; chứng chỉ chủ hộp đưa vào không bị đụng.
- **GUI**: SHA-256 của script thay đổi khi chứng chỉ ghim đổi (script nhúng nó).

## Modifying: script cài (`/install/osquery.sh|ps1`, `GET /inventory/agents` khối `install`)
- Máy chủ khách đã cài: script chỉ chạy một lần; đổi **nội dung** thì SHA-256 trên GUI đổi (người dùng so lại), đổi **tham số** thì lệnh một dòng trong GUI + hướng dẫn gỡ phải sửa cùng lúc.
- **web/features/inventory** (`scripts/osquery.sh`, `scripts/osquery.ps1`, `installScripts.ts`): `modules/agent-intake/scripts/` là bản chép; sửa một bên mà không sửa bên kia làm `TestInstall_ScriptsEqualTheGUI` đỏ (chép lại bằng `cp`). Đổi cách GUI điền `@@BOX@@/@@VERSION@@/@@CA@@` (dòng `const fill`) cũng làm test đỏ: sửa `fill` ở `install.go` cùng lúc.

## Modifying: "ask the agent now" (`report.go`: `AskReport`, `ReportState`, `askOpen`, `answeredAsk`, `osAnswer`; INV-23)
- **The close rule**: the ask ends on a list taken after the node's own OS answer (`os_taken_at` >= `report_asked_at`). A change of how `nodeKernel`/`nodeWindows` read `kernel_info`/`os_revision`, or of which answer builds the Kernel or Windows row, must keep `osAnswer` in step, or an OS update's ask closes on a list with the old build.
- **web/features/findings** (`Updated.tsx` `AgentAsk`, `ToFix.tsx` `DeviceUpdated`, hooks `useAgentReport`/`useAskReport` in `web/src/features/inventory/api.ts`): the button, its busy state and the "Asked at …" line read `agent`, `asked_at` and `wazuh_interval_minutes`; renaming a value or the 409 `cannot_ask` / 429 `rate_limited` codes changes what the person sees. The To fix card shows one control per device, so the answer must be per device, not per software row.
- **Schedule** (`nodeSchedule`, `reportQueries`): adding a software query to the schedule (a new package table) must decide whether an ask speeds it up; `TestScheduleIsReadOnly` still pins every query, an ask only changes `interval`.
- **inventory** (`observe.AgentDevices`, `inventory.Service.AgentDevice`): the device → node link is `inv_asset.agent_key`. A device whose binding the inventory released (re-enrolment, revoke) is answered `none`/`wazuh` until its node reports again.
- **Wazuh marker** (`wazuhReads`): the same rows as `WazuhAgentAddresses` (current generation, IP or MAC); a change of how the pull records where it delivered changes which devices get the Wazuh line.
- **Timing words in the GUI** ("within about 5 minutes"): depend on `--config_refresh=300` in the install scripts, `firstReportInterval` and `sourceWindow`; changing any of them changes the promise. An old install without `--config_refresh` never re-reads its config: the ask then ends after 15 minutes without effect.
