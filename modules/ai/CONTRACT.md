## Invariants (always true)

### Profiles, assignments, internal data
- **INV-1** The API key is stored through `core/secrets` (AES-GCM); the API only returns `key_last4`; it is never logged or exported (SYS-4). `key_last4 = null` is valid only with `location=internal` (`usable = key ≠ null ∨ location = internal`). **A key only goes where it was stored for**: a stored key is reused only while the provider type is unchanged **and** the origin (scheme, host, port) of the base URL is unchanged; changing the address or the type without entering the key again → 400 `key_required` ("Changing the address needs the API key entered again.") on both profile edit and connection test; for an internal profile (key optional), changing the address drops the key and sends it nowhere. Tests: `TestContract_INV1_StoredKeyGoesOnlyToTheAddressItWasSavedFor`, `TestContract_INV1_EditingTheAddressNeedsTheKeyAgain`.
- **INV-1a** **A key that cannot be opened**: a profile key sealed with a different master key (a restored backup without the decryption key, or a regenerated master key; `secrets.IsWrongKey`) does **not** make the module `degraded`: the profile still loads with `key_lost = true`, `usable = false`, `key_last4` being the 4 characters that were stored, and one WARN per profile at startup (profile id, no key). That profile is never called (including an internal profile, which is otherwise usable without a key): `candidates` skips it with its own reason, its jobs **move to the fallback profile** (INV-2), and when no profile is left → 409 `secret_lost` naming the profile ("… was not restored (…), so <job> did not run and nothing was sent. An administrator opens Settings, AI assistant, presses Edit on the profile and enters the key again."), nothing is sent; `Ready` returns the same error so the `response-plan` job stops its run (`planError`). Connection test, model list and profile edit **without a new key** → 409 `secret_lost` ("The saved API key of the AI profile "X" was not restored (…). Open Edit, enter the key again and save, then test it. Nothing was sent."), nothing is sent or saved; an edit with a new key → `secrets.Replace` on the same old row, the profile is usable immediately; delete does not open the key. A profile that lost its key keeps its place in existing assignments (assignments are not deleted on restore; the page still shows the assignments table, with its own row when every profile lost its key), but `PUT /ai/assignments` assigning it to a new job and `PUT /ai/knowledge/settings` choosing it as the knowledge-index profile → 409 `secret_lost` with its own sentence ("… so it cannot take <job> / the knowledge index. Open Edit on the profile and enter the key again first. Nothing was saved."). Deliberate: an internal profile (key optional) that lost its key also cannot be saved with the key left empty; the administrator enters the key again or deletes the profile and adds it again without a key (there is no implicit "drop the key"). Other errors when opening the key (a row of a different key version, a read error) still make the module `degraded` as before. INV-3 still holds: an internal profile that lost its key never pushes an internal-data job to the cloud. Tests: `restore_nokey_test.go` (including `TestRestoreWithoutTheKeyInternalOnlyNeverFallsToTheCloud`), `TestContract_L2_ABadSavedStateDoesNotStopTheBox` (including "a key that fails to open for another reason").

- **INV-3** **Internal data rule**: jobs that send logs/device data (every job except `cve-news`, `translate-advisory`) when `assignments.internal_only = true` may only be assigned to, and only call, `location=internal` profiles. Blocked in **two places**: `PUT /ai/assignments` rejects a wrong assignment; at run time a cloud profile never receives this kind of data, including during failover and including when the settings change midway (each attempt rereads the current settings). Any request that carries tools or tool results is treated as internal data; the tools for `cve-news`/`translate-advisory` must be marked `public` and name the job. **`location=internal` is enforced by address, not only a label**: an IP in the base URL must be RFC 1918, ULA or CGNAT (**not** link-local; loopback is rejected as Vedette itself, see below); a host name is accepted but at dial time every resolved address that is public is refused (against DNS rebinding) and the environment proxy is not used; `http` is allowed only for internal profiles; the anthropic/openai/gemini base types are never `internal`. No valid profile left → 409 `ai_unavailable` with a clear reason, never a silent switch to the cloud. Ollama on the machine itself at the machine address or `host.containers.internal` and its own port is still allowed. The sentence `provider.OwnText` is the same as in feeds, notify and logs; at dial time it is `provider.ErrOwnAddress` (a kind of `ErrNetwork`), and Test returns 502 `unreachable` with that sentence; `TestOwnAddress_ProfileOnTheMachine`, `TestOwnAddresses`. **Addresses forbidden for every profile, at save and at dial time**: link-local (169.254.0.0/16 including the metadata service 169.254.169.254, fe80::/10), cloud metadata outside link-local `fd00:ec2::254`, `fd20:ce::254`, `100.100.100.200`, `192.0.0.192`, multicast, the unspecified address (0.0.0.0, ::) and broadcast; a **cloud** profile is additionally forbidden loopback, RFC 1918, CGNAT, ULA and `localhost` (the "cloud" label means the data goes to the provider; a machine on the network must be labelled internal), checked at dial time on the resolved address (unless there is an environment proxy: then the connection goes to the proxy and only the forbidden addresses above are refused). - **INV-4** Token level ∈ {min, med, max}, chosen by the administrator and **never changed automatically**. **Monthly token budget**: a shared `monthly_budget` (`ai_setting` key `config`) of 1,000..150,000,000, default 6,000,000; per profile `ai_profile.monthly_budget` in the same range. No money is shown: tokens are counted, and the user is advised to set a spending limit in the provider's console. Estimate per day by level: min ≈ 10,000, med ≈ 60,000, max = `null`. **Month = calendar month in the box's time zone** (`core_org.timezone`, default `Asia/Ho_Chi_Minh`, read once when the service starts; dates shown to users go through `core/orgtime`), restarting at 00:00 on the 1st (`Meter.Renews`); a clock that moves backwards does not start a new month; a new day within the month resets nothing. **The only stop rule is at 100 %**: below the budget every call goes through; this month's total + the part currently reserved ≥ the shared budget → every call is refused before it is sent (429 `budget_reached`, the sentence "This month's AI budget of N tokens is used up, so AI jobs are stopped until it renews on <date>. An administrator can raise the budget in Settings, AI assistant."); a profile that is out of its own budget → the job moves to the fallback profile, and without one → 429 `budget_reached` naming the profile. Every 429 `budget_reached` carries `retry_after` (seconds until the new budget date) and `Retry-After`. **"Used up" only when the tokens spent ≥ the budget** (`Meter.UsedUp`): when spent < budget but the reservation of calls in flight reaches the budget, `Reserve` returns `ErrBudgetHeld` / `ErrProfileHeld` (profile: moves to the fallback like an exhausted budget) → 429 `rate_limited` "Other AI calls running now are holding the rest of this month's AI budget… Try again in a few seconds." with `retry_after` 15; nothing is sent, no `ai_activity` row (except a call that already sent earlier turns, which keeps its row). **Scheduled jobs stop at 80 %** (`scheduledPausePct`, `Actor = "system"`, today that is response-plan): from 80 % of the shared budget spent, and once it is used up, `RunJob` returns 429 `budget_reached` before anything else (no call, no `ai_activity` row, not counted by the fuse; one log line per month per reason), so background jobs do not eat the whole month and Ask/Explain keep the last 20 %; when **a profile's own** budget is used up with no fallback profile, `system` jobs also stop the same way (429 `budget_reached` naming the profile, no call, no `ai_activity` row, one log line per month per reason; test `TestScheduledJobsWriteNoRowWhenTheProfileBudgetIsUsedUp`), while a person's call still gets a `capped` row. The budget does not lower the level (there is no new `ai_downgrade`; old rows still show in the history). The budget is checked and **reserved before the call** (`max_tokens` + input estimate) and settled after the call, so N concurrent calls cannot all pass; a failed call that has figures (a refusal) and every profile attempt are counted; plus saturation, token values from the provider are clamped to 0..10,000,000; a restart reloads this month's total from `ai_activity`. **Early warning**: the `budget-watch` job (5 minutes; only when `Config.Alert` is connected and the module is on) sends through `Config.Alert` one incident notification per budget (shared, per profile) per threshold per month: medium at 80 %, high at 100 % (at 100 % the 80 % one is not sent as well); what was sent is remembered in `ai_setting` key `budget_alerts` (`{month, sent: ["<box|profile id>:<threshold>:<budget>"]}`) so a restart does not send again and raising the budget warns again; a failed send is retried on the next run, and when notify is off (`Config.Alert` returns an error wrapping `ErrAlertOff`) it waits silently, which is not a job error; the content is only the profile name, token numbers and date, no key or content. `GET /ai/config` has `month_used`, `renews_on`; `GET /ai/profiles` has `used_month`; Home shows a card from 80 %. **Loop fuse**: a job starts at most 30 `RunJob` calls in a minute (fixed window by `Config.Clock`); extra calls → 429 `rate_limited` ("…which looks like a loop… Nothing was sent."), nothing is sent, no `ai_activity` row; the first time each minute it writes one `core_audit` row `ai.fuse` (target = the job) and one log line; other jobs are not held. The automatic reading and identification (actor `system`, both `explain-finding`) share that job's fuse with a person's Explain, so they keep a pace below it: one call every 3 s at most (`paceAuto`, 20 a minute, two thirds of the fuse; the reading and the identification share it), waited on the job clock (`Config.Sleep`), so a person's call in the same minute is never refused by the fuse (`TestResearch_AutomaticPaceAndDailyNumber`). Tests: `TestContract_INV4_*`, `TestBudgetWatch*`, `TestRunawayFuseCutsALoopAndSaysSo`, `TestMeterHoldsAreNotUsedUp`, `TestBudgetHeldByCallsInFlightIsNotUsedUp`, `TestScheduledJobsPauseAt80AndWriteNoRowWhenUsedUp`.

### Harness
- **INV-7** The built-in rules (`br-scope`, `br-evidence`, `br-readonly`, `br-untrusted`) are always included in every call and cannot be edited, deleted or turned off. Custom rules: 3..300 characters, `jobs=[]` means every job. **Custom rules (`ai_rule`, `/ai/rules*`)**: at most 30 (400 `too_many`; the trigger `ai_rule_max` keeps the limit a second time), the text is collapsed to one line and then checked at 3..300 **characters** (not bytes; 400 `invalid_rule`), the jobs must be known jobs (400 `invalid_jobs`), no control or hidden characters (as with hooks, `invalid_rule`). Rules go into the **system prompt** after the four built-in rules, under a heading that says the company's rules only add and do not replace or loosen the rules above; a rule that is off or belongs to another job does not go in; a rule never goes into the user's message. Each `RunJob` uses one generation of rules + hooks for both the question and the answer; an edited rule takes effect on the next call, with no restart. One stored rule line that is corrupted puts `New` into the degraded state (fail closed, never silently dropping a constraint). Tests: `TestContract_INV7_*`.
- **INV-8** Memory (`ai_memory`, `ai_memory_suggestion`, `ai_setting` key `memory`; `/ai/memory*`): the AI only **suggests**; a suggestion that the admin has not accepted (`accept`) **never** enters the context: it lives in the separate table `ai_memory_suggestion`, and the prompt-building path (`Service.memoryForCall`) only reads `ai_memory` with `enabled = 1`, so a pending suggestion, a rejected one or a disabled entry has no path to the provider. A memory entry: collapsed to one line and then checked at 3..300 **characters** (400 `invalid_memory`; the OpenAPI schema answers first for the length, with 400 `invalid` on the `text` field), no control or hidden characters (`auth.HasInvisible`), at most 100 (400 `too_many`; the trigger `ai_memory_max` keeps it a second time), viewable/editable/disableable/deletable, an entry typed by hand has `source=user`, an entry from a suggestion has `source=ai`; editing an entry keeps its `source`. **Memory is data, not instructions**: `RunJob` puts the enabled memory into **one fenced data block** (`DataMemory`, `kind=memory`) together with the other data blocks, so (a) it sits in the user's message between two `<<<DATA-…>>>` markers, never in the system prompt or the rules (`PromptBuilder` has no place left for memory); (b) **each memory line** goes through the `before_ai` hook on its own (`memoryForCall`) (and the memory block does **not** go through the second `guard` pass: a hook pattern does not match across the line break between two memories): `block-pii` masks email/phone so the line that is sent is masked; a line that a hook blocks/holds or that cannot be checked is **left out of the call** (fail closed: never sent) but the call still runs with the remaining lines, and the `ai_activity` row records the names of the hooks that blocked in `hooks` (every call) together with the ids of the memories that were left out in the summary part (no text; only for a successful call) so that one memory does not stop every call; adding/editing/accepting a memory that a hook would block is refused with 400 `invalid_memory` naming the hook (the suggestion remains when accept fails; `SuggestMemory` skips such text). **Cost**: each call of a job that carries internal data sends up to 100 × 300 more characters (about 7,500 tokens in the worst case) and counts against the token cap; the cache key of `explain` includes the hash of the memory lines that would be sent and the job's rules, so editing a memory or a rule turns a stored explanation into a miss. Only jobs with `CarriesInternalData()` carry memory: `cve-news` and `translate-advisory` (public text, which can run on a cloud profile that the privacy rule does not let receive internal data) do not. ## When the module is off (SYS-5)
No `/ai/*` routes, no provider calls, no jobs, **except** `activity-prune`: it only deletes rows past retention so it still runs when off. The "Explain", "Ask my AI" buttons, the AI digest, the AI comments in reports and the AI plan of `response` disappear or say "the `ai` module is off". Profiles, rules, memory, knowledge and the log stay as they are (the hash chain can still be verified). Connections to devices belong to `core`: turning `ai` off does **not** make `response` lose connections or actions on devices; only the AI's proposals and plans are lost.

## Four answers (finding brief and CVE explanation)
- **INV-23** `Service.Brief` (explain-finding, mitigation-config) and `ExplainCVE` answer four questions in this order: `affected` (am I affected, with the evidence and who confirmed it), `fix` (the exact release the data names), `workaround` (the CVE record's workaround or its "none published" sentence), `urgency` (why it matters now, attack conditions, privileges). The answer is `answers[]` (key, text, links); an answer that is missing, repeated, empty or has another key is a format error (`ai_bad_format`), never an empty section. `paragraphs` stays only on results stored before. Tests: `TestBrief_TheFourAnswersAreRequired`, `TestBrief_InstructionsAskTheFourQuestionsAndNoWhyThereIsNo`.
- **INV-24** The model never writes a link. The caller offers numbered references (`BriefRequest.Refs`, `CVEFacts.Refs`); an answer names them by number and the box writes the links, dropping any number it did not offer. The task text forbids a paragraph that explains why something is absent, and gives firewall or roll-back steps only when the attack is over the network and a device has an open port for the product, or when a configuration change is proposed.
- **POST-9** `ExplainResult` carries `affected` (decided by the box), `answers`, `citations`. `CVEFacts.Brief` is the CVE brief as a data block; any CVE the catalogue holds can be asked about. `device_updates` takes its rows from the By device fix blocks of findings (`aiAsk.DeviceUpdates`), the blocks the Findings page shows.
