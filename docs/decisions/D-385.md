| D-385 | **Amends D-263 (which stays the rule: without `vedette-host` the latest passive heartbeat decides the sensor's card, with a host D-118) with what D-263 did not cover.** (1) **90 s freshness:** without a host only a heartbeat younger than 90 s counts, the same rule as `online` (`onlineWithin`); an older one is "not reported in the last 90 seconds" (`bad_interface` in `SetInterface`). (2) **The box's own cards (`boxAddresses`, INV-6) follow the same source as `SetInterface`**, replacing D-263's "`netHost.Interfaces` stays for `boxAddresses`": with a host, `Host.HostCards`; without one, the fresh heartbeat's cards, never the core container's own interfaces (on the bridge it sees only its own link, so the real host cards were not excluded and the box could appear as a device). `osInterfaces` is removed from `cmd/vedette`; `netHost.Interfaces` is `HostCards` for `Service.Run` only (never started in production, D-141). (3) When those cards are unknown (configured host with no list yet; no host and no fresh heartbeat) the batch is held with **503 `not_ready`** (new code of the closed sensorlink set, `Retry-After` 5 s); the capture splits batches and blames lone items only on `store_busy`, so `not_ready` is retried whole and never drops an item. Accepted: an older sensor treats `not_ready` like `store_busy`, but sensor and core images ship in one release; a box with a socket path set but no helper holds passive batches (logged; queue max 5000). A compromised sensor can list extra addresses as the box's to hide devices, which it can already do by not reporting them; the list stays bounded by `sensorlink` (≤ 32 cards). | Freshness reuses the protocol's liveness window (`docs/specs/sensor-protocol.md` §6.3), as Prometheus marks a target down after failed scrapes instead of trusting its last sample (https://prometheus.io/docs/concepts/jobs_instances/). "Not yet" kept apart from "this item is bad" follows OTLP, which retries 503 whole and drops only what the server marks rejected (https://opentelemetry.io/docs/specs/otlp/#failures).
