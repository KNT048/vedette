# Host (`vedette-host`) Contract

> Type: **component**, not a module that can be switched on/off · Story: S-CORE-7, S-INV-5 (+ the box's network configuration) · Last verified: 2026-11-21 (every statement checked against the code)
> The only part of the box that runs as **root**. Everything else (core, sensor, honeypot, scan) runs unprivileged inside containers.

## Invariants (always true)
- **INV-1** **Fixed command list (allowlist)**: only the commands in the "Commands" section below; an unknown command → rejected with `unknown_command`; there is no "run an arbitrary string" path. Command names match `^[a-z][a-z0-9_]*(\.[a-z][a-z0-9_]*){1,3}$`; the command table is a closed `Registry` built once in `cmd/vedette-host` from `ops.Commands()` (there is no add/remove function: `TestRegistryHasNoMutators`). Adding a command = editing this CONTRACT + a test + `THIRD_PARTY_NOTICES.md` if an external tool is added.
- **INV-2** **No shell** (SYS-1): every child process runs with a fixed `argv` and parameters validated by type (`netip` for IP/CIDR, regex `^[a-zA-Z0-9][a-zA-Z0-9_.-]{0,63}$` for card/container names, an enum for `scope`/`when`, `HH:MM` for times). A parameter of the wrong type → rejected before touching the system.
- **INV-3** **One state-changing operation at a time** (global lock): a second command while one is running → 409 `busy` (including when the earlier command already reported `timeout` but its process has not returned yet: the lock is held until it returns, and past the ceiling the host exits so systemd restarts it; including a parked self-update run `server.Parked`: the lock follows the run across a host restart when `Options.Resume` holds it, FW-7); a reboot during an installation → 409.
- **INV-4** **Only `core` can call**: communication goes over an internal Unix socket, with socket permissions and a check of the calling process's identity; no network port. Users/the UI never call it directly; `core` checks the role (admin/operator) and writes `core_audit` (SYS-3) **before** calling `host`.
- **INV-5** **Installing OS patches**: only a fixed list of apt commands (`security` or `all`); **back up the DB first**, **check health afterwards** (`health[]`), progress shown live (`lines`), result `installed`, `security`, `backup`, `reboot_required`. **Never upgrades the OS release by itself** (it only returns `release_upgrade` instructions).
- **INV-6** Restart: `core` accepts `now`, `window` or `custom` with `at` (HH:MM) **inside the maintenance window** (computed in the organisation's time zone, `core/orgtime`), then sends the host `os.reboot` with `when ∈ {now, at}` and `at` as RFC 3339 UTC; the schedule can be cancelled; rejected while an install is running (INV-3). Automatic security updates = `unattended-upgrades` on/off; the maintenance window is a `core` setting: `always | window{days 1..7, from, to}` (`to < from` = crossing midnight).
- **INV-7** **Container images**: only images whose digest is in a correctly minisign-signed release manifest (embedded key, not revoked according to the stored index) and that have a **valid cosign signature** (carried in the manifest, `images[].cosign`) are pulled and run; the pull reference is built from the constant `ghcr.io/knt048/vedette-<service>@sha256:<digest>`, never from a request string; a wrong/missing signature → rejected, nothing starts; no downgrade through `container.start`; rollback = re-running the verified `previous`. **Cohorts and rollout are `core`'s job** (`update-manifest.md` §6): the host knows nothing about cohorts, it only checks the signature, revocation and version order. **The one exception**: the ZAP image of `zap.baseline` (INV-31), a compile-time constant `ghcr.io/zaproxy/zaproxy@sha256:<digest>` equal to `ZAP_IMAGE` in `deploy/containers/pins.env` (a test keeps the two equal), integrity by digest (upstream does not sign with the project's key), never a service, unit or release.
- **INV-8** **Network configuration**: the management card (DHCP or static: IP, gateway, DNS), the SPAN/TAP card (no IP, listen mode), secondary IPs for decoys (macvlan in the `vedette-hp` namespace), NTP (chrony). The host writes only **one** netplan file of its own (`90-vedette.yaml`, renderer `networkd`); any other netplan file → rejected with `net_backend_unsupported`, not parsed. IP/CIDR are validated through `netip`; a secondary IP must be inside the box's network range and differ from the box IP (re-validated in `host` even though `core` already checked). The host reports only the SPAN card's **interface counters**; the number of MACs other than the box's and the time of the last received packet are measured by the `sensor` container (INV-18); packet contents are not stored.
- **INV-9** `GET /v1/state/packages` is read-only and is the source of the box's own package list ("This box", confidence 1.0, S-INV-5): **one** fixed line `dpkg-query -W -f=${Package}\t${Version}\t${Architecture}\t${source:Package}\t${db:Status-Status}\n` (no parameter from the request, shared runner, output ceiling 8 MiB), no lock, no audit line (like the read commands in §5). The reader fails closed on structure: a line without exactly 5 fields, an unknown dpkg status, truncated output, a non-zero exit code, no installed package at all, or more than `api.MaxPackages` (20 000) → 500, never half a list. An installed package whose name/version/architecture/source package breaks dpkg's rules (an old third-party package with `_`, a version > 128 characters, a CR in a field) is dropped on its own, counted and logged (its text is never used), and the rest is still returned (`TestContract_INV9_AnOddPackageDoesNotHideTheRest`, `TestParsePackages`). Only packages that have files on the box (`installed`, `triggers-awaited`, `triggers-pending`; exactly the wording of dpkg-query(1)); `not-installed` and `config-files` are dropped. A package that is mid-change (`half-installed`, `unpacked`, `half-configured`: apt is running or a run was interrupted) → **409 `packages_changing`** (`api.CodePackagesChanging`), no list, no host error log: the list at that moment is not a snapshot of the box; `core` keeps the old list and reads again on the next round (`TestContract_INV9_PackagesMidChangeAreRetryable`). The structure of every line is still checked first (a broken line next to a half-installed package → 500). Ceiling: the host returns at most 20 000 packages; `core` never truncates the mapped list, inventory stores at most 5 000 entries per device, and a longer list → the whole list is rejected and the old list kept (inventory INV-3). The applier of `host.self_update` does not have this form (`TestTheHostRunnerNeverInstallsAndTheApplierRunnerDoes`). `TestContract_INV9_PackagesAreTheBoxsDpkgList`, `TestContract_INV9_PackagesFailClosed`.
- **INV-9b** `GET /v1/state/ports` (inventory INV-3) is read-only and is the source of the box's own open services (the box is never scanned by its own sensor): it reads the kernel socket tables (`/proc/net/{tcp,tcp6,udp,udp6}`) and, for held sockets, the process holding them (`/proc/<pid>/fd`, `comm`, `cgroup`; the same reader as the port check): it runs no program, opens no socket, takes no lock, writes no audit line. It keeps TCP in `LISTEN` and UDP with no peer, bound to **every address** (0.0.0.0, ::) or to an address of a **network card** of the box (a device with a hardware parent in sysfs, or the management interface from netplan/the default route): sockets on loopback, container bridges (Podman's aardvark-dns at 10.89.0.1:53, docker0) or other virtual links are not listed because only the box can reach them; if interfaces cannot be listed → only sockets bound to every address; one entry per (port, protocol), sorted by protocol then port, at most `api.MaxPorts` (1000, keeping low ports, logged). `process` = the Vedette unit name (`vedette-core`) when the process runs in (or under) a `vedette-*.service` cgroup, or the unit name when the process is `conmon` (Podman holds a container's published ports through conmon); otherwise `comm` (printable ASCII, ≤ 15); `""` when no process is found. Socket-activated by systemd (Ubuntu's `ssh.socket`): pid 1 is ranked after every other process holding the same socket, so a service that is already running (`sshd`, holding the socket systemd handed over) is named rather than `systemd`; when only pid 1 holds it (the service is not running yet, or `Accept=yes`), the name is the service the socket unit activates (`Service=`, otherwise the unit name; `.service` and `@` removed), read from the `*.socket` unit file and the `*.socket.d/*.conf` drop-ins (`/etc`, `/run/systemd/system`, `/run/systemd/generator`, `/usr/local/lib`, `/usr/lib`, `/lib`, in systemd's order of precedence; an empty `ListenStream=`/`ListenDatagram=` clears the list) — still running no program; a port that no unit names, or that two units name for two different services, keeps `systemd` (no guessing). Strict reading (`socketsWhole`): a missing `/proc/net/tcp`, or a table that is present but cannot be opened or cannot be read to the end (read error, line too long, line ceiling exceeded) → 500, `core` keeps the old list and never replaces it with a partial one; another table being absent (no IPv6) says nothing; the port check keeps its own lenient reading. An old host returns 404 `unknown_command` and `core` keeps things as they are. Tests: `host/ops` `TestReadPortsListsWhatTheBoxServes`, `TestReadPortsNamesAContainerByItsUnit`, `TestReadPortsFailsWithoutTheSocketTable`, `TestReadPortsFailsOnATableItCannotReadWhole`, `TestReadPortsNamesASocketActivatedService`, `TestParseSocketUnit`.
- **INV-10** DB backup: the file contains no passwords/keys (like `/core/data/backup`); keys/secrets never leave `host`/`core` in readable form (SYS-4).
- **INV-13** **Root never parses `core`'s data**: `core` snapshots the DB itself into `<core_data>/snapshots/<id>/` (contract in `host-api.md` §6.11), and the host only copies the snapshot's bytes. No package under `host/` or `cmd/vedette-host` imports `database/sql` or a SQL driver; `db_schema` and `includes_key` are statements made by `core`; a corrupt DB or a newer schema is detected by `core` at startup (failed health check → the host puts the previous version back).
- **INV-14** **Access to `core`'s tree only through descriptors**: `core_data` is checked (a real directory, every parent directory owned by root and writable by no one else, sticky included), then opened with `open(O_DIRECTORY|O_NONBLOCK)` + `os.Root` on the descriptor path; every file is opened with `O_NOFOLLOW|O_NONBLOCK` and checked on the descriptor (regular file, `nlink == 1`, owner `core_uid`, size ceiling); `chmod`/`chown` only on the descriptor; the owner of a restored file is `core_uid:core_gid` from `host.conf`. There is no path-based call (`os.*`, `syscall.*`, `Root.Chmod|Chown|Lchown|Chtimes`) anywhere that handles `core`'s tree other than `openCore`/`checkChain`/`checkParents`, and `Config.CoreData` is read only in `openCore`, `checkChain`, `checkCoreAtStart`, `NewWithDeps`, **`ensureCoreData`** (bootstrap: creates `core_data` when it does not exist, relative to a checked parent, or checks an existing directory through a descriptor) and **`fillFor`** (only puts the path string into the `Volume=` line of the `core` unit, opening nothing) (checked by type with `go/types`).
- **INV-15** **No write command runs while the box is about to reboot**: from the moment the host decides to reboot until `boot_id` changes (at most 10 minutes), every write command gets `409 rebooting`.
- **INV-11** The host's outbound network consists only of: the OS's apt package repositories (the host mirrors listed in `OSDetails.Mirrors`), the fixed image registry `ghcr.io` through `podman pull` (PRIVACY flow 6) and ARP frames on the LAN to check addresses/the gateway; plus the Debian package repository that the `apt-get install nmap` step of the Containerfile always calls when the host builds the `scan` image locally (`PRIVACY.md` flow 6); plus, only while `zap.baseline` runs: the ZAP image from `ghcr.io/zaproxy` (flow 6, pulled on first need), the three public-IP services of `core/egressip` (IP target) or a TXT lookup through the system resolver (domain target) to re-check ownership (flow 9), and the requests of the ZAP container itself **only to the site's `ip:port`** (flow 9, nft fence INV-31); plus, only when the admin turns OpenVAS on: Greenbone's images and feed from `registry.community.greenbone.net` through `podman compose` and the `docker-compose(-v2)` package from the OS apt repository the first time (flow 16, INV-32); no other flows (SYS-7). NTP is done by chrony, not by the host.
- **INV-12** Every write command records a structured result line (a command that runs also has an `accepted` line written at the start; a run waiting for network confirmation has an extra `awaiting_confirm` line) (command, secret-redacted parameters, time, code, the caller passed along by `core`); the history is shown in Settings → Updates through `core` (`core_os_run`).
- **INV-16** **A new network configuration is made durable only when confirmed**: changing the management side writes the new version to `/run/netplan/90-vedette.yaml` (tmpfs, shadowing `/etc`) and to `net/pending.json`; `/etc/netplan/90-vedette.yaml` is written only at `net.confirm`. A timeout, `net.revert`, a host crash past `revert_at`, or a reboot all return to the old configuration; the waiting run holds the write lock (other write commands → `409 pending_confirm`), only `net.confirm`/`net.revert` with the right `run_id` pass; `Claim` then `Finish` (or `Settle`) ends the run exactly once; confirm/revert must Claim before doing their effects (FW-2).
- **INV-18** **Root never parses captured traffic**: the host's `AF_PACKET` socket (exactly one, `host/ops/arp_linux.go`, bound to `ETH_P_ARP` and one card) only sends 42-byte ARP frames (address probes, gateway checks) and only reads ARP frames: a received frame of 42 bytes or more that fits the read buffer (Ethernet pads to 60, a trailer is possible) has only its first 42 bytes read and the rest is never read; the socket is created with protocol 0 and then bound to `ETH_P_ARP` and the card in a single `bind` (no packet is queued before that), and a frame with a different `Ifindex` than the card is dropped; `parseARP` is a pure function that accepts exactly 42 bytes, and is fuzzed; the host does not count MACs, reads no other packets and opens no pcap. SPAN traffic figures (`other_macs`, `last_packet_at`) come from the unprivileged `sensor` container through `core`.
- **INV-19** **`container.pull` verifies itself before any effect and trusts nothing but the signature**: the host checks the index (against the **stored** index, `sequence` never going backwards, revocation only from the stored index), the manifest, the platform, the install mode and the cosign signature with `internal/release` **before** running `podman`; the pull reference is the registry constant + the manifest's digest, every `podman` argv has a fixed form, and the validator accepts exactly what the builder builds (`pull -q`, `container inspect`, `container exists <Id>`, `image inspect`, `tag`, `image ls --format json`, `rmi <Id>` (64-hex Id), `untag <ID> <local tag>`, `volume exists`, `build` (exactly the network `--network vedette-int` and `--cap-drop NET_RAW`), `run … nmap --version`, `tag <ID> <tag>` and `image inspect <ID>` of the `scan` build; the ZAP forms are in INV-31); the output of `podman image inspect` is read strictly and the digest must match before tagging and before recording the pulled version (the tag is also read back); a corrupt stored index, or one that no longer verifies → rejected, not treated as absent; a build without a real key rejects every pull (`no_trusted_keys`); a retired key only re-verifies the stored index and accepts nothing new; every time a new index is stored it leaves a warning and an audit line `release_index_stored`. A failed pull records no pulled version and does no `rmi`. End-to-end tests with real vectors run on CI through `-tags releasetestkeys` (`Makefile`, `scripts/check.sh`).
- **INV-20** **Version change and rollback verify themselves, and can always be reset**: `container.start` with `version` and `container.rollback` decide every rejection at `Check` (412, no run, no writing `podman`, no file changed); the record of the target version (or of `previous`) is **re-checked** against the stored index (signature, key, version/digest revocation, cosign) every time; the unit is changed through a transition journal first, `core` has a `pre_update` backup made in the run **before** the unit changes; not healthy → the old unit bytes come back **identically** and it restarts, and for `core`, when the target/running version has `rollback.safe=false`, the DB also comes back (the `pre_update` backup just created, or the files renamed to `.rollback`) **before** the old version starts; a failed reset → `failed`, the host **stops**, journal `pending`, no loop; the host dying at any step → `Start` resets the bytes, `AfterReady` resets the DB and the state, and only a change that is `verified`+`applied` writes `versions` (idempotent). `current` and `previous` live in one file written atomically once; rolling back twice returns to where it started **except for `core`**, where going upward by rollback is rejected with `rollback_is_upgrade`; if the running version is unknown, a digest change is rejected with `current_version_unknown`. The host only renames/resets/deletes exactly the journal-listed names (`aside`), only `Remove`s regular files (no `RemoveAll` on a name `core` controls); while the DB is waiting to be reset, commands touching `core` (`core`'s `container.*`, `backup.*`) get `transition_pending` while other commands run; the reset does not give up on a recoverable error, and stops (journal `unrecoverable`, one audit line `core_data_unrecoverable`) on an unrecoverable error; something foreign next to the DB is rejected before `core` is stopped (`core_data_invalid`) or renamed `*.quarantine-*`, never `RemoveAll`; if the `verified` journal cannot be written there is no `settle` and the run is `failed`.
- **INV-21** **Retention of images never removes the running version or `previous`**: after a **successful** start that changes the digest, or a rollback (not after a failure), the host removes the service's images with `podman rmi <Id>` (64-hex Id; no digest, no name, no `-f`, no `prune`), after `podman untag <Id> <tag>` removes the local tags (`localhost/vedette-<service>:<version>`, `localhost/vedette-scan-nmap:<version>`) so the image has exactly one name left: Podman 4.9.3 refuses `rmi <Id>` for an image with several names (exit 125), and every pulled version has two names (a local tag and the pull reference). If `untag` fails there is no `rmi`: the image stays, with its tag, and one `image_removal_failed` line is written; if `untag` succeeds but `rmi` fails, the audit line records the tags that were removed (`untagged`). An image that still has more than one name after the local tags are removed (two registry names) is skipped and does not count toward the per-run ceiling. An image is removed only when every name of the image belongs to the service's two repositories, it has no container, and none of its digests is in the keep set (the digests of every unit, every `current`/`previous`, every pulled version, running containers); the list is read with `image ls --format json` read strictly, and if it cannot be read nothing is removed; a failed `rmi` is only logged and audited and does not fail the run. The one exception for an unnamed image: a `scan` image built on the box that lost its tag, recognised by the label `io.vedette.build=scan` of the constant Containerfile, is removed by Id when `sha256:<Id>` is not in the keep set; any other unnamed image is never touched.

- **INV-22** **`vedette-host -bootstrap` is the first install, a one-shot run, not through the socket**: it verifies with **exactly** the `verifyPull` of `container.pull` (embedded key, revocation, `sequence` floor, platform, `install_modes` containing `appliance`, manifest hash in the index, cosign in the manifest), every rejection decided **before** the first write; it pulls images with the same `pullAndRecord`; only **after every image has been pulled** does it write the units (from a constant template, the safe unit writer) and `containers/versions-<service>.json` with `current` = the verified record (closing `current_version_unknown`). Failing midway leaves no unit for an unverified service; running again with the same document finishes the job; running again on a box that is already done changes nothing. A different version on a box that already has `current` → `already_installed` (including with `-force-units`). A unit that is not the host's is overwritten only with `-force-units` (each file is reported, the old bytes kept in `containers/units/<service>.prev`). Refused while the daemon is running (a live socket, and the lock `<state>/host.lock` that the daemon holds for its lifetime and bootstrap holds for the whole run: two bootstraps do not run at the same time). A `-services` subset does not put this version next to a service running another one (`mixed_versions`). An existing `core_data` is checked (owner `core_uid` + 0700, or if empty it is handed to `core`; otherwise `core_data_invalid`), and if it does not exist it is created relative to a checked parent. It writes to the daemon's audit chain (`release_index_stored`, one `installed` line per service). When `scan` is in the run, before the pull step it runs **one** synchronisation of the `DOCKER-USER` rules (the same `dockerFwdSync` as the daemon, idempotent, changing nothing when there is no Docker or network file) so that the build on `vedette-int` can reach the network (`TestContract_Bootstrap_PutsTheDockerForwardRulesInPlaceBeforeTheScanBuild`). The `core` unit binds `core_data` to `/var/lib/vedette` and has no `-key`: the key `core` reads is `<core_data>/vedette.key`, the key that `backup.*` backs up and restores. It never starts services. No registry command is named `bootstrap`.
- **INV-23** **The way out of `core_data_unrecoverable` is `backup.restore`**: when `core`'s journal is valid and marked `unrecoverable`, `backup.restore` passes `Check` (every other command touching `core` still gets `transition_pending`; a journal that is being processed, corrupt or unreadable still blocks `backup.restore`); if the restore succeeds and `core` is healthy, and the version records match the installed unit (or are reconciled again: `current` = the unit's digest, via `previous` or a pulled version; otherwise the journal stays), the journal is deleted and an audit line `core_data_recovered` is written; on failure (state reset first) the journal stays. The `pre_update` backup that the journal needs for the restore is also `unrecoverable` when the index is readable but does not contain it, the archive file does not exist, or the file has a wrong checksum/is invalid (unpacked and checked before `core` is stopped: no retry, `core` not stopped); an I/O error, an unreadable index or a full disk is still retried; `retain` never drops a backup that `versions-*.json` (`current`/`previous`.`backup_id`) or a journal (`backup_id`) points to, and that backup does not count toward the quota of 3 `pre_update`/`pre_os_update` backups (`pre_restore` has its own group of 3, so a restore does not push out the update's backup) (if such a file cannot be read, that round keeps every `pre_update` backup, other kinds still expire normally, and one audit line `backup_retention_unknown` is written); a backup that was just created is always kept and counts toward the quota, even when the clock goes backwards (the oldest other backup is dropped), so `backup.restore` is never blocked by the clock; `os.install` goes through `coreFree()` at `Check` like `backup.create`.
- **INV-24** **`backup.purge` deletes everything and only what belongs to the store**: every backup of every `kind`, `index.json` and `.tmp-*`, only regular files written by the host through `os.Root` (symlinks are not followed, the target stays intact), not touching `core_data`; plus the host's `exports/` and `tmp/` (not the systemd journal); `busy` when another run exists, `412 transition_pending` when `core`'s transition journal is pending or `unrecoverable` (every backup stays intact); unknown args → `400`; afterwards `rollback_backup_missing` and `pre_os_update` can still be created. Tests: `TestContract_BackupPurge_*`.
- **INV-25** **`vedette-host -recover-core-data` is the way out of `core_data_unrecoverable` when `core` is stopped**: a one-shot run, root, not through the socket; refused when the daemon is running (a live socket, then the `host.lock` lock: exit code 6) and, with `-yes`, when the `core` unit has not stopped (`core_running`); it starts and stops nothing. Without `-use` or without `-yes` it **changes nothing** (the audit file is not even opened). It runs only when `core`'s journal is valid and `unrecoverable` (no journal: "nothing to recover", exit 0; a journal that is not `unrecoverable` or is corrupt: refused). `core_data` goes through `openCore` (`checkChain`, no symlinks, descriptor); a `.rollback` file that the journal names but that is not a regular file → `core_data_invalid`, nothing changed. `-use rollback` puts back every `<name>.rollback` file that the journal (`aside`) names, by renaming inside `os.Root`; a file occupying the name (and `-wal`/`-shm`/`-journal` when `vedette.db` comes back) is kept as `<name>.replaced-<unix nano>`, never deleted; `*.quarantine-*` and `*.replaced-*` are not touched. `-use current` only deletes the journal. Before changing anything it must pass `coreVersionPlan` (the same conditions as INV-23's `reconcileCoreVersion`: a unit that cannot be explained → `versions_mismatch`); after the files: write the version record, delete the journal, one audit line `core_data_recovered` (`command: recover-core-data`, name only). **A safe order when stopped at any point**: the audit line `core_data_recover_start` is written **before** any change and if it cannot be written nothing changes (`audit_unavailable`); then progress (`recover`: `at`, `phase`, `names`) goes into the journal before the first rename; the `moving` phase moves **every** file occupying a name (and `-wal`/`-shm`/`-journal` when the database comes back) to `.replaced-<at>`; the `putting` phase puts back the key, then the sidecars, and **the database last** (a missing database shows immediately, while an old database without its WAL silently loses transactions); running `-use rollback` again reads `recover` and finishes the job (not moving again what has been put back, reusing the same `at`), `-use current` is refused (`recovery_in_progress`); a re-run that finds a live file where a copy is about to be put back (core has run in the meantime) stops with `core_ran_since`, renaming over no file. It never puts back a `-wal`/`-shm`/`-journal` copy when the journal's `vedette.db` copy is already gone (`db_copy_missing`). `-use rollback` only when the `core` unit pins exactly the journal's `from_digest` (`unit_mismatch`). Every name taken from `core_data` is printed with `%q`, and the `.quarantine-` pattern is anchored at the start. Tests: `TestContract_Recover_*`, `cmd/vedette-host` `TestRecover*`.
- **INV-26** **`host.self_update`: only a signed package, only upward (host-api §6.14)**: the host hands `dpkg`/apt only a file that it has **itself copied** into `<state>/selfupdate/staged/` (root, 0700) from `<core_data>/host-packages/<package>.deb` (opened through `openCore`, descriptor, a regular file of `core`, one link, exactly `size`), hashed in the **same pass** as the copy and renamed to `staged/<sha256>.deb` only when SHA-256 + size equal the `host.files[]` entry `vedette-host_<host.version>_<arch>.deb` of a manifest that has passed exactly the same checks as `container.pull` (`verifyRelease`: embedded key, stored index, revocation, manifest hash, `install_modes`); `host.version` must be **higher** than the running version (equal → `succeeded`, `changed: false`, touching nothing), no `-test.` except in a test-key build; `current_package_missing` when `versions.json`, the binary and `dpkg-query` do not agree on the running version or its kept `.deb` is missing/changed; every rejection at `Check` writes nothing (apart from a new index); the host opens no network connection and accepts no path, URL or hash from the request. The simulation `apt-get -s … install <staged>` is rejected (`dependencies_unavailable`) when apt would remove, purge or **upgrade** another package, or when a new package has a name outside Debian's package-name rules or has an `:<arch>` suffix; the simulation's **new** packages are merged into `<state>/selfupdate/installed-by-us` (sorted, no duplicates, 0600) **before** the journal is written and the applier is handed over, so that `install.sh --uninstall` hands them back to apt; if that file cannot be read/written → `failed applier_failed`, nothing changed.

## Preconditions (before calling)
- **PRE-1** **Appliance** install type. The "Containers only" type: there is no `host`; `core` returns a clear `unsupported` for `/core/updates/os*` and deep network configuration, **without pretending to succeed**.
- **PRE-2** The caller (`core`) has checked the role and written the audit; a `request_id` is present for cross-checking.
- **PRE-3** No other operation is running (INV-3).

## Postconditions (after completion)
- **POST-1** After `os.install`: the number of installed packages matches `OSRunResult.installed`; the backup really exists; `health[]` reflects real checks (not defaulting to `ok`).
- **POST-2** After `container.rollback`: the container runs again with the verified `previous` (exactly the `ImageDigest`) and has passed the health check; for `core` with `rollback.safe=false`, the DB is the `pre_update` backup of that update, restored in the same run; if health fails, the running version is put back and the run reports `reverted`/`failed`, not success.
- **POST-3** After a `net.*` change: the state read back (`GET /v1/state/net`) matches the value just set and the effects were checked (address on the card, gateway answering ARP, `chronyc` seeing a source, the decoy present in `vedette-hp`); no match → rolled back or an error reported. A `net.apply` that changes the management side ends in `awaiting_confirm` until `net.confirm`/rollback (INV-16).
- **POST-5** `host.self_update` `succeeded` → `dpkg-query` prints the new version as `installed`, `GET /v1/info.host_version` is the new version, `versions.json` has `current` = the new version and `previous` = the old version with its `.deb` still present and with the right SHA-256, `packages/` contains only those two files, `staged/` is empty, the journal and `applier` are deleted, and the audit chain still verifies; `reverted` → the same with the old version and `versions.json` unchanged.
- **POST-4** Every failed command leaves the system in its old state or clearly reports the half-finished state; no hung operation holds the lock forever (per-command timeouts).

## Forbidden (never)
- **FORBID-1** Running a command outside the allowlist; running through a shell; concatenating a command string from parameters (INV-1, INV-2).
- **FORBID-2** Listening on a network port; accepting commands from a process that is not `core`.
- **FORBID-3** Upgrading the OS release by itself; restarting by itself outside the `os.reboot` command / a schedule that was set.
- **FORBID-4** Running an image without the cosign signature check (exceptions: the digest-pinned ZAP image of `zap.baseline`, INV-7; the OpenVAS project's images, pinned by digest except the four feed-data images Vedette runs, which follow Greenbone's tags, pulled by `podman compose`, INV-32).
- **FORBID-5** Touching the content of customer data (DB, logs, devices) beyond copying the bytes of the snapshot on a `backup.create` command (and `os.install`, `backup.restore` through the internal backup); never opening or parsing the DB.
- **FORBID-6** Opening ports or editing firewall rules outside the command list (no "opening ports around UFW by itself": the reason Podman was chosen). The constant nft ruleset that blocks outbound traffic in the `vedette-hp` namespace and the `inet vedette_zap` table of `zap.baseline` (matching only the bridge `vedette-zap0`, only **blocking**, generated from one validated public `netip.Addr` and one port, deleted after every run) are the two exceptions.
- **FORBID-7** Running `dpkg`/apt to install the **`vedette-host` package** from the cgroup of `vedette-host.service` (INV-27); `os.install` drops the name `vedette-host` from its own upgrade list (a second layer: no apt repository has this package); downgrading `vedette-host` at `core`'s request (INV-29).

## Endpoints owned

None. The run history and the maintenance-window setting are stored in `core` (`core_os`, `core_os_run`, `core_audit`).

## Installed awaiting-confirmation framework
Code: `host/server/awaiting.go` (+ `registry.go`, `handlers.go`, `server.go`, `readers.go`), `host/api` (`pending_confirm`, `not_awaiting_confirm`). `net.apply`, `net.confirm`, `net.revert` (section "Installed network commands" below) are the production commands that use the framework; the framework's tests use the commands `test.park`, `test.confirm`, `test.revert`… defined in `host/server/awaiting_test.go`. The framework's invariants (INV-16 is the network part built on them):
- **FW-1 A waiting run holds the write lock.** Only a command that declares `Spec.Awaits` (a write command, not `WhileAwaiting`; the two flags are mutually exclusive, checked in `NewRegistry`) may return `server.Awaiting{RevertAt, Result}`, and only when it is holding the lock, there is no waiting run yet, `RevertAt` is in the future and no later than `started_at + 660 s`; otherwise the run is `failed command_failed` ("invalid Awaiting") and the lock is released as usual. When valid → the run is `awaiting_confirm` with a `revert_at`, and the lock is **not** released; every other write command → `409 pending_confirm` with the `run_id` of the waiting run (even before `Check`, so `os.reboot`'s `net_pending_confirm` is only a second layer); read commands are not locked. A waiting run has exactly three audit lines: `accepted`, `awaiting_confirm`, the final result. A waiting run's events are written to disk after **every** event (including the timer's log line). `rc.OnParked(fn)` runs right after the run has entered the waiting state and the lock has been published: the revert timer is set there, so a timer that fires early never meets a run that is "not waiting yet". **The lock is never left open**: when the waiting run releases the lock while a `WhileAwaiting` command is still running, the lock is handed to that command and it releases it when done; `WriteActive()` and the write-command gate count that command as well.
- **FW-2 A waiting run ends exactly once: Claim, do the work, Finish.** `(*Server).Claim(runID)` is a compare-and-swap: it takes the run out of the waiting state (every other `Claim`/`Settle`/`WhileAwaiting` command for that run gets `ErrNotAwaiting` / `412`) but **keeps the write lock**; the winner does its own effects and then calls `Claimed.Finish(status, *RunError)` (exactly once): final audit line, write the run, release the lock, final event. `net.confirm` and `net.revert` **must Claim first, do the effects, then Finish**, so the confirm/timer race is decided before either side touches the system. `Settle(runID, status, *RunError)` = `Claim` + `Finish` for an ending with no effect in between. A second call, or a run that is not waiting → `ErrNotAwaiting`, nothing changed. After `Shutdown` has begun → `ErrShuttingDown`, nothing changed (the run still waits on disk); a `Settle` that already passed that check is waited for by `Shutdown` before it closes the audit log.
- **FW-3 `WhileAwaiting` passes the gate only for the right run.** A command with this flag (only `net.confirm`, `net.revert`; it must be a write command) runs if and only if `args.run_id` is the waiting run; otherwise `412 not_awaiting_confirm` and the command does **not** run (wrong run, already `Settle`d, or no waiting run). Only one such command runs at a time (a second one gets `busy` with the `run_id` of the running one). Re-sending the same `X-Request-Id` returns exactly the old run without running again (idempotency).
- **FW-4 Restart.** `recover()` (inside `New`, so it finishes before `Listen`) asks `Options.Resume(run)` for each `awaiting_confirm` run (and each parked run, FW-7; any other unfinished run is never asked): `true` → the run still waits and holds the lock, and the stored events are continued (seq does not repeat); `false`, `nil`, a panic, or a second waiting run → `failed host_restarted` like an interrupted run. A kept run is always treated as a write run (releasing the lock when it ends), and a stored `revert_at` beyond `started_at + 660 s` is clamped to that point (logged), never trusted further. The `AfterFinish` and `OnParked` callbacks are **not** restored after a restart: the caller rebuilds the timer **after** `New` (`Resume` then `Ops.Start` from `pending.json`) and ends the run with `Claim`/`Finish` or `Settle`. `Shutdown` does not end a waiting run.
- **FW-5 Per-command body limit.** `Spec.MaxBody` (0 = 512 KiB, at most 4 MiB; `NewRegistry` rejects values outside the range); exceeding it → `400 invalid_args` naming that command's own limit.
- **FW-6 Reads.** `Readers.Net`, `Readers.Containers` are wired to `GET /v1/state/net|containers`; not wired (`nil`) → `404 unknown_command` like any route that does not exist yet.
- **FW-7 A parked run survives the host restarting itself (code `host/server/parked.go`).** Only a command that declares `Spec.Parks` (a write command; mutually exclusive with `Awaits` and `WhileAwaiting`, checked in `NewRegistry`) may return `server.Parked{Deadline, Result}`, and only when it is holding the lock, there is no waiting or other parked run, its `ctx` has not ended (not past `Spec.Timeout`, `Shutdown` not started), `Deadline` is in the future and no later than `started_at + 3 h`; otherwise the run is `failed` (`command_failed`; `host_shutting_down` or `timeout` when `ctx` has ended) and the lock is released, and `OnParked` does not run. When valid → the run stays `running`, with `parked_deadline` (an `api.Run` field), `result` = `Parked.Result`, and the run is written to disk **before** the audit line `parked`, the `log` event and `OnParked` (a failed write → not parked: `failed command_failed`, lock released, `OnParked` does not run) (the command does its first effect outside the state directory in a goroutine it starts from `OnParked`: "park first, hand over afterwards"); the command's goroutine ends so `Spec.Timeout` no longer applies; the lock is **held**: another write command → `409 busy` with the `run_id`, a `WhileAwaiting` command → `412 not_awaiting_confirm`. Events are written to disk after each event. `Shutdown` leaves a parked run as it is on disk; `recover()` asks `Options.Resume` for a `running` run that has a `parked_deadline` **and belongs to a command declaring `Spec.Parks`** (a waiting run: a command declaring `Spec.Awaits`; a corrupt run file carrying another command is never kept) and keeps it together with the lock when the answer is yes, a stored `parked_deadline` beyond `started_at + 3 h` is clamped to that point (only one run holds the lock: the first waiting or parked run is kept, the second gets `host_restarted`); `false`, `nil`, a panic → `failed host_restarted`, lock released. `(*Server).SettleParked(runID, status, result, *RunError)` ends a parked run exactly once (compare-and-swap; a nil `result` keeps `Parked.Result`): final audit line, write the run while releasing the lock, final event (seq continuing from the stored events, `Last-Event-ID` still usable), then `AfterFinish`; a second call or a run that is not parked → `ErrNotParked`; after `Shutdown` has begun → `ErrShuttingDown`, nothing changed. The framework does **not** end the run at `parked_deadline` by itself: the command's goroutine does that.

## Installed network reading and ARP
Code: `host/ops/{netstate,netplan,arpframe,arpprobe,arp_linux,arp_other}.go`, `host/ops/bins.go` (`netplan`), `host/api/net.go`, `host/client` (`StateNet`). This section only **reads** and builds, it does not write or apply (the `net.*` commands are in the next section). Invariants:
- **NET-1 `GET /v1/state/net` is read-only, runs no program and opens no network socket** (the only socket is the kernel's netlink: the interface list of the `net` package, one dump of the neighbour table, `Deps.NeighDump`, and one `RTM_GETADDR` address dump in `systemInterfaces`). Counters, state, speed and the promisc flag are read from `/sys/class/net/<card>/…` through `os.OpenRoot(<root>/sys)`: the root is `/sys` and not `/sys/class/net`, because `class/net/<card>` is a relative symlink into `/sys/devices`; a link leading outside `/sys` is refused by the root and read as "absent". It lists **every** non-loopback interface that has an address, of any type (VLAN, bond, bridge, WireGuard, Podman bridge) because `core` treats every such address as the box's own, plus a card that has a `device` (hardware parent) and a card that the host's netplan file names; order: the management card, physical cards, the rest (by name); at most 64 interfaces (the management card is never cut) and 64 addresses per interface, global addresses before link-local, IPv4 before IPv6, cut from the end so a global address is never lost while a link-local one remains; physical cards have counters, virtual links may be zero; names go through `ifaceNameRE`. The management card is the card in the host's netplan file, or the card of the default route when the host has not written a file. The default route comes from `/proc/net/route` (lowest metric, flags UP+GATEWAY, unicast gateway, at most 4096 lines, broken lines dropped). `default_routes6` comes from `/proc/net/ipv6_route`: every `::/0` route of every table and each equal-cost next hop (UP+GATEWAY, not REJECT, unicast next hop including link-local, no zone; lower metric first; a pair of card + next hop once; sorted by metric and only then cut to 16; the same line ceiling; never `null`); the `mac` of each route's gateway comes from an `RTM_GETNEIGH` dump (an entry with the route's own card index, state REACHABLE/STALE/DELAY/PROBE/PERMANENT, not NOARP, a unicast 6-byte non-zero MAC; a pure-Go reader, ≤ 8 MiB, a length mismatch stops it; a failed dump → no `mac`, the rest left as it is); `resolvers` comes from `/run/systemd/resolve/resolv.conf` and then `/etc/resolv.conf`: the host is root while resolved's directory belongs to `systemd-resolve`, so only a regular file of 1 B–64 KiB by `lstat` is read, opened `O_NOFOLLOW|O_NONBLOCK|O_NOCTTY`, and `fstat` must be the same file; `/etc/resolv.conf` follows a link exactly one level (an absolute target is read under the root), never opening a device or a procfs file; ≤ 1024 lines, loopback/unspecified/multicast and zones dropped, no duplicates, at most 16, never `null`. `interfaces[].dynamic` are the addresses in `addresses` that have a lease (DHCP, SLAAC): the kernel's `IFA_F_PERMANENT` flag is not set (the 32-bit `IFA_FLAGS` attribute wins over the 8-bit field of `ifaddrmsg`; IPv4 takes `IFA_LOCAL`), as `ip address` prints "dynamic"; a pure-Go reader, ≤ 8 MiB, a length mismatch stops it; a failed dump → every address is treated as static (`[]`); never `null`. There is no `other_macs` or `last_packet_at`. `decoys` are the decoys being held (`[]` when there are none). `pending` has `{run_id, revert_at}` when a run is waiting for confirmation and `net/pending.json` is readable (otherwise `null`); `config.ntp` are the servers in `vedette.sources` (`[]` for the default pool or a file that is not the host's).
- **NET-2 YAML is built from typed structs, every value checked first.** `renderNetplan` checks: the card name (the kernel's narrowed rule, first character a letter or digit), IPs through `netip` and printed back in canonical form, DNS/search names through the name regex, static IPv4 `/8`–`/30` that is not a network or broadcast address, a gateway inside the subnet, at most 3 DNS servers and unicast, at most 6 search domains, SPAN different from mgmt. The SPAN card: no DHCP, no RA, `link-local: []`, `optional: true` (promisc is not a netplan key: the sensor sets it on its socket). `parseNetplan` accepts only a file that renders back exactly byte for byte: a foreign or hand-edited file never becomes configuration.
- **NET-3 `CheckBackend()`** returns `412 net_backend_unsupported` when `/usr/sbin/netplan` is missing, when any `*.yaml` file other than `90-vedette.yaml` exists in `/etc/netplan`, `/run/netplan` or `/lib/netplan` (our own name in `/lib` is also foreign), when a directory is a symlink, or when our file is not a regular file (a symlink, a directory). It only lists directories and opens no file. It does not look at `/etc/systemd/network/*.network`, ifupdown or NetworkManager: that is the installer's job.
- **NET-4 ARP.** `Prober` (`Deps.Probe`): `Probe` 3 times 1 s apart and then listens for 2 s; any ARP whose sender IP equals the address being probed, and another host's probe for the same address (sender IP 0.0.0.0, a request whose target is that address, RFC 5227 §2.1.1), from a MAC other than the box's MAC is a conflict; `GatewayCheck` retries every 1 s up to 15 s, and only an ARP **reply** from the gateway IP, sent to our own source address and not from the box's MAC, counts as an answer. Frames are built by `probeFrame`/`requestFrame` (the sender IP of a probe is 0.0.0.0). The socket is closed on every path (conflict, timeout, cancel, send error, read error); each read takes at most 250 ms so a context cancellation is noticed at once; the card name and IP are checked before the socket is opened. A non-Linux system: `ErrARPUnsupported`.
- **NET-5 The `netplan` argv grammar.** The grammar `generate --root-dir <directory>` (absolute, clean, lower-case characters, at least 2 levels deep, not under `/etc`, `/run`, `/usr`, `/var`…, not `/`) only checks the string (a symlink to `/` slips through), so **no production runner has it**: only a CI test builds a runner that has it (`validateNetplanGenerate`). `net.apply` does not need `generate` (`netplan apply` checks the file itself), so the production grammar is exactly `apply` (NET-11). There is no `networkctl` grammar: addresses come from the `net` package (`ip` is used only for decoys, DECOY-2).

## Installed network commands
Code: `host/ops/{net,netpending,netfs,ntp}.go`, `host/ops/bins.go` (`netplan apply`, `chronyc`), `host/api/net.go` (args types, codes), `host/client` (`NetApply`, `NetConfirm`, `NetRevert`), `cmd/vedette-host` (`Options.Resume`). Invariants (INV-16 is the root; the items below are how it is kept):
- **NET-6 `net.apply` does things in the right order.** Args are the **entire** desired state (`mgmt{iface,mode,address,gateway,dns}`, `span{iface|null}`, `ntp[≤4]`, `confirm_timeout_s` 30–600, 0 = 120): missing means "none", not "keep". `Validate` uses the rules of `renderNetplan` (NET-2) and turns `*fieldError` into `400 invalid_args` with `details[]`; two rules that have their own codes are left to `Check` (`412 same_iface`, `412 gateway_outside_subnet`), together with `412 iface_unknown` (the card does not exist or is `lo`) and `net_backend_unsupported` (NET-3). Classification: **changing the management side** = card, mode, address with prefix, gateway (or the host has not written any configuration yet) → enters the confirmation window; changing only DNS, SPAN or NTP → written straight to `/etc`, `netplan apply`, effect check (failure → the old file is put back, `reverted connectivity_check_failed`), `succeeded` at once; the same state → `succeeded` without running any program. Changing the management side, in order: ARP probe of the new static address (skipped if the card already holds that address; a host answers → run `refused address_conflict`; probe error → `failed arp_probe_failed`; **nothing written yet**) → NTP (NET-10) → `net/pending.json` → `/run` overlay → `netplan apply` → effect check (the address is on the card within `Deps.NetWait`, DHCP: there is an IPv4; the gateway answers ARP; see `GatewayCheck`) → hook to re-apply decoys (`reapplyDecoys`) → `revert_at = now + confirm_timeout_s` written back into the note → `Awaiting`. Any error after the overlay exists → **revert at once** (`reverted`, code `connectivity_check_failed` or `netplan_apply_failed`); if the revert itself fails → `failed revert_failed` and the note is **kept** (the next startup retries). NTP is not part of the revert: reverting concerns netplan only.
- **NET-7 `net.confirm`, `net.revert` and the timer: Claim first, do the effects, then Finish.** Three parties (confirm, revert, the timer in `rc.OnParked` through `Deps.AfterFunc`, and `Start`) all go through `Notifier.Claim`; the loser gets `412 not_awaiting_confirm` (or does nothing, for the timer) and **changes nothing**. `net.confirm` writes `/etc/netplan/90-vedette.yaml` only when the note is exactly the bytes the host wrote (NET-8), with the same `run_id`, and the overlay has a `sha256` equal to `new_sha` and `parseNetplan` can read it; otherwise it **reverts** instead of keeping (`reverted pending_invalid`, the confirm command `failed pending_invalid`). A failed `/etc` write → revert `confirm_failed`. `/etc` written but the overlay cannot be deleted → run `failed confirm_failed`, the note stays so `Start` can finish the cleanup (`/etc` equals `new_sha`). Every path Finishes the run exactly once (including a panic: `defer`).
- **NET-8 `net/pending.json` and restart.** `{run_id, revert_at, boot_id, old_sha, new_sha}` (0600, written atomically through `os.Root`: a temporary file `O_EXCL|O_NOFOLLOW`, fsync, rename). Reading: a symlink, directory, FIFO, a file that is not 0600 owned by the host, an unknown field, trailing data, a malformed value (run id, boot id, 64-hex sha) → **not trusted**: always revert, never keep the configuration. `Ops.Resume` (wired to `Options.Resume`, read-only) keeps a waiting `net.apply` run when a note exists (valid or not); `Ops.Start` (before `Listen`) handles it: the same `boot_id` → re-arm the timer for the rest of `revert_at` (clamped to 660 s), or revert at once if it has passed; a different `boot_id` → `reverted reverted_by_reboot` (no `netplan apply`: the boot already applied the old file); an untrustworthy note → revert `pending_invalid`. A note or overlay **with no run** (a crash while building or while confirming): `/etc` already equals `new_sha` → delete the overlay and the note (the confirm had finished); a different `boot_id` and no overlay → drop the note; otherwise revert. Each case writes one audit line of the host.
- **NET-9 System files written through `os.Root`.** `/etc/netplan` and `/run/netplan` (0600), `/etc/chrony/sources.d` (0644, chrony reads it as its own user) are opened with `os.OpenRoot` after checking that the directory is a regular directory (no symlink), owned by the host, and not writable by group/others; written through a temporary file `O_EXCL|O_NOFOLLOW` and then renamed inside the root; deleting a symlink at the target name deletes the link itself and never follows it. Reading: `O_NONBLOCK|O_NOFOLLOW`, must be a regular file, with a size ceiling. (Known limitation: only the directory containing the file is checked, not the whole parent chain up to `/`; upgrade path: walk `ChainTop` as `coredata.go` does.)
- **NET-10 NTP.** The host writes only `vedette.sources`: `pool pool.ntp.org iburst` (default) or at most 4 lines `server <name|ip> iburst`; names follow the name regex and do not consist only of digits and dots, IPs go through `netip` (IPv4 unicast, not loopback/link-local/multicast), no duplicates (case-insensitive), no control characters, so a chrony directive cannot be injected. Then `chronyc reload sources`; the effect is checked with `chronyc -N -c sources` (every `server` must appear in the list within `Deps.NetWait`; the default pool: at least one NTP source, because pool members have their own names); failure → the old file is put back (or deleted if there was none) and `reload` runs again, run `failed ntp_not_applied`, **netplan not touched yet** (NTP is done before the network part). `parseSources` accepts only exactly the bytes `renderSources` builds; a file at that name that is not a regular file → the write is refused.
- **NET-11 Argv grammar.** `netplan`: exactly `apply`. `chronyc`: exactly `reload sources` and `-N -c sources`. No `generate`, `try`, `get`, `set`, no flags, no extra parameters.

- **NET-12 A rejected park, a failed revert and time bounds.** Invariant: **a rejected park never leaves an overlay that nobody is watching.** The framework measures the 660 s bound as `elapsed(monotonic) + (RevertAt − now)`; the command registers `AfterFinish` right before writing the note/overlay and, if the run ends while `OnParked` has not run (framework rejection, an error after the overlay, a panic), removes the overlay with `undoOverlay` and writes `unwatched_overlay_undone` (skipped if another write command or a waiting run exists at that moment: the next `Start` cleans up). `readNetplanConfig` treats an overlay with no waiting run as foreign (never the current configuration). An overlay still in `/run`, or an unreadable `boot_id` at startup → a full revert with `netplan apply` (`pending_invalid` / `not_confirmed`), `reverted_by_reboot` only when the overlay is gone and the boot id is readable and different; the same rule for `recoverOrphan`. `412 span_has_address`, `412 span_not_physical`. The revert tries `netplan apply` 3 times (~60 s), and on failure `os.reboot` after 60 s through the existing path, audit, `pending.reboot_at`. `pending.json` exists (see host-api §18); `started_at` and `reboot_at`; `net.confirm` Finishes exactly once even on a panic; `net.apply` timeout 120 s.

## Installed decoy commands
Code: `host/ops/{decoy,decoyargv,decoystate,hpns,hpns_linux,hpns_other,mac}.go`, `host/ops/bins.go` (`ip`), `host/api/decoy.go`, `cmd/vedette-host/notify.go`. Full design: `host-api.md` §6.6 and §18.
- **DECOY-1 The namespace is used only once proven.** `/run/netns/vedette-hp` must be a regular file (no symlink, directory or FIFO) in `/run/netns`, which is a regular directory owned by the host and not writable by group/others, the same inode between `lstat` and the descriptor, and `fstatfs` must say nsfs; otherwise the host touches nothing. It is created in `Ops.Start` (before `recoverNet`) and recreated when missing; sysctls and the ruleset are set at creation, at Start and (the ruleset) every time `nft list ruleset` in the namespace shows no blocking rule. **While the ruleset's effect has not been verified, no decoy is added** (`hp_namespace_unavailable`).
- **DECOY-2 A closed `ip` grammar.** Only `ip` from the allowed list; `sysctl` and `nft` only through `netns exec vedette-hp <constant path>` with a fixed argv; each value position is a checked type (`netip`, a regex, the table range 100…131) and no word starts with `-` except fixed flags; deleting a link only inside the namespace (`-n vedette-hp link del`), except cleaning up a link just created when `link set netns` fails.
- **DECOY-3 MAC.** `hp/mac.key` 32 bytes, 0600, created once, never recreated or read through a symlink/wrong permissions; MAC = HMAC-SHA256(key, 4 IPv4 bytes) with the local-administered bit on and the multicast bit off, or `oui` (6 hex, the two low bits of the first byte 0) + 3 bytes; the same IP and key give the same MAC.
- **DECOY-4 Order of refusals, and doing nothing on refusal.** `invalid_args` → `not_appliance` → `ip_not_in_mgmt_subnet` → `ip_is_network|broadcast|gateway|host` → `duplicate_decoy` → `limit_reached` (32) → `ip_in_use` (ARP probe) → `mac_in_use` → `link_name_in_use`; any refusal runs no writing `ip` command and changes no state. A link `vdh<8 hex>` that exists outside the namespace and that the host did not create is never touched.
- **DECOY-5 Creation checks its effect.** After building, `ip -n vedette-hp -j addr show` must show a link with exactly that MAC, `UP` and the address; otherwise it is removed and `hp/decoys.json` restored. Routing tables 100…131 are stored with the decoy, the lowest unused number, never two decoys in one table. `route flush table N` of a table that does not exist yet (a new decoy, a namespace recreated after reboot) has nothing to delete: iproute2 6.19+ returns exit 2 with `Error: ipv4: FIB table does not exist.` and only exactly that sentence counts as success; any other non-zero exit still fails the build (the fake `ip` of `opstest` answers like 6.19).
- **DECOY-6 `hp/decoys.json` is untrusted input.** Ceiling 64 KiB, strict decoding, every value checked, no symlink; if corrupt it is renamed `decoys.json.invalid` and the host starts empty (audit line `decoys_state_invalid`); the reader returns only `[]`. A `vdh*` link that no entry owns is removed at the next re-apply.
- **DECOY-7 Re-applying does not break a network change.** After `net.apply`, a revert and Start, a decoy outside the subnet (or turned into a network/broadcast/gateway/box address) is removed and reported (`decoy_ip/decoy_dropped` + log + disappears from `state/net`); an error in the namespace only writes `decoy_reapply_failed` and leaves things as they are; only an error writing the state is returned. `remove` writes the state first and then deletes the link, and is idempotent.
- **DECOY-8 `READY=1` after `Listen`** through `NOTIFY_SOCKET` (one datagram, not listening); with no `NOTIFY_SOCKET` it does nothing.

- **DECOY-9 Additional conditions.** The unit has no filesystem-namespace options (`deploy/systemd/unit_test.go` checks the unit text); an empty `vedette-hp` file on the same device is removed and recreated, a namespace that belongs to the process itself is refused; if egress cannot be proven the link is deleted and `decoys[]` is empty but `decoys.json` remains; sysctls are read back with `sysctl -n`; a cancelled re-apply does not drop decoys; the state file is moved to `.invalid-<time>` only when truly corrupt; a leftover link of the host's own is deleted at Start; a corrupt `hp` directory turns decoys off while the host keeps running.
- **DECOY-11 A decoy link does not speak IPv6.** Before `link set up`, the host sets `disable_ipv6=1` for exactly the link `vdh<8 hex>` in `vedette-hp` and reads it back; if that fails → the decoy is not built (`decoy_failed`). A re-apply (startup, `net.apply`) also sets it again for a kept decoy, without rebuilding the link. `TestContract_Decoy_AReapplySwitchesIPv6OffOnAnOlderDecoy`. `TestContract_Decoy_AddBuildsTheLinkAndChecksTheEffect`, `TestTheLinkIPv6SysctlGrammar`.
- **DECOY-10 Each decoy IP answers only on its own ports.** The `input` chain also records every new TCP/UDP attempt toward a decoy in the dynamic set `touched` (source . decoy, 2 minutes, at most 1024), and `GET /v1/state/hp-touches` reads it (`nft -j list set`, fixed grammar); the effect check requires that set (type, flags `dynamic,timeout`, `size 1024`, `timeout 2m`, no foreign lines; elements are not compared) and the rule `add @touched` (only `pkttype host`) right after `iif lo accept`. If nft prints the set/rule in a form the check does not know → the ruleset is loaded without them (when that can be proven the decoy still comes up, `recording: false`, audit `touch_record_off`), and every decoy is never turned off because of the attempt-recording part. `TestContract_DecoyPorts_AnUnknownTouchFormFallsBackToTheRulesetWithoutIt`, `TestTouchedSetAndRuleForms`. `TestContract_DecoyPorts_TouchesListWhoTriedADecoy`. A decoy with `ports` (from `decoy_ip.add` or `decoy_ip.set_ports`) answers only exactly those (proto, port) pairs; a decoy without `ports` (from an earlier `core`) answers every port; an IP that belongs to no set answers on no TCP/UDP port. The `inet vedette_hp` ruleset is built from `hp/decoys.json` (the `open` set, `allow`, the `input` chain), loaded as a whole and **listed again to prove it** after every change (the egress part, each rule of `input`, the elements of the two sets equal to what was intended); `ensureHP` reloads when the current ruleset differs from the intended one. If it cannot be proven: `add` is reverted, `set_ports` returns the old entry and the old ruleset; if the old ruleset cannot be proven either, it is as in DECOY-9 (the link is deleted, `decoys[]` empty, the intent remains). `set_ports` for an IP that is not yet a decoy → 412 `not_a_decoy` before a run; invalid `ports` (proto other than tcp/udp, port outside 1…65535, duplicates, more than 64, missing in `set_ports`) → 400 `invalid_args`. `GET /v1/state/net` `decoys[].ports` (absent = no filter). `core` sends `ports` only when `commands[]` contains `decoy_ip.set_ports`.

## When absent / on error
There is no "off" (it is not a module). On the `core` side, `host/client` returns `client.ErrUnreachable` when the socket is absent or cannot be connected to: that is the signal "not an appliance / the host is not running", different from a host error (`*client.Error` with a §11 code). The "Containers only" type: every feature that needs `host` returns `unsupported` with a reason. An appliance whose `host` does not respond: Settings → Updates and Box network show "Cannot reach vedette-host" together with the last known state; the other modules run normally but the OS/network/images cannot be changed.

## `DOCKER-USER` rules for the `vedette-int` network (`host/ops/dockerfwd.go`)
- **FWD-1 (only when the chain exists)**: at `Ops.Start` and then every 30 s (`Deps.FwdAfter`, not `AfterFunc`), if `iptables -w 5 -S DOCKER-USER` succeeds then for each of the five fixed rules, in this order: `-i vedette0 -o docker0 … -j RETURN`, `-i vedette0 -o br-+ … -j RETURN`, `-o vedette0 -d <range> -m conntrack --ctstate DNAT,ESTABLISHED,RELATED … -j ACCEPT`, `-i vedette0 -s <range> … -j ACCEPT`, `! -i vedette0 -o vedette0 … -j DROP` (all with `--comment vedette-int`) it runs `-C`; **above** them, for each bridge in `<root>/sys/class/net` named `br-` + 1–12 characters of `[A-Za-z0-9_.-]`, which does **not** have Docker's bridge form (`^br-[0-9a-f]{12}$`) and has a port (`<bridge>/brif/<port>`) that is not a container veth — a network card (`<port>/device`), a bond (`<port>/bonding`) or a link stacked on another link (`<port>/lower_*`, such as a VLAN); a Docker bridge, even with a custom name such as `br-app`, has only veths — there is one `-s <range> -i vedette0 -o <name> … -j ACCEPT` (the box's own bridge, such as the uplink `br-lan`, is not cut off from the internet by the `br-+` RETURN; recognised through `-S`, with `-C` before inserting so a copy is never inserted; at most 32, beyond that nothing changes and it logs once; if the directory cannot be read it is treated as having no bridges: fail closed). A missing rule (exit 1) is inserted with `-I DOCKER-USER <position>` inside our block (the bridge ACCEPTs at the top of the block, the k-th fixed rule at `block start + number of bridge ACCEPTs + k`) so that the final order is fixed (an administrator's rules above are not touched). If there are more `--comment vedette-int` lines than rules that exist in the right form (a foreign form or a duplicate), or an insertion is needed while our block has someone else's line in the middle (the position would be wrong: a DROP above the ACCEPT for reply packets), then **nothing is inserted** and it logs once. If the chain does not exist (no Docker, or Docker's nftables backend) nothing more is run. Idempotent; logs once whenever the state changes (and every time a rule is added). Only `-C`/`-I`/`-S`: it never deletes or reorders rules.
- **FWD-2 (the range)**: only from `Subnet=` in `<root>/etc/containers/systemd/vedette-int.network` (a regular file, no symlink, owned by the host, not writable by others, ≤ 4 KiB, exactly one `Subnet=` line and exactly one line `PodmanArgs=--interface-name=vedette0`), through `net/netip`: only a masked `172.30.x.0/24` (as install.sh does); otherwise no `iptables` is run and a warning is logged. A file without the bridge name (an old install): nothing is run, one log line "needs reinstall" (no migration). Never from a request.
- **FWD-3 (closed grammar)**: `iptables` is the runner's tenth binary (`/usr/sbin/iptables`); only the three shapes `-w 5 -S DOCKER-USER`, `-w 5 -C DOCKER-USER <rule>`, `-w 5 -I DOCKER-USER <1..1000> <rule>`, where the rule is only one of the five rules of `fwdRules` (the two RETURNs and the DROP have no range; the two ACCEPTs take a valid range) or `fwdBoxAccept` for a valid range and an accepted `boxBridge` name (never `+`, `!` or a Docker-bridge-shaped name); no `-D/-F/-P/-A`. Stopping the host does not remove the rules; removing them is the job of `install.sh --uninstall`. `TestValidateIptables`, `TestDockerFwd_*`.
