| D-228 | **A domain feed that lists a name for itself and all of its subdomains matches the subdomains in logs; every other feed matches exact names (S-LOG-4, logs L4; closes the hagezi line of `fix-feeds-deferred-v1-mlee.md` and the wildcard line of `feat-logs-l4-ioc.md`).** (1) **Per feed, not global**: a built-in source says so with `Source.Subdomains`; today only `hagezi-tif` (`wildcard/tif.mini-onlydomains.txt`, header "Syntax: Domains (without subdomains)": the list drops the subdomains of a listed name because the name covers them). The other built-in IOC feeds list addresses; a custom feed is always exact (its owner's list may be either kind, and an exact match never invents a hit). `IOCLookup` returns `IOCSighting.Subdomains`; the logs adapter puts those feeds in `Listing.SubFeeds`. (2) **The walk** (logs `matchIOC`): the name the device asked for first, exact, by every enabled feed; if no feed lists it, its parents, nearest first, by the `SubFeeds` only; never a single label (a top-level domain); a two-label public suffix (`co.uk`) is never an indicator (`feeds.IOCKey` refuses it). At most the 10 shortest parents (a name has up to 127 labels; listed names sit near the registrable domain), each looked up once per batch (the batch cache), inside the 5 s budget. (3) **Said**: the hit keeps `dest` = the name asked for (what the device did); `feeds`/`confidence` are those of the parent's subdomain feeds; the incident says "(listed as <parent>, with all of its subdomains)" and is keyed `ioc:<parent>`, so the many subdomains of one listed name that a device asks for (random-label C2, tracking hosts) are one incident, not dozens. The parent is not stored in `logs_ioc_hits` (no schema or API change). | The software hagezi made this format for treats a plain name as the name and its whole zone: dnscrypt-proxy blocked-names "`example.com` — identical to `*.example.com`: matches example.com and all names within that zone" (`=example.com` for exact only); hagezi's README lists "Wildcard Domains" for DNSCloak/DNSCrypt/Technitium/FRITZ!Box and shows a parent rule `\|\|app-measurement.com^` matching `region1.app-measurement.com`. AdGuard Home's own rule `\|\|example.org^` blocks "the example.org domain and all its subdomains", while a plain line or a hosts line blocks "example.org but not its subdomains", and Pi-hole gravity lists are exact: so the meaning is the list's, not universal, hence the per-feed flag and exact by default. Not chosen: a global suffix walk (would turn exact lists into wildcard ones and invent hits); matching the public-suffix list in logs (feeds already refuses suffixes as indicators); storing the listed name (a new column and API field for a text the incident already carries).
