# Feeds: change impact map

What else to check when you change part of this module. Signatures and behaviour are in the code; this file names the readers.

| If you change | Check |
|---|---|
| Product names of ranges and exploited entries (`core/productid`, `Range.MatchRow`, `RangeProducts`, `CatalogueProducts`, `KevIndex`) | inventory "do you have it" matching and the findings match pass; the candidates of findings' AI identification of software (`CatalogueProducts`, findings P-9); findings golden tests (`modules/findings/testdata/kev-nvd-*.json`, `equiv-*.json.gz`). |
| Range readers (`Ranges`, `RangeCVEs`, `RangesOf`, `Catalogue`, `SchemeRangesOf`, `SchemeCVEs`, `DistroFixesFor`, `DistroCVEs`) or how NVD's and the record's rows are read together (`matchRows`, `kevRecordView`, `AffectedOnly`, `VendorList`, `ownCNA`, `recordEvery`) | the findings match pass through `cmd/vedette/wiring.go` (findings' `decide`, `nvdNames`, `recordDecided`); the selfcheck `findings.range_precedence`; `TestCVE5Status_EndToEnd`. A change of what the record reader stores needs `recordReader` bumped. |
| Vendor version schemes (`RangeScheme`, `core/versionscheme`, `scheme` in `content/catalog/products`; a scheme's `NVDNotation` and `Described`, `describedRows`) | which vendor rows become matchable (NVD's rows and the description's fixed releases too); the brief's fixed releases; the version form inventory stores (`Scheme.Stated`). |
| VMware's ESXi words (`esxitext.go`, `RecordTextType`), `content/catalog/esxi-builds.json` | which ESXi updates findings calls not affected (`esxiLaterTrains`) and when NVD's rows win (`esxiDisagrees`); a change of what the record reader stores needs `recordReader` bumped so boxes read the whole list again. |
| What the CVE records feed asks for by ID (`recordDue`, `recordBacklogSQL`, `recordIDBudget`, `recordPause`, `recordLeftPause`) or when it reads the whole list again (`recordsBulk`, `recordsOwn`, `recordOwnAgain`) | `PRIVACY.md` flow 1 and the Privacy screen's text (`web/src/locales/en/core.json`); `TestCVERecordsByID_OnlyPublicSources` (never a CVE only this box keeps), the `TestCVERecords_OwnList*` tests (a CVE only this box's own lists keep brings the whole list early, at most once a day). |
| Line sources (`lines.go`, `content/catalog/line-sources.json`, `feeds_line_*`, `LineData`, `LineCVEs`) | findings' release-line verdicts (`modules/findings/linejudge.go`, M-13) through `withLines` in `cmd/vedette/wiring.go`; `PRIVACY.md` flow 1, Settings → Privacy and `THIRD_PARTY_NOTICES.md` for a new source; the golden and equivalence fixtures of findings. |
| `PickCVSS`, `Severity` | the severity shown on every finding, list, report and notice. |
| `Store.Brief` fields | the CVE page and finding page (`web/src/features/feeds/brief.ts`, `cmd/vedette/findingcase.go`), the AI context (`cmd/vedette/ai.go`, `ai_plan.go`), MCP (`cmd/vedette/mcpserver.go`). |
| `feeds_signal` or `feeds_kev` columns, `UrgencyReader`, `ReadSourceNames` | finding urgency (`cmd/vedette/urgency.go`, selfcheck `findings.urgency_recomputed`) and notice text (`cmd/vedette/notifyfindings.go`). |
| Catalogue retention and the reporting window (`window.go`: `Window`, `keptSQL`, `keptSignalsSQL`, `publicListedSQL`, `datedSignalSources`, `OutsideWindow`; `retention`, `pruneCatalogue`, the 365-day window, `Deps.Pins`) | `findings.PinnedCVEs`; the selfchecks `findings.cve_in_catalogue` and `findings.catalogue_retention` (same rule, written again in SQL); the match set's `OutsideWindow` mark (`cmd/vedette/wiring.go` `MatchSet`) and findings' close as `outside_window` (M-15); what is asked by ID and when a whole read starts (`PRIVACY.md` flow 1, Settings → Privacy); the help text of Settings → Feeds (`web/src/locales/en/feeds.json` `window`). |
| Event names or payloads (`service.go`) | the subscribers in `cmd/vedette/wiring.go` (inventory re-match, scan re-scan, baseline handling in notify). A renamed event silently stops re-matching. |
| The custom-feed parser (`ParseFeed`, limits, reject reasons) | `parse-test` and the parser editor: `web/src/features/feeds/parsers.ts` applies the same rules in the browser, and `parse_test.go` (`TestCross_*`) runs the cases of `parsers.test.ts`; golden files in `testdata/golden`. |
| Indicator normalisation or verdict (`IOCKey`, `Judge`, whitelist) | logs indicator hits (`cmd/vedette/logsioc.go`), the AI and MCP `lookup_ioc`. |
| Networks as indicators (`ParseSpamhausDROP`, `networksAround`, the network read in `IOCLookup`, `dropMinBits4`/`dropMinBits6`) | every address lookup (logs hits, Feeds → Look up, the AI): a bound changed in the parser and not in `networksAround` makes stored networks unreachable; `TestSpamhausDROP*`, `FuzzParseSpamhausDROP`. |

| How VulnCheck KEV is read (`VulnCheckPageURL`, `buildVulnCheck`, `vulnCheckMaxPage`) | `PRIVACY.md` flow 1 and `THIRD_PARTY_NOTICES.md` (both name the request); `TestVulnCheckPull_ReadsAListOfMoreThanSixtyPages`, `TestVulnCheckPull_FailsClosedWhenTheListIsNotComplete`. |
| `KevVulns`, `IsStale`, `DisplayOf` | the weekly report (`cmd/vedette/reports.go`). |
| `feeds.Inventory`, `DistroLister`, `PlatformChecker`, `TxSettler` | the adapter `feedsInventory` in `cmd/vedette/wiring.go`. |
| Which distribution rows a pull keeps (`DistroWant`, `distroKeep`, `distro_packages`) or when it pulls again (`distroBehind`, `distroPartial`) | findings' verdicts of distribution packages and the causes it names for the rest (`modules/findings/distro.go` `distroVerdict`, `distroSilence`; the coverage of Settings → Diagnostics); the peak memory of the ubuntu-vex and ubuntu-osv pulls (logged with each pull); `TestDistroPullRunsAgainWhenTheWindowAppears`, `TestDistroPullKeepsTierRowsOfTheDevicesPackages`. |

## Switching the module off

Routes and the pull job stop; tables stay. Findings keep matching against what is stored, with no new exploited entries or ranges.
Logs stops getting new indicators. Nothing else fails.
