| D-452 | **`container.pull` with `source: bundle` loads the image from the offline bundle core uploaded, verified exactly like a registry pull, and ends on the registry path unchanged (replaces `412 bundle_unsupported`).** (1) **Where the bundle is**: core streams the upload to `<core_data>/bundles/<bundle_id>.tar`; `bundle_id` is 32 random lowercase hex chosen by core (like a `snapshot` id or a `host-packages/<id>.deb`), not a hash of the tar (core would read 8 GiB to name it, and the host trusts no hash core computed). The host builds the name from the id, opens it through core's tree (INV-14: `os.Root`, the descriptor must be a regular file owned by `core_uid` with one link, at most 8 GiB, not a symlink, `O_NONBLOCK`), and never takes a path. Missing → `412 bundle_not_found`; anything else wrong → `412 bundle_invalid`. Core removes the file afterwards; the host never writes or deletes in `bundles/`. (2) **The tar is untrusted and never extracted by name**: headers are read (members skipped by seeking), the names are a closed list (`bundle.json`, `index.json` + `.minisig`, `release-manifest.json` + `.minisig`, `sbom.json`, `images/<service>.oci.tar` for the five services, `host/<name>.deb`, and the folders `images/` and `host/`), regular files and those two folders only (no link, hard link, device, FIFO or sparse entry), no duplicate, at most 64 entries, each under its cap (256 KiB a document, 2 KiB a signature, 1 MiB `bundle.json`, 64 MiB `sbom.json`, 256 MiB a `.deb`). The four documents are read into memory; `bundle.json`, `sbom.json` and `host/*.deb` are allowed but not read by the host. (3) **Verification**: the documents go through the very same `verifyPull` (same refusals, same order, all in `Check`; the bundle's index is stored like a sent one, sequence never goes back, expiry only warns, so a stale index is accepted with `index_expired`); the request carries no documents (`400` if it does: one source of truth). Idempotent: an image already here with the right digest is not copied or loaded (signatures still checked). The layout is removed right after the load, at the next bundle pull and at `Start`.
