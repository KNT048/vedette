The Alibaba metadata address 100.100.100.200 lies in 100.64/10; a scope that contains it may probe it with nmap/nuclei like any LAN host (scan results stay on the box; the SSRF guards still refuse it). | Why: RFC 6598 (https://datatracker.ietf.org/doc/html/rfc6598 §1, §4) defines 100.64/10 as Shared Address Space that MUST NOT be forwarded across provider boundaries, and IANA marks it "Globally Reachable: False" (https://www.iana.org/assignments/iana-ipv4-special-registry/iana-ipv4-special-registry.xhtml); companies and Tailscale number real LANs from it (Tailscale: https://tailscale.com/kb/1015/100.x-addresses, "addresses aren't exposed to the public internet"). Browsers' Private Network Access treats it as private address space (WICG spec §2.1, https://wicg.github.io/private-network-access/#ip-address-space-heading: `100.64.0.0/10` → private). OPNsense's "Block private networks" covers "RFC 1918, loopback, link-local and carrier-grade NAT" (https://docs.opnsense.org/manual/interfaces.html), while pfSense's covers RFC 1918 and loopback only (https://docs.netgate.com/pfsense/en/latest/interfaces/configure.html) and runZero's `private` keyword names "RFC-1918 and private use" (https://help.runzero.com/docs/discovering-assets/): the leading products differ, and the ones that judge "is this a local network" (PNA, OPNsense, Tailscale) side with local.
