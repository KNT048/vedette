# FULL-5: map a verified domain's surface and scan every name at the depth its terms allow

Owner: AI-Mlee (exposure: discovery, UI, terms, gating, caps, CONTRACT INV-27). Touch points owned by AI-Trưởng (scan container worker, host ops, fence key, images) are marked **[T]**.
Status: plan only. Decision: D-567 (`docs/decisions/D-567.md`), **amended 2026-11-14: kien dropped CDN classification and slice 4** ("ko quan tâm domain đó là cdn hay thật": it does not matter whether a name sits on a CDN or a real server). No open question for kien.

**kien (2026-11-14):** "for a domain target, after ownership is verified, map the surface (subdomains via cert-transparency + DNS, their IPs/web apps) and scan each."
**Done:** on the N100, a verified domain shows its subdomains, their IPs and web apps, and each one is scanned at the depth of the domain's testing terms; what was not scanned this run says why and when it is next in line.

## 1. Today

- **Discovery** (D-229, exposure INV-12, `modules/scan/surface`): crt.sh names (expired certificates excluded, more than 300 names → 400 `too_many`, crt.sh down → 502, whole or nothing), each resolved for A records only (`resolveAll`, `"ip4"`), kept as `HostRow {name, ip}` with the first address only. No CNAME, AAAA, MX or NS; a name with no publicly logged certificate (a VPN portal or `mail.` with a self-signed certificate) is never found.
- **Scanning a name** (D-57 (7), LEGAL §3): `GET /` on 80 and 443 by name with its certificate; passive ZAP by name (INV-24, at most 4 pages a run); read-only nuclei only on the box's IP (D-520). An address a name points at is port-scanned only when `ScannableIP` says it is the box's own verified egress IP.
- **Terms** (D-566, INV-26): per target; `Mode.Full` makes every scan of the box's IP a deep scan; for a domain, FULL-3's active web tests go only to names that resolve to a verified box IP. The text says "Accept only if {value} is yours alone … not … a CDN or hosted service that serves your names"; slice 3 replaces that sentence for domains (§3.5).
- **Fences** [T]: the scan container worker re-checks the box's egress (2 of 3 services) before any job on a public IP (`own_ip`, D-520, plan 2026-11-13 §1.3); the host's `zap.baseline` re-checks the domain's TXT and that the name still resolves to the pinned IP (`zapOwned`, D-521 (1)).
- **Gap found while planning (for [T], fixed in slice 2):** both fences take the TXT **token from core**. A TXT value is public, so a compromised core could pass another Vedette customer's domain with that domain's visible token and the fence would agree. Today that reaches only passive ZAP; with FULL-5 it would reach port scans and deep scans. The fence must check a token it can derive itself (§5).

Providers' own rules for testing through them: Cloudflare permits scans of "Customer-owned IPs", "Cloudflare's designated public IPs" and "The customer's registered DNS entries", testing "application and network-layer aspects of their own assets … without attempting to actively exploit" ([policy](https://developers.cloudflare.com/fundamentals/reference/scans-penetration/)); AWS lists CloudFront among services testable without approval, and prohibits DoS, "port flooding", "request flooding (login request flooding …)" and "DNS zone walking via Amazon Route 53 Hosted Zones" ([AWS policy](https://aws.amazon.com/security/penetration-testing/)). **Reading:** everyone discovers broadly (CT + DNS records; Detectify adds a curated wordlist). On what to scan, Detectify's model fits kien's call: monitoring "is enabled per root asset and propagates to all its subdomains", after one proof of the root (TXT or file). Qualys and Intruder put a human step per asset and keep CDN edges out by default; kien chose the per-root model (2026-11-14): the customer verified the domain and accepted its terms, so every name under it is scanned the same way, whatever sits in front of it. The fence keeps the per-root proof live at every step.

## 3. Decisions (D-567, as amended)

1. **Discovery = CT + DNS + MX/NS + a small wordlist.** For each crt.sh name (wildcards `*.` dropped) and the apex: A, AAAA and the CNAME target (`LookupCNAME`: the final canonical name), through the box's own resolver (the system resolver, as today). The apex's MX and NS hosts are added as names when they are the domain or under it; outside it they are listed as plain lines ("mail: aspmx.l.google.com") and never probed, because they are not under the verified domain. **Wordlist: yes, bounded** (Detectify's standard practice, and what attackers try first): a fixed list of ≤ 150 labels (`www`, `mail`, `vpn`, `remote`, `owa`, `portal`, `admin`, `dev`, `staging`, `api`, `git`, `jenkins`, `fw`, `nas`…) shipped in `content/surface/labels.txt`, after a wildcard check (two random 20-character labels; any answer → the wordlist is skipped and the page says why), at most 20 lookups a second, one wordlist pass per run. ~150 queries to the customer's DNS provider through a recursive resolver is ordinary load and is not zone walking (no NSEC walking, no AXFR). Not chosen: passive DNS (a paid third-party feed and a new outbound flow of the domain), AXFR (a direct connection to the customer's name servers), a big wordlist (load without proportionate finds).
2. **The 300-name rule stays whole or nothing** (D-229 (6)), counting CT + wordlist + MX/NS names: the listing is complete, so day-to-day "gone" rows stay true. Caps apply to the **expensive steps**, which rotate (§4) and are listed as "not scanned this run", never to the listing.
3. **One rule for every name: the domain's terms depth, whatever sits in front of it** (kien, 2026-11-14). No classes, no provider lists, no "CDN" or "hosted" handling. Each public IPv4 a name under the verified domain resolves to is scanned like the box's IP at the domain's `Mode`: without accepted terms, the K-4 scope (D-229 by-name checks, passive ZAP by name, nothing to the IP beyond today); with the terms, the deep scan (all ports, nmap -sV, CVE match, nuclei, OpenVAS when it is on, the active web scan by name); with the disruptive tick, the disruptive checks too. A name on the box's own verified IP reuses the box IP's pipeline (one scan of an IP per run, whichever name led to it). Private addresses: listed, never dialed (today). AAAA: listed, "IPv6 is not scanned yet".
4. **Subdomain takeover check, kept**: it needs no classes. A name whose CNAME points at a platform and whose existing D-229 `GET /` answer carries that platform's "no such site" text ("There isn't a GitHub Pages site here", Heroku "No such app", S3 `NoSuchBucket`…) is a `danger` finding of its own, read from the response the check already gets (no new request). The fingerprints are a short list in `content/surface/takeover.txt` (CNAME suffix + body text), written from each platform's own documentation. Detectify and every EASM product report it; it is the one surface finding a customer can fix in a minute (delete the DNS record).
5. **Terms version bump** (slice 3, `2026-11-1Xa`): the domain text drops "not … a CDN or hosted service that serves your names" and says: "Every name under {value} that resolves to a public address is scanned at this depth, whatever serves it: your own server, a hosting provider or a CDN. If a provider serves a name, its testing policy applies to you (for example, Cloudflare and AWS forbid denial-of-service tests); leave the disruptive checks off unless that provider allows them." A new version asks again (D-566). The IP-target text is unchanged.
6. **Scan now on a domain** = discovery + takeover check + by-name checks of every name at the terms depth, then the deep steps on the names' IPs in rotation under the caps (§4), one at a time; box-wide one scan at a time stays; the domain run's own time limit grows with the caps (each deep IP keeps the IP target's 10 minutes, OpenVAS its 90).

## 4. Data model and caps

- `HostRow` (snapshot of the domain) becomes `{name, source: ct|dns|mx|ns|wordlist, cname, ips [{ip, family, box, ptr}], web {status, title, product, cert_expiry}, takeover, checks [kind], not_checked}`; old snapshots read with `source: ct`.
- The domain's snapshot carries the deep results per IP (ports, services, exploited CVEs, nuclei, web findings, OpenVAS rows), each with the names that led to it; the day diff compares them like an IP target's. No new target kind, no migration of `exp_target`.
- `CheckRow`/`NotCheckedRow` per name or IP: "not scanned this run (cap), last scanned …, next in line", "IPv6 not scanned", "wordlist skipped: wildcard DNS", "private address, not dialed".
- Caps per run (each a "not scanned this run" line naming what was left and when it was last scanned; rotation by last-scanned date, so every name and IP is reached in turn): deep IPs (port scan, nmap -sV, nuclei, OpenVAS) `MaxDeepIPs` 3; ZAP pages `MaxWebScans` 4 (passive) / 2 (active, Full); http nuclei by name 50 names; names listed 300 (hard, whole or nothing). Many names on one CDN address are one IP for the deep steps.
- Probe log (LEGAL §3): unchanged per probe; one `dns` row per run for the wordlist ("150 lookups via the box's resolver"), written before.

## 5. The fence [T]

Every step that sends anything beyond the D-229 checks to a public IP that is not the box's egress is a **`domain_ip` job**: nmap shape `external` with scope `domain_ip`, nuclei scope `domain_ip`, `zap.baseline`/`zap.active` kind `domain`, OpenVAS's target. Job fields: `{domain, name, ip, token, ports}`.
The executor (scan container worker for nmap/nuclei, host for ZAP and OpenVAS) checks, on its own, right before each tool start (each nuclei job, each ZAP page, the OpenVAS task start), cached ≤ 5 minutes per `(domain, name, ip)`:
1. Grammar: `domain` by exposure's domain RE; `name` = domain or ends in `.`+domain; `ip` public IPv4 (`localnet.Public`); `token` 32 hex → else `invalid_job`.
2. **Box-bound token**: `token == hex(HMAC-SHA256(fence_key, "vedette-verify\x00"+domain))[:32]`. `fence_key`: 32 random bytes the host makes at install (`<state>/fence.key`, 0600), mounted read-only into the scan container, **never into core**; core gets a domain's token from the host op `exposure.token {domain}` when the domain is added. Another box's token never matches → `token_foreign`. Domains verified before this keep their old token for today's scope; "Verify again" shows the new TXT value to add, and `domain_ip` jobs need it (`zap.baseline` gets the same check in this slice).
3. TXT of `domain` contains `vedette-verify=<token>` → else `target_not_owned`.
4. `name` resolves (A, system resolver, 10 s) to a set containing `ip` → else `name_moved` (that item only, like `zap_name_moved`).
5. Lookup or DNS failure → `ownership_unchecked`. All refusals fail closed, nothing sent, audited by the executor.
A compromised core can then aim deep scans only at IPs that a domain carrying **this box's** TXT points at now: the customer's own DNS is the authority. Container-only install (no host): no `domain_ip` jobs; the row says "needs the Vedette host".
