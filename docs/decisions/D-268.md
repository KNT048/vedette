| D-268 | **vedette-host deletes the stale UDP conntrack entries of the syslog port after core runs again (review M1 of D-167, #297).** Problem (measured, rootful Ubuntu 26.04): core publishes 514 -> 5514 (udp, tcp) through netavark DNAT; a device sending UDP syslog from one fixed source port without pausing keeps its flow after core restarts, so after `podman restart`, an upgrade, a reboot or a crash restart nothing reaches the new core (none within 10 s; the entry never times out while the device keeps sending). Cause: a stale UDP conntrack entry (one that DNATs to the old container, or one created without DNAT while core's rules were gone) keeps the flow; the delete clears both; the rootful lab run will say which (the supervisor reruns the rootful check after the push). TCP opens new connections and is not affected. Decision: when the host sees core run again it runs once, through its allowlisted exec, `/usr/sbin/conntrack -D -f ipv4 -p udp --orig-port-dst 514` (validator: exactly that argv, no other filter, no flush-all). Exit 1 is success only when stderr carries the "N flow entries have been deleted" line (N may be 0; conntrack also exits 1 on real errors, which are logged as errors); the count is logged once; a missing binary is logged once per host run and nothing else happens. "Sees core run again" = (a) the health wait of a start the host ran itself (container.start, version switch, rollback, recovery), and (b) a look at core's container every 30 s (`Deps.CoreWatch`) comparing container ID + StartedAt, which also covers a systemd crash restart and backup.restore; the first look after the host starts ALWAYS deletes once (at boot core starts after vedette-host, so entries made while core's rules were gone are otherwise never cleared; the same for a core that restarted while the host was down; a correct entry that is deleted is re-created by the next datagram, so the cost is one log line; review round 1, MEDIUM-1). The package `conntrack` (conntrack-tools, GPL-2.0, separate process, not linked) is added to `install.sh` PACKAGES with an effect check (`/usr/sbin/conntrack --version`) and listed in THIRD_PARTY_NOTICES; `scripts/dev/syslog-ports-check.sh` step 5 runs the same delete after `podman restart` to emulate the host. Limits: IPv4 only, port 514 fixed (the constant of core's unit); the .deb does not Depend on conntrack (the installer adds it; a box without it logs one error).
