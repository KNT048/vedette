# Inventory — Change Impact Map

## Modifying: quiet private-address devices (`quiet.go`: `PrivateMAC`, `stablePrefixes`, `quietSQL`, `toReviewSQL`, `isQuiet`, `earnReview`, `EarnReview`, `inv_asset.review_earned_at`; `Asset.private_mac`/`quiet`; INV-49)
- **Every reader of "not approved" that means To review** uses `toReviewSQL` (list filter `approved=false`, `Counts.Pending`, `DeviceCounts` for Home and findings' summary); a new reader that tests `approved = 0` counts quiet devices as To review again. Readers that mean "a person has not approved it" (SNMP, scans, `ApproveEnrolled`, hand binds) keep `approved`.
- **Every writer that can add a service, move last_seen, fold or merge** (`Record`, `services`, `replaceSoftwareTx`, `settle`, `Merge`) calls `earnReview` after its write; a new writer of those must too, or a device passes a day or gets a port with no mark and no notice. `joinInto` carries `review_earned_at`. cmd/vedette wiring calls `EarnReview` on `findings.finding.created` and `honeypot.hit.created`; the column is in the export policy.
- **notify** opens the new-device incident for `inventory.asset.updated` with `notify: true` (`assetUpdated` calls `assetEvent`); a discovered event of a quiet device has `Notify` false. Changing what makes a device quiet changes when that notice goes out: both read the same SQL.
- **Adding a stable prefix** keeps a virtual machine out of the quiet set; the join rules (`macKinds`, `sameMachine`) still treat every locally administered MAC as private, so VM rows fold exactly as before.
- **Web** (`DevicesPage.tsx` lists, `NameChips` Private address chip, `DevicePage.tsx` notice and note, locale `chip.privateMac`, `approval.quiet`, `privateMac.note`; `mocks.ts` `isPrivateMac`/`isQuiet`): the Devices tab holds approved and quiet rows, To review the rest.

## Modifying: nmap's OS guesses (`osguess.go`: `guessFamilies`, `guessContradicts`, `dropContradictedOS`, `hiddenGuess`; `ObservationRow.ContradictsType`; INV-42)
- **Every reader of a device's software** must add `NOT hiddenGuess` (alias `s`) or go through `liveSW`/`loadSoftware`; a new reader without it shows a guess the device does not use.
- **findings** sees the change only through `MatchInput`: guess rows have no match key, so no finding comes or goes with them; a device whose OS changes (the guess no longer wins) is matched again through `inventory.asset.updated` `match: true` and findings' normal re-evaluate path (platform rules read `MatchDevice.OS`).
- **The table**: add a type only when no real device of that type runs the family (Android desk phones, Android point of sale, Windows NVRs and print servers exist). `TestOSGuessContradictionTable` holds both the ruled-out and the kept pairs.
- **Web**: the Observations table shows "Not used: nmap's guess does not fit the device type" for `contradicts_type` (`DevicePage.tsx`, `obs.notUsedType`).

## Modifying: what a device states vs a scan's guess (`stated.go`: `lldpStated`, `markStated`, `osBasis`; `obs.rank`; `Observed.Basis`, `fingerprintRow`; INV-44)
- **The ranking is one place**: `winners` marks the LLDP statement before picking; every current-value pick goes through it. A new pick that calls `better` without `winners` must call `markStated` first or it ranks a statement as plain passive.
- **content/catalog/network-os.json** is shared with findings (`deviceOS`, `lldpCard`): giving a row `lldp_oui` lets that OS outrank nmap's guess here and count for matching there, in one change. Check both modules' tests.
- **findings** sees it through `MatchDevice.OS` (and `inventory.asset.updated` `match: true` when the OS changes); the statement itself already reached it as `StatedOS`. `osIdentity` knows no network OS, so a Junos statement changes no distribution rule.
- **Web**: `components/common/SourceBadge.tsx` takes `basis` (locale `common.basis`); `DevicePage.tsx` Overview rows (`Identity`), the Software tab OS line (`software-os`) and the guess version text (`software.guessNoVersion`); mocks mark an nmap OS as a guess (`osGuess`).

## Modifying: the declared identity (`declared.go`: `osProducts`, `declaredCandidates`, `declaredChoice`, `storeDeclared`, `ReconcileDeclaredOS`, `modelKeys`; `Config.DeclaredOS`; `Observed.SoftwareID`; INV-45)
- **The choice is the matcher's** (findings `DeclaredOSRow`, INV-4c (2)): never add a rule here that keeps or drops a candidate on its own, or the page and the findings name two OSes. cmd/vedette `TestWiringDeclaredOSPageIsTheMatchersOS` checks every case.
- **The decision is stored** (`storeDeclared`, called by `recomputeColumns`): `inv_asset.os`/`os_obs_id` and every reader (`loadDevices`, `Names`, `deviceName`, `MatchInput`, the export) hold the declared OS; the matcher is asked only at write time, only for a device with a candidate and a source that may outrank it (`outranking`: keep that gate in step with what `deviceOS` and `withoutCoveredWindows` read). The stored observation is its own source, `declared`, with the software line's id as evidence (`declaredObsSQL`): it never shares a key with a person's typed OS (`manual`), so a merge cannot fold one into the other and a reader of manual OS observations needs no exception. A reader of what the sources read (`recomputeColumns`, `deviceDifferences`, the join's move) leaves source `declared` out; the Observations tab shows it, labelled "Declared software". A new write path that changes software lines must call `RecomputeAsset`. The naming rule reads the observations' maker and model (`fillDeclaredHardware` fills the rest at read).
- **content/catalog**: `"os": true` on a curated row makes a declared product of it an OS candidate (the web catalog ignores the field); a network-os.json row does too.
- **Web**: `DevicePage.tsx` shows no Software tab OS line when `os.software_id` is set; `nameOf.ts` leaves such a maker or model out of the name.

## Modifying: software lines (`inv_software`, `inv_software_reading`, `inv_software_event`, `Resolve`, `settleLine`, `identify`, `matchKeys`, `EditSoftware`, `RemoveSoftware`, `SoftwareSink.ReplaceSoftware` scope; INV-41, INV-50, INV-52, INV-54)
- **findings** reads them only through `MatchInput`: one row per present line (its effective reading, the line's id; `Correction`/`ReportedSource` when a person's entry is the value), then the other readings that feed matching (same id, `Key` = line, source and instance); `NotInstalled` holds the lines a person marked. `Superseded` and `StaleCorrections` are empty. A finding's `software_id` survives a version move.
- **agent-intake, sensor-active, the box** send lists through `ReplaceSoftware(hint, source, scope, items)`: agents name themselves (`observe.Osquery`, `observe.Wazuh`, `observe.Box`); a sensor may pass a scope of instances to replace only those (`observe.Software.Instance`).
- **core/productid** decides the product and train of a line and its match keys: a change of a product's key, keys or train rule re-keys lines only for new readings (no re-resolve pass yet); `TestMatchKeys_KeepEveryKeyASourceGives` fails when a key a source gives would be lost.
- **Web**: the device detail's `software` is `SoftwareLine` (one row per line, built on the server with `also_seen`, `differs`, `correction`); the list's `Software` says `not_installed`. Nothing merges software in the browser.
- **Export** (`modules/core/export_policy.go`) classifies the three tables and `inv_asset.agent_source`.
- **Self-check**: the three software-line rules in `selfcheck.go`; the fixture tests (`lines_fixture_test.go`, testdata/software_lines.json) count the class.

## Modifying: detected values that differ from an entered one (`differences`, `sameValue`, `UseDetected`, `KeepEntered`, `Detail.DetectedDiffers`, `inv_detected_keep`; INV-47)
- **Trusted sources** are decided in `trustedRead`: a new source or a new statement that should count is added there, and `TestINV47_EachFieldAgainstEachSource` lists which sources raise a notice and which never do.
- **Noise rules** are `sameValue` and `makerSuffixes`; a rule that is too loose hides a real difference, one too tight raises a notice on every device: add a case to `TestINV47_NotADifference` with the change.
- **Export**: `inv_detected_keep` is classified in `modules/core/export_policy.go` (a column added later needs its entry; `TestExport_PolicyClassifiesEveryColumn`). A merge moves its rows in `joinAs`.
- **Use detected** deletes manual observations of one field, so anything else that writes a manual observation of that field (a new edit path) must keep working with that delete.
- **Web**: `DetectedNotice.tsx` (own component, Overview rows), `useDeviceAction().useDetected/keepEntered`, locale `detectedNotice.*`; the mock computes the list in `differsOf` and gives a device entered as "edge-fw" an SNMP reading (`SNMP_READS`).

- **cmd/vedette** (`inventory.go` `findingCounts.DeviceStatuses`) gates it on the findings module.
- **Web**: `features/inventory/RiskMarker.tsx` (`RiskMarker`, `riskWord`, `riskDescription`, `riskRank`) is the one marker of every page. Devices (column, chips, `risk:` token in `deviceQuery.ts`, the `risk_unavailable` note), the device page title, To review read inventory's `risk`; Findings (device column, filter options, To fix cards), Recommended updates and the tier CVE page read `risk` from their own findings answers (to-fix, plan), never the device list. Its link is the device's To fix (`/findings?tab=fix&device=`); its accessible name starts with the words shown. The mocks (`inventory/mocks.ts` `toRow`, `findings/mocks.ts` `deviceRisk`/`riskOfCard`) follow the same rule, the box never marked.

## Modifying: Ignore (`inv_asset.ignored_at`, `SetIgnored`, `DeviceFilter.Ignored`, `Counts.Ignored`, `inventory.asset.ignored`, INV-38)
- **The vulnerability readers** (`MatchInput` ok=false, `AssetIDs`, `DevicesRunning`) leave an ignored device out: findings (match, reconcile, plan, Home summary), feeds (`Distros`, the CVE page's devices, "Do you have it?"), `cmd/vedette` reports' fixes. A new reader of vulnerabilities must go through them or check `IgnoredAt`, or an ignored staff phone raises findings again. `AssetIDs` no longer means "every device": a caller that needs every row (to drop data of deleted devices only) must not use it for that.
- **Joins** (`joinAs`) carry a watched, approved row's approval onto a kept declared row in a machine join (neither row suspicious) and nowhere else: never from an ignored row, never in a chassis join; no `inventory.asset.approved` is published (a system join is no person's approval). They keep the kept row's `ignored_at` and return the watch event the caller publishes after the merge events; a new caller of `joinAs` must publish it, or the moved findings keep the other row's state.
- **findings** reads `IgnoredIDs`/`IsIgnored` (list filter, reconcile repairs, write-time check, the urgency pass), and its selfcheck `ReadIgnoredIDs`; **reports** (`cmd/vedette/reports.go`: `IgnoredIDs` and `IgnoredAt`), **exposure** (`cmd/vedette/exposuregateway.go`: appliance devices) and the **AI/MCP** lists read `IgnoredAt`.
- **findings** keeps the device's findings as they are while it is ignored (no subscriber of `inventory.asset.ignored`/`unignored`): its lists and `Views` leave them out and its urgency pass does not rate them. Stop ignoring re-rates the device through the `asset.updated` with `match` of the same write: dropping that event (or its `match`) leaves a rise that happened while it was ignored untold. Nothing is deleted: a person's decisions and history stay. Its reconcile's orphan pass keeps them (its second look `Assets` = `DeviceRefs` still finds the device: filtering ignored rows out of `DeviceRefs` deletes an ignored device's findings and decisions on a pass whose `IgnoredIDs` read fails; `TestDeviceRefsKeepsAnIgnoredDevice`), and a risk acceptance of a device `MatchInput` refuses does not expire. notify sends nothing for the reasons `device_ignored` / `device_watched`.
- **notify** closes the open new-device incident on `inventory.asset.ignored` ("Closed by Vedette: the device was ignored by <person>."). The trap and log incidents never read inventory state: keep it so (a security exception), never filter them by `IgnoredAt`.
- **sensor-active / scan** read the per-device sources (INV-37) through `scanCols`/`effectiveSources`, which read both as `off` while the device is ignored (the stored value is kept); a new policy query that reads `scan_source`/`snmp_source` directly must use `effectiveSources` or check `ignored_at`. Turning one on while ignored is 409 `device_ignored`; `cmd/vedette/scan.go` leaves ignored devices out of the targets. `Devices()` (zero filter) still lists them for honeypot, MCP, AI and response.
- **Web** (`IgnoreDevice.tsx`: the confirmation, the Ignored tab, the device page notice; `PendingPanel.tsx` Approve / Ignore / Remove; `DevicePage.tsx` Ignore for an approved device, mark unknown in the approval notice; `DevicesPage.tsx` the Ignored tab while `counts.ignored > 0`; `api.ts` `useIgnoredDevices`, `ignore`; `mocks.ts`). `modules/core/export_policy.go` exports `ignored_at`; audit labels `inventory.ignore`, `inventory.unignore` in `web/src/locales/en/core.json`.

A new reader that names a device by `Hostname` alone shows the old name after a rename: use `Names`, `DisplayName` or `NameOrHost`. `cmd/vedette` `TestTheNameInVedetteReachesEveryReader` lists the readers.

Changing the limits (64 characters, no < >) changes `contract.ts`, the mock's `LABEL_RE` check and the page's field.

## Modifying: the address rules (`claimIP`, `confirmIP`, `ipTrust`, `inv_asset.ip_confirmed_at`, `AssetHint.From`; INV-35)
- **sensor-active** (version scans, SNMP rounds) and **agent-intake** (Wazuh, software lists) send hints by address only: while the discovery sweep runs and probes the device (`sweptAway`, `sweepSkips` shared with `ProtectedIPs`: a change of which devices the sweep skips changes which can be judged stale), a device it has not confirmed at its address for 72 h gets none of them (dropped, logged once an hour per device). `sweptAway` reads sensor-active's `nmap` `mac` observations: a change of what the sweep sends, or a sweep pass longer than 72 h, changes what is dropped. Shortening `ipTrust` below the sweep's period would drop a live device's facts. Having version scans and SNMP send the MAC they saw would confirm addresses directly (follow-up, sensor-active).
- **agent-intake** sends `Agent` + `From` for a report whose connection address the node did not declare; a change of how `keyHit` treats `From` changes whether a moved laptop's facts arrive before its next interfaces answer, and whether a copied node key writes anything.
- **A device added by hand** moves with its MAC and loses its address to another MAC; the scan policy (`declared_by_hand`) and the Devices page read the same `ip` column.
- **The hand-added bind** (`handSeen`, `firstAtHand`, `inv_hand_seen`): a hand-added device known by its address only binds a MAC only when it is the first and only MAC any source saw at that address since the person added it. Loosening it (binding the newest MAC, ignoring private or known MACs, or an agent's) lets a second machine DHCP puts at the address become the approved device with its declared software: wrong CVEs and no new-device alert. **agent-intake** (osquery, Wazuh) hints its reports by address only and sends the card as a `mac` observation: `handClaims` reads that shape, so a change of how agent-intake hints a report (the MAC in the hint, or no card) changes who binds; a software or service list by address only to a hand-added device whose address saw a MAC it did not take is dropped until a person merges. **notify** sees the refusal as an ordinary new device (`inventory.asset.discovered`); the **web** device page shows the pair as `possible_same` with the address `why`. `modules/core/export_policy.go` lists `inv_hand_seen`.
- **`inventory.asset.updated` for a device that lost or changed its address** (INV-35 (5); `claimIP` records it in the outbox, `write` announces it before the write's other events): **sensor-active** cancels the SNMP batch holding it (`snmpChanged`) and the nmap run of it (`checkRun`: the device left the run's address, or `no_ip`), so a device that took the address mid-run never gets a community. Dropping it, or announcing only rows whose fields changed (`RecomputeAsset` does not compare `ip`), sends the credential to the newcomer. **findings** (`match` false: only `MarkPlan`), **notify** (`assetUpdated`: a device line's label follows, as the periodic `followDevices` does) and **honeypot** (a re-apply hint) take one more event per move.

## Modifying: a device's addresses, merge of several devices, split (`addresses.go`, `mergesplit.go`, `inv_asset_address`, `addr_id` of `inv_software_reading`/`inv_service`, `joinAs` keep, `moveAddresses`; INV-57)
- **The one-home rule** is kept by inventory's writers, not by the database across the two places: a new writer of `inv_asset.ip`/`mac` or of an address row must free the address from the other place first (`freeMainIP`, `releaseExtraIP`, `claimRowIP`), or the resolver finds two devices for one address. The selfcheck `inventory.address_has_one_home` and `TestAddresses_*` catch it.
- **sensor-active** reads `AddressMap` and `KnownMACs` (the sweep's known devices) and scans a device at its main address; a sweep that sees another address of a device reaches that device, and a version scan of it is stored under that address (`addr_id`). A change of which sources are `addressBound` changes which readings two interfaces keep apart. Reading the interface table of a device over SNMP (ipAddrTable) would attach its addresses directly; today only a person's merge adds them.
- **findings**: the matcher reads every live reading (INV-54 rule 4), so a merged device with two interfaces read at two releases is matched on both until a scan of each address agrees. A merge folds findings through the lifecycle participants as before (`DeviceMerged`, once per merged device). A split re-creates the moved readings on the new device's lines: the new device's findings are matched afresh, and the old device's finding on a line that lost its last reading closes by the usual rules; a person's decision on it stays in its history but does not follow to the new device (no lifecycle hook moves a finding with a software line to another device).
- **agent-intake**: a split refuses the interface an agent reports from (409 `agent_address`, `agentIfaceOf`): the osquery binding's `agent_ip` and the Wazuh agents' addresses (`Config.WazuhAgents`). A new agent source, or a change of what `agent_ip` records, changes which address a person may split off.
- **web** (`features/inventory`): `DeviceDetail.addresses`, `Service.address`, `DeviceAddress.agent`, `PossibleSame.reason`, `SamePair.reason`, `MergeInput.from` (an array) and `fields`, `MergePreview`, `SplitInput`; the mock (`mocks.ts`) keeps a device's other addresses in `inv_addresses`.
- **`modules/core/export_policy.go`** lists `inv_asset_address` and the `addr_id` columns; **audit labels** `inventory.split` in `web/src/locales/en/core.json`.

## Modifying: possibly the same device, Merge, Keep separate (`samedevice.go`: `PossibleSameAs`, `PossibleSamePairs`, `Merge`, `KeepSeparate`, `strongConflict`, `inv_separate`; `join.go` `joinAs`, INV-34)
- **web** (`features/inventory`): the device page shows `possible_same` with Merge / Keep separate; `why` is shown as is, so its words are the product's. Changing a field or an error code (`not_same_device`, `box_device`) changes `contract.ts`, the mock (`mocks.ts` `samePairs`), `api/openapi.json` and the UI together.

- `DevicesOfKind(ctx, kinds)` (type `KindDevice`: id, hostname, IP, MAC, kind) reads **every** device of the kinds, **with no row limit** (unlike `Devices`, cut at `MaxListed`, newest first): **response** (`responseDirectory` in `cmd/vedette/response.go`) uses it for the never-touch list (router/firewall); adding a limit or changing the order silently makes the oldest gateway fall off the list. A read error must return an error, not a short list.
- Neutral types (`DeviceRef`, `MatchDevice`, `ProductQuery`, `DeviceMatch`, `ManualDevice`) import no module; `cmd/vedette/wiring.go` converts them to each side's gate: **feeds** (`feedsInventory`: `you_have`, `matched_assets`, "I have it"), **findings** (`findingsInventory`: `AssetView`, the matcher input), **mitigation** (`mitigationVendors`: `firewall[].detected`, including the kinds `firewall` and `router`). Changing the meaning of "yes/maybe", the display name (`DeviceRef.Display` = the first software by name, otherwise the kind; findings does not use it for `AssetView.display` but uses `DeviceRef.OS`, then the kind) or the match key would change the "Do you have it?" column, the findings list and the "detected" label of the firewall guidance.
- `AddManualDevice` keeps the event in `Service.pending[tx]` until `Settle`: the caller **must** call `Settle` after every transaction that calls it (feeds does so in `writeDeclaring`), otherwise memory keeps it and the event is never emitted.
- `RematchCVEExcept(ctx, cve, vendor, product, known)`: like `RematchCVE` but skips a device that `known` says has matched; the only caller is `cmd/vedette` `rematchUpdated` (the event `feeds.vuln.updated`), with `known` = `findingKnown` (already has a finding, or has already been emitted for in the same event). Changing the payload of `feeds.vuln.updated` (feeds) → `rematchUpdated` changes with it.
- `RematchAll`/`RematchCVE`/`RematchMany` emit `inventory.match.changed` for **findings** (`OnMatchChanged` recomputes the whole device each time). `RematchAll` and `RematchMany` emit **once per device** (the event's CVE is the device's first CVE); any listener that needs each CVE must reread the device's match (currently only findings listens, and only uses `asset_id`). `cmd/vedette` `findingsFeeds.Vulns` keeps the list by `feeds.Store.MatchStamp`.
