(1) **One mechanism for every chat channel**: Telegram joins Zalo personal in `response`'s confirm-link list (`sendLink`, D-447): when an administrator saves a Telegram approver (or presses **Send again**), notify asks `response.ChatLinkToken` for a token (128 random bits after an 8-hex hint of the person; single use, 10 minutes, hashed with (person, channel, Telegram user ID), one a minute and five an hour per person) and the bot sends ONE message: "<name>: open this link to link your Telegram account to Vedette … <box base URL>/link/telegram?c=<token>". It goes privately to the approver's Telegram user ID when the bot can write to them (they pressed Start in a chat with the bot once), so that only that account receives it; otherwise into the channel's approval chat, addressed by name. The link is bound to the Vedette user: whoever opens it must sign in (normal sign-in with two-step), the page `/link/telegram` asks "Link Telegram account <ID> to your Vedette user <name>?" and only **Confirm** (POST + CSRF) links; another signed-in person is refused before the token is read (403 `other_account`, audit `response.identity_link_refused`), an expired or used link says so and how to get a new one. Opening the page never links; no administrator can link anyone (INV-24). The press-for-a-private-code path of D-191/D-243 is removed (`chat_code` gone), so a press from an unlinked Telegram ID now answers "open the link Vedette sent … or ask your administrator to send it again". The links use notify's `BaseURL` (the box's management address, cmd/vedette `boxBaseURL`), never a hard-coded name; without it the send answers 503 `no_base_url`. (2) **Where the status lives**: the Telegram channel dialog shows each saved approver as Not linked / Sending / Waiting for <name> (sent hh:mm) / Linked, with **Send again**; My account shows the status and the same **Send again** (`POST /response/me/identities/{channel}/code` on a confirm-link channel asks notify to send a new link to the person's own listed ID, `Config.LinkSender`). Audit: `notify.telegram_link_code` per send (never the token), `notify.telegram_unlink` when a save removes or changes a linked approver (their proof is dropped, so naming the old ID again needs a new confirm), `response.identity_link` on confirm. Email approvers keep the mailed code. The code field in My account (email) keeps Confirm disabled until 6 digits are typed: no red error before typing. (3) **2FA setup guide**: under the QR, three steps recommending Google Authenticator (App Store and Google Play links; any TOTP app works): install, tap + then Scan a QR code, type the 6-digit code.
