| D-556 | **A refused Host gets a readable page in a browser; container-only host ports change through a file of the customer's own (MW-doc1, MW-doc2; S-CORE-9, walks 2–3 on byn2).** (1) **421 page.** The Host allowlist (DNS rebinding defence, WP-04b part 2) stays exactly as it is: same test, same 421, nothing routed. Only the body differs: a GET/HEAD outside `/api/` whose `Accept` has `text/html` gets a short HTML page ("This address is not one Vedette answers to", the name the browser sent, normalised and escaped, how to add it: `VEDETTE_HOSTS` + `up -d`, or the Box address of D-465 on the appliance, and a link to `docs/INSTALL-CONTAINER.md` §2). Every other request keeps the JSON `misdirected_request` the interface and scripts branch on. The page does **not** list the names the box answers to: a refused visitor (possibly the rebinding page itself) need not learn them; the name it typed is its own. No script or style (the CSP of `Envelope` allows no inline either). Sources: Vite `server.allowedHosts` answers a blocked host with a plain-text page that names the host and the setting to add it to (https://vite.dev/config/server-options#server-allowedhosts); Django's `ALLOWED_HOSTS` names the host and the setting only in DEBUG and otherwise answers a bare 400 (https://docs.djangoproject.com/en/stable/ref/settings/#allowed-hosts). Chosen: Vite's "name the host and the fix" for the person at the browser, Django's "never echo the configuration" for production. Not chosen: listing the configured names (Vite does not either; it would hand a rebinding attacker the box's names). (2) **Host ports, container-only.** No new variable now: the documented way is a `compose.ports.yaml` of the customer's own with `ports: !override`, last on the `-f` list (Docker Compose 2.24.4 or later, https://docs.docker.com/reference/compose-file/merge/#replace-value; checked with `config` on 5.1.0 and by the walker on 2.40.3), so the four signed release files stay unedited and an update does not overwrite it. `docs/INSTALL-CONTAINER.md` §4 says the consequences read from the code: links keep `:8443` (core takes the link port from `-listen`, `cmd/vedette/boxaddress.go` `baseURL`), `-listen` cannot move (the health check asks `127.0.0.1:8443`), 8444 must stay while the sensors run (their command lines name it), `DOCKER-USER` sees the container port (`--ctorigdstport`, https://docs.docker.com/engine/network/firewall-iptables/), and the self-call guard knows only the fixed ports (`core/netguard` `vedettePorts`). A way to tell core its outside port is deferred (`.ai/deferred/docs-runbook-install-gaps.md`). |
