| D-345 | **Confirmed mitigation packs ship as signed files inside the core image, and the box loads them itself.** The maintainers keep the confirmed packs (D-21) in `content/mitigation/packs/*.json`; the release job signs them (`make release-packs`, minisign, maintainer machine, D-164) into `VERSION` + `packs.minisig` (+ `packs.list`, the signed text for people who check it by hand), and the core Containerfile copies the directory to `/opt/vedette/content/mitigation/`. Nothing is fetched: the packs arrive with the signed software update (D-36), so there is no new outbound flow and no new server (D-81). Until a confirmed pack is added there, a box loads none (an empty directory is not an error; the dev seed `VEDETTE_SEED_PACKS_DB` stays for GUI checks). | D-36 makes the software update the only channel and the confirmed packs part of it; the UPDATES.md "content pack" channel (daily `.tar.zst` download) is superseded by it. Signing the pack set as well as the image keeps the D-21 rule ("only maintainer-confirmed packs") checkable on the box and lets a pack set travel outside an image later (offline bundle) with the same check. Sources: Debian/apt signed Release files (https://wiki.debian.org/SecureApt) — one signed list of file hashes covers every file; Sigstore/minisign detached signatures (https://jedisct1.github.io/minisign/). Not chosen: go:embed into the binary (no signature of its own, and maintainers could not ship packs without a code release step); a separate download channel (contradicts D-36, D-81). | 2026-11-12 |
