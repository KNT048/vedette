# features/ai

Stories: S-AI-1 (several AI profiles, connection test, data-flow disclosure), S-AI-3 (new CVE news, sources fetched by the box), S-AI-4 (level, shared cap and per-profile caps, downgrade, gauge, log, primary/fallback job assignment, the rule "internal data goes only to an internal profile"), S-AI-5 (ask the data with read-only tools), S-AI-6 (every output inside `AiBlock`, no action button).
Slots provided: `cve.panels` (props `{ cve }`), `logs.panels`. Settings: `ai` (order 40, admin). The UI and all text produced by the mock are English only.

- **AI profile** (`AiProfile`): Anthropic, OpenAI, Gemini, OpenAI-compatible (Ollama, vLLM) or custom (name, address, API style OpenAI/Anthropic/Gemini, model, a key that is optional for an internal server, internal or cloud, its own token cap). The key is not stored and not returned; only the last 4 characters (SYS-4).
- **Job assignment**: 9 jobs (explain finding, write mitigation config, ask the data, summarise logs, investigate logs, weekly report commentary, assessment report commentary, CVE news, translate advisory), each with a primary profile and a fallback. `runJob` (mocks.ts) switches to the fallback when the primary does not answer, runs out of its own cap or is excluded by the privacy rule; it records the profile name in the run log and in `AiBlock` (model + profile name).
- **One-click suggestion**: a fast model for bulk jobs, a strong model for jobs that need reasoning; internal-data jobs prefer an internal profile, public-data jobs prefer the cloud (`suggest` in mocks.ts).
- The default address/model of each provider was checked against the official documentation on 2026-11-06 (sources in `AiSettings.tsx`).
- Shared (mocks/stores.ts, added at the end): `aiProfilesStore`, `aiAssignStore`, `aiCandidates(job)`, `aiAvailable(job?)`, `recordAiRun(skill, in, out, target, profile?, fallback?)`; `aiConfigStore.configured` = at least one usable profile (the ai module updates it).
- Own tables: `ai_sample_runs`, `ai_downgrades`, `ai_explains`, `ai_news`, `ai_asks`, `ai_log_digests`. A clean install: no sample runs, no sample digest.
- No money is shown. The "Ask your data" answers are pre-written, but the tables/numbers are computed from `assetsStore`/`findingsStore`.

## Harness (S-AI-7)
Settings → AI assistant has tabs (`?tab=`): profiles, rules, memory, skills, knowledge, connections, hooks. UI in `harness/`, endpoints in `harness-mocks.ts`, tables and the hook engine in `harness.ts` (tables `ai_rules`, `ai_memory`, `ai_memory_suggestions`, `ai_memory_settings`, `ai_skills`, `ai_knowledge`, `ai_knowledge_settings`, `ai_hooks`, `ai_hooks_builtin`; connections moved to core, Settings → Connections: the connections tab only links there; their mock store is `mocks/connectors.ts`). "Ask your data" runs hooks before the AI, on each tool call and on the answer; `AskResult.hooks` names what acted. "Write tools need approval" is locked on. Knowledge status is computed from upload time (uploading, indexing, ready).
