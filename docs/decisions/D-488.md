| D-488 | **"What to do" names the fixed version for this device, from NVD's affected versions (S-MIT-1 (a), walk finding W1-31).** Every finding said only CISA's "Apply updates per vendor instructions" while the story promises "the fixed version + link". Since D-500 the box holds NVD's affected ranges of the KEV CVEs, so `FindingDetail.fixed_in` is computed on GET (`findings.FixedInFor`, no new column, so it follows every NVD refresh) with the matcher's own reading of the device's software: **(1)** version readable and inside a range with `EndExcl` X: "Fixed in X: upgrade <device> from <version> to X or later" (the range of the device's own branch, so FortiOS 7.4.1 in [7.4.0, 7.4.3) gets 7.4.3, not 7.2.7); **(2)** inside a range with only `EndIncl` X: "Versions up to X are affected ... upgrade to a release after X" (NVD names no fixed release and we do not invent one); **(3)** no readable version: the fix of each release line, the line named by the START of its range ("7.0.0" -> "7.0"), newest first, one entry per fixed release, the highest where a line has two ranges, at most 5 then "and N more"; lines whose only range ends at an affected version are counted ("NVD names no fixed release for N more line(s)"), never given a number; a version that is given but unreadable ("7.0.x") gets the same list with its own wording ("cannot read the version"), not "add the version"; **Review rules (Opus review of the first cut):** a number is named as the fix only when it lies OUTSIDE EVERY applicable NVD entry (an iPadOS-only bound 17.7.6 is not a fix for an iPhone whose range runs to 18.3; the answer does not depend on NVD row order); the evidence range quoted by the finding is the widest one containing the version, so it agrees with the fix; software on a distribution OS (Ubuntu/Debian) gets "install your distribution's security updates" and no number, because apt backports fixes under its own versions; of several software rows of one product the most definite answer wins; ranges with bounds Vedette cannot read are skipped. **(4)** no end bound, an exact-version entry, a version outside every range, no NVD data, a closed finding or a failed read: `fixed_in` is null and the page keeps today's text (CISA required action, vendor advisory link). The source is always shown ("NVD affected versions") with "check the vendor advisory before you upgrade". A confirmed pack keeps its own fixed-version line; the device line is added above it. Not done: a vendor's own fix naming (Junos "22.4R2", Cisco trains) shows as NVD writes it; backports that NVD lists as separate exact versions are not read; no per-CVE aggregation across a device's findings ("upgrade once to fix 4 CVEs") yet.
