| D-226 | **Ollama on the machine that runs Vedette is reached through `host.containers.internal`, not `localhost`; no exception for the rootless address, no `extra_hosts` (ai, S-AI-1, walk 2).** Core runs in a container on every install (the appliance is a rootful Podman Quadlet on the `vedette-int` bridge, the container-only install is compose), so `localhost` is the core container. (1) The OpenAI-compatible profile defaults to `http://host.containers.internal:11434/v1`, which rootful Podman points at the bridge gateway (a private address the internal-profile dialer accepts). (2) The hint says per install what works: install.sh / rootful Podman → `host.containers.internal`; Docker on Linux → the machine's LAN IP (Docker Engine adds `host.docker.internal` only with `extra_hosts: host-gateway`, which the shipped compose does not have and `deploy/compose/compose_test.go` keeps out on purpose; Docker Desktop has it); rootless Podman → not reachable (pasta maps the host to 169.254.1.2, which the box refuses as link-local — the metadata-service range stays forbidden, INV-3 dialer — and the LAN IP is refused inside the rootless netns), so Ollama runs on another machine. (3) Ollama must listen beyond localhost (`OLLAMA_HOST=0.0.0.0`) and has no sign-in, so the hint says to let only the Vedette machine reach port 11434. Not chosen: an exception for 169.254.1.2 (it would open the link-local range that cloud metadata services use, for one install mode), adding `extra_hosts` to the container compose (a deliberate deploy change for Kiên's area; the LAN IP already works).
