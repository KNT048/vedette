The tag is for people; nothing downstream reads a tag. Refused: any registry but `ghcr.io/knt048` except a loopback rehearsal (127.0.0.1, [::1], localhost; Linux only; only there TLS verification and the release guards are off), a `-test.` version, a dirty tracked tree, HEAD other than kien's tag `v<version>`, `CONTAINER=docker` (the OCI-archive path would need skopeo/regctl, a new dependency). `images.json` (fixed schema: version, images[service, repo, index_digest, platforms[platform, digest]]) is written only after all four are read back; part C reads it for `cosign attest`. (2) **`release-in`** writes `release.in.json` from `images.json` (strict; a rehearsal's file is refused) and the two SemVer-named `.deb`: index digests, platforms, `size` = largest unpacked platform size of the local list (free-space check only, D-104), `install_modes` appliance+container (D-451), `released_at` empty; `channel` and `rollback.safe` must be given, never defaulted; an existing file is never overwritten. (3) **`release-publish`** re-runs the box's verifier, records each file's SHA-256 and size, verifies again and compares (so the record is of verified bytes; symlinks refused), refuses a `-test.` version, verifies `install.sh` (signed by the manifest's key, trusted comment `file:install.sh version:<v>`, the three baked lines equal to the signed manifest's version and package hashes), checks each `.deb` against the signed manifest, requires the tag; with `PUBLISH=1` the signers must be the production keys compiled into the build (backup key only for a rescue; `-keys-dir` never admits another signer), and the live `index.json` + `.minisig` of the `index` release are downloaded, verified and must equal `RELEASE_PREV_INDEX` byte for byte (mandatory; only `-first-release` with no live index skips it). Then: `gh release create v<v> --verify-tag --draft --notes-file`, re-hash and upload all assets, read back name/size/`sha256` (no digest from GitHub → download and hash) and no extra asset (named with `gh release delete-asset`), anonymous pull of every image digest (`GET https://ghcr.io/token?scope=repository:knt048/vedette-<svc>:pull`, `HEAD /v2/…/manifests/<digest>` with the OCI index and Docker list Accept types; denied → "make the package public", the release stays a draft), `gh release edit --draft=false`, then **last**, after the pull check and the live index are checked again, `index.json` + `.minisig` to the release `index` with `--clobber`, read back. A re-run fills a draft again, compares a published version and never changes it (a bad release is followed by the next version and a `release` revocation). (4) **kien by hand**: tags (AI creates no tag), the one-time `index` release, the ghcr and gh tokens, making the four ghcr packages public after the first push, and keeping GitHub immutable releases off (they would lock the weekly-replaced `index` release). | Draft → attach → publish is what GitHub prescribes for releases whose assets must not change after publication ("immutable releases … assets and associated Git tag cannot be changed after publication"; recommended flow: create a draft, attach all assets, then publish: https://docs.github.com/en/code-security/supply-chain-security/understanding-your-software-supply-chain/immutable-releases, read 2026-11-12) and what `gh release create` does itself when given assets (`gh release create --help`, gh 2.103.3). Sigstore: "you should always sign images based on their digest (`@sha256:...`) rather than a tag … otherwise you might sign something you didn't intend to" (https://github.com/sigstore/cosign/blob/main/README.md, read 2026-11-12), so everything after the push uses the digest the registry returned. `podman manifest push --digestfile` "write[s] the digest of the resulting image to the file", `--all` defaults to true (https://docs.podman.io/en/latest/markdown/podman-manifest-push.1.html). The anonymous pull check is the registry token flow of the OCI distribution API that a box's podman uses. Top-tier practice measured on 2026-11-12: Rancher's GitHub release v2.15.3 carries `rancher-images-digests-linux.txt` and `images-digests-sha256sum.txt` beside the images (`gh release view --repo rancher/rancher`), i.e. the digest list is a release artifact as `images.json` is here; Home Assistant publishes `ghcr.io/home-assistant/home-assistant:<version>` as one OCI index with amd64 and arm64 (`podman manifest inspect`), as ghcr + one index per version does here; Grafana ships its `.deb` packages per architecture as release assets (v13.3.1).
