| D-215 | **Notify keeps its history 1 year; a Housekeeping job `retention` deletes the rest (BEFORE-V1).** (1) `notify_send` by `at`, `notify_incident` only when `resolved` by `handled_at` (else `last_seen`), `notify_notice` by `created_at`: older than 365 days is deleted, hourly, also while the module is off (D-160: it deletes data past the retention the product states, opens no route or connection). (2) Safe by rule, not by age: an incident that is `new` or `acknowledged` is open work and is never deleted; `notify_pending` (undelivered queue) is never touched; a notice is kept while a queued message names it or a send newer than the cut still covers it (a resend of an old notice), so no notice row disappears under a message that can still be shown. (3) One audit row `notify.retention` per run that deleted something (counts only, no content); a run that deletes nothing writes none. Alternatives: delete open incidents after N years (rejected: an unhandled incident is a customer to-do, not history), prune `notify_send` by row count (rejected: DATA_MODEL states time).
