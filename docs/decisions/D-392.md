| D-392 | **A failed software update check is kept and shown (S-CORE-2; update-manifest §12, §13; D-388).** (1) `UpdatesState.last_check_error` `{at, code, message}` or null: `code` is `update_source_unreachable` or `update_check_failed`, `message` is the box's own fixed sentence for that failure (the message of the 503/502 answer of `POST /core/updates/check`); text received from the network never reaches it (it is only logged). (2) It is stored in `core_setting` `core_updates` after every check that fails with one of those codes (page or periodic job), cleared in the same write that moves `last_check` after a whole good check, kept by a change of channel or mode and by a rollback, and left as it was by a cancelled request. (3) The Updates page of both install kinds shows "Last check failed <when>: <reason>" under the last good check; a container-only box that never had a good check stops guessing the cause. (4) The automatic mode installs nothing while it is set, also after core restarts (before: only an in-memory flag, so a restart forgot the failure and only the 6 h 40 min age rule remained). | A check that silently fails looks like "up to date": the administrator must see that the box is blind, and why, without reading the core log.
