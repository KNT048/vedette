| D-548 | **An installed version the device's own agent reports inside the affected range is a detection: the page says "Detected by the agent", the evidence says what the agent reports and the build that fixes it, and "How to check it yourself" asks nothing Vedette already has; "Confirmed" keeps meaning a safe scan template saw it. The agent's enrolment host name names the device until its system_info answer arrives (customer walk 3, TUNE-5b W-1/W-2; findings INV-2/INV-17, mitigation `genericRecheck`, agent-intake INV-21; S-MIT-1, S-SCAN-3, S-INV-4).** (1) **Why.** A Windows Server 2025 VM enrolled with osquery reported build 10.0.26100.1742; its 44 findings said "Suspected … no scan has confirmed it yet, so this is only suspected" and "Check which version … in its About screen". Agent-based products treat an installed-build match as a finding, not a guess: Qualys reports authenticated/agent detections as *confirmed* and only unauthenticated ones as *potential*; Defender Vulnerability Management lists the device as exposed from its own inventory; Tenable's agent plugins report from the installed version. (2) **Rule.** A version match (basis version) on a software row whose source is `agent` (osquery, Wazuh, the box's own package list), including the distribution path (D-516), sets `evidence.agent`; its sentence is "The agent on WIN-LAB reports Windows Server 2025 build 26100.1742. Microsoft fixed CVE-… in build 26100.2314 (NVD: …), so this device has the flaw until it installs that monthly update or a later one." (other software: "The agent on X reports OpenSSL 3.0.2 installed. That version is inside the range NVD lists as affected by …"; a package: "… installed from Ubuntu 24.04's packages. Ubuntu fixed … in …, so this device has the flaw until it installs Ubuntu's security updates."). A repeated match of the same basis (never scan) brings its evidence, so findings written before take the new words at the next match (reconcile runs hourly). The status stays `suspected` in data: INV-2 and the table's CHECK keep `confirmed` for a scan template's proof, and filters, alerts and counts are unchanged; the chip reads "Detected by the agent" (title explains), the page heading "<device> has <CVE>: its agent reports an affected version", the status filter "Suspected or detected". "How to check it yourself": "Nothing to look up: the agent on <device> reports the installed version …", then install the update, the agent reports the new version by itself (usually within two hours) and Vedette closes the finding by itself (D-530). (3) **W-2.** The device was named after its network card's maker ("QEMU virtual NIC", passive OUI) although osquery gave its host name at enrolment. Until the node's system_info answer reaches the inventory, each written log also records the enrolment's `host_details.system_info.hostname` as an agent `hostname` observation at 0.9 (below system_info's 0.95), so the agent's name wins over any sensor's guess (inventory INV-1 source rank) and system_info's own value replaces it.
