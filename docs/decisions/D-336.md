| D-336 | **A pre-approved rule never acts on its own on a known-bad connection that names a domain only, or with an action on the device the hit names.** A hit is read from a syslog line, which any LAN host can forge over UDP, and a domain seen in a DNS- or web-filter line is attributed to the line's `srcip`, so a DNS forwarder or a proxy becomes "the device" of every client behind it (D-213). `heldForAuto(ev, rule actions, recs)` (engine.go, replacing `forgeable`) keeps such a request pending with the reason in the log ("pre-approval not used, …"): `dest_kind` ≠ `ip`, or the rule puts `{{trigger.src_ip}}`, `{{trigger.device}}` or `{{trigger.switch_port}}` into any value (inside text too), or a fixed value is the hit's address, device name or switch port. Everything else a pre-approved rule may do (INV-5: low risk, undoable, ≤ 24 h) still runs without a person when an address hit arrives, which is what S-RESP-3 promises ("IOC match → block the destination"); since the hit can be forged, the admin should keep such rules to the destination. The destination of an `ip` hit must be a public address (a feed listing private space must not make a rule block a LAN host).
