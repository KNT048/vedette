# Honeypot — Change Impact Map

> Go code: package `modules/honeypot`. Actual signatures: `Service.Hits(ctx, HitFilter) ([]Hit, error)` (each row has `IsTest`, `SourceIP()`), `Service.Overview(ctx)`, `Service.TrapIPs/AddTrapIP/EditTrapIP/SetTrapIPEnabled/DeleteTrapIP`; entry ports: `Inventory`, `Host`, `Logs` (optional), `Publisher`. Differences from DATA_MODEL 4.7: `src_asset_id` is not stored (looked up by IP at read time, INV-8), the token password is in `core_secret`, the table `hp_trap_ips`, `hp_ignored_day`, the columns `conn_key`, `conn_count` (the number of connections in the hit's 10-minute window). When changing columns of `hp_*`, also edit `modules/core/export_policy.go` (which columns are exported).

## Modifying: `Hits(ctx, HitFilter) ([]Hit, error)`, `Hit`, `ExportHits`
- **web/features/honeypot** (`GET /honeypot/hits`, `?asset=`; `HitPage.tsx`, `DevicePanel.tsx`): `Hit` is the contract; changing it → regenerate OpenAPI + edit the mock. `Hit` has `trap_ip`, `trap_hostname` (the Trap IP column of the hit table); readers that go through JSON do not break.
- **response**, **notify**, **inventory**, **logs** do not call `Hits`: they receive hits through the `honeypot.hit.created` event (section below); a test hit does not emit an event, so it never reaches them.
- **core/logs export** (`/core/logs/export?categories=honeypot`): `Service.ExportHits` reads the columns of `hp_hits` directly (`hitCols`, `events` is JSON, no `conn_key`), registered in `cmd/vedette/logexport.go`; changing a column → the downloaded file changes; offline hash verification is not affected (hits have no hash chain).
- **notify** (`cmd/vedette/notify.go` `notifyHits`, `HitConnections`): reads the `id` and `conn_count` of the hit through `ExportHits` so the trap incident shows the number of connections; renaming a column or dropping `conn_count` from the export → the connection count on the incident is wrong.

## Modifying: `Service.Tokens(ctx)`, `MaskTokens`, `GET /honeypot/tokens`
- **web/features/honeypot** (`Tokens.tsx`, mock + MSW): in `Tokens.tsx` the viewer sees what the API sends (`password: ••••••••xxxx`); the mock masks for a viewer exactly as the handler does. `Tokens(ctx)` returns the full password for internal callers (`token()`, tests); only the handler masks, by the role of the principal (operator, admin: full). A new reader of `Tokens` that leaves the module must go through `MaskTokens` unless it is operator-only. The `hits` export (`ExportHits`) never carries the password.

## Modifying: `Service.Disable`, `Service.EnsureOff`
- **cmd/vedette** (`honeypotEnsureOff` → `moduleWiring.EnsureOff` → `modreg.OffGuard`): called at start with the module off and after each switch-off, retried with backoff until nil; the run loop's own `Disable` on cancel stays (same lock as `Apply`, `applyMu`). `Disable` returning nil means the host confirmed; an error keeps the host status at "turning off". Changing `EnsureOff` to return nil early leaves traps listening after a failed teardown.

## Modifying: the `honeypot.hit.created` event (`HitEventData`) — 4 receivers
- **notify** (`modules/notify/events.go` `hitEvent`): the content of the alert (source IP, source device, 1 hour of events). It also reads `kind`, `decoy`, `src_asset_id`, `src_name`: `kind=scan` → **one** High incident per source (target `scan`), everything else Critical; when the source device has a name the incident records it (the Device column). Renaming `kind`/`src_name` → scans become repeated Critical incidents by label, and the incident loses the device.
- **response**: the `honeypot` trigger source: `modules/response/events.go` `honeypotEvent` reads `id, ts, kind, src_ip, decoy, src_asset_id` through JSON; renaming or changing the meaning of a field silences honeypot rules (test `TestHoneypotHitEvent`, `cmd/vedette` `TestResponseHoneypotHitFiresTheRule`).
- **logs/siem** (`modules/logs/siem_run.go`): the `honeypot` channel forwards to the SIEM (S-LOG-3).
- **inventory** (`cmd/vedette/wiring.go`): reads `src_asset_id` and then `EarnReview` on the source device; renaming `src_asset_id` → a device that touched a trap no longer gets queued for review.

## Modifying: `Overview(ctx)`, `TrapIPs(ctx)` and the Trap IP commands — GUI + host
- **web/features/honeypot**: `HpOverview` is the contract; changing it → regenerate OpenAPI + edit the mock.
- **host**: the commands `decoy_ip.add/set_ports/remove` and `container.start/stop` (service `honeypot`) receive a checked IP, the vendor's `oui` and the service `ports` (host-api 6.6); changing the format → the Trap IP cannot be built, `conflict`/`failed`; dropping `ports` → every address answers on every service (the old bug returns). When the port `Host.AddDecoyIP(ctx, ip, DecoySpec)` changes: the adapter, `notAnAppliance` and `fakeHost` change in the same round. The `Host` adapter in `cmd/vedette/honeypothost.go` (CONTRACT "The `Host` adapter on the `core` side") compares against `decoys` of `GET /v1/state/net` and sends only the difference: `syncIPs` calls `AddDecoyIP` for every IP on each `Apply`, and sending them directly would make 32 decoys hit the host's cap of 10 write commands/minute. Changing the `Host` signature (such as `StartContainer(ctx, restart)`) requires changing the adapter, `notAnAppliance` and the test's `fakeHost` in the same round.

## Modifying: the container network (namespace `vedette-hp`)
- **host** (Quadlet unit, `decoy_ip.*`): the container joins a namespace owned by the host (`Network=ns:/run/netns/vedette-hp`), the MAC of each IP is generated by the host, egress is blocked with nft inside the namespace, `DropCapability=ALL` thanks to `ip_unprivileged_port_start=0`. Switching to a Podman macvlan network or one container per IP is wrong by design (one IP per attachment, and a restart would be needed); adding a `vedette-int` leg reopens the path to `core` that was removed.
- **honeypot image**: OpenCanary must run with no capability on low ports (relying on the namespace's sysctl) and without needing outbound network. The image must contain `/vedette` (a static binary, 0755): `HealthCmd=["/vedette","honeypot","healthcheck"]` (exec form) reads the ports from `opencanary.conf`, so the keys `<service>.enabled` and `<service>.port` of `RenderConfig` are a contract with it (test `TestFirstTrapPortReadsWhatRenderConfigWrites`). **The host adapter (`cmd/vedette/honeypothost.go`) must call `container.start` with `restart: true` whenever `opencanary.conf` changes** (`Service` sets the `restart` flag): the health check reads the file on disk, but OpenCanary reads it only at startup, and `container.start` does nothing to a healthy container without `restart`.

## Modifying: the two shared directories under `-honeypot-dir` (`config/`: `opencanary.conf`, `honeytokens.json`; `log/`: `opencanary.jsonl`)
- **honeypot container**: `config/` is mounted **read-only**, `log/` is mounted writable (with the right owner/permissions for the container's user); `log/` is a tmpfs volume of 64 MiB / 1024 files (`vedette-hp-log`), and changing it means changing `host/ops/quadlet.go` and DEPLOYMENT §6.1; `opencanary.conf` points to the log's absolute path, so `log/` must be mounted at the **same path** in the container (or change `Config.LogDir`). Changing the file name, the log line format or the rotation flag (`RotatingFileHandler` 10 MiB × 3) → hits do not get in or the log grows. Golden test `testdata/opencanary.golden.json`.
- **cmd/vedette**: the `-honeypot-dir` flag is the parent directory; the two subdirectories have fixed names `config`, `log` (`HoneypotConfigDir`, `HoneypotLogDir`).

## Modifying: `Service.DecoyIPs(ctx) []netip.Addr`, `DecoyIPsRead`, `TrapIPAddrs`, `ExpectedMACs`, `TrapIPSince`
- **cmd/vedette** wires them into: `core/conn` (`BoxAddrs`), the `core` network page (`AddressInUse`: the box's address is not allowed to equal a Trap IP, `wiring.go`), `SelfAddrs` of `feeds`, `notify`, `logs`, `ai` (`ownaddr.go` `vedetteSelf`) and of `response` (`DecoyIPsRead`, `response.go`): a webhook or a call to a Trap IP is rejected, because it would become a trap hit; changing the meaning → the box calls its own trap.
- **inventory** (through `inventory.Config.BoxOwnedIPs` and `BoxDecoyMACs`, wired in `cmd/vedette/inventory.go`, read when needed because honeypot is built after the store): an observation whose IP is in the list does not create/update a device, and `ProtectedIPs` (hence `sensor-active`) lists them. Changing the meaning (the IPs handed to the host in the most recent `Apply`, read from `hp_config.applied`) → ghost devices appear in the store (the trap causes its own `conflict`) or `sensor-active` scans a trap IP. Empty when the host is not an appliance.

## Modifying: `Service.TrapConflicts()`, `Stats()` — no GUI yet
- The reason an IP is excluded (a device, the box's IP, outside the LAN, the host refused, more than 32) reaches the GUI through `TrapIP.reason` and `Overview.Problem`; the full list and the counters (`Implausible`, `Suppressed`, `NotRegular`, `SkippedBytes`) exist only here and in the log (changing the GUI is a new story).
- `Trap.state`/`TrapIP.state` `listening` reads `hostCache.placed`: changing the meaning of `placed` (the IPs the host confirmed at the most recent `Apply`) makes the GUI say "Listening" for an IP the host does not hold, or "failed" for a Trap IP that is listening.

## Modifying: `Config.BoxURL`, the `url` token type
- **cmd/vedette** (`honeypot.go`): `BoxURL` = `deps.BaseURL` (the Box address of Settings → Box network). Removing the wiring = a URL token carries the store's box IP on 8443 (not following the Box address the user set). The GUI/mock (`honeypot/mocks.ts`) uses `boxAddress()` of `mocks/network.ts`; 409 `no_box_address` has the same sentence.

## Disabling this module
- The Honeypot page and the trap panel on the device page are empty ("module is off").
- `response`: the `honeypot` trigger and the templates `tpl-trap-*`, `tpl-sweep-vlan` no longer get events; rules are kept, with no error.
- `notify`: no more trap-touch alerts. `logs/siem`: the `honeypot` channel has no records.
- The `honeypot` container stops, and the Trap IP addresses are removed. `hp_*` is kept; turning the module back on shows the history again.

## Modifying: the optional parts of `Host`, the OUI table, the Trap IP state, `ErrHostBusy`
- **Optional `Host.DecoyLinks(ctx) map[netip.Addr]DecoyLink`** (S-HP-1): `cmd/vedette/honeypothost.go` reads it from the same `state/net` call as `held` (MAC, link `vdh<8 hex>`, the management card); removing it means the GUI does not show MAC/vendor/link, and nothing else changes. **Optional `Host.KeepsPorts(ctx) bool`** (`portKeeper`): false → a listening Trap IP notes an old host and `open_services` = every service that is running.
- **content/oui** (table, data): the module reads it to produce `mac_vendor`; changing the table → a different vendor is shown (the test `TestVendorOUIsBelongToTheVendor` keeps a vendor's OUIs correct for that vendor).
- `Trap.state`/`TrapIP.state` also have `starting|stopping|failed`: the GUI (`TrapStateChip`), the mock (`features/honeypot/mocks.ts`) and `api/openapi.json` must change in the same round.
- **`ErrHostBusy`**: the host adapter (`cmd/vedette/honeypothost.go` `errHostBusy`) must wrap it for `busy`/`rate_limited`/host busy; without wrapping, after every trap update it shows `failed` "the honeypot container did not start" for ~2 minutes. **cmd/vedette `GET /scanning`** (`honeypotState`) reads `Trap.state` `starting` when no Trap IP is listening yet → the honeypot card is `starting`, not `error`.

## Modifying: `Service.AddToken` rejects `type=dns`
- **web/features/honeypot** (`Tokens.tsx`, `mocks.ts`): the form does not offer DNS (`TOKEN_TYPES`), the mock returns the same 409 `dns_unavailable` and wording; changing the sentence in `msgDNSUnavailable` means changing both the mock and the error-code table in `docs/API_CONVENTIONS.md`. Token presets (`presets.ts` `TOKEN_PRESETS`) only fill fields that already exist and do not touch the API.
- **Old data**: `hp_tokens` rows of type `dns` can still be read and deleted; `TokenDNS` is kept for reading.

## Modifying: `Service.OpenURLToken(ctx, URLTokenOpen)`, `ValidURLTokenID`, `UnknownSource` — 1 caller
- **cmd/vedette** (`honeytoken.go`, wired in `topHandler` at `/t/{id}`): every `/t/<x>` returns the same `404 page not found`; making the answer depend on whether the token exists would reveal tokens to someone probing. Changing the id format (`AddToken`: 10 characters `a-z0-9`) requires changing `ValidURLTokenID` at the same time, otherwise new tokens never fire. The per-address limit: `server.AddrLimiter` (`core/server/publimit.go`), asked only through `URLTokenOpen.RepeatOK` for a repeated open; asking before the token is known would let made-up ids silence a real link. The box itself: `machineAddrs` + `appliance` (`honeyTokenSources`). **response** receives a `src_ip` that is not an IP (`unknown (container-only port proxy)`) and ignores that hit. Hits go through `upsert`/`newIngest` of `ingest.go`: changing their signatures requires editing `urltoken.go`.
- **notify** (`hitEvent`): a `kind=token` hit has the title "<ip> opened the URL token <name>" (reading the `URL token `/`File token ` prefix of `label`, `tokenLabel`); changing `tokenLabel` makes the title go back to "used".

## Modifying: `Service.PollTouches`, the optional `Host.Touches(ctx) ([]Touch, error)`
- **cmd/vedette** (`honeypotHost.Touches` → host `GET /v1/state/hp-touches`): the `Run` loop calls it every `touchEvery` (15 s), 4 reads/minute out of the host's 60. Removing it means a SYN scan (the nmap default) no longer becomes a scan alert; only scans that use real connections remain.

## Modifying: `HitDetail(ctx, id)`, `SourceConnected(ctx, src, at, window)` — caller: `cmd/vedette` `responseIncidents`
- Respond on a trap incident (`response`) reads the source from `HitDetail` (`SrcIP`, `SrcAssetID`, `IsTest`, `Kind`, `NoHandshake`) and, for a `scan` hit or a UDP hit (`NoHandshake`), asks `SourceConnected`: is there a real (non-test) `service` hit **over TCP** (`handshake = 1`) from the same `src_ip` within `at ± window`. Read only. Changing `kind`/`src_ip`/`ts` of a `service` hit, or letting the flow that creates `scan` also create a `service` hit from an attempt with no handshake → response treats a spoofable source as confirmed (risk of blocking an innocent machine); returning an error → response returns an error (hands over nothing).
- **Device types**: reads `content/devicetypes` (a leaf package, standard library only). Preset suggestions compare the type it behaves as (`ActsAs`): a virtual machine behaves as a server, a DVR as an nvr.

## Modifying: the services (`types.go` `serviceDefs`, `Services`)
- **API / GUI**: `HpService` in `web/src/features/honeypot/contract.ts` is the enum of `api/openapi.json` and `core/api/oas`; `presets.ts` (`SERVICE_PORT`, `UDP_SERVICES`, `LOGIN_SERVICES`) and `locales/en/honeypot.json` (`service.*`, `serviceHint.*`) name each one. A new service is a row in `serviceDefs`, the enum, those maps, the `hp_hits.service` CHECK in the baseline migration and a real log line in `testdata/opencanary-0.9.10-lines.jsonl`.
- **host**: the allow-list of each Trap IP carries the service's protocol (`ports()`); UDP needs host-api 6.6's `udp` (it has it). The attempt record (`touched`) already counts UDP.
- **cmd/vedette `firstTrapPort`** (the image health check) skips UDP services and reads the banner's port from `tcpbanner_1.port`: renaming a port key in `RenderConfig` breaks it (`TestFirstTrapPortReadsWhatRenderConfigWrites`).
- **deploy/containers + `make honeypot-check`**: `TestHoneypotWriteFixture` writes `https.pem` (key + certificate) next to `opencanary.conf` (all services on); without them OpenCanary cannot start the HTTPS trap (it tries to write a certificate into the read-only image). The check probes every service and wants its log type.
- **notify / response / logs**: read `service`, `port`, `label` as text (no enum): the new values flow through unchanged. A new `label` ("HTTP proxy", "SMTP") appears in incident titles.

## Modifying: `https.go` (the HTTPS trap's certificate)
- **core_secret** (purpose `hp_https.key`): never exported, purge deletes it with everything (a new pair is made at the next Apply). Signing it with the box CA (`cmd/vedette/boxca.go`) would put a certificate browsers trust inside a container an attacker talks to: do not.
- **config/**: `https.pem` (key, then certificate, one file replaced in one rename: never a new key with an old certificate) is readable by the container on purpose (it serves TLS); it is the decoy's own key. It is removed when no Trap IP has HTTPS and when the module turns off (also the purge path, which runs `Disable`); the `core_secret` row goes with every other row on purge and is kept while the module is off, so the trap keeps its certificate when it comes back, as a device does.

## Modifying: `hp_hits.handshake`, `Hit.NoHandshake`, `HitEventData.Unconfirmed`
- A UDP service hit (TFTP, NTP, SIP: `ServiceName.Proto() == "udp"`) is stored with `handshake = 0`: one datagram with any source address makes it. `SourceConnected` and the sweep's forged-note check count only `kind = 'service' AND handshake = 1`; a UDP line never feeds the sweep. Counting a UDP hit as a connection again would let one forged datagram confirm any address (Respond offers "block source", attempt scans lose "may be forged").
- **response**: the event's `unconfirmed: true` makes `honeypotEvent` store field `unconfirmed = "1"`, `heldForAuto` hold the request for a person and the hit draw from `maxScansPerHour`, as a scan. **cmd/vedette `responseIncidents`** sets `IncidentInfo.Unconfirmed` for it unless a TCP connection of the source is near (`SourceConnected`). Dropping the field from the event lets a pre-approved rule run on a forged source.
- **Budget**: new UDP hits have their own `maxUDPHitsPerHour` (20), never the listener's 500/poll and 2000/hour, so a flood of forged datagrams cannot silence real hits for the hour. **notify** still opens a Critical incident per UDP hit (at most 20 an hour).
- **core/logs export**: `handshake` is exported (`modules/core/export_policy.go`).
