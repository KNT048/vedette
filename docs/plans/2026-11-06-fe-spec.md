# Spec FE M1 — GUI hoàn chỉnh trên mock API (D-22)

Lập: 2026-11-06 · Chủ: AI supervisor (kien uỷ quyền) · Áp dụng cho mọi agent làm `web/`.

## 1. Mục tiêu và "xong"

SPA hoàn chỉnh, production-ready cho FE, chạy trên mock API (MSW) cho **mọi story** trong `docs/USER_STORIES.md` (trừ S-MIT-4 là công cụ của người duy trì dự án). Người dùng làm được **mọi việc trong GUI**: không gọi API tay, không SSH, không sửa file. Ví dụ: cách cấu hình FortiGate gửi syslog → GUI hiện đoạn lệnh copy-dán cho FortiGate; khoá AI → nhập trong form; sao lưu → nút tải file.

"Xong" cho một module:
- Mọi story của module có màn hình, nút, trạng thái rỗng/lỗi/đang tải, quyền theo vai, chuỗi giao diện qua i18n (chỉ locale `en`, D-28).
- Mock API đầy đủ: đọc, ghi, validate ở biên (lỗi tiếng Anh nói cái gì sai, sửa sao — D-28), ghi `audit()` mọi thao tác ghi, dữ liệu lưu qua `collection()` nên còn sau khi tải lại trang.
- Test vitest: mỗi trang render + `expectNoA11yViolations()`, mỗi luồng ghi chính, vai `viewer` không ghi được, ít nhất một trạng thái lỗi API.
- `pnpm exec tsc -b` sạch cho thư mục của bạn; `pnpm exec vitest run src/features/<module>` xanh.

## 4. Khuôn một module

```
src/features/<m>/
  index.tsx      export const feature: Feature  (routes, nav, settings, slots)
  mocks.ts       export const handlers = [...]  (tự được gom, không đăng ký ở đâu khác)
  api.ts         hook TanStack Query; queryKey bắt đầu bằng ['<m>', …]
  types.ts       kiểu API của module
  *Page.tsx      export default; mỗi trang mở đầu bằng <PageHeader title="câu trả lời" … stories={[…]} />
  *.test.tsx
  README.md      story ID module phục vụ, slot cung cấp/tiêu thụ
src/locales/en/<ns>.json   (ns = tên thư mục; chỉ tiếng Anh, D-28)
```

- Đường dẫn API: `/api/v1/<m>/…` (handler dùng `${API}/<m>/…` từ `@/mocks/http`). Không trùng đường của module khác.
- Quyền: `guard('viewer' | 'operator' | 'admin')` ở mọi handler; UI dùng `useCan('operator')` để tắt nút, kèm `title={t('common:needRole', …)}`. Cấu hình hệ thống (kênh, AI, module, người dùng, phạm vi quét) = admin; thao tác hằng ngày (duyệt thiết bị, đánh dấu đã xử lý, quét ngay) = operator.
- Validate ở biên: dùng `IPV4_RE`, `CIDR_RE`, `DOMAIN_RE`, `EMAIL_RE`, `NAME_RE` trong `@/mocks/http`; trả `fail(400, code, 'câu tiếng Việt')`.
- Secret (khoá, token, mật khẩu): UI dùng `type="password"`, sau khi lưu chỉ hiện 4 ký tự cuối, không bao giờ trả lại secret đầy đủ từ API (SYS-4).
- Bảng: `DataTable`. Chọn một trong vài giá trị: `Segmented`. Tab chỉ khi có nội dung tab thật (`Tabs`). Form: `Field` + `Input/Select/Textarea`, `Switch`, `Checkbox`, `RadioGroup`. Hộp thoại: `Dialog` + `DialogContent title=…`. Thông báo: `toast.success/error` (sonner). Đoạn cấu hình: `CodeBlock`. Output AI: `AiBlock` (không bao giờ hiển thị output AI ngoài `AiBlock`). Trạng thái: `Chip`, `StatusChip`, `SeverityChip`. Nguồn dữ liệu: `SourceBadge`. Module tắt: `RequireModule` / `ModuleOff`. Ba trạng thái query: `QueryState`.
- Tải file: `download(path, filename)` từ `@/lib/api`; handler trả `new HttpResponse(text, { headers: { 'Content-Type': …, 'Content-Disposition': 'attachment; filename=…' } })`.
- Tải lên file (bundle offline, văn bản đồng ý, CSV): `<input type="file">` đọc bằng `File.text()`/`arrayBuffer()` rồi gửi JSON (tên, kích thước, sha256 qua `crypto.subtle`, nội dung base64 nếu nhỏ). Giới hạn kích thước, báo lỗi rõ.
- "In / Lưu PDF": route in riêng với CSS `@media print`, nút gọi `window.print()`; không thêm thư viện PDF.
- Thời gian thực (quét đang chạy, dừng ngay): mock giữ trạng thái + `refetchInterval` 1000 ms khi đang chạy.

## 5. Ngôn ngữ và thiết kế (rút từ FRONTEND.md — rớt review nếu sai)

- Tiếng Việt thường, động từ rõ ("Gửi thử", "Áp dụng", "Đánh dấu đã xử lý"). Dòng đầu mỗi trang là câu trả lời ("3 thiết bị mới chưa duyệt", "Bẫy chưa bị chạm trong 7 ngày").
- Màn trống = hướng dẫn hành động. Lỗi nói cái gì sai và sửa thế nào, không xin lỗi, không "Oops".
- Cấm: emoji, chữ hoa toàn bộ cho nhãn, eyebrow label, "→" cuối nút/link, "A · B · C", "WORD — fragment", mono cho nhãn (mono chỉ cho cấu hình/log/mã), gradient, glass, tím, lưới card giống hệt nhau có bóng, fade-in từng khối, "AI-powered"/"thông minh", chatbox AI nổi.
- Màu chỉ có nghĩa: danger = xác nhận/khẩn, warn = nghi/cần xem, ok = ổn/đã xử lý, off = tắt/không biết; luôn kèm chữ. Một màu nhấn (accent) cho hành động chính.
- Mọi dữ liệu có nguồn và thời điểm. Dữ liệu mẫu có `SampleDataNote` ở đầu trang nếu trang hiển thị dữ liệu thiết bị/khách.
- Không tiền: không hiện giá token hay giá bán (D-6); chỉ đồng hồ token.
- Bảo mật hiện trong UI: quét chỉ trong scope đã xác thực + có văn bản đồng ý (LEGAL §3); Vedette không chặn traffic (PRODUCT §5); AI không có nút hành động trực tiếp (S-AI-6).
- a11y: label cho mọi input, `aria-label` cho nút chỉ có icon, bảng có caption, điều khiển bằng bàn phím, không chỉ dùng màu.
- Responsive: desktop chính; ≥ 375 px đọc được (bảng cuộn ngang trong khung).

## 8. Phân việc

### A1 — inventory (`features/inventory`, ns `inventory`) — S-INV-1, S-INV-2, S-INV-3, S-INV-4
- `/devices`: câu đầu "30 thiết bị, 2 chưa duyệt". Segmented lọc: Tất cả / Chưa duyệt / Mỏng manh / Khai tay. Bảng: tên, IP, loại, hãng + model, hệ điều hành/phiên bản, nguồn + độ tin cậy (SourceBadge), lần thấy cuối. Xuất CSV, nhập CSV (khai hàng loạt, có báo lỗi theo dòng).
- Khai tay ≤3 bấm (S-INV-2): "Khai thiết bị" → ô tìm gợi ý tên thương mại (FortiGate, MikroTik, Synology, QNAP, WordPress, Windows Server, Exchange, Hikvision, Ivanti, Cisco ASA, Palo Alto, VMware ESXi, GitLab…) → chọn (phiên bản tuỳ chọn) → "Thêm". IP không bắt buộc.
- Chưa duyệt (S-INV-3): duyệt / đánh dấu lạ / xoá; tuỳ chọn "Báo khi có thiết bị mới".
- `/devices/:id`: các trường với mọi observation (nguồn, độ tin cậy, thời điểm — không ghi đè, ARCHITECTURE §4), dịch vụ mở, phần mềm, ghi chú, đổi loại, cờ mỏng manh, `<Slot name="device.panels" props={{ assetId }} />`.
- Tab/trang "Phạm vi và cảm biến" (`/devices/setup`, admin): dải mạng LAN (CIDR), cửa sổ quét chủ động (ngày, giờ), tốc độ, loại trừ, loại thiết bị mỏng manh chỉ thụ động, cảm biến (hộp này + cảm biến ở site khác: tạo mã đăng ký một lần, thu hồi, giao diện mạng/SPAN), trạng thái module sensor-passive/sensor-active. Agent (S-INV-4, module agent-intake): tạo token cho Wazuh/osquery/Trivy, đoạn cấu hình copy-dán, lần nhận cuối.

### A2 — findings + scan (`features/findings` ns `findings`, `features/scan` ns `scan`) — S-MIT-1..3, S-SCAN-1..5, S-AI-2, D-21
- `/findings`: câu đầu "3 phát hiện chưa xử lý, 1 đã xác nhận". Lọc trạng thái, `?cve=` từ trang CVE. Bảng: thiết bị, CVE, sản phẩm, StatusChip, mức, cơ sở (quét xác nhận / theo phiên bản / chỉ khớp sản phẩm), lần thấy.
- `/findings/:id` "Làm gì": bằng chứng (S-SCAN-3: tóm tắt, mẫu, request/response rút gọn, cách tự kiểm tra lại); khối khuyến nghị theo D-21: **Vedette đã xác nhận** (người, ngày, "soạn với AI") cho f-1 với (a) bản vá (link khuyến cáo QNAP trong KEV), (b) vá tạm, (c) đoạn cấu hình theo vendor firewall (FortiGate, MikroTik — dùng IP thật của NAS 192.168.10.21; mỗi bước một CodeBlock; lệnh phải đúng cú pháp, có tác dụng phụ và bước kiểm tra), (d) checklist xác nhận; **Chưa có khuyến nghị đã xác nhận** cho f-2, f-3: thông tin gốc KEV + nút "Hỏi AI của tôi" (chỉ khi `aiAvailable()`, kết quả trong `AiBlock origin="customer"`, ghi `recordAiRun`); "Tôi đã bị chưa?" (S-MIT-3: dấu hiệu + lệnh kiểm tra, ví dụ tệp `.deadbolt` cho f-1); tải rule pack (S-MIT-2: Suricata, CRS, CrowdSec, nftables); "Giải thích" (S-AI-2) trong AiBlock; nút "Đã áp dụng" ghi nhật ký; đổi trạng thái (đã vá / đã giảm thiểu / báo nhầm / không liên quan) kèm ghi chú; lịch sử. `device.panels`: phát hiện của thiết bị.
- `/scans` (S-SCAN-1..5): mục tiêu (từ kiểm kê + bề mặt ngoài đã xác thực), "Quét ngay", tiến độ, **"Dừng ngay"** (dừng ≤5 s), lịch, an toàn (cửa sổ giờ, req/s, loại trừ, tự dừng khi thiết bị không phản hồi, bỏ phép thử nguy hiểm — hiện rõ "không khai thác, không DoS"), tự quét lại khi có KEV mới có mẫu (bật/tắt + nhật ký sự kiện), lịch sử lần quét và bằng chứng, nhật ký probe (đích, thời điểm, mẫu; giữ ≥90 ngày). Quét có tài khoản (S-SCAN-5, module scan-credentialed): máy chủ đích, khoá SSH (dán, chỉ hiện 4 ký tự cuối), kiểm tra kết nối.

### A3 — exposure + honeypot (`features/exposure` ns `exposure`, `features/honeypot` ns `honeypot`) — S-EXP-1, S-HP-1
- `/exposure`: thêm domain/IP công cộng → xác thực sở hữu (DNS TXT `vedette-verify=<mã>`, hiện bản ghi để copy, "Kiểm tra lại"; IP: reverse DNS hoặc lưu lượng từ hộp) → bắt buộc văn bản đồng ý (form theo `docs/templates/consent-scan.md` + tải lên bản ký) trước khi quét. Kết quả: subdomain, IP, cổng mở, giao diện quản trị lộ ra, chứng chỉ sắp hết hạn; ảnh chụp theo ngày, so sánh hai ngày (thêm/mất). Không quét thứ chưa xác thực (nút bị khoá kèm lý do).
- `/honeypot`: câu đầu "Bẫy chưa bị chạm trong 7 ngày" hoặc "2 lần chạm hôm nay". Bật bẫy theo dịch vụ (SMB, RDP, SSH, MSSQL, HTTP), IP phụ (validate, không trùng thiết bị trong kiểm kê), tên máy giả; trạng thái từng bẫy; danh sách lần chạm: thời điểm, dịch vụ, IP nguồn, thiết bị nguồn (link `/devices/:id`), trích phiên; chi tiết: 1 giờ sự kiện quanh đó; loại trừ máy quét của chính Vedette (hiện rõ); "Thử chạm bẫy" tạo một lần chạm thử có nhãn "thử". `device.panels`: lần chạm từ thiết bị.

### A4 — logs + notify (`features/logs` ns `logs`, `features/notify` ns `notify`) — S-LOG-1..3, S-ALERT-1..2, S-NOT-1
- `/logs`: nguồn log (thêm: FortiGate, MikroTik, pfSense/OPNsense, Windows, Suricata; UDP/TCP/TLS, cổng, IP gửi được phép) với **đoạn cấu hình copy-dán cho chính thiết bị đó** để gửi syslog về hộp; trạng thái từng nguồn (nhận lần cuối, số dòng/giờ); digest: "Cái mới so với 7 ngày trước", "Tăng đột biến", "Kết nối tới IP/domain xấu" kèm thiết bị nguồn; tìm sự kiện (khoảng thời gian, nguồn, chữ); lưu giữ (ngày). `<Slot name="logs.panels" props={{}} />`. Cài đặt `siem` (S-LOG-3): đích syslog/CEF/JSON webhook, gửi thử.
- `/alerts`: câu đầu "2 cảnh báo chưa xử lý". Danh sách gộp theo sản phẩm (không gửi CVE không khớp), mức, trạng thái mới / đã xử lý / không liên quan, link phát hiện; chi tiết: nội dung đã gửi (xem trước đúng như tin Telegram/Zalo/email), nhật ký gửi theo kênh. - Cài đặt `channels` (S-NOT-1): Telegram (bot token, chat id), Zalo OA (OA id, access token), email SMTP, webhook (URL + secret); "Gửi thử" từng kênh; định tuyến theo mức; lịch im lặng; gộp tin.

### A6 — core + fleet (`features/core` ns `core`, `features/fleet` ns `fleet`) — S-CORE-1..4, S-MCP-1, S-FLEET-1, cài đặt ban đầu
- `/setup` (publicRoute): lần đầu chạy. ## 9. Lệnh cho agent

- Gõ kiểu: `pnpm exec tsc -b` (chỉ sửa lỗi trong thư mục của bạn; lỗi ở thư mục module khác là do agent khác đang làm — bỏ qua, chạy lại trước khi xong).
- Test: `pnpm exec vitest run src/features/<m>` (không chạy toàn bộ suite — rule agent-safety). Timeout lệnh ≤ 2 phút.
- Không chạy `pnpm install/add`, không `pnpm build`, không git commit, không sửa docs ngoài README module.
- Báo cáo cuối (≤ 25 dòng): file đã tạo, story đã phủ, test đã chạy và kết quả, việc chưa làm/nghi ngờ, yêu cầu với nền.
