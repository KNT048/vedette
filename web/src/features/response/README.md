# features/response

Standalone Response feature. Stories S-RESP-1..4 (+ S-AI-8 log). Decisions D-40, D-41, D-44, D-46, D-47, D-48, **D-51 (wins)**.
Page tabs: Rules (WHEN/IF/THEN builder, template gallery, recent events), Requests (pending/history, rules and AI, AI plans), Block list, Log, Metrics (acceptance, AI budget and quality, rejected requests, preview-only "try an AI request").
Settings section `response` (admin): execution switch, limits, approval channels, safety envelope (circuit breaker, multi-target limit, maintenance windows), AI gates, never-touch list, action catalog by vendor pack.

- Files: `identity.ts` (approver identities: link codes, My account card data, D-191), `contract.ts` (all endpoints), `state.ts` (stores, log, catalog, request lifecycle and gates), `engine.ts` (events, conditions, planning, firing, simulate, templates), `ai.ts` (AI gates, quality breaker, metrics), `data.ts` (trigger catalog, built-in action packs, 15 templates), `mocks.ts` (handlers, AI plans), `logic.ts` (pure: SHA-256, typed placeholders, escape per transport, conditions, connection-kind field rules).
- Tables: `resp_settings`, `resp_plans`, `resp_actions` (bundled requests with `items`), `resp_catalog`, `resp_rules`, `resp_allowlist` (never-touch), `resp_blocklist`, `resp_tokens`, `resp_done`, `resp_ai_notes`, `resp_hints`, `resp_log` (`{ id, ts, kind, actor, detail, prev_hash, hash }`, unchanged hash rule).
- Reads other modules with `peek`: `notify_channels` (approvers), `logs_ioc_hits`, `hp_hits`.
- Gates (server side of the mock, tested): approval by default, pre-approved only for low-risk + reversible + undo <= 24 h (admin), two different approvers for high risk or many targets, typed placeholders from attacker-controlled trigger data, dedupe, per-rule and global circuit breaker, maintenance windows, never-touch list, dry run, simulate executes nothing, emergency stop, expiry 15-30 min, hash-chained log. AI: allowed trigger, "AI may propose" flag, no commands, real evidence, confidence >= 0.8, one open request per (target, action), 7-day repeat block, budget with digest, quality breaker, second checker and in-app two-step code for high risk.
- Custom action form follows the connection kind (API: method/path/body, HTTP adds headers, SSH: command, MCP: write tool + arguments); read-only connections cannot be chosen; the server refuses both.
- ponytail: the rule engine runs on a button in the preview build (a real box runs it continuously); the in-app two-step code is any 6 digits once two-step is on (the core module checks it on a real box); KEV flag in events is "critical" in the mock.
