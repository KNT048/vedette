| D-406 | **Walk 4 fixes on network-supplied names and decoy addresses (S-INV-1, S-INV-3, S-HP-1).** (1) **LLDP system description**: it is free text from any host on the LAN, so the passive sensor never passes it on as a value. A model and an OS come only from a known vendor layout (`modules/sensor-passive/capture/sysdesc.go`: Juniper "Juniper Networks, Inc. ex4200-48t …, kernel JUNOS 15.1R7.9, …" → model `EX4200-48T`, OS `JUNOS 15.1R7.9`; Cisco IOS / IOS XE; HP/Aruba ProCurve; MikroTik RouterOS; lldpd on Linux → OS only), each a short token checked by a character class and capped (model ≤ 40, OS ≤ 64 bytes); a description of up to 40 characters with no comma and at least one digit is taken as a bare model ("GS308T"); anything else gives nothing. Line breaks in the description become spaces before the printable check (Cisco writes several lines). The OS observation of the passive sensor is capped at 0.5, the confidence of the description. The device name stays LLDP sysName (0.7) when the switch sends one. (2) **Source of a device seen only by ARP**: the list's `summary` falls back to the current hostname and MAC observations when there is no vendor, model or OS, so "Unknown 192.168.18.1" says Passive instead of "–". (3) **Unknown-device incident title**: hostname, else "IP (vendor)", else "MAC (vendor)", the kind only when nothing else is known (`DeviceDirectory.DeviceLabel`); the name is clipped so the title stays ≤ 200 characters. (4) **Decoy addresses are never called "spare" from the inventory alone**: the field is "Decoy IP" and the suggestions are "Not seen by Vedette so far: …", followed by what really checks the network (the host's RFC 5227 ARP probe in `decoy_ip.add`, which already runs before any decoy takes an address and refuses `ip_in_use`) and the advice to use an address outside the router's DHCP pool or reserve it there. A live ARP probe of the suggestions before they are shown (a new read-only host command) is left as a follow-up: it is a new command on the privileged host API and adds ~4 s to the page, while the probe that matters, at the moment the address is taken, already exists. (5) Trap switches keep one label ("SSH trap") whose state `aria-checked` gives, like every switch in the app; the empty Trap hits text has a sentence for "a trap is on". | Why: LibreNMS and Netdisco read sysDescr with per-OS regular expressions and show the raw text only in a description field, never as the device name (https://docs.librenms.org/Developing/os/Initial-Detection/); an LLDP description is attacker-controlled on a shared LAN, so a whitelist of layouts is safer than "first clause" heuristics. Decoy address wording: Thinkst Canary takes a static address from the admin and relies on rollback, not on a "free" claim (https://help.canary.tools/hc/en-gb/articles/360012820218-Assigning-a-static-IP-using-remote-management); pfSense/OPNsense advice is that static addresses go outside the DHCP pool (https://forum.netgate.com/post/825647); RFC 5227 is the standard way to check an IPv4 address is unused (https://www.rfc-editor.org/rfc/rfc5227). WAI-ARIA: a switch's name should not change with its state; the state is `aria-checked` (https://www.w3.org/WAI/ARIA/apg/patterns/switch/). | 2026-11-13 |
