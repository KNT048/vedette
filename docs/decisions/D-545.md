Only actions a person can take: `fixed` (a Windows release row: "Install the latest cumulative update for Windows Server 2025 (build 26100.2314 or later)"; any other software: "Upgrade <software> from <v> to <fixed> or later"), `esu`, `feature_update`, `distro` ("Install Ubuntu's security updates for OpenSSL"); `none`/`up_to` (no release named) stay rows. A group needs two or more of the rows shown; one finding is its own row. (2) **Where.** Findings → Open: a notice "N updates each fix several findings" above the table, one line per group (device link, action, count), a disclosure with each CVE (link to its finding, status, severity) and "Handle these N findings in the list" (`?fix=<group>`: the members as ordinary rows, to select and mark them; "Show all findings" clears it). Grouped findings are not rows of the table (and so not in "select all"). The device page lists the same groups before its other findings. Counts (title, KPIs, badge) stay per finding. When every row of the Open list is in a group the table is replaced by "Every unresolved finding in this list is in an update above." (no "No unresolved findings").
