| D-522 | **nmap results are read as nmap means them: TLS comes from `tunnel="ssl"` on any port, an address that answers on almost every port is not 98 services, and a host nmap gave up on is never "no services" (TUNE-1a, tool-tuning plan §1 N1 and N5).** (1) **N1, TLS on any port.** nmap's XML keeps TLS apart from the service name (`<service name="http" tunnel="ssl">`); its text output prints the two together as `ssl/http`. The sensor-active parser now stores that text form (`ssl/<name>`, or `ssl` with no name), so the inventory, exposure and every consumer see TLS without a schema change. The scan's `endpoints()` and exposure's `schemeOf()` choose `https` from the name on any port (FortiGate 10443, Proxmox 8006, Synology 5001, a lab page on 4443); `endpoints()` also speaks only https to a port any source names TLS. The port guess (443/8443/9443) stays in `schemeOf()` only for an `http` row nmap read nothing else about (no product, no version: a row stored before this change). Without it, nuclei, which runs with `-nh` (no httpx probing) and speaks only the scheme core gives it, sent plain HTTP to a TLS port and the row read "No match reported" without the template having checked anything. No packet is added. Every reader of the name was checked: scan endpoints, exposure `schemeOf`, `isWebService`/`isTLSService` (ZAP) and `ServicesPanel` already read `ssl/`; the KEV matcher compares product and CPE, never the name; devicetypes, the inventory list and CSV export show the name as text ("443 (ssl/http)", as nmap prints it); the exposure risky-service labels read the surface scan's port names, not nmap's. (2) **N5 (a), an address that answers on every port.** More than `commonports.MaxBelievableOpen` (40) of the 98 ports open is the shape of an ISP router or a firewall with a SYN proxy that completes every handshake; nmap -sV then reads dozens of `tcpwrapped` rows or runs into its host timeout. Exposure checks the surface scan's open ports first and does not send nmap at all; sensor-active's `externalOf` applies the same bound to nmap's own result (`ErrAnswersEverywhere`, rows discarded, probe row "failed: the address answers on almost every port"). Either way the snapshot gets one "Not checked" line, "This address answers on almost every port (a router or firewall answering for them), so service identification and the template checks were skipped.", no service rows and no template job. 40 is far above what a small office exposes on purpose and far below 98. (3) **N5 (b), host timeout.** nmap prints no port table for a host it skipped at `--host-timeout` (`<host … timedout="true">`), so the external run already returned `ErrHostTimedOut`; it now reaches exposure as `ErrServicesTimedOut` and its own line, "Service identification (nmap -sV) did not finish within 3 minutes, nmap's limit for one address, so no service versions were read. This does not mean no services are open; scan again later.", instead of "did not run: …". The LAN shapes already keep the device's services and software on a timed-out host and say `timed_out` on the scan run (D-501); unchanged.
