| D-397 | **The box's own TLS certificate follows `-hosts` (`VEDETTE_HOSTS`) at start.** At every start of core, when the box's own self-signed leaf (organization `Vedette (self-signed)`) lacks an entry of `-hosts` or the box's name (a DNS name compared without case, an address by value; the container's own addresses of `localNames` do not count), core issues a new leaf for the same key, **from the same box CA**, that keeps every name and address the old leaf had and adds the missing ones, and logs `the self-signed certificate was re-issued for the names of -hosts or the box name it did not cover` with them. On a container-only install a name dropped from `-hosts` stays in the certificate but gets 421 (the Host allowlist is `-hosts`); on an appliance the address-driven re-issue of `selfSignedRenewer.Check` (D-139) may drop it again, which is equally harmless. A certificate the owner supplies (`-tls-cert`, or another organization in the box's files) is never touched. Like the upgrade under the CA (D-262), it is optional: a CA that cannot be read or a directory that cannot be written keeps the leaf in use, with a warning. `cmd/vedette/tls.go` `reissueSelfSigned`, `uncoveredHosts`; `TestEnsureCertReissuesForANewHostsEntry`. | Mac walk 4 (2026-11-13): INSTALL-CONTAINER §2 says to change `VEDETTE_HOSTS` and run `up -d`; the new name then passed the Host check but its TLS failed (curl "no alternative certificate subject name matches") and so did the pinned osquery installer, since the leaf kept the names of the first start. The CA stays so that agents pinned to it (D-262, agent-intake) keep working. Sources: Caddy's internal issuer keeps its local root and issues a leaf for each name it is asked to serve (https://caddyserver.com/docs/automatic-https#local-https); kubeadm adds SANs to the API server by issuing a new serving certificate from the same cluster CA (https://kubernetes.io/docs/tasks/administer-cluster/kubeadm/kubeadm-reconfigure/). Not chosen: a doc line "delete the certificate in the volume" (a hand step the next owner forgets; a new key would also break nothing but is not needed); a new CA (every enrolled agent would need its install command again); dropping removed names (a bookmark would break for no gain: the allowlist already refuses them). | 2026-11-13 |
