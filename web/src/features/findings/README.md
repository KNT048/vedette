# features/findings

Module `mitigation`. Story: S-MIT-1 (What to do: patch, temporary workaround, FortiGate/MikroTik/generic firewall configuration, checklist, "Applied"), S-MIT-3 ("Have I been hit?"), S-SCAN-3 (evidence + how to re-check by hand), S-AI-2 ("Explain" and "Ask my AI" inside `AiBlock origin="customer"`).

- Findings live in the shared `findingsStore` (seed: `src/mocks/seed/findings.ts`); the finding page (`GET /findings/{id}`, "Applied", the AI answers) also reads the findings model's rows (`modelMocks.ts`), the ids every list links to. Confirmed packs and signs of exploitation are signed project content (packs.ts, not stored); own table: `mit_ai_outputs`.
- A confirmed Vedette pack (drafted with AI, confirmed by a maintainer through a GitHub PR) exists only for CVE-2022-27593; every other CVE currently shows "No confirmed recommendation yet" + the original KEV information + "Ask my AI". Pack content is server data (English); `{IP}`/`{HOST}` are replaced with the real device.
- Provided slot: `device.panels` (props `{ assetId }`). Consumed slots: none.
- Screen `/findings` (findings model API, `modelMocks.ts`, `possibleMocks.ts`): tabs By device (default), By fix, AI proposals (while some wait), Handled, Ignored devices; one status filter (`?status=`) over By device and By fix; `?device=` narrows By device and Handled. By device and By fix end with the possible findings (`Possible.tsx`, `GET /findings/possible`): the CVEs Vedette cannot decide, counted apart from the open findings, by device or by software and version, each software line with the one input that decides it and each CVE with its reason and answers; "Check N possible" (`POST /findings/possible/check`) reads the vendor advisories first and leaves AI proposals for the rest (`Proposals.tsx`: confirm one, confirm a group, reject). The device page's Findings tab shows the device's possible findings, what a check settled not affected, and the answers given. Mark as handled… is one dialog (`HandleDialog.tsx`) acting on findings of one device (`POST /findings/handle`, by ids or by device and fix). `/plan` redirects to the update-recommended findings by device. Older query shapes (`?tab=open|accepted|input`, `?tab=fix&device=`, `?cve=`, `?by=fix`) are rewritten on load.
- Routes: `/findings`, `/findings/:id`; links out to `/scans?target=<assetId>` (the device with "Check this device now", #850), `/devices/:id`, `/settings/scanning`, `/cve/:id`, `/settings/ai`.
- item 14: "I updated <software>" (`Updated.tsx`, `rematch.ts`) on the finding page and the device panel: manually declared software → `PATCH /inventory/devices/{id}/software/{sid}`, then re-read `GET /findings?asset=` until the re-match shows (up to 12 times, 500 ms), saying how many were closed; software read by a scan → tell the person to scan the device. The software of a CVE comes from `kev_cves` of `GET /inventory/devices/{id}`.
