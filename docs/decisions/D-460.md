| D-460 | **The release gates keep a record, and every later step ships only what it names; a rehearsal is as strict as a release (WP-08k).** (1) The final `release gates` run (`make release-gates`, step 3) writes `dist/release/gates.json` only when every check passed: the version, the floor, per `.deb` arch its file name, SHA-256 and size (the bytes compared with the rebuild), per image and platform the **config digest** (podman's image ID), and that digest must also be the image the kept trivy report (`dist/vuln/<local>-<arch>.json`, `Metadata.ImageID`) and SBOM (`dist/sbom/<local>-<arch>.cdx.json`, `aquasecurity:trivy:ImageID`) were made of. `make release-gates` removes an earlier record on its first line, so any failing step leaves none; `-preflight` writes nothing. The config digest is chosen over the local manifest digest because the rest of the chain already uses it (push compares a list already in the registry by it, `images.json` records it, part C requires the SBOM's ImageID to equal it); a re-read of the same list gives the same one, a rebuild another. (2) `release push` (all four lists checked before anything is pushed, and each list read again after its own push), `release in` (each `.deb`, `images.json` and the local lists) and `release manifest` (the `.deb` hashes the manifest names, so bake-install and publish inherit it) read it strictly and refuse a missing record, another version or other bytes: "run make release-gates again". (3) A rehearsal against a loopback registry gets no bypass and no rehearsal record: a real SemVer version tagged locally in a scratch clone, steps 1–3 with `MIN_SEQUENCE=0`, then `release-push REGISTRY=127.0.0.1:<port>`; `-test.` is refused there too. This replaces the rehearsal part of D-457 ("only there TLS verification and the release guards are off": now only TLS verification and the git checks are). | A `make images` or `make host-deb` between step 3 and steps 4–8, or during the scans of step 3, would otherwise ship bytes the gates never saw (Opus review of #614, M; review round 1 of this branch, M1–M3). Leading practice binds every later step to the digest that was checked: SLSA's verification step is "Verify that statement's subject matches the digest of the artifact in question" (https://slsa.dev/spec/v1.2/verifying-artifacts; Build L3 requirements https://slsa.dev/spec/v1.0/requirements, opened 2026-11-12, v1.0 page marked retired in favour of 1.2); cosign attestations name the image by its sha256 digest in the in-toto subject (https://docs.sigstore.dev/cosign/verifying/attestation/, opened 2026-11-12); GoReleaser builds once and signs the artifacts and checksums of that same run before uploading them (https://goreleaser.com/customization/sign/, opened 2026-11-12). A rehearsal bypass would be a second path that ships without the gates; the lead chose strict over convenience. Plan: `docs/plans/2026-11-12-wp08k-release-job.md`. | 2026-11-13 |
