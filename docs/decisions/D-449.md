| D-449 | **The Email channel signs in with every common provider: presets, SMTP AUTH PLAIN/LOGIN, OAuth2 (XOAUTH2/OAUTHBEARER) for Microsoft 365 and Google Workspace without a browser; Gmail personal uses an app password (notify; S-NOT-1; kien 2026-11-13).** (1) **Presets** (`web/src/features/notify/emailProviders.ts`; the box knows only how each signs in, `channel.EmailAuth`): Custom SMTP; Gmail `smtp.gmail.com:587` STARTTLS, address + app password; Yahoo `smtp.mail.yahoo.com:465` TLS, app password; iCloud `smtp.mail.me.com:587` STARTTLS, full address + app-specific password; Zoho `smtp.zoho.com:465` TLS (paid org domains `smtppro.zoho.com`, other data centers: the server Zoho shows), password or app-specific password; Fastmail `smtp.fastmail.com:465` TLS, app password; SendGrid `smtp.sendgrid.net:587` STARTTLS, username literally `apikey`, password an API key; Mailgun `smtp.mailgun.org:587` STARTTLS (EU `smtp.eu.mailgun.org`), the domain's SMTP credentials (not the API key); Amazon SES `email-smtp.us-east-1.amazonaws.com:587` STARTTLS (region in the name), SES SMTP credentials (not AWS access keys, one region); Postmark `smtp.postmarkapp.com:587` STARTTLS (465 not offered), the server API token as username and password (never stored as a field); Brevo `smtp-relay.brevo.com:587` STARTTLS, SMTP login + SMTP key; Microsoft 365 `smtp.office365.com:587` STARTTLS (Microsoft: 465 lacks the TLS versions it requires), OAuth2; Google Workspace `smtp.gmail.com:587` STARTTLS, OAuth2 service account. A preset fills host, port and encryption; they stay editable. (2) **SMTP AUTH**: PLAIN if offered, else LOGIN; with OAuth2 XOAUTH2, else OAUTHBEARER (RFC 7628); on a refusal the client answers the server's JSON challenge (empty line, or `%x01`) and the 535 comes back. The SASL code refuses to start on a connection that is not TLS, on top of the existing STARTTLS-required (587) and implicit TLS (465) rules; D-446 and the errors-under-the-field table stay. (3) **Microsoft 365**: client credentials to `https://login.microsoftonline.com/<tenant>/oauth2/v2.0/token`, scope `https://outlook.office365.com/.default`; fields tenant ID (GUID or domain, the only configured part of the URL), client ID (GUID), client secret (the channel secret), mailbox (username). The dialog lists what the admin does once (SMTP.SendAsApp + admin consent, client secret, `New-ServicePrincipal` with the Enterprise application's Object ID, `Add-MailboxPermission … FullAccess`, SMTP AUTH on for the mailbox) with the doc link. Microsoft is ending Basic auth for SMTP AUTH (off by default for existing tenants at the end of December 2026), so the preset has no password mode. (4) **Google Workspace**: service account key file (JSON, the channel secret; only `type`, `client_email`, `private_key_id`, `private_key` read; `token_uri` ignored, the endpoint is fixed), RS256 JWT bearer grant (RFC 7523) with the Go standard library to `https://oauth2.googleapis.com/token`, `sub` = mailbox, scope `https://mail.google.com/`, one hour. (5) **Tokens**: fetched before the SMTP session opens (no session when the token service refuses), cached in memory per service until 5 minutes before expiry (key = hash of method, tenant, client, mailbox and secret), dropped when the SMTP server refuses it, never logged; token answers bounded (64 KiB, token ≤ 8 KiB printable ASCII), redirects never followed. Refusals are fixed sentences per OAuth error code (`invalid_client`, `unauthorized_client`, `invalid_grant`…); the provider's `error_description` and the SMTP server's text after an OAuth AUTH are never shown or logged. A saved secret is reused only with the same sign-in method (changing method without a new secret → `secret_required`). New codes `bad_provider`, `bad_tenant_id`, `bad_client_id`; `bad_secret` also for a key file or client secret of the wrong shape. (5b) **After the security review**: a saved secret is bound to the sign-in method, the server and the port (`fields.secret_for`, written by the box); changing any of them without a new secret is `secret_required`, or deletes the saved secret when the new configuration needs none ("No encryption"), so a client secret cannot be walked over to a password login in two saves and a password is never sent to a server it was not saved for. The OAuth presets accept only the provider's own SMTP server (`smtp.office365.com`, `smtp.gmail.com`): a `.default` token carries every permission of the app. Google keys are 2048–4096-bit RSA; passwords and usernames with control characters are refused under their field; token fetches are single-flight per key and the token cache is cleared when the email channel is saved or removed. The token requests skip D-446's connect-time check on purpose: their hosts are fixed public names. (6) **Gmail personal: app password, not browser OAuth.** Browser OAuth would need a redirect back to the box, and Google refuses raw IP hosts and non-HTTPS redirect URIs for web clients (the box is usually `https://192.168.x.y:8443`); the copy-paste (OOB) flow is gone since 2022/2023; `https://mail.google.com/` is a restricted scope, so a shared Vedette client would need Google's verification and a yearly security assessment, and each admin's own unverified "Testing" client gets refresh tokens that expire after 7 days.
