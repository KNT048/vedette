| D-615 | **Age rule for every tier (kien 2026-11-15, amends D-613): a CVE published more than 12 months ago is shown only on confirmed evidence; within 12 months the tier rules of D-613 apply.** (1) **kien's words:** "giới hạn mọi cve dù thế nào cung trong 12 tháng … bỏ hẳn cve quá cũ, trừ các cve theo engine vì engine phải quét mới ra thì đã chuẩn", then "A đồng ý" to the evidence variant for KEV below. (2) **"Published"** = the CVE's published date as NVD gives it (`published` of the CVE API 2.0, `feeds_recent_cve.published`), else the CVE record's `datePublished` on CVE.org; never CISA's `dateAdded` (CVE-2008-4250 was added to KEV in 2026). "Older than 12 months" = published before now − 365 days, judged at each match, so a CVE ages out by itself. (3) **Tier 1 (KEV, CISA or VulnCheck), any age stays, but cut by evidence, not age:** a KEV CVE published more than 12 months ago becomes a finding (and an alert) only with **confirmed evidence**: a scan engine found it (nuclei, OpenVAS, ZAP: basis `scan`), the device's own agent reports an exact build or package inside the affected range (basis `agent`, D-548), or the distribution's own verdict says the installed package is affected (basis `distro`, Ubuntu/Debian, D-516). A product-only match or a version read from a banner (nmap `-sV`, a manual entry: basis `version` or `product`) on such a CVE is **not shown and makes no finding**; open findings of that kind close with the reason "older than 12 months without confirmed evidence" when slice 2 lands. A KEV CVE of the last 12 months keeps today's rules (version and product matches included, as D-543/D-546 say). (4) **Tier 2 (EPSS ≥ 0.1)** is now limited to CVEs published in the last 12 months (replaces D-613's "any age"); an older high-EPSS CVE appears only if a scan engine found it. (5) **Tier 3** stays the last 12 months, version-confirmed (agent, distro or exact version); older only if a scan engine found it. (6) **Why:** old KEV CVEs are still exploited every day (EternalBlue CVE-2017-0144, Fortinet CVE-2018-13379, Log4Shell CVE-2021-44228) and CISA BOD 22-01 sets no age cut-off, so an age cut on KEV would hide real attacks; the noise kien saw came from product-only matches on old CVEs (Windows XP/2000-era NVD rows matched on Windows Server 2025, customer walk 3 N52-1, D-610), which evidence removes while keeping a scan-confirmed EternalBlue. A scan finding is proof on the wire, an agent's build or a distro verdict is proof on the device; a banner or a product name is a guess. (7) **Data:** tier 2 and 3 now need nothing older than 12 months, so the slice-2 question of version data for ~16,000 old high-EPSS CVEs (D-614 (5)) is gone; `nvd-recent` (D-614) covers both tiers; `feeds_epss` stays for every CVE (CVE pages, and a scan-found old CVE's score). (8) **Contract (slice 2, mock first):** every tier item and every finding carries `basis` (`scan` / `agent` / `distro` / `version` / `product`) and `published`; the "Updates to plan" API of D-613 (5) adds `basis` and `published` to each CVE and an `old_evidence` count; the UI shows the basis as the evidence chip ("Found by a scan", "Reported by the agent", "Ubuntu says affected", "Version matches") and never shows a `version`/`product` item older than 12 months. (9) **Terms:** TERMS.md says it in slice 2, with the matcher (older CVEs only on confirmed evidence; an old vulnerability Vedette cannot confirm is not reported); slice 1 does not change TERMS.md (supervisor, review r1 #3). (10) **Not chosen:** a plain 12-month cut on KEV (hides EternalBlue-class attacks, contradicts BOD 22-01); keeping banner versions as evidence for old KEV (the noise source). **Amended by D-616 (supervisor 2026-11-15, after measuring slice 2):** for a KEV CVE published more than 12 months ago only **product-only** matches (basis `product`, no version compared) are dropped; any version comparison keeps the finding with its usual label (scan engine, agent build or package, distribution verdict, SNMP- or LLDP-stated version, a version the admin typed, the banner version of the device's own service; banner and typed stay "Suspected").
