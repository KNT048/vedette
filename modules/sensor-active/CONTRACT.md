# Sensor-active Contract

> Tier: standard · Story: S-INV-1, S-SCAN-4 (time window, rate, exclusions for discovery) · Last verified: 2026-11-21 (every claim checked against the code)

The scan configuration lives in `GET/PUT /inventory/settings`, `PUT /scanning/safety` (one store with the `scan` module's window, inventory INV-32) and `PATCH /inventory/devices/{id}` (the `inventory` module); this module **enforces** that policy. Its only own endpoint: per-device SNMP `/inventory/snmp*` (INV-10); "Scan the LAN now" and "Check this device now" are `core` routes (`/scanning/engines/nmap-discovery/run`, INV-21). Source of behaviour: `web/src/features/inventory/{contract,mocks}.ts`.

Module imports only a few leaf packages of other modules: `scan/nucleiargv`, `scan/nucleiout`, `scan/pack`, `scan/commonports` (the first -sV batches of the `external` shape) and `sensor-passive/capture` (the new-device budget `FloodBudget`, `ParseSysDesc`). The device store is reached through the `sensoractive.Inventory` port and `core/observe` (adapter in `cmd/vedette/sensoractive.go`). nmap runs only through `core/exec` (name `nmap`, absolute path, `ValidateNmapArgs` re-checks the whole argv). That `core/exec` runs in the worker of the `scan` container; `core` calls it through the `Prober` seam and keeps the whole policy.

## Invariants
- **INV-1**: `sensor-active` never sends a packet to an IP outside the stored `lan_ranges` or inside `exclusions` (SYS-7), **except** the `external` shape of INV-16, the two deep shapes `external_full`/`external_disruptive` of INV-19 (sensor-active; not exposure's INV-19), the `domain_ip` job of INV-20 (a public IP that a name of a domain in vedette-host's list points to, behind the worker's domain fence; **note**: a compromised core can obtain tokens for its own domains, at most 20 domains, each with a host audit line, so the fence proves "the domain is in the host's list, its DNS carries the box's token, and it points to the address", not that the address belongs to the customer) and the nuclei job with scope `own_ip` of INV-17 (one public IP, the box's own outgoing Internet IP, with consent owned by exposure; both pass the two own-IP fences). Every target is scope-checked right before it goes into the argv, **in this order: publish the run's targets first, then check** — discovery: each batch reads `Settings` once and tests each address in memory (the same `InScope` rule as the store, `Settings.InScope`; `TestSensorActiveScopeRuleMatchesTheInventory`), then `probe` re-reads the settings, window and scope of **every** target in the batch; device scans: `setCur` before `permit`, the address published as soon as it is known, `inventory.InScope(ip)`, then `probe` checks again. There is also a settings version counter (`SettingsChanged` increments it): if it moves between the read and the nmap run, the run stops. A scope change midway makes `SettingsChanged` re-check the running addresses and stop. Discovery also skips the store's `ProtectedIPs` addresses (manually declared devices, `regular_scan=never`, fragile/unclassified devices whose gentle scan is done, the box; by IP, so a new MAC at that address does not lose the protection; `TestContract_INV5_SweepSkipsProtectedAddresses`, `TestSensorActiveSweepSkipsProtectedAddresses`). Hosts nmap reports outside the requested list are dropped, not recorded. **Consent lives only in `core`**: every scope, window and policy check above runs in `core` **before** `Prober` hands out the job; the worker in `scan` holds no scope and only checks the grammar (private IPv4, eight LAN shapes), so a compromised `core` can scan exactly what `core` could already scan. `TestContract_INV1_NeverOutsideScope`, `TestContract_INV1_ReportedHostsOutsideTheRunAreIgnored`, `TestContract_INV1_ExclusionAddedMidRunStopsIt`, `TestContract_INV1_ExclusionSavedAfterTheScopeCheckSendsNothing`, `TestContract_INV1_SweepExclusionSavedBetweenCheckAndExecSendsNothing`, `TestContract_INV2_ScanningTurnedOffDuringTheChecksSendsNothing`
- **INV-2**: No scanning when `active.enabled=false` or `scope_confirmed_at=null`; no scanning when `lan_ranges` is empty (both discovery and device scans; the store's `ScanPolicy` also blocks it). `TestContract_INV2_NothingWithoutScopeAndSwitch`
- **INV-3**: Runs only inside the window (`days` 1..7 with Monday = 1, `from`–`to` in **the organization's time zone** (`Config.Location`; the organization time zone from core's general settings, read on every use so a time zone change takes effect at the next check (`orgLocation` in `cmd/vedette/sensoractive.go`); if it cannot be read, the box's time zone `time.Local`; `Health.Zone` reports the zone in use; `cmd/vedette` embeds `time/tzdata` so zone names resolve in a container without the OS time zone data), may cross midnight: the window belongs to its start day); **no exception outside the window, not even the first gentle scan of a fragile device**. The deadline of each nmap run = min(end of window, 2 hours); the deadline passing or a settings change that no longer allows it → the process group is killed at once; **shortening the window while a run is in progress** (the new end time earlier than the run's deadline) also stops the run at once (`TestWindowShortenedMidRunStopsAtTheNewEnd`), and the next run continues from the run cursor. "Killing the process group" is `cancel:[id]` in the `jobs` long-poll plus the worker's 60 s lease; `core` treats the probe as `stopped` after at most 30 s and hands out no new job while the worker still reports `running`. `TestContract_INV3_OnlyInsideTheWindow`, `TestContract_INV3_StopsWhenTheWindowCloses`, `TestContract_INV3_SettingsChangeStopsTheRunningScan`, `TestContract_INV3_WindowIsReadInTheConfiguredZone`, `TestWindow`
- **INV-4**: The rate does not exceed `rate` packets/second (`--max-rate`; device scans take min(the store's decision, `rate`)); **note: `--max-rate` only limits port scanning and host discovery; OS detection (`-O`) and version detection (`-sV`) time themselves** ([man-performance](https://nmap.org/book/man-performance.html)), so normal scans also have `--host-timeout 30m` and gentle scans `--host-timeout 15m` to bound the time per host. Lowering `rate` in the settings stops the running run at once (it runs again at the next tick at the new rate). The argv is built from private IPv4 `netip.Addr` values (RFC 1918 or the RFC 6598 shared range 100.64/10, `core/localnet.Addr`), integers and fixed flags, never through a shell (SYS-1, SYS-2). `ValidateNmapArgs` (in the leaf package `modules/sensor-active/nmapargv`, shared by `core` and the worker) re-checks the whole argv before the process runs and accepts **exactly eleven shapes** (the three LAN shapes `extra_ports`, `all_ports` and `port_versions` in INV-20; the sixth shape `external` in INV-16, and the two deep shapes `external_full`, `external_disruptive` in INV-19: exactly one public IP; the five shapes below only private IPs) (sweep, normal, gentle, `versions` = normal without `-O`, and `gentle_titles` = gentle plus `--script http-title,ssl-cert,http-hp-ilo-info,vmware-version --script-timeout 20s`; only the rate of discovery/normal/versions/`extra_ports`/`all_ports` (≤ 100)/`port_versions`, the port list of `port_versions` (1..20 ascending ports, carried in the job) and of `external_disruptive` (1..40 ascending ports, INV-19) and the target list can vary; everything else is refused): discovery `--privileged -sn -PE -PP -PS21,22,23,80,135,139,443,445,554,3389,8000,8080,9100 -PA80,443 -n --max-rate R` (`nmapargv.SweepProbes` = 17 packets per pass for each address behind a router, more when nmap resends to silent addresses; on the box's own network segment nmap only sends one ARP request); normal `--privileged -sS -sV -O --script rdp-ntlm-info,http-ntlm-info,http-title,ssl-cert,http-hp-ilo-info,vmware-version -n --max-rate R --max-retries 3 --top-ports 1000 --host-timeout 30m` (two NTLM scripts; `http-title`, `ssl-cert`; `http-hp-ilo-info`, `vmware-version` (INV-25); exactly those six scripts, in exactly that order, `nmapargv.Scripts`; `--max-retries 3` instead of the default 10); `versions` is that line without `-O`; gentle `--privileged -sS -n -T2 --max-retries 1 --max-rate 1 --host-timeout 15m --top-ports 100`; `gentle_titles` `--privileged -sS --script http-title,ssl-cert,http-hp-ilo-info,vmware-version --script-timeout 20s -n -T2 --max-retries 1 --max-rate 1 --host-timeout 15m --top-ports 100` (the single gentle scan of a device of unknown type that nobody has marked fragile, `gentleShape`; fragile devices keep exactly the gentle shape); followed by `-oX -` and 1..64 private, canonical, distinct IPv4 addresses (0/8, 127/8, 169.254/16, the part of 100/8 outside 100.64/10, 224/4, 240/4, broadcast and public addresses are not accepted; 100.64/10 is accepted). `TestContract_INV4_RateAndFlags`, `TestContract_INV4_LoweringTheRateStopsTheRunningJob`, `TestSweepProbes`, `TestNoShapeWidensScripts` (no shape has `--allports`, `-A`, `-sC`, script categories, wildcards or script arguments), `TestBuild`, `TestValidate`, `TestValidateRefusesNonPrivateTargets`, `FuzzValidate` (all four in `nmapargv`) (the oracle knows every shape, `external` and the two deep shapes with their own public address rule, `port_versions` with its own port rule)
- **INV-5**: Fragile **or unclassified** devices (`kind=unknown`; devices created by discovery are always this kind): exactly one gentle scan at the lowest rate (`--max-rate 1`, `-T2`, `--max-retries 1`, `--host-timeout 15m`, 100 TCP ports; **no `-O`, no `-sV`** because `-sV` runs the NSE scripts of the `version` category by itself, such as s7-info, enip-info, omron-info on PLCs, [nse-usage](https://nmap.org/book/nse-usage.html); no `--script`) when first seen, **in the next window**; `-O` and 1000 ports only after the device is classified as not fragile (passive data, or a person sets the kind). `first_scan_at` is set when nmap finished successfully, even when writing the result to the store fails afterwards (the packets were sent, no second gentle scan); an nmap error or broken output does not set it (retry); after that only when `ScanPolicy` allows it (`regular_scan=allow` or the kind ∈ `regular_scan_kinds`); `never` wins. Manually declared devices are never scanned. Devices with `approved=false` inside the scope are still scanned for discovery. `TestContract_INV5_*` (including `TestContract_INV5_FirstScanIsMarkedWhenNmapFinishedEvenIfRecordingFails`), and `TestSensorActiveFirstScanOfAnUnclassifiedDeviceIsGentle` (real store), `TestSensorActiveFragileDevicePolicy`, `TestSensorActiveScansADiscoveredDevice` (real store) in `cmd/vedette`
- **INV-6**: nmap is an OS package (`/usr/bin/nmap`), not shipped with Vedette: it is installed from the OS package repositories into the `scan` image that `vedette-host` builds on the box. It runs with `--privileged` thanks to `CAP_NET_RAW`. **Where it runs**: nmap runs **only** in the `scan` container (`vedette-sensor active`): host network, `User=<sensor_uid>:<sensor_gid>`, no `UserNS`, `DropCapability=ALL` + only `AddCapability=NET_RAW` (ambient; lab gate, fallback UID 0 + `NET_RAW`), no `NET_ADMIN`; `core` needs no capability. A missing or non-executable binary → `Service.Health` = `unavailable` with a clear message, every run returns `ErrUnavailable`, and the `window-tick` job reports the error in the job history; there is no fallback. The source of this state is the `active` role heartbeat: 90 s without a heartbeat, or `nmap.present=false`, or a `refused`/`nmap_missing` result → `unavailable`, and `Prober` returns `ErrUnavailable` without creating a job. `TestContract_INV6_MissingNmapIsUnavailable`
- **INV-7**: nmap output (XML) is untrusted data (SYS-6): read as a stream, `MaxOutput` cap 8 MiB (`Truncated` → the whole batch is dropped), depth limit 16 (structured script output nests `<table>`), 24 attributes, 256 hosts, 1500 ports, directives only `DOCTYPE nmaprun`, a charset other than UTF-8 is refused, a truncated document is refused; a limit error drops the whole batch, never truncating to fit; strings are only stored as printable text ≤ 200 characters. `TestContract_INV7_UntrustedOutputIsDiscarded`, `TestParseRefusesBadOutput`, `FuzzParseNmapXML`
- **INV-8**: Observations are written with `source=nmap` and `confidence` < 1 (nmap's OS accuracy × 0.95; service `conf` 1..10 × 0.095; device type × 0.8), through `core/observe` (`Record`, `ReplaceSoftware`, `ReplaceServices`): hostname/vendor/os/kind, software from the `<cpe>` of services and the OS (without a CPE the product name stands in for the vendor) — services with an application/hardware CPE (`a:`, `h:`) become software even without a version (matched by product); services with only an OS CPE or no CPE **only become software when `-sV` read a version**: a versionless banner such as "Microsoft Windows RPC" only sits on the open port, and **open ports** (`state=open`, only tcp/udp, ports 1..65535, the name/product/version of `<service>`, `conf` × 0.095; a name or version longer than 100 characters is left empty instead of breaking the whole list; at most 1000) replace the device's whole `nmap` list on a **normal scan**; a gentle scan (top 100, no `-sV`) only adds ports through `AddServices`, never deleting or overwriting the product/version of the normal scan. Only hosts that **answered** (`status=up`) are recorded; a host with `timedout="true"` (`--host-timeout` ran out, nmap prints no port table) only records observations and does **not** replace software and services (an empty list would wipe the previous result). With `Config.Services` nil no ports are recorded. Discovery records the MAC and vendor of hosts that answer; hosts without a MAC (outside the segment) cannot be recorded because `core/observe` has no "IP seen" field (deferred). `source=snmp` is written by SNMP reads (INV-10). The XML is parsed **inside `core`** (`parseNmapXML`, `onlyTargets`, INV-7) from the job result's `xml_b64`: observations and software never travel on the wire, and the worker writes nothing to the store. `TestContract_INV8_ObservationsAndSoftwareFromTheScan`, `TestSoftwareAndObservations`, `TestContract_INV8_OpenPortsFromTheScan`, `TestNoServicesFromAHostThatDidNotAnswerOrTimedOut`, `TestServicesOfKeepsOnlyWhatTheInventoryAccepts`, `TestGentleScanAfterANormalOneKeepsItsServices`
- **INV-9**: Every nmap run writes one **compact** `sa_probe` row: time, run (`run_id`), **the command line shape** (`shape` sweep|normal|gentle|versions|gentle_titles|snmp|external|external_full|external_disruptive|extra_ports|all_ports|port_versions; `flags` ≤ 16,384 characters because the two deep shapes record each script (the full shape about 7,000 characters, the disruptive shape about 2,000 with its port list), the `-p` list of `external` is 540 long) + `rate` + the number of targets + **the flags part of the argv exactly as reviewed** (`flags`, stored on the same row: history does not change when a shape changes) + **the targets as merged ranges** (`targets`: `a-b,c,d-e`, in send order; a discovery batch skips protected addresses so it has holes, and only this list can answer "did the box probe 192.168.10.20 last night?"; 64 addresses always fit) + the result, **written before the process runs** (before `Prober` hands the job to the worker), with the result updated afterwards; kept for 365 days (≥ 90), and the daily `prune-probes` job deletes older rows (core/run keeps runs for 400 days). `Service.Probes(since, limit)` (returns `Shape`, `Rate`, `Target` = the merged ranges, and `Argv` = the stored flags up to `-oX -`) is the read method for the `scan_probes` category of `/core/logs/export` (registered in `cmd/vedette/logexport.go` through `ExportProbes`). `TestContract_INV9_ProbeLog`, `TestProbeRowsAreCompact`, `TestPruneRemovesOldProbes`, `TestProbeRowExistsWhileTheRunIsInProgress`
- **INV-10**: **SNMP is read-only, from the worker of the `scan` container, and set up per device.** (a) SNMP packets leave only from the worker (job kind `snmp`, sensor protocol 5, the `Dispatcher`'s third slot; `SNMPReader` = `SNMPHealth`, `RunSNMP`), never from `core`; the worker sends only **one GET** of its fixed OIDs (sysDescr, sysObjectID, sysName, entPhysicalClass/ModelName/SoftwareRev/SerialNum index 1, MIKROTIK-MIB `mtxrLicVersion.0`; a second GET of the system group only when the agent refuses the PDU), never SET/WALK/GETBULK, no OID from the wire; timeout 2 s, 1 retry, one device at a time, at most `rate` packets/s (2 per read). Job: `{rate 1..1000, targets ≤64 distinct canonical local IPv4, each {ip, credential}}` (`sensorlink.CheckSNMPJob` + `core/localnet` in both `core` and the worker): **a credential travels inside its one target** and the worker sends it to that address only (`TestSNMPSendsEachTargetItsOwnCredentialOnly`). (b) **Settings per device** (`sa_snmp_device`; `SetSNMP`, `DeleteSNMP`, `SNMPDeviceOf`, `SNMPDevices`): v2c community, or v3 user + SHA/SHA-256 + AES-128 or none (no v1/MD5/DES/noAuthNoPriv); UDP port (NULL = 161, not on the wire; `bad_port`); **read address** (`read_from`, the device's IP by default (`read_from_default`), or a management address a person types: `checkReadFrom` refuses a non-IPv4, unspecified, loopback, link-local, multicast or broadcast address, a LAN range's network or broadcast address (`bad_read_from`), a non-local one (`read_from_not_local`, `core/localnet`) and the box or a decoy (`read_from_box`); inside or outside lan_ranges); a device with no address is `no_ip`, the box `box_device`. Secrets sealed in `core/secrets` per device (purposes `sa_snmp.secret`, `sa_snmp.priv`; ids in `sa_snmp_device.secret_id`/`priv_secret_id`), only their last 4 characters reach the API, never logged (`sensorlink.SNMPCredential` redacts itself), never exported (`sa_snmp_device` secret ids `skip`). A blank secret keeps the saved one, except when the read address changes (`secret_required`); a kept secret this box cannot open is 409 `secret_lost`. **Copy from** (`copy_from`) copies version, user, algorithms, port and the secrets of another device inside the transaction, sealed again as this device's own, and only for a read address that is the device's own IP (another one is 400 `secret_required`: the secret is typed for a new address); no answer holds a secret (`TestSNMPCopyFromNeverReturnsTheSecret`, `TestSNMPCopyFromToAnotherAddressNeedsTheSecretTyped`). One read address is one device's: a second device given it is 409 `read_from_taken`, naming the first (`TestSNMPAReadAddressBelongsToOneDevice`). The form is checked before the switch is turned on, so a refused save changes nothing (`TestSNMPARefusedSaveLeavesTheSwitchAlone`). Saving first turns the device's SNMP source on through the inventory (`Inventory.TurnSNMPOn`, audited there; an ignored device is 409 `device_ignored` and nothing is saved). Audit `inventory.snmp_set` (with "copied from <device>"), `inventory.snmp_remove`, `inventory.snmp_check`; never a secret. (c) **Who is read** (`snmpAllowed` = `snmpPolicy` + the read address): the inventory's `SNMPPolicy` (INV-22) without the fragile rule (fragile and unclassified devices are read), approved only (`Asset.Approved`), never the box or a decoy (`Inventory.BoxIPs`, by the device's IP and by the read address); a read address left to the device's IP that the device has since left is **not followed** (`moved`: a copied network card looks the same; a typed read address stays), never an excluded read address (`excluded`), never a non-local one. (d) Order as INV-1/INV-9: the batch is published (`snmpCur`), settings/window re-read (not for Check now; a round's batch ends at min(window end, 1 h)), **each target's settings and policy re-read** (`recheckSNMP`: removed, read address changed, now refused → dropped), the probe row written (`sa_probe` `shape=snmp`, `flags` name the versions and ports, never a secret), then `snmpJob` opens the secrets in **one read transaction** that re-reads each device's row: **a target that is not the stored read address of the device whose secret it carries is refused** (`errSNMPNotReadAddress`, nothing opened or sent, logged; `TestSNMPTheJobRefusesAnyAddressButTheDevicesReadAddress`), and a row changed since (version, secret ids, `updated_at`) or removed stops the batch (`ErrStopped`). An edit, a removal, a delete or a merge of a device the batch holds stops it (`snmpSettingsChanged`, as a device change: the round reads the batch again with the new settings), a job with the worker too. `SettingsChanged` and `Stop` stop it as before; `AssetChanged` of a device it holds stops it only when the change matters to the read (`stillReadable`, the rules of `recheckSNMP` with the settings now: refused, gone, moved off its read address; fail closed when that cannot be read): devices change all the time (a sensor learns a name, a check records its ports), and such a change no longer stops another device's or its own read (`TestSNMPAReadEndsWithWhatTheDeviceAnswered`). A read's run counts the devices that answered: Check now ends done 1 of 1, or failed with what the device said (`snmpMessage`: no answer, wrong user, ...); the window's round ends done, partly done naming up to three devices that did not answer, or failed when none did. (e) **Answers are untrusted**: `Dispatcher.RunSNMP` refuses an answer for a target the job did not name (`ErrResultRejected`); `identifySNMP` cleans (valid UTF-8, no control/format characters, ≤ 200 runes) and reads only through the fixed layouts (enterprise number, LLDP sysDescr layouts, ENTITY-MIB class 3/11, FortiOS, RouterOS from `mtxrLicVersion.0`). They are recorded **on the device the read was for** (`observe.AssetHint.Device`, never by the read address, so no device is found, made, joined or moved there; inventory `TestContract_*`), `source=snmp` (0.9; kind 0.8), and the state of the device's last read is kept (`last_checked_at`, `last_status`, `last_answer_at`, `answer` = the cleaned values as JSON, only through the fixed layouts). (f) **Schedule**: one round per window, before the pass (its own lane, `snmp_read`; a stopped round does not count, and a round a restart left queued runs as it is due), every device with SNMP set up that `snmpAllowed` lets be read, one read per address per job, batches of 64; **Check now** (`CheckSNMP`, `POST /inventory/snmp/devices/{id}/check`, an `snmp_read` run with trigger manual) reads one device at once with every rule but the window. No discovery and no sweep with shared credentials exists. Tests: `TestSNMP*` in `snmp_test.go`, `snmp_device_test.go`, `snmp_review_test.go`, `snmp_round_test.go`, `snmp_sources_test.go` (end to end through `Dispatcher` + mTLS link + real worker + `internal/snmptest` fake agent), `TestIdentifySNMP`, `TestSNMPTable`, `FuzzIdentifySNMP`; worker: `worker/snmp_test.go`.

- **INV-21** (S-INV-1, S-SCAN-4; `runnow.go`): **"Scan the LAN now" and "Check this device now"** (core's `POST /scanning/engines/nmap-discovery/run`, through cmd/vedette). `StartManual(ctx, by, targets, record)` checks everything before it queues anything and sends nothing on a refusal: the module on (`ErrStopped`), active scanning on (`ErrScanningOff`), the scope confirmed with a range (`ErrScopeNotConfirmed`, `ErrNoRanges`), nmap present (`ErrUnavailable`; a check asked while the scan worker has not reported since a restart, or for 90 s, is not refused: it is created waiting for "the scan worker to be available", listed as queued, and starts as soon as the worker reports (the Dispatcher's `OnReport` hook at every heartbeat, and the window's tick), whatever the window; it gives up as failed in plain words when the worker reports that nmap is missing, or after 30 minutes without the worker, `personWaitMax`, counted from core's start at the earliest so a box that was off does not fail it at boot), for a sweep no pass going now and none that gave way to other work and goes on by itself after it (`ErrSlotBusy`: no second consent, no second resume) and none started in the last `SweepGap` = 10 min (`*TooSoonError`; a sweep queued that never started does not count). A busy scanner never refuses a person's run (INV-28): another person's run, the window's checks or the weekly scan of every port, it is queued behind it; a device that already has a person's check queued, waiting for the worker or going keeps that one (its run is the answer, nothing new is queued or recorded), at most 64 targets, each a known device allowed by its policy as a person's pick, with an address, never the box or its decoys, inside the ranges and outside the exclusions (a `*TargetError`). `record` (core's audit row, the consent) is written in the transaction that queues the runs; its error queues nothing. No targets: a pass (`lan_sweep`, trigger manual) that runs outside the window for `manualFor` = 1 h, then waits for the window; a pass that already waits is replaced by a fresh pass when one pass of the scope takes less than that hour at the rate (it ends stopped, saying a person started a new sweep), and otherwise goes on now from its cursor under the person's hour, the answer saying so with how far it got (never a second pass); the devices it finds are checked right after it as its child runs. The person's hour starts at the pass's first turn after the person's latest ask (its queue time for a person's own pass, or a person's Resume or Start now of any pass, which therefore also goes now outside the window) and is read from the run's record (`run.Manager.Asked`), so it holds across a restart. A pass that waits for the scan worker past any person's hour says, outside the window, that it waits for the window (its log too). Targets: one `device_check` run per device (trigger manual), run whatever the window, each re-checked right before nmap, queued behind a busy scanner (INV-28). A person's check stopped while it ran says the one reason it was stopped for (`stopCause`, set by the path that stopped it: the device left the address, its safety rules changed, scanning off, the scope, the rate, the module off), never a list of guesses; when the reason is one it can go on after (the device moved, or the settings changed just before nmap but may still allow it) it starts again from its checks, at most 3 tries (`maxIdentifyTries`), its log says so on every try another follows, and each try's progress line starts afresh; otherwise it ends failed with that reason. `Manual` is the newest person's run, `Persons` every one queued, waiting for the worker or going (oldest first; `Engine.Persons`, each listed in `GET /scanning` `running[]` with its summary and `queued`, `ManualRun.Queued`), `WaitManual` waits for their end. `Jobs` and `JobsOf` (read only) list the module's runs for core's `GET /scanning/history` and a device's Last checks (its checks: the runs whose subject it is; and, only while it has SNMP set up, the SNMP reads whose compact target list names its read address). `TestContract_INV21_*`, `TestReview857_*`, `TestRunsScanTheLANNowGoesOnWithTheWaitingPass`, `TestJobsOf_TheRunsOfOneDevice`, `cmd/vedette` `TestScanningRunNow`.

- **INV-22** (S-INV-1; `snmp.go` `snmpPolicy`/`snmpAllowed`, `window.go` `excluded`, `service.go` `checkSweep`): **SNMP keeps to each device's own switch, its read address and the exclusions; the LAN ranges bind it only by default.** `snmpPolicy` asks the inventory's `SNMPPolicy` (not `ScanPolicy`): a network scan turned off does not stop SNMP, SNMP turned off (`snmp_off`) does, and a device added by hand is read only once its SNMP is on (`declared_by_hand` until then). Outside lan_ranges only a device whose SNMP switch is stored `on` is read (saving its SNMP settings turns it on: the person's consent for that device; nothing starts reading outside the LAN by itself). The read address may be inside or outside lan_ranges (the person set it on this device) but is always local (`localnet`: RFC 1918 + 100.64/10, at save, at dispatch and in the worker): a public address is never sent to. ## The `Prober` seam and the worker (sensor protocol)
- **Seam**: `probe()` calls `s.prober.Probe(ctx, argv)` instead of `s.runner.Run(nmap, argv)`. `Prober` = `Probe(ctx, argv []string) (Output{XML, Truncated}, error)`; `ctx` carries the deadline (end of window or `maxRun`), cancelling ctx = killing the run; a non-zero exit is still an `*exec.ExitError` (`errors.As`). The local implementation `NewLocalProber(log, path)` = `core/exec` with `NmapBinary(path)` (with `Config.Prober` nil, `New` uses it; `cmd/vedette` always passes the `Dispatcher` and refuses a nil `Prober`). The argv is built by `nmapargv.Build` and checked again by `nmapargv.Validate` (through `ValidateNmapArgs` in `NmapBinary`). The leaf package `modules/sensor-active/nmapargv` only imports the standard library (`TestIsALeaf`) and holds `Kind` (`Sweep|Normal|Gentle`, `Name()`), `Flags`, `Build`, `Validate`, `MaxBatch`, `MaxOutput`; `FuzzValidate`, `TestBuild*`, `TestValidate*` live there; `TestProbeGoesThroughProber` proves that `probe()` only runs nmap through `Prober` (a pure refactor: every `TestContract_INV*` runs unchanged; the check order of INV-1 and INV-9 does not change). Two implementations: local `core/exec` (tests, dev) and the remote dispatcher. The window, scope, `ScanPolicy`, the core/run runs (queue, run cursor: INV-29), the `sa_probe` row written first and the settings version counter stay in `sensoractive` inside `core`.
- **Dispatcher and worker** (the production `Prober` is `*Dispatcher`; `NewLocalProber` is only for tests, `cmd/vedette` refuses a nil `Prober`):
  - `dispatch.go`: `Dispatcher` is both the `Prober` and the `sensorlink.Backend` of the `active` role (`Jobs`, `JobRunning`, `JobResult`, `ActiveHeartbeat`, plus `JobResultRejected` of `sensorlink.ResultRejector`; the `passive` role functions are composed by `core`). One job in memory (`pending`, then `running`). The checked argv is turned back into `{shape, rate, targets}` by `nmapargv.Parse`; `timeout_s` is computed **when handing out** from the ctx deadline (`min(remaining, 7200)`), not when queueing.
  - Errors (`errors.Is`): `ErrWorkerUnavailable` and `ErrNmapMissing` wrap `ErrUnavailable` (the queue keeps the device, retries later; no job is created); `ErrWorkerLost`, `ErrWorkerRefused`, `ErrResultRejected` make the probe `failed`. The `sa_probe.result` row: `failed: worker_unavailable`, `failed: nmap_missing`, `failed: worker_lost`, `failed: the worker refused the job`, `failed: the worker's result was rejected`, and with `413` (or `truncated`) `failed: output over the size limit, discarded`.
  - Result: `core` only trusts the exit code (`> 0` → `*exec.ExitError`; `< 0` or `status ≠ done` → error), `truncated` and the XML (through `parseNmapXML` + `onlyTargets`); `refused` → `ErrWorkerRefused` and log ERROR; `reason=nmap_missing` → `unavailable` until the next heartbeat. A result body refused by the server (`413` XML > 8 MiB after decoding, or `400`) reports `ErrResultRejected` at once (the worker does not resend), without waiting for the lease.
  - Whether a running job is alive is judged by **the last poll that names it** (not by heartbeats): 90 s without any poll, or past `timeout_s` + 30 s (the `core`-side cap; a probe without a ctx deadline carries a cap of 7200 s) → `ErrWorkerLost`, and `Health` says clearly when it is because of the deadline. Every `running` id `core` does not hold (a dropped job, or one from a restarted `core`) gets `cancel:[id]` at once on that poll (answered at once the first time): INV-3 cannot be bypassed by losing the worker. A waiting job whose probe ctx has ended is dropped at once on the next poll.
  - A discovery scan that meets `ErrUnavailable` (worker lost, nmap missing) midway stops, does **not** move the cursor, and the job is `stopped`, so the next `Tick` runs again from the cursor; the remaining batches are not burned into failed `sa_probe` rows.
  - Cancellation: the probe ctx ends → a job not yet handed out is dropped (the worker never sees it); one already handed out gets `cancel:[id]` once at once on the open long-poll (which is woken) and then in every later reply, until the worker reports it done; the probe returns when there is a confirming result or after 30 s. A new job is only handed out when the poll reports an empty `running`. A poll that still names a just-finished job is answered at once, **once** (so the worker polls again with a free hand, without waiting out `wait`).
  - Health: `Service.Health` asks the `Prober`'s `NmapHealth()` when it has one (no more `os.Stat` of the nmap path): "no heartbeat for 90 s" or "nmap is not installed in the `scan` container" → `unavailable` (INV-6). **Install kind**: `DispatcherOptions.ContainerOnly` (from `modreg.Registry.ContainerOnly()`, no new flag) only changes the advice in the message: the container-only install says the project's `scan` image has no nmap (it does not say "rebuild the image"), and for missing nuclei/pack it says to pull the release's image again; the appliance keeps "until the scan image is rebuilt". The state and errors do not change. `TestHealthAdviceFollowsTheInstallKind`.
  - `worker/` (a leaf package for the `vedette-sensor` binary: only the standard library, `core/exec`, `core/sensorlink`, `internal/jsonstrict`, `nmapargv` (with `core/localnet`, only `net/netip` + `slices`); `TestBinaryDependencies` in `cmd/vedette-sensor` walks the imports (`go/build`, `ImportDir`) of every package of this module from the binary down, for the build machine and Linux, forbidding `database/sql`, SQLite, ogen, `core/store`, `core/pki`, the `sensoractive` module and every third-party package): long-polls jobs, **checks them again** (known shape, `rate` 1..1000 and `gentle` carrying `1`, 1..64 distinct canonical private IPv4 targets, `timeout_s` 1..7200; invalid → `refused`/`invalid_job`, nmap does not run), runs `nmap` through `core/exec` (its own process group, SIGKILL of the whole group), one job at a time (a second job → `refused`/`busy`). Kills the process group on: `cancel` (result `stopped`/`cancelled`, also when the cancel arrives in the same reply as the job: nmap does not run), 60 s without a `200` poll, a changed `instance` (on a poll or heartbeat), `409 module_off`, the `timeout_s` deadline (result `stopped`/`deadline`), worker shutdown; the three cases lease, instance and module off send **no** result. Results are resent on 429, 503 or a connection error (per `Retry-After` or backoff, within the 60 s lease), and not resent on 400/404/413/403/409; the poll loop waits while sending. A job id that is not exactly 32 hex is dropped and never used in a URL or log. Heartbeat every 30 s (`nmap --version` through a second allow-list entry that accepts only `--version`). Output capped at 8 MiB (`truncated`). The long-poll `wait` is at least 1 s (the wire only carries whole seconds).
  - Tests: `TestSuiteThroughTheDispatcher` reruns **the whole test package** twice (the test binary reruns itself with `VEDETTE_SA_PROBER=local` and `=remote`) and requires both passes to pass exactly the same set of tests, including the stop-path tests (window closed/shortened, settings change, lowered `rate`, deadline, resuming discovery, the probe row while running); the `remote` pass uses the `Dispatcher` + a real mTLS link + a real worker + a fake nmap script. What is rerun remotely is every test that builds the `Service` through `newEnv`, `e.build()` or `buildWith`/`e.prober()` (changing the nmap path and rebuilding builds a new worker); tests that inject a fake `Prober` into `sa.New` behave the same in both passes; `dispatch_test.go` (wire, 60/90/30 s deadlines with a fake clock, cancel before/after hand-out, unconfirmed cancel, unknown/finished/resent ids → `404`, the `passive` role → `403`, `413` and the `failed` probe row, `status` not trusted, one job at a time, `instance`); `worker/worker_test.go` (grammar, killing the process group after cancel/lease/instance/deadline/shutdown/module off, a cancel racing the start, `busy`, the 8 MiB cut, heartbeat, no orphan process after each test); `cmd/vedette-sensor/main_test.go` (dependency boundary, subcommands).
- **Nuclei jobs** (protocol version 2; callers of `RunNuclei` are `cmd/vedette/scan.go` `scanEngine` and `cmd/vedette/exposuretemplates.go`):
  - **Wire** (`core/sensorlink`): `X-Vedette-Proto: 5` (version 5: the `snmp` job, and the nuclei job's `scope` and the heartbeat's `nuclei.own_ip`, INV-17, added before the first release of version 5; version 4: the passive heartbeat's `capture_error`, the worker only changes the number; version 3: `host_errors`; `core` also accepts workers of the version right before, never a worker newer than itself, and updates switch `core` before the worker); `Job.kind` (`nmap`, `nuclei`, missing = `nmap`; an unknown kind decodes into a job with only `id`/`kind` so it gets `refused`); the nuclei job `{pack, templates (id), targets{host, port, scheme}, rate, max_host_errors, timeout_s, scope?}` sits at the same level as `id`/`kind` (`scope` only on `own_ip` jobs, INV-17); results add `jsonl_b64` (≤ 4 MiB, not together with `xml_b64`) and `host_errors` (≤ 16 entries `{target, errors, unreachable}`: per-target timeouts the worker counts from `-elog`, only when `done`); the heartbeat `nuclei{present, version, pack{version, sha256}, own_ip?}` (`own_ip` = the worker runs `own_ip` jobs and has the own-IP checker, INV-17); `running` ≤ 2 ids (`Backend.Jobs(ctx, wait, running []string)`). Strict decoding: unknown fields, duplicate keys, the other kind's fields are `400`.
  - **Dispatcher** (`dispatch.go`, `nuclei.go`): two slots (nmap, nuclei) with the same rules as the nmap slot (an unknown id gets `cancel` on the first poll, a `core`-side cap of `timeout_s` + 30 s, `JobResultRejected`); an unknown id holds both slots; a cancel wakes the open long-poll, so Stop takes ≤ 5 s (`TestEndToEndStopLandsWithinFiveSecondsAndLeavesNoOrphan`, `TestNucleiCancelWakesTheLongPollWithinFiveSeconds`). `NmapHealth()` and `NucleiHealth()` are independent (nuclei: no heartbeat for 90 s, `present=false`, empty `pack.sha256`, overdue and not yet stopped).
  - **Seam for `scan`**: `Scanner` = `Ready(ctx) error` + `RunNuclei(ctx, NucleiRequest{PackVersion, PackSHA256, Templates (id), Targets []nucleiargv.Target, Rate, MaxHostErrors}) (nucleiout.Outcome{Results, HostErrors}, error)`; satisfied by `*Dispatcher`. `scan.Engine` (only `Ready` at first) is satisfied by `*Dispatcher` as is. `RunNuclei` checks the grammar before handing out (exactly the `nucleiargv.Build` grammar, each template id standing for one path; targets only private IPv4); `ErrScannerUnavailable` (wrapped by `ErrScanWorkerUnavailable`, `ErrNucleiMissing`, `ErrPackMismatch`) = 503 `scanner_unavailable`, nothing is sent; `ErrWorkerLost`, `ErrWorkerRefused`, `ErrResultRejected`, `ErrOutputTruncated`, `*exec.ExitError{Name: "nuclei"}` make the run `failed`. `core` only trusts the exit code, `truncated` and the JSONL bytes, parsed with `nucleiout.Parse` (fail-closed, `FuzzNucleiResultPath`); a run that prints no line is an empty result, not an error (`scan` decides what that means).
  - **PRE of `Scanner.RunNuclei` (the caller is responsible)**: the confirmed scope and consent have been checked (scan INV-1, INV-2: active scanning only inside the confirmed scope, every probe logged) and the probe row has been written **before** the call; `Scanner` holds no scope, only the grammar. The two `cmd/vedette` adapters keep this.
  - **Host errors**: `Outcome.HostErrors` is the per-target timeout count the worker takes from nuclei's error log; `RunNuclei` fails closed when a target is not part of the request or `Unreachable` ≠ (`Errors` ≥ `MaxHostErrors`) (`ErrResultRejected`); an nmap result carrying `host_errors` is refused. `scan` uses them for INV-6 because stdout only has matching lines.
  - **POST of `Scanner.RunNuclei`**: nuclei only prints JSONL for templates that **match**, so an **empty** result (or missing lines) means "no match reported", **never** "not vulnerable", and it does not prove the template ran either. `scan` must not mark a finding as handled/gone from an empty result until a lab-checked "template loaded" signal (how nuclei reports a template excluded by `-etags`/`-pt`) exists and is added to the result.
  - **Pack**: `RunNuclei` compares the request's `pack` with the latest heartbeat's `pack` **before handing out**: different → `ErrPackMismatch` ("the scan image has template pack X, the request needs Y"), not wrapping `ErrScannerUnavailable`, no endless retry. The worker's `pack_invalid` (a file hash mismatch, a link/special file in the pack: a sign of tampering) → `ErrPackInvalid`, log ERROR, `NucleiHealth()` says "ERROR: … integrity check" and `Ready` returns `ErrPackInvalid` until the image reports another pack (a different hash); no retry.
  - **An unknown id holds both slots**, and `NmapHealth()`/`NucleiHealth()` say so ("the scan worker is still running a job that core does not know…") until the poll no longer names it. **`waitPost`**: while the worker sends one slot's result, the poll loop waits (at most the lease), so the other slot is slow to get a new job during that time (accepted).
  - **Worker** (`worker/nuclei.go`): checks again with `nucleiargv` (private IPv4 targets, no domain names, ≤ 16 targets, ≤ 32 templates, `rate` 1..20, `max_host_errors` 2..20, `timeout_s` ≤ 3600; invalid → `refused`/`invalid_job`), `pack` must equal the index in the image (`pack_mismatch`), each id must be in the index, the whole pack tree has only directories and regular files (`Lstat`; symlink, fifo, socket → `pack_invalid`), hashes each selected template through `os.Root` (`pack_invalid`), runs `nuclei` through `core/exec` (environment not inherited; a new empty `HOME` on tmpfs; its own process group; 4 MiB; stderr not sent). Kills the group on cancel, lost lease, a changed `instance`, `module_off`, the deadline and shutdown (`TestNucleiProcessGroupDiesWhenItMust`). Two slots: a second job of the same kind → `refused`/`busy`, the other slot is not touched.
  - Tests: the worker's refusal table (`TestNucleiRefusesWhatTheGrammarForbids`: domain names, public IPs, loopback, link-local, CGNAT, benchmark, 240/4, multicast, IPv6, flags as hosts, > 16 targets, > 32 templates, `rate` out of range, `max_host_errors` out of range, deadline), a clean environment (`TestNucleiEnvironmentIsClean`: a fake nuclei prints `env`), the pack (`TestNucleiRefusesAnotherPack`, `…APackThatDoesNotCheckOut`, `…ALinkOrASpecialFileAnywhereInThePack`), unknown kinds, a job without `kind` still runs nmap (`TestKindlessJobStillRunsAsNmap`), two slots (`TestNmapAndNucleiRunAtOnceAndASecondNucleiWaits`), result checks (`TestNucleiResultsAreChecked`), the two shapes of nuclei JSONL lines (`testdata/nuclei_host_port.jsonl`, `nuclei_bare_host.jsonl`; `nucleiout` accepts the first and refuses the second until `hostOf` changes, `TestNucleiOutputShapesOfTheLabLine`). No test runs real nuclei or touches the network.
- **Jobs on the wire** (`active` role, `docs/specs/sensor-protocol.md` §6.4–§6.5): `{id, shape: sweep|normal|gentle|versions|gentle_titles|external, rate 1..1000, targets 1..64 private IPv4 (external: exactly one public IPv4, rate 100), timeout_s ≤ 7200}`; no argv, flags, paths, URLs or ranges. The worker builds the argv with `nmapargv` + `ValidateNmapArgs`, a 2-hour cap, one job at a time; invalid → `refused` (`invalid_job`). Because the wire only carries the shape name, an old-release worker builds `normal`/`versions` its own way (without the two NTLM scripts): only during an update (core and worker come from the same release); `sa_probe.flags` then records scripts that were not sent, never the reverse.
- **Progress of a running job** (#830, sensor protocol §6.6): every nmap shape ends with `--stats-every 5s -oX -` (`nmapargv.StatsEvery`, `StatsFlags`; `Validate` refuses it missing, moved, doubled or at another interval; it sends no packet; `sa_probe.flags` ends with it, INV-9: the row shows what ran); `parseNmapXML` skips the `<taskprogress>`/`<taskbegin>` elements it adds. The worker runs nmap on a terminal of its own (`core/exec` `Binary.TTY`, the `nmap` entry only: nmap 7.95 prints `--stats-every` only with a controlling terminal in its foreground; no terminal → it runs as before, logged once) and names the phase itself where nmap says nothing: the first phase of the command line (`discovery`, `ports` with `-Pn`) as nmap starts, posted at once, then `ports` at nmap's first `<hosthint>`, only ever forward. The worker reads nmap's stdout and nuclei's `-ms` lines while they run (`worker/progress.go`: `core/exec` `RunWatch`, lines over their cap skipped, a fixed task-name table, `nucleiout.Read` per line), keeps only the latest state and posts it at most every 5 s (`Config.ProgressEvery`), once, never after the result. `Dispatcher.JobProgress` (`sensorlink.ProgressReceiver`) hands it to the `progress.Sink` of the probe's context (scan run, exposure scan) with the pass note of the shape (`extra_ports`: "Second pass: administration and alternative ports"), under `mu` (never after the result), at most one per job within 4 s (`progressMin`), and stores nothing; a probe without a Sink drops it. A target nuclei gives up (`max_host_errors` timeouts in its error log, `nucleiout.TimeoutTarget`) keeps only its finished pairs in the total. Advisory: never a reason for a result. The first report of each job reaching a Sink opens a new pass of its phase (`progress.Update.NewPass`). Tests: `TestProgressReachesTheSinkOfTheProbe`, `TestEachJobOpensAPass`, `TestNmapRunsOnATerminal`, `TestNmapPhaseMovesWithoutItsProgressLines`, `TestNmapWatchNamesThePhaseItself`, `TestNoProgressAfterTheResult`, `TestProgressIsThrottledPerJob`, `TestNucleiCounterDropsAGivenUpTarget`, `TestNmapProgressIsReportedFromItsXML`, `TestNucleiProgressCountsItsChecks`, `TestParseSkipsTheProgressLines`, `TestStatsEveryIsFixed`, fuzz `FuzzNmapProgress`, `FuzzNucleiCounter`.
- **Dispatcher** (in memory, one running job = one nmap on the box): a job not picked up within 60 s → probe `failed` (`worker_unavailable`); a poll reporting a `running` other than the handed-out job with no result yet → `failed` (`worker_lost`); the probe context ends → `cancel:[id]`. The worker kills the process group when cancelled, after 60 s without a successful poll, or when `core`'s `instance` changes (lease; a `core` crash leaves no orphan nmap).

Tests: `TestAProvenIPRunsWhileTheBoxGoesOutThroughAnotherLine`, `TestAProofThatDoesNotHoldIsRefusedLikeNoProof`, `TestAProofDoesNotWidenTheGrammar`, `TestAFullJobOnAProvenIPKeepsRunningWhileTheProofHolds` (worker), `TestScanExternalOfAProvenIPWhileTheBoxGoesOutThroughAnotherLine`, `TestScanExternalWithAProofThatDoesNotHoldIsRefused`, `TestTheProofGoesOnlyToAWorkerThatSaysOwnProof`, `TestOwnIPNucleiCarriesTheProof`.

- **INV-10 (g)**: **Check now** reads one device (INV-10 (f)). **Module off sends nothing** (SYS-5): `Stop` sets a sticky `off` flag (cleared by `Resume`) before it reads `snmpCur`, and every `snmpBatch` (Check now, round) checks it right after registering, so either `Stop` cancels the batch or the batch sees `off` and sends nothing.
- **INV-10 (h)** (#868; S-INV-1): **a secret this box cannot open is sent nowhere.** A device whose saved community or password is sealed under another master key (a backup restored without its decryption key: `secrets.IsWrongKey`) shows `secret_lost: true` and `blocked.reason = secret_lost`; Check now answers 409 `secret_lost` in plain words before anything is written or sent; the window's round leaves it out and reads the others (no round starts while every device is so, so one typed again is read in the same window); an edit that leaves it blank, or a Copy from it, is 409 `secret_lost`; one that types it again seals it under this box's key. The Scanning card of `snmp` names those devices (`error` when all are). Any other failure to open a secret stays an error, never "lost". `TestSNMPADeviceWhoseSecretWasNotRestoredSendsNothing`.
- **INV-10 (i)** (S-INV-1): **a device that moved away from a read address left to its IP is named, never followed.** `read_from_default` is 1 when the read address was the device's IP when saved; if the device's IP is now another one, nothing is sent (`blocked.reason = moved`, "<name> is now at <ip>, but its SNMP reads go only to <read address> … then open Edit and set Read from to <ip> (type the community or passwords again)"), the round logs it and the Scanning `snmp` card says it. A read address a person typed is kept whatever the device's IP does. The settings go with the device (`DeviceDeleted`, secrets included) and move with a merge (`DeviceMerged`: the settings whose last read answered win, section "Events"). `TestSNMPADeviceThatMovedIsNotFollowed`, `TestSNMPSettingsFollowDeletedAndMergedDevices`.
- **INV-20** (a firewall's SSH on port 22222 was never seen): **non-standard ports.** (a) Every `normal` or `versions` scan of a device (queue, Scan now) is followed by an **`extra_ports`** scan at the same rate: `-sS -sV` + the six scripts of `nmapargv.Scripts`, `--max-retries 3`, `-p nmapargv.ExtraPorts` (the 99 ports of `commonports` plus `nmapargv.AdminPortList`, 69 alternative SSH/RDP/VNC/WinRM/HTTPS/HTTP management ports and management ports, each port with a reason and a source), `--host-timeout 30m`; the two scans are two `sa_probe` rows, and the results are merged into **one** host (`mergeExtra`: new open ports of the second scan are added with their scripts, NTLM when the first had none; a `timedout` first scan keeps its meaning; ports both saw keep the first scan's answer) before being recorded as in INV-8 (replacing services and software). An `extra_ports` scan that fails or is stopped: the top-1000 result is kept (already done, POST-3) and a log line is written. **When only the `extra_ports` scan sees the device** (the top-1000 scan did not see the host): ports are only **added** (`AddServices`), services and software are not replaced; Scan now identification is then `host_down`. The top-1000 list is still nmap's `--top-ports 1000` on the box: `nmap-services` (NPSL) is neither copied nor embedded. (b) **An all-ports scan every week** (`all_ports`), after `Tick`'s queue and SNMP round, inside the window, **one device at a time** (the lock is released between devices), only when the window still has ≥ `nmapargv.AllPortsWindowRoom` (120 minutes: 90 for the discovery pass and 30 for the `-sV` pass that follows) and the configured rate is ≥ `AllPortsMinRate` (50; lower and it does not run, and `Health.Warning` says why): **port discovery only** `-sS -n --max-rate R --max-retries 1 -p- --host-timeout 90m`, R = min(settings, the store's decision, `AllPortsMaxRate` 100), no `-sV`, no scripts, no `-O` (`-sV`/scripts time themselves and open full connections); then **one `port_versions` scan** (`-sS -sV` + the six scripts, `--max-retries 3`, `-p <ports>`, `--host-timeout 30m`, at the normal LAN rate = min(settings, the store's decision)) on **at most `MaxPortVersions` (20)** open ports the normal scan does not cover, ports never read before first, then the ports read longest ago (the time each open port was read with `-sV` is the `inv_service.read_at` of the `nmap` row, inventory INV-23, read through `Services.PortReadTimes`; normal scans and `port_versions` scans move it, port discovery does not) (outside `ExtraPorts` and outside the ports read in the last 6 days, which are the ports the latest normal scan saw open); a device answering on more than `commonports.MaxBelievableOpen` (40) ports, or on so many that nmap's output is refused (more than 1500 ports, over the cap): records `answers_everywhere` ("answers on every port (a firewall or SYN proxy); the weekly scan learns nothing"), counts as done for the week, no `port_versions`, no ports added. The `port_versions` job carries the port list on the wire (`ports`, sensor protocol) and is only handed to a worker whose heartbeat has `nmap.ports` (`ErrPortsUnsupported`: the ports are recorded without versions). Devices that are due: never scanned or last scan ≥ 7 days ago (`sa_all_ports.last_at`), never-scanned first, then the oldest. **Never** for devices that are fragile, of unknown type, "never", still waiting for their gentle scan, the box itself (by policy **and** by `BoxIPs`: every scheduled device scan checks the box's and decoys' addresses), manually declared or out of scope (`allPortsPlan`; checked when choosing, again under the lock right before nmap with the kind registered at the start, and while running: `checkRun` on a device change **or a settings change** (fragile kinds, regularly scanned kinds) stops the run when the device no longer qualifies); a device that does not qualify is recorded as `not_eligible` and considered again after 7 days. **Priority**: Scan now identification and exposure scans (`lockWithin`) stop the running weekly run (the partial result is dropped, the device is still due) and take the slot at once; the weekly round starts no device while someone is waiting, and continues at the next tick of the window or the next window. A run cut by the window, the settings or the user is still due; a run that fails otherwise, or whose result fails to be written, is retried **once in the next window** (`retry`, kept out of the rest of this window), and a second failure waits **until next week** (`failed`), never daily; a cancellation by a user scan (context cancelled) is always a stop: nothing is written, the device is still due. Results are written straight into the store, **scoped to what the scan looked at** (there are no more per-device JSON copies): services through `ReplaceServices` scoped to every TCP port (`<scaninfo>`) **except the ports read with `-sV` in the last 7 days that this run did not see open** (discovery tries each port only once, `--max-retries 1`: one dropped answer packet does not wipe the product, version and `read_at` the normal scan read; the next normal scan, or the next week's run once the port is older than 7 days, decides; `weeklyScope`, `TestAllPortsLeavesAPortANormalScanReadThisWeek`), `NoVersions` (ports no longer open are deleted, ports with no product keep the existing product, inventory INV-23), then (separate transactions: software, discovery and reads are three writes; one failure turns the weekly run into `retry` and it runs again in the next window, so until then the service and software rows of a read port may disagree) a second `ReplaceServices` scoped to exactly the ports `port_versions` read (no `NoVersions`: the name, product and version of those ports are what the read says, even nothing, and their `read_at` moves forward, so next week other ports are read first); products `port_versions` read go into the `nmap` software with `Instance` = `observe.PortInstance(port)` through a `ReplaceSoftware` scoped to exactly the ports read (a changed version replaces the old one; a port that no longer answers loses its reading), and the normal scan's software and the guessed OS are not touched. A normal scan replaces only the ports it looked at (top 1000 plus `ExtraPorts`, taken from the `<scaninfo>` of both scans, a scoped `ReplaceServices`) and the software with an empty `Instance`, `stated`, or the `observe.PortInstance` of the ports it saw open (a scoped `ReplaceSoftware`: an old `port_versions` reading on a port the normal scan read itself does not stay next to the new one, `TestNormalScanReplacesTheFollowUpReadingOfItsOwnPorts`): ports the weekly run found outside that scope, and their software, are kept **until the next weekly scan sees them or not, or 14 days** after they were last seen (`KeepFor`, `allPortsKeep`), whichever comes first; the store's 90-day rule still applies. A gentle scan never updates products (product and version are dropped before `AddServices`). Rows of devices no longer in the store (`Asset` returns `ErrNotFound`) are deleted by the weekly round; a device that only lost its address is kept. Estimate: 65535 half-open SYNs at 50–100 packets/second = 11–22 minutes when the device answers, at most 44 minutes when the device drops every packet; the default 7-hour window fits about 10–18 devices a night. `TestAllPortsOncePerWeekAndNeverForAFragileDevice`, `TestAllPortsNeedsRoomRateAndAKnownSafeDevice`, `TestAllPortsAddsPortsKeepsSoftwareAndTheNextWeekReplacesTheCarry`, `TestNormalScanKeepsThePortsOfTheWeeklyRunFor14Days`, `TestNoPerDeviceJSONCopiesAfterAScan`, `TestAllPortsGivesWayToScanNow`, `TestAllPortsStoppedDuringTheFollowUpRecordsNothing`, `TestAllPortsDeviceThatAnswersEverywhereIsDoneForTheWeek`, `TestAllPortsFailureRetriesOnceThenWaitsAWeek`, `TestAllPortsVersionChangeReachesSoftwareAndServices`, `TestAllPortsFollowUpRotates`, `TestAllPortsFollowUpPicksByTheInventoryReadTimes`, `TestAllPortsCleanupKeepsADeviceWithoutAnAddress`, `TestAllPortsStopsWhenTheDeviceTurnsFragile`, `TestExtraOnlyHostOnlyAddsPorts`, `TestExtraRunFailureKeepsTheTop1000Result`, `TestPortVersionsNeedsAWorkerThatSaysSo`, `TestMergeExtra`, `TestExtraPorts`, `TestAllPortsShape`; worker `TestRunsAPortVersionsJob`; `cmd/vedette` `TestSensorActiveScansADiscoveredDevice`.

## Preconditions / Postconditions
- **PRE-1** (`DiscoverRanges(ctx)`): INV-2, INV-3 hold, nmap is present. **POST-1**: every address of the scope (but the network and broadcast address of a range wider than /31 and the protected addresses) is probed at most once per pass, in batches of at most 64, block by block (INV-29: known /24 blocks first); the settings and the window are read again before every batch; the pass is one `lan_sweep` run whose step done counts are its cursor: a window that cuts it goes on from there in the next window, a range added during the pass is swept in it, and a pass that reached its end is followed by a new one (`TestSweepCutByTheWindowResumesWhereItStopped`, `TestSweepNewPassStartsAfterTheLastEnded`, `TestRunsARangeAddedMidPassIsSweptInIt`); a scope one pass of which would not end within a week of windows is refused when it is saved (inventory INV-32); results go to the inventory; event `sensor.scan.finished {job_id, targets, new_devices, status}` (job_id is the run).
- **PRE-2** (`ScanDevice(ctx, assetID, reason)`): `ScanPolicy.allowed=true`, the window is open, the address is still in scope. The refusal reasons `scanning_off` and `scope_not_confirmed` are states of the box, not of the device: they return `ErrScanningOff`/`ErrScopeNotConfirmed` and the device **stays in the queue** (`TestScanningOffDuringDrainKeepsTheQueue`); only reasons specific to the device (`box`, `declared_by_hand`, `regular_scan_never`, `*_passive_only`, `out_of_scope`...) drop it from the queue. A run stopped while still checking (settings or device changed) returns `ErrStopped` and does not count as an attempt (`TestSettingsStopDuringPreChecksIsNotAnAttempt`). **The `scan` module must treat the reason `first_gentle_scan` as a refusal** (it only allows sensor-active's gentle scan, not a normal scan). **POST-2**: `first_scan_at` is set if it is the first scan of a fragile device; if blocked, `sensor.scan.blocked {asset_id, reason}` is emitted and no packet is sent.
- **PRE-3** (the window ends midway, a settings change no longer allows it, the module is turned off). **POST-3**: the nmap process group is killed, the running batch is dropped, finished batches stay stored, the job is marked `stopped` (a job still `running` after a restart is closed at the next tick). A stop of a pass's batch for a reason of its own (`stopCur`: a device of the batch protected now, an exclusion or a lower rate saved, the window shortened) stops **that batch only** (`batchCtx`): the pass reads the rules again and sweeps the batch again from its cursor at once (without the address that left, at the new rate), or waits for what no longer allows it (scanning off, the scope, the window) with that reason; its log says "A batch was stopped because …; it is swept again". It never ends on a bare "stopped" (`TestSweepStopsWhenADeviceItProbesIsTurnedOff`, `TestContract_INV1_ExclusionAddedMidRunStopsIt`, `TestContract_INV4_LoweringTheRateStopsTheRunningJob`, `TestContract_INV3_SettingsChangeStopsTheRunningScan`).
- **POST-4**: `DiscoverRanges` counts new devices **by MAC**: a MAC already in inventory (`KnownMACs`, read once at the start of the run, no row limit) is free whatever its IP (DHCP changes IPs); every unknown MAC is charged to discovery's own new-device budget, even at an IP inventory already has. Budget: `capture.FloodBudget` with **1,000 new devices/minute and 1,000/hour** (enough for a new install to discover the designed scale of 1,000 devices in one run without a passive sensor, while a compromised `scan` container cannot create 65 thousand fake devices on a /16), in memory. Each target only counts the first entry of the result. New hosts beyond the budget are dropped (log `dropped`), the cursor still moves on, and the next run sees them again. A write error does not charge the budget yet. Each sensor has its own counter: this budget is not shared with the passive sensor's 60/200. Tests: `TestRecordSweepStopsAtTheNewDeviceBudget`, `TestRecordSweepChargesByMACNotByIP`.

## Forbidden
- **FORBID-1**: Scanning IPs outside the `inventory` scope; scanning public ranges (that is `exposure`'s job). The only exceptions: the `external` shape (and the two deep shapes of INV-19) and the nuclei `own_ip` job on exactly the box's own outgoing Internet IP, when exposure calls and both own-IP fences agree (INV-16; INV-17); and the `domain_ip` job of INV-20 when the worker's domain fence agrees.
- **FORBID-2**: Scanning before the scope has been confirmed.
- **FORBID-3**: Calling nmap through a shell command string; adding flags outside the allow list. No shape uses a script category expression; long script lists only exist in the two deep shapes `external_full`/`external_disruptive` (INV-19), each exactly one fixed reviewed list (`nmapargv.FullScripts`, `nmapargv.DisruptiveScripts`; new scripts of a newer nmap do not get in by themselves), one argv element, never `--script-args`; every other shape keeps its pinned script list (`TestNoShapeWidensScripts`).
- **FORBID-4**: Shipping or embedding nmap (NPSL).
- **FORBID-5**: Periodic repeated scans of fragile devices without permission.
- **FORBID-6**: Running exploits or NSE scripts beyond what `-sV` runs by itself, the two script lists of the deep shapes on the box's own public IP after the testing terms have been accepted (INV-19; only the `external_disruptive` shape, with its tick, has `dos`/`brute`; no shape has `external`/`broadcast`) and **exactly the pinned list `rdp-ntlm-info,http-ntlm-info,http-title,ssl-cert,http-hp-ilo-info,vmware-version`** of the normal/versions shapes (each NTLM script sends one NTLM NEGOTIATE without credentials and reads the CHALLENGE, never AUTHENTICATE, so it does not log in; `http-title` sends one GET "/" and reads the title, `ssl-cert` does one TLS handshake and reads the certificate subject, both in nmap's "default, safe" categories; `http-hp-ilo-info` sends one GET `/xmldata?item=all` and `vmware-version` one SOAP POST `RetrieveServiceContent` to `/sdk`, both in the "safe" category, no login, INV-25); never categories, wildcards, `default`/`safe`, `-sC`, `-A`, or scripts that open sessions (such as `smb-os-discovery`: an anonymous session, then guest) (the argv grammar does not have them). Fragile devices get no `-sV` or scripts (gentle scan). Devices of unknown type that are not fragile get `http-title`, `ssl-cert`, `http-hp-ilo-info`, `vmware-version` in their gentle scan (`nmapargv.TitleScripts`, each script at most 20 s) and nothing else.

## Events
- **Emits** (after the write transaction commits): `sensor.scan.started {job_id` (the run), kind: "sweep"|"device"|"snmp", targets}` (snmp: `targets` = 0 at the start of a window's round, 1 for Check now) (discovery: `targets` = the number of addresses in the ranges before exclusions are removed), `sensor.scan.finished {job_id, targets, new_devices, status: "done"|"stopped"|"failed"}`, `sensor.scan.blocked {asset_id, reason}` (the reason is `ScanPolicy`'s reason, or `scanning_off`, `scope_not_confirmed`, `out_of_scope`; no packet is sent). Go types: `StartedEvent`, `FinishedEvent`, `BlockedEvent`. `TestEventPayloads`
- **Consumes** (registered in `cmd/vedette/sensoractive.go`, acting only when the module is on): `inventory.asset.discovered` → a `device_check` run waiting for its turn in the window (`Enqueue`); `inventory.settings.changed` → `SettingsChanged` (stops the running run if the settings no longer allow it); `inventory.asset.updated` and `inventory.asset.deleted` → `AssetChanged` (stops the SNMP batch containing the device; stops the running device scan if that device has left the address the scan is probing (an address move, or another device taking the address, inventory INV-35 (5); each nmap run of a device scan also re-reads the device right after publishing the target, so a device that leaves the address between the two scans of a run, while the target is empty, is not scanned a second time and the first scan's result (recorded by address) is dropped, the run `stopped`, `TestADeviceThatMovedBetweenTheTwoScansGetsNoSecond`) or no longer passes `ScanPolicy`: marked fragile, `never`, manually declared, deleted; or the run is heavier than the policy allows now; not counted as an attempt; `TestSensorActiveDeviceChangeStopsTheRunningScan`; other devices are not affected). Module off → `core/jobs` cancels the running run at once. A merge or delete of a device is not an event here: `DeviceMerged`/`DeviceDeleted` run inside the inventory's write (core/lifecycle, registered by `sensorActiveService`), whether or not the module is on. Delete: its queued and waiting runs are stopped, the SNMP settings with their secrets and the weekly port record go; finished runs stay as a log. Merge: the runs of the merged device become into's; the weekly port record moves unless into has its own; SNMP: from's settings move when into has none; when both have some, the ones whose last read answered (then the later answer, then the later save; into's on a tie) stay, the others go with their secrets and a notice names both (`sa_snmp_notice`).

## Schedule
`window-tick` every minute: when the window is open, continues **the existing discovery run** (a `waiting` run is resumed from its cursor). **New runs are created by the `inventory.sweep` schedule** (core/schedule, key `ScheduleKey` = `inventory.sweep`, owner `ScheduleOwner` registered in `cmd/vedette/sensoractive.go`, daily at 22:00 by default, held until the window opens; `Service.startSweep` queues the run inside the schedule's transaction, also when the schedule is run at once (manual trigger, with the same `SweepGap` check); skipped with a reason when scanning is off, the scope is not confirmed, nmap is missing, or an unfinished run already exists); the window is still the run's safety limit. Order within a tick (INV-29): devices never checked yet (at most 25, INV-27), **one SNMP read round** per window (INV-10 (f)), the discovery run (waiting devices interleaved between batches), then the remaining devices in the queue (an nmap error or **timeout** midway counts as one attempt and moves the device to the end of the queue, at most 3 times and then dropped, so one unfinished device does not block the devices behind it; stops because of a settings change do not count; blocked by policy → dropped from the queue; `--host-timeout` bounds the time per host), then the **weekly all-ports scans** (INV-20 (b)), one device at a time, while the window still has `nmapargv.AllPortsWindowRoom` (120 minutes). `prune-probes` daily. Only one nmap process at a time on the box, and one snmp job (`snmpMu`, separate from `runMu`: a Test does not wait for a two-hour discovery run, it only waits for one SNMP batch for at most 30 s, then returns `busy`).

## Behaviour when off
No jobs, no nmap/SNMP processes (the `active` role routes return `409 module_off`, the worker kills nmap, the host stops the `scan` container); devices only have passive/agent/manually declared data (no OS, services, versions); new fragile devices get no first scan; the `/inventory/snmp*` routes return 404, no SNMP reads, and the devices' SNMP settings are kept. `scan` still runs with the existing data but finds fewer products.
