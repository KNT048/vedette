# Feeds — Change Impact Map

> Last verified: 2026-11-21 (every sentence checked against the code)

## Modifying: `feeds.Store` — `VulnByCVE(cve)`, `VulnsByProductKey(key)`, `HasTemplate(cve)`, `IOCLookup(value)`, `IOCListed()`, `IOCSubdomainsOn()`, `KevPairs()`, `HaveSince()`
- `HaveSince`: **findings** (`ServiceConfig.HaveSince`, INV-11 of findings) matches the versionless software of a product answered "I have this", on exactly the device that was declared, only from `have_since`. `feeds.Inventory.AddManualDevice` returns the device id ("" = unknown, scope off). Changing `have_since`/`device_id` = changing the finding count of that device.
- **inventory** (`catalog`, product↔KEV matching by the lowercase key `vendorproject|product`): changing how the key is normalised = every "Do you have it?" match is off.
- **mitigation** (`KevInfo` in `FindingRow`, through `findings`), **scan** (`has_template`), **mcp-server** (`lookup_cve`, `lookup_ioc`), **ai** (slot `cve.panels`, `lookup_ioc`), **reports** (`NewlyExploited`, the KEV section), **notify** (the `new_kev` event), **logs** (`IOC*`).
- **logs** (`cmd/vedette/logsioc.go`) and **ai** (`lookup_ioc`, `cmd/vedette/ai.go`): `IOCLookup` decides what they report about an indicator. `honeypot` and `response` do not read feeds directly.

## Modifying: `feeds.Fetch(ctx, feedID)` and the event `feeds.vuln.new_kev`
- **inventory** (match again), **scan** (rescan within ≤ 60 minutes if `has_template`), **mitigation** (check whether a package exists yet). Renaming the event or its fields = silently losing the automatic rescan.

## Modifying: `feeds.ParseFeed(ctx, data []byte, kind Kind, p Parser) (Result, error)`, `ParseSource(ctx, src Source, data)` and the limits (5,000,000 bytes, 50,000 rows; a built-in source has its own `Source.MaxRows`)
- **feeds** (the real pull, `parse-test`), **SPA** (`ParserEditor`, `parsers.ts` must give the same result as Go: a cross test on the same samples `modules/feeds/testdata/samples` and `testdata/golden`). Go is stricter than TS on IPs (netip, dropping private/special addresses), domains (public suffix, local names), control/hidden characters, empty-file hashes: a TS sample with documentation IPs (198.51.100.x, 203.0.113.x) is dropped by Go.
- Changing a signature that has `ctx`: every caller (pull job, `parse-test`) must pass a ctx with a deadline; a ctx cancelled midway returns `ctx.Err()` and no record at all (fail-closed). A cell longer than 4096 bytes does not run the regex (dropped); a regex that compiles to > 1000 instructions gets `ErrBadConfig`.
- Errors: `ErrTooLarge` (→ 413 `too_large`), `ErrBadConfig`, `ErrBadSample` (→ 400); the displayed sentence is in `(*feeds.Error).Detail`. `Result.Records` contains every accepted record; `Result.Preview()` cuts the first 20. `CheckParser(kind, p)` checks the configuration before saving.
- `Reason.Example` (`json:"-"`): the first row of each group with the value shown; only `note`/`accepted` (the status sentence of a pull, stored in `feeds_source.error`) read it. Whoever receives that sentence (SPA, notify) draws it as plain text.
- `reasons[]` groups by message pattern, at most 50 groups + `other`; a value is quoted with `%q` and cut to 40 characters. A feed value is untrusted plain text: consumers (`notify`, `reports`, `ai`, SPA) must escape according to their own environment.
- `rejects[]` (S-FEED-5): `row` is the line number of the sample for `lines` (`rawRow.line`, counting comments and blank lines too; a hosts-file row with several names gives the same line number), the record number for other formats; `ParserEditor` shows each row with a `reason` that has the value (plain text, escaped by React) because only `parse-test` returns it. Do not put `rejects[]` into the pull status or any other stream: only the masked `reasons[]` goes there. Changing a reason sentence = changing the group key of `reasons[]` (the "Most often" status) and `testdata/golden`.
- Changing the normalisation (IP through `netip`, lowercase domain/hash, UTC date) or the list of dropped addresses/names = changing the IOC match key of **honeypot/logs/response**. A hosts-file style row (`0.0.0.0 name`) yields the name, never the target IP.

## Modifying: `Fetcher.Fetch(ctx, Request)` (one GET to exactly the URL)
- **feeds** the pull job and `POST /feeds/sources/{id}/fetch`. Redirects: same host only (`ErrRedirect`), no downgrade https→http, at most 5 hops, `Referer` dropped. Changing this policy = changing which hosts the box can contact (INV-1, INV-13, `PRIVACY.md`).
- Connection (`NewClient`): always refuses link-local (169.254/16, fe80::/10), cloud metadata addresses, unspecified and multicast; `http` only to private/loopback IPs (an internal name that points to a public IP is blocked); DNS is resolved once per connection (against DNS rebinding); the environment proxy is not used. A self-supplied `Fetcher.Client` must go through the same protection (only used in tests).
- Fixed outgoing headers: `User-Agent: Vedette/<version>`, `Accept`, the conditions `If-None-Match`/`If-Modified-Since`, the feed's authentication. Adding a header = changing the outgoing data flow (legal.md).

## Modifying: `State.RetryAt/Due/Record`, `IsStale`, `Backoff`, `Service.ScheduleOwner` (pull schedule, INV-5/8/9) and `Judge`, `IOCKey`, `NewWhitelist`, `SightingOf` (IOC verdict, INV-12)
- The schedule of each source is a `core_schedule` row `feeds.source:<id>` (`feedschedule.go`: the owner `feeds.source` of `core/schedule`, interval only, limits `scheduleLimits` 1…168 hours; the API's `interval_hours` is read from there, not stored in `feeds_source`). The schedule does not pull by itself when due: the `pull` job (`PullEvery` 5 minutes) compares `State.Due` with the time the schedule was last due (`scheduledDue`). Seed and `POST /feeds/custom` create the schedule through `ensureSchedule`; deleting a custom feed deletes the schedule. Changing the interval limits = changing the schedule editor and the feed dialog too.
- **feeds** job (schedule, error state in Settings → Feeds): a timestamp in the future (wrong clock) counts as due and stale. **honeypot/logs/response** read `verdict`: changing the block/alert thresholds = changing the response rules.
- `Judge` normalises the source id (trim whitespace, lowercase) and takes the flags of a built-in source from the registry: an aggregated source (`ipsum`, `hagezi-tif`) never `block`s on its own and does not count as a second source when its origin is present; `tor-exit` is informational and not counted toward `block`; a CC0 source (abuse.ch) is enough to `block`. The whitelist accepts `google.com`, `*.google.com`, `.google.com` equally, an invalid entry is the error `ErrInvalidWhitelist`.
- Private/special IPs and local names/public suffixes never get a verdict (a second layer of protection after the parser).
- `localName` also includes `testName` (`example.com|net|org` and names under them, `*.test|example|invalid|localhost`): `Judge`/`IOCKey` no longer accept those names, so **logs** (DNS/connection matching, `cmd/vedette/logsioc.go`), **honeypot**, **response** and search never match them; tests of other modules that use fake names `*.example.*` as IOCs must switch to another name (`cmd/vedette/logs_test.go` has been changed).

## Modifying: the way a pull applies an IOC list (`applyIOCs`, `iocChunkRows`, `Service.afterChunk`)
- **core** (`core/store` writer, one connection): every write of the box queues behind the transaction that is open. Raising `iocChunkRows` or going back to one transaction per list makes boot, login, setup and every other module's write stall for as long as the list takes (~20 s for 250 000 rows). Keep each transaction short. `iocChunkRows` is a `var` only so that the package's tests run with 200 (`TestMain`, store_test.go); the chunk tests are written in units of it.
- **logs / honeypot / response** (future `IOCLookup` readers): during a pull they see the old and the new listings together, never fewer; a pull cut off halfway leaves extra listings until the next pull (`maintain` never touches `feeds_ioc_source`). A feed switched off mid-pull keeps the committed chunks until it is pulled again (switched-off feeds' listings are kept anyway). A new reader must not assume a list is applied atomically.
- **logs** (digest `ioc_matching`): `IOCListed` says whether a switched-on feed lists at least one indicator (`feeds_ioc_source` joined with `feeds_source.enabled`); a change in what counts as listed changes when the Logs page says that nothing can be matched. Test: `TestIOCListedNeedsASwitchedOnFeedWithListings`.
- **logs**: `IOCSubdomainsOn` says whether a switched-on built-in source with `Source.Subdomains` exists (`feeds_source.enabled`, `builtin`); false makes logs skip the parent walk of unlisted names. Setting `Subdomains` on another built-in source turns the walk on with it. Test: `TestIOCSubdomainsOnFollowsTheSwitchOfHageziTIF`.
- **logs**: `IOCLookup` returns `IOCSighting.Enabled` (the feed is switched on now); the logs adapter (`cmd/vedette/logsioc.go`) ignores sightings of switched-off feeds, whose listings stay in `feeds_ioc_source` until the feed pulls again. `/feeds/search` (`iocHit`, which MCP `lookup_ioc` reads) and the AI `lookup_ioc` (`cmd/vedette/ai.go`) skip them the same way: an indicator that only switched-off feeds list is not listed (POST-4).
- **logs**: `IOCLookup` returns `IOCSighting.Subdomains`, true only for a sighting of a built-in source with `Source.Subdomains` (today `hagezi-tif`, whose list says "Domains (without subdomains)": a listed name stands for itself and all of its subdomains); a custom feed is always exact. The logs adapter puts those feeds in `Listing.SubFeeds`, and logs then matches a subdomain the device asked for through the nearest listed parent. Setting the flag on another built-in source (or a URL/variant change of `hagezi-tif` to a list of exact names) changes which subdomains logs reports as bad connections: measure what the list means first.
- **core export** (`export_policy.go`): `feeds_ioc_source.seen` stays in the export list but nothing reads or writes it now.
- Not chunked: `applyVulns`, `applyTemplates`, `applyEPSS` (a custom vulnerability list is capped at 50 000 rows, about 3 s). Raise that cap and these need the same treatment.
