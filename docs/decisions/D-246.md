| D-246 | **Server-side wait limit on the database writer (issue #251, INV-29 of core).** (1) A request waits for the single writer at most `store.RequestWriteWait` = **5 s**, set on the request context by `core/server` (every API route) and by the sensor link wiring (8444); past it `Write` returns `store.ErrBusy` before running anything, the API answers **503 `server_busy`** with `Retry-After: 5` (the code logs search and the password hashing gate already use; body shape of API_CONVENTIONS 3.1), the sensor link `503 store_busy`. Never 500, never a silent hang. (2) The limit lasts only while the request does: work detached with `context.WithoutCancel` keeps the context value but waits on its own context once the request has ended, so a scan run or an audit row started by a request is not cut short. (3) **Jobs and other background work have no limit** and wait on their own context (feeds pull, retention, scan, job history): they are not waited on by a person, and failing them on a busy writer would only add retries; the risk they carried, holding the writer, is made visible instead by (4). (4) Every write transaction that holds the writer longer than `store.SlowWrite` = 1 s is logged as a warning with the module and the calling function (from the stack) and the duration; no SQL text, no values (security.md). A refused request logs one warning with its caller. (5) Only the wait for the connection is bounded (`sql.DB.Conn` with a timeout context); the transaction itself keeps the caller's context, so a slow but started write is never rolled back by the limit. Not chosen: one global limit for every caller (HikariCP style), because a job queued behind a feed chunk would fail for no gain; a configurable value, because no one has asked for one (ponytail). | Connection-pool checkout timeouts of the leading stacks bound how long a caller waits for a busy connection and fail it with a typed error instead of hanging: Rails `checkout_timeout` default 5 s, `ActiveRecord::ConnectionTimeoutError` (https://api.rubyonrails.org/classes/ActiveRecord/ConnectionAdapters/ConnectionPool.html); HikariCP `connectionTimeout`, `SQLTransientConnectionException` (https://github.com/brettwooldridge/HikariCP#gear-configuration-knobs-baby); PgBouncer `query_wait_timeout` (https://www.pgbouncer.org/config.html). 503 with Retry-After for a temporary overload: RFC 9110 15.6.4 (https://www.rfc-editor.org/rfc/rfc9110#section-15.6.4). 5 s matches the logs search limit and the SQLite `busy_timeout(5000)` of the store. | 2026-11-11 |
