| D-229 | **External exposure scan: the `scan` module's runner, Go standard library, in `core` (S-EXP-1; exposure INV-12, scan INV-12).** (1) **Owner and switch:** `exposure.Runner` is the `scan` module's (D-55), built in `cmd/vedette` (`scanRunner`) over the leaf package `modules/scan/surface`, set as `exposure.Config.Runner`. It runs only while `scan` is on; off, `POST /exposure/targets/{id}/scan` answers 409 `module_off` after the ownership gate and nothing is probed. 501 `not_implemented` stays only for a build with no runner. (2) **Standard library, not ProjectDiscovery:** a TCP connect (`net`), `crypto/tls`, `net/http` and `encoding/json` do what the scan needs from the box's own network; naabu needs pcap/cgo for SYN scans and httpx/subfinder pull large dependency trees into `core`'s `go.mod` (the reason D-125 kept nuclei out of `core`). It runs in `core`, which already makes outgoing HTTPS; no raw socket, no new dependency, no container job. THIRD_PARTY_NOTICES drops httpx/naabu/subfinder/dnsx from "planned". (3) **Targets:** only what exposure hands over after INV-1/INV-13. A domain's names come from certificate transparency at crt.sh (one search per scan, asked again once on failure, 45 s, streamed, at most 200 names, only valid names under the domain, no wildcards), then A records; a name is probed only when its address passes `exposure.IsPublicIPv4` (a name on a private address is listed, never dialed), at most 32 addresses; every dial checks the rule again and goes to the planned address (no re-resolve, no proxy). This settles exposure's open question on subdomain IPs: EASM products scan the hosts that a verified domain's names point at; the D-26 commitment covers them. (4) **Probes:** TCP connect (nothing sent) to a fixed list of 98 commonly exposed ports, about naabu's top-100 default but chosen for what attackers probe first (admin and web, remote access, file sharing, databases, mail, VPN, devices, out-of-band management; no UDP), 1.5 s a dial, at most 300 new connections a second and 100 at once; one `GET /` per (name, open web port), Host and SNI = the name, Go's default User-Agent (D-81's rule), TLS not verified (the page and certificate are read, never trusted), 64 KiB, 8 s, redirects followed only on the same scheme, host and port (httpx does not follow redirects by default; `-fhr` follows same-host ones); a TLS handshake on the other TLS ports for the certificate; at most 64 pages/handshakes; the whole scan at most 5 minutes. A built-in list of page fingerprints (title, a few headers, product-only markers; never a word an ordinary site could contain) names admin pages: `danger` for network/firewall, NAS, server and out-of-band management, and tools that run code (several are on CISA KEV); `warn` for applications with their own sign-in often published on purpose; VPN portals name the port only. Probes are logged (`exposure_scan_ct`, `exposure_scan_ports`, `exposure_scan_page`) and the scan has its `exposure.scan` audit row. (5) **Failures save nothing:** crt.sh not answering, or the time cap, is 502 `unreachable` with a sentence that says so; a snapshot without the subdomains would make the day comparison report them gone. (6) **Hairpin, said honestly:** the box scans its own public IP from inside, through the router (NAT loopback); a router may show its own login page only to the inside, one without loopback shows nothing. The results page says this instead of "scans from outside". Not chosen now: an outside view from a third party (Shodan InternetDB, free, no key) would remove the limit but is a new outbound flow of the customer's IP, which needs kien (decide-like-top-tier: new data flow); recorded as deferred.
