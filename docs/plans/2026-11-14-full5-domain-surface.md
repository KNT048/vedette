# FULL-5: map a verified domain's surface and scan each part at the depth its terms allow

Owner: AI-Mlee (exposure: discovery, classification, UI, terms, gating, CONTRACT INV-27). Touch points owned by AI-Trưởng (scan container worker, host ops, fence key, images) are marked **[T]**.
Status: plan only. Decision: D-567 (`docs/decisions/D-567.md`). One question for kien (§9, K1) gates slice 4 only.

**kien (2026-11-14):** "for a domain target, after ownership is verified, map the surface (subdomains via cert-transparency + DNS, their IPs/web apps) and scan each."
**Done:** on the N100, a verified domain shows its subdomains, their IPs and web apps, and each one is scanned at the depth its testing terms allow; what was not scanned says why.

## 1. Today

- **Discovery** (D-229, exposure INV-12, `modules/scan/surface`): crt.sh names (expired certificates excluded, more than 300 names → 400 `too_many`, crt.sh down → 502, whole or nothing), each resolved for A records only (`resolveAll`, `"ip4"`), kept as `HostRow {name, ip}` with the first address only. No CNAME, AAAA, MX or NS; a name with no publicly logged certificate (a VPN portal or `mail.` with a self-signed certificate) is never found.
- **Scanning a name** (D-57 (7), LEGAL §3): `GET /` on 80 and 443 by name with its certificate; passive ZAP by name (INV-24, at most 4 pages a run); read-only nuclei only on the box's IP (D-520). An address a name points at is port-scanned only when `ScannableIP` says it is the box's own verified egress IP.
- **Terms** (D-566, INV-26): per target; `Mode.Full` makes every scan of the box's IP a deep scan; for a domain, FULL-3's active web tests go only to names that resolve to a verified box IP. The text already says "Accept only if {value} is yours alone … not … a CDN or hosted service that serves your names".
- **Fences** [T]: the scan container worker re-checks the box's egress (2 of 3 services) before any job on a public IP (`own_ip`, D-520, plan 2026-11-13 §1.3); the host's `zap.baseline` re-checks the domain's TXT and that the name still resolves to the pinned IP (`zapOwned`, D-521 (1)).
- **Gap found while planning (for [T], fixed in slice 3):** both fences take the TXT **token from core**. A TXT value is public, so a compromised core could pass another Vedette customer's domain with that domain's visible token and the fence would agree. Today that reaches only passive ZAP; with FULL-5 it would reach port scans. The fence must check a token it can derive itself (§5).

Providers' own rules for testing through them: Cloudflare permits scans of "Customer-owned IPs", "Cloudflare's designated public IPs" and "The customer's registered DNS entries", testing "application and network-layer aspects of their own assets … without attempting to actively exploit" ([policy](https://developers.cloudflare.com/fundamentals/reference/scans-penetration/)); AWS lists CloudFront among services testable without approval, and prohibits DoS, "port flooding", "request flooding (login request flooding …)" and "DNS zone walking via Amazon Route 53 Hosted Zones" ([AWS policy](https://aws.amazon.com/security/penetration-testing/)). A SaaS platform (GitHub Pages, Shopify, Wix…) runs the vendor's application, not the customer's: no leading product treats it as the customer's to attack.

**Reading:** everyone discovers broadly (CT + DNS records; Detectify adds a curated wordlist); nobody deep-scans what discovery found without a human saying "this is ours" (Intruder: add it; Qualys: enable scan after attribution); CDN edges are excluded from network scans by default (Qualys) and reached by hostname (Intruder); proof of a single IP beyond the domain is a separate step where it exists at all (Detectify file).

## 3. Decisions (D-567)

1. **Discovery = CT + DNS + MX/NS + a small wordlist.** For each crt.sh name (wildcards `*.` dropped) and the apex: A, AAAA and the CNAME target (`LookupCNAME`: the final canonical name), through the box's own resolver (the system resolver, as today). The apex's MX and NS hosts are added as names when they are the domain or under it; outside it they are listed as "provider" lines (e.g. "mail: Google Workspace") and never probed. **Wordlist: yes, bounded** (Detectify's standard practice, and what attackers try first): a fixed list of ≤ 150 labels (`www`, `mail`, `vpn`, `remote`, `owa`, `portal`, `admin`, `dev`, `staging`, `api`, `git`, `jenkins`, `fw`, `nas`…) shipped in `content/edges/labels.txt`, after a wildcard check (two random 20-character labels; any answer → the wordlist is skipped and the page says why), at most 20 lookups a second, one scan per run. ~150 queries to the customer's DNS provider through a recursive resolver is ordinary load and is not zone walking (no NSEC walking, no AXFR). Not chosen: passive DNS (a paid third-party feed and a new outbound flow of the domain), AXFR (a direct connection to the customer's name servers), a big wordlist (load without proportionate finds).
2. **The 300-name rule stays whole or nothing** (D-229 (6)), counting CT + wordlist + MX/NS names: the listing is complete, so day-to-day "gone" rows stay true. Caps apply to the **expensive steps**, which rotate (§4) and are listed as "not scanned this run", never to the listing.
3. **Every (name, IP) gets one class**, decided in core and again by the fence from the same shipped list:
   - `box` — the IP is this box's verified, current IP target (`ScannableIP`): the full IP pipeline as today, by IP and by name.
   - `edge` — a CDN/reverse proxy (Cloudflare, CloudFront, Fastly, Akamai, Azure Front Door, Google Cloud CDN, Imperva, Sucuri): by IP range or CNAME suffix. **By name only on 80/443**: the D-229 checks, passive ZAP, and, with the domain's terms `Mode.Full` and once kien says yes to K1 (b), the active web scan and http nuclei by name (FULL-3/4), **never** the disruptive checks (Cloudflare and AWS forbid DoS and request flooding), **never** a port scan, nmap or Greenbone of the edge IP (it is the provider's machine; Qualys excludes CDN by default).
   - `hosted` — a SaaS or shared platform (GitHub Pages, Shopify, Wix, Squarespace, Webflow, Netlify, Vercel, Heroku, Google Sites, Microsoft 365, Zendesk, HubSpot; shared-hosting PTR suffixes such as `secureserver.net`): the D-229 checks only, plus the **subdomain-takeover check** (a CNAME to the platform whose page says the site does not exist: "There isn't a GitHub Pages site here", Heroku "No such app", S3 `NoSuchBucket`), a finding of its own. The application is the vendor's, so nothing active.
   - `other` — any other public IPv4 (an office static IP that is not the box's egress, a VPS, a cloud VM): listed with its PTR name and cloud tag (e.g. "AWS EC2 eu-west-1", from the same lists), the D-229 checks and passive ZAP by name (K-4 scope, as today). **Deep scans only after an admin adds it as a server** (decision 4), and only once kien says yes (K1).
   - `private` (non-public address): listed, never dialed (today). AAAA: listed, "IPv6 is not scanned yet".
   The list is **content shipped with the release**, signed like every release (`content/edges/`, `edges.source` + generator `scripts/edges`, the pattern of `content/oui`): Cloudflare `ips-v4`, AWS `ip-ranges.json` service `CLOUDFRONT` (and EC2 for the cloud tag), Fastly `public-ip-list`, GitHub `meta` `pages`, Google `goog.json`/`cloud.json`, Azure service tags (`AzureFrontDoor.Frontend`), CNAME suffixes for the rest (Akamai publishes no edge list). No live lookup to any provider from the box. Unknown means `other`: the default leans to "needs your OK", never to a deep scan.
4. **A non-box server is scanned deeply only after an admin adds it** (Intruder: the user adds discovered targets; Qualys: scan after attribution). "Scan this server" on an `other` row opens the **server's testing terms** (INV-26 flow, admin + two-step): "I confirm that the server {ip}, which {name} points at, is dedicated to my company (not a shared hosting server, a CDN or a hosted service) and that I am authorized to test it in depth …" + the existing list, risk and disruptive tick. Accepting creates a **server target** (decision 5); withdrawing returns it to `other`. No HTTP file proof on the IP (Detectify's single-IP method): a mail or VPN server cannot serve one, and the fence (§5) re-proves the DNS link at every step.
5. **A server is an `exp_target` of kind `server`**, so the whole existing IP pipeline (port scan, nmap -sV, CVE match, nuclei, ZAP, Greenbone, snapshots, day diff, terms, Mode, stop on withdrawal) is reused, not rebuilt. It is valid while its parent domain is verified, the TXT is there and the name still resolves to the IP (gate in core, and the fence); a name that moved pauses it (`name_moved`, shown like `ip_not_current`). Servers count toward `MaxTargets` (20).
6. **Scan now on a domain** = discovery + classification + by-name checks of every name at its class's depth, then each server target of that domain in turn (oldest scan first, at most `MaxServersPerRun` = 3, one at a time, each its own snapshot and `exposure.scan` row); the rest are "not scanned this run, next in line". Box-wide one scan at a time and 10 minutes per target stay.
7. **Terms version bump** (`2026-11-1Xa`): the domain text adds "Names under {value} that a CDN or proxy serves are tested by name, through the CDN, without the disruptive checks; the CDN's servers are not scanned. Names on a hosted service (for example GitHub Pages or Shopify) get basic checks only. A server your names point at is scanned in depth only after you add it." A new version asks again (D-566).

## 4. Data model and caps

- `HostRow` (snapshot of the domain) becomes `{name, source: ct|dns|mx|ns|wordlist, cname, ips [{ip, family, class, provider, ptr, server_id}], web {status, title, product, cert_expiry}, checks [kind], not_checked}`; old snapshots read with `source: ct`, class unknown → shown as "classified from the next scan".
- `exp_target`: `kind` CHECK adds `server`; columns `parent_id`, `name` (migration 0010). `TargetView.server {parent, name, class_at_add}`.
- `CheckRow`/`NotCheckedRow` per name: "by name only (Cloudflare edge)", "basic checks only (GitHub Pages)", "deep scan waits for your OK", "not scanned this run (cap), last scanned …", "IPv6 not scanned", "wordlist skipped: wildcard DNS".
- Caps per run (each a "not scanned this run" line naming what was left and when it was last scanned; rotation by last-scanned date, so every name is reached in turn): ZAP pages `MaxWebScans` 4 (passive) / 2 (active, Full); http nuclei by name 50 names; servers 3; names listed 300 (hard, whole or nothing).
- Probe log (LEGAL §3): unchanged per probe; one `dns` row per run for the wordlist ("150 lookups via the box's resolver"), written before.

## 5. The fence [T]

Every step that sends anything beyond the D-229 checks to a public IP that is not the box's egress is a **`domain_ip` job**: nmap shape `external` with scope `domain_ip`, nuclei scope `domain_ip`, `zap.baseline`/`zap.active` kind `domain` on a `server` or `edge`, Greenbone's target. Job fields: `{domain, name, ip, token, class, ports}`.
The executor (scan container worker for nmap/nuclei, host for ZAP and Greenbone) checks, on its own, right before each tool start (each nuclei job, each ZAP page, Greenbone task start), cached ≤ 5 minutes per `(domain, name, ip)`:
1. Grammar: `domain` by exposure's domain RE; `name` = domain or ends in `.`+domain; `ip` public IPv4 (`localnet.Public`); `token` 32 hex → else `invalid_job`.
2. **Box-bound token**: `token == hex(HMAC-SHA256(fence_key, "vedette-verify\x00"+domain))[:32]`. `fence_key`: 32 random bytes the host makes at install (`<state>/fence.key`, 0600), mounted read-only into the scan container, **never into core**; core gets a domain's token from the host op `exposure.token {domain}` when the domain is added. Another box's token never matches → `token_foreign`. Domains verified before this keep their old token for today's scope; "Verify again" shows the new TXT value to add, and `domain_ip` jobs need it (`zap.baseline` gets the same check in this slice).
3. TXT of `domain` contains `vedette-verify=<token>` → else `target_not_owned`.
4. `name` resolves (A, system resolver, 10 s) to a set containing `ip` → else `name_moved` (that item only, like `zap_name_moved`).
5. Class from the executor's **own** embedded `content/edges`: an `edge`/`hosted` IP refuses any port scan, nmap, nuclei-tcp or Greenbone (`edge_ip`); by-name http through an `edge` is allowed with `Host`/SNI = name, never the disruptive set.
6. Lookup or DNS failure → `ownership_unchecked`. All refusals fail closed, nothing sent, audited by the executor.
A compromised core can then aim deep scans only at IPs that a domain carrying **this box's** TXT points at now: the customer's own DNS is the authority. The per-server OK is core's (decision 4); the fence does not repeat it. Container-only install (no host): no `domain_ip` jobs; the row says "needs the Vedette host".

## 9. Questions for kien (legal; recommendation given)

- **K1 (legal, amends D-25, D-57 (7), LEGAL §3).** May Vedette (a) port-scan and deep-scan a server that is not the box's own egress IP, when the domain carries this box's TXT token, a name under it points at the server at the moment of the scan (re-checked by the fence), and an admin with two-step sign-in accepted the server's terms saying it is dedicated to the company; and (b) run the non-disruptive active web scan by name through a CDN for names under a verified domain? **Recommendation: yes to both.** It is what Intruder (add the IP behind Cloudflare yourself) and Qualys (scan after attribution) do, with a stronger technical gate than theirs; Cloudflare's and AWS's policies allow (b) without DoS. Without it, slices 1–3 still ship and `other` rows say "scanned by name only (D-57 (7))".
- **K2 (money, small).** The slice-4 N100 check needs a server the team owns that is not the N100 (for example the cheapest VPS, about USD 5 a month), or a second static IP at the office. Recommendation: one VPS for the test month, deleted after.
