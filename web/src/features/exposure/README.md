# features/exposure

Screens (target tree, `GET /exposure/tree` and `/exposure/tree/{id}/*`): the list is the tree of targets (a name under a domain target sits under it, with whose ownership proof covers it), its open services and issues and its last run; Add and Edit are dialogs (a domain's scope: only this name, every name found, or the names chosen on its Names tab). A target's page has Issues (open, handled, no longer seen; handled in the findings vocabulary with a note for false positive, not relevant and accepted, and a last day for accepted), Services and Names (rows with first and last seen), Scans (its runs; steps, log and Stop are the shared run's, `/runs/{id}`), Ownership (proof, scan confirmation, testing terms) and, for an IP, what Shodan sees. The schedule of a target is the shared schedule `exposure.target:<id>`, set with the shared schedule editor under the scan line of its page. `conformance.test.ts` runs one script of calls against the mock and, with `VITE_EXPOSURE_REAL_URL`, against the real backend.

Story: S-EXP-1 (domain or public IPs the box finds itself → prove ownership → an administrator's first Scan now → list subdomains, IPs, open ports, exposed admin interfaces, expiring certificates; daily snapshots and comparing two days).
LEGAL §3 rule: no scan unless ownership is verified, and the commitment ("my company owns this and I am authorized to scan it", with who and when) is recorded. "Deep scan now" (a target whose testing terms are accepted) asks once in a dialog that shows the scope and warns that the scan can put a heavy load on the router or firewall in front of the target; the first Scan now shows that warning in its confirmation dialog. The "Scan now" button is locked with a reason, and the API returns 409 `not_verified` / `expired`, or 400 `commitment_required`, if called directly. A proof holds 90 days from its last pass: a check since that did not find it (a record or file gone, a lookup that failed, an IP the box does not go out through now) is a warning in `last_check` and under the ownership chip, not a refusal; removing the target whose record proved another one withdraws that proof at once.
Ownership: a domain = DNS TXT record `vedette-verify=<token>`, re-checked right before every scan (missing = blocked). A public IP = only an IP this box itself uses to reach the Internet; no endpoint takes an IP as input (typing one is 400 `ip_not_allowed`). Private, reserved and CGNAT results are refused (400 `not_public`); verification attempts by people are limited to 10 per hour; everything is audited.
Public IPs, auto-detect: the section "Public IPs of this box" has an auto-detect switch (on by default), a check interval (1 min to 24 h, default 60 min, only shown while auto-detect is on), "Detect now" and the IP list with last seen, expiry and Remove. The box asks three public "what is my IP" services (checkip.amazonaws.com, icanhazip.com, ifconfig.me/ip) over several rounds of new connections at first start and then every interval, accepts an IP only when at least two agree in a round, and adds or renews every IP that passed (several IPs behind a load balancer are all found). An IP is valid for 90 days after the box last saw it (`verified_at` = last seen, `expires_at` = +90 days, `validity` expiring at 5 days or less); it expires only when the box has not seen it for 90 days, and stays scannable until then even while the box goes out through another IP. Turning auto-detect off keeps the list. A removed IP comes back if the box keeps using it while auto-detect is on. API: `GET /exposure/targets` carries `box_ip {auto, interval_min, last_run}`; `PUT /exposure/box-ip/settings`; `POST /exposure/box-ip/verify` ("Detect now", `{items, message}`); remove = `DELETE /exposure/targets/{id}`.
Mock tables: `exp_targets`, `exp_snapshots`, `exp_commitments`, `exp_attempts`, `exp_settings`. DNS simulation: the first TXT check of a new domain says "not found", from the second it is found. The mock runs the automatic check when `GET /exposure/tree` or `GET /exposure/targets` finds it due (no timer); every IP a check sees is a node of the tree (`origin: box`), and "Verify again" of such a node passes only while the box leaves through it. Box egress simulation: localStorage `vedette-mock-egress` is a comma separated list of the public IPs the box currently leaves through (default `203.0.113.10,203.0.113.11`, a load balancer), , `offline` when no service answers, or `disagree` when they never agree.
For the scan module: `exposureTargetsStore` (kind, value, verified_at, expires_at), `exposureSnapshotsStore`, `exposureCommitmentsStore`; or `GET /api/v1/exposure/targets` and use only `scannable` targets.
Roles: add/delete target, auto-detect settings, Detect now, the first Scan now of a target = admin with two-step sign-in (it records the commitment); re-check ownership, scan now = operator; view = viewer.
Slots: none provided, none consumed.
Scan-time check (INV-13): `POST …/scan` of an IP runs the check that the box still goes out through it (a check of the last 5 minutes is reused, else one full check runs, and its answer, a "not seen" included, is reused for 5 minutes); a sighting renews the IP, and an IP not seen now stays scannable until its 90 days run out. Only the Shodan check answers 409 `ip_not_current` (`exposureIpPaused`). Tests move the clock (`vi.setSystemTime`, Playwright `page.clock`). Audit of the box's own runs: only on change (INV-11), a person's click always. The tree shows the state without probing: proof `not_current` while the last full check that got an answer did not see the IP and nothing has seen it since (the page says "Not in use now" and that the IP stays scannable until its proof expires). `box_ip.retry_in_min` is the wait when the 10 attempts an hour (shared by Detect now, Verify again and the DNS Check) are used up. Dates: `dates.ts` (feature-local, "9 Nov 2026, 21:01").
